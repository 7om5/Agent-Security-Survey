## 1. 150–300 字中文概述

本文针对 Claude Code、Codex CLI、Gemini CLI 等支持的 Agent Skills 生态，构建首个大规模、经行为确认并带标签的恶意 Skills 数据集。作者于 2026 年 1 月抓取 skills.rest 与 skillsmp.com 共 98,380 个技能，用 14 条静态模式（代码正则 + GPT-5.2 指令分析）筛出 4,287 个候选，再在 Docker 沙箱中以 60 秒窗口、蜜罐凭证和网络/系统调用监控做动态验证，经双人独立标注确认 157 个恶意技能、632 个漏洞。测量发现恶意技能平均含 4.03 个漏洞、跨中位 3 个 kill chain 阶段，84.2% 的漏洞位于 SKILL.md 自然语言文档；生态分化为负相关的 Data Thieves 与 Agent Hijackers 两类，单一发布者 smp_170 占 54.1%。研究不含任何密码学构造或证明，属于供应链测量与检测工程。

## 2. 研究背景、现有方法不足、精确定义的问题

Agent Skills 是可复用的文件包：`SKILL.md`（YAML frontmatter + 自然语言指令）加可选的 Python/Shell/JavaScript 辅助代码；安装后由 Agent 在本地以用户权限执行（p.2, §1；p.4, §2）。作者指出，技能安装通常直接授予完整本地用户权限、缺少交互确认，因而同时暴露代码级与指令级攻击面（p.3, §1；p.4, §2）。

现有工作的不足（p.4, §2 "Agent Skill Security"）：
- Shen et al. 测量 755,297 个 OpenAI GPTs，发现 2,051 个存在隐私泄露/有害内容等策略违规，但 GPTs 在服务端执行，没有技能这种本地权限攻击面；
- Schmotz et al. 证明技能文件可实施提示注入并绕过 Claude Code 护栏，但只覆盖指令注入，未做生态测量；
- Liu et al. [19] 标记 26.1% 技能存在潜在风险模式，但无法区分恶意意图与开发者失误，也无法确认可疑代码是否真的执行；
- Cisco Skill Scanner 将 10.7% 技能标为 CRITICAL（p.4）；其参考文献 [9] 则称在本文数据集上 false positive rate 为 10.7%，原文对同一数字的两种说法并不一致（见 §9）。两者都缺少行为确认。

因此本文要解决的问题是：在没有 ground truth 的情况下，如何构建一个经行为验证的恶意技能标注数据集，并据此回答三个 RQ（p.3, §1）：RQ1 威胁版图（技术、kill chain 阶段、复杂度分层）；RQ2 攻击策略与攻击者原型；RQ3 规避检测与平台原生攻击向量。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **技能包**：`SKILL.md` 持久指令（YAML frontmatter） + 可选辅助脚本（Python/Shell/JS）；由 Claude Code、Codex CLI、Gemini CLI 等加载（p.4, §2）。
- **分发**：社区注册表 skills.rest 与 skillsmp.com 从公开 GitHub 仓库爬取并索引，不实施集中治理或安全审查（p.5, §3.1–3.2）。
- **执行**：安装即授予完整本地用户权限，脚本可读文件、读环境变量、发网络请求；Agent 同时把 `SKILL.md` 当指令读取（p.3, §1；p.5, §3.1）。这与 MCP 不同：MCP 工具代码运行在单独管理的服务器上，技能在本地运行（p.4, §2）。
- **信任边界（原文未画独立图，按 §3.1 与 Fig.1 归纳）**：不可信的技能发布者 → 无审查的注册表 → 无确认安装的用户 → Agent 上下文（自然语言指令直接进入 LLM）→ 本地 OS/凭证/网络。论文的威胁模型只覆盖"发布者→用户"这一条链，未形式化 registry、平台、模型提供方之间的信任关系。
- **受保护资产**：API keys、tokens、passwords、SSH keys、`.env`、源代码、对话上下文、Agent 记忆、用户邮件收件人（BCC）等（p.9, §4.1；p.12–13, §4.2–4.3）。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- **攻击者**：技能发布者（skill publisher），发布看似无害的技能，诱使不知情用户安装并执行（p.5, §3.1 "Threat Model"）。
- **能力**：可任意编写 `SKILL.md` 与捆绑脚本；无需内存破坏或提权漏洞，因为技能已预授权用户权限（p.4, §2；p.14, §5.2 "collapsed privilege model"）。
- **目标**（p.5, §3.1）：(1) 数据窃取（凭证、源代码、对话上下文）；(2) Agent 劫持（未授权动作、绕过安全控制）；(3) 持久化（供应链植入、隐藏触发器）。
- **攻击向量**（p.5, §3.1）：代码级（凭证收集、网络侦察、数据外传）与指令级（`SKILL.md` 中的提示注入、隐藏指令）。
- **前提/排除**：只研究"有意滥用"，排除过失性漏洞与针对底层 LLM 的攻击（p.5, §3.1）；数据仅覆盖两个社区注册表的 2026 年 1 月快照，不含私有/未索引仓库、直接分享、企业部署、MCP servers、官方 curated 集合（p.5, §3.2）。
- 原文没有形式化的攻击者能力定义、trust boundary 图或安全游戏；"Threat Model" 是操作型描述，而非可证明模型。

## 5. 核心方案：算法、协议、架构、公式、关键步骤

本文没有新密码协议或算法，核心是一条"静态筛候选 → 沙箱行为确认 → 人工标注 → 统计分析"的测量流水线（Fig.3, p.3）。

1. **数据收集**（p.5, §3.2; Table 2）：skills.rest 通过分页 API 获得 25,187 个技能（2,337 个 GitHub 仓库）；skillsmp.com 通过字母前缀搜索枚举获得 73,193 个技能（8,909 个仓库）；合计 98,380 个技能、11,246 个仓库。
2. **静态候选识别**（p.5–6, §3.3; Table 3）：把技能行为映射到改编自 MITRE ATT&CK 的 6 个阶段（Reconnaissance、Credential Access、Execution、Defense Evasion、Exfiltration、Impact），定义 14 条检测模式。代码级用正则（E1、E2、E3、E4、SC1、SC2、SC3、PE1、PE2、PE3 等，完整简化正则见 p.20 Table 9）；指令级（P1 指令覆盖、P2 隐藏指令、P4 行为操纵）因自由文本变化大，改用基于 GPT-5.2 的 LLM 分析代理，对每个 `SKILL.md` 输出 JSON `{P1, P2, P4, evidence}`（p.6 脚注 0；p.19 A.2）。共得 4,287 个候选（4.4%）。14 条模式中 13 条在确认样本中出现，E4（网络侦察）从未出现。
3. **行为验证**（p.6, §3.4; p.19 A.3）：4,287 个候选全部放入隔离 Docker（Ubuntu 22.04、Python 3.10、Node.js 18），每容器 2 GB 内存、60 秒超时；监控包括 tcpdump 出站流量、strace/dtrace 系统调用、auditd 文件审计、蜜罐凭证（fake API/SSH keys）。激活方式三种：(1) 按文档入口调用；(2) GPT-5.2 根据技能描述生成典型/边界/对抗输入；(3) 每技能 3–5 轮多轮执行。762 个技能触发至少一个运行时指标；两名作者独立复核（行为日志、代码检查、文档-行为对比、1–3 置信度），只有双方均 ≥2 才确认，κ=0.89；最终 157 个确认恶意（3.7% 候选，0.16% 全库）。
4. **漏洞标注**（p.7, §3.5）：两名作者按 Table 3 模式独立标注 632 个漏洞实例，分歧讨论解决，κ=0.91；严重度按 OWASP agentic 框架分 CRITICAL/HIGH/MEDIUM/LOW。另比较"文档声明"与"实际运行行为"，标注 shadow feature（不可从公开描述推断的能力），κ=0.83；115/157（73.2%）技能含 shadow feature。
5. **共现与统计**（p.7, §3.6）：对 13×13 模式共现矩阵计算 odds ratio 与条件概率：
   - `OR(Pi,Pj) = (n11 · n00) / (n10 · n01)`（Eq.1）
   - `P(Pj|Pi) = |{s: Pi∈s ∧ Pj∈s}| / |{s: Pi∈s}|`（Eq.2）
   使用 Fisher 精确检验、Mann-Whitney U、Spearman 相关，所有成对检验做 Bonferroni 校正（α=0.05/k）；用 Louvain 做社区发现。按漏洞数、规避技术、shadow feature 把技能分为 Level 1–3（p.7, §3.6）。
6. **披露验证**：向注册表维护者报告全部 157 个技能，最终 157/157 被移除（p.8, §3.6; p.15, §6）。

## 6. 安全属性与安全性论证

- 论文**没有形式化安全定义、定理或证明**。其"malicious"是操作型行为定义（Table 1, p.5）：技能表现出凭证收集、未授权外传、远程代码执行、提权或指令操纵等行为，且实现显示是有意滥用而非偶发 bug。
- 论证方式是经验性的：行为确认（不是模式命中）、双人独立标注（κ=0.89/0.91/0.83）、300 个技能上的 5 折交叉验证（99.6% precision）、以及注册表维护者独立下架 157/157（作者称为外部验证）。
- 没有 soundness/completeness 保证：静态阶段只缩小搜索空间；动态阶段受 60 秒、单会话、Docker 环境限制；作者明确承认确认集是 lower bound（10% 未确认样本中 93.2% 为未触发 dormant 恶意）。
- 这不是密码学意义上的安全属性（如不可伪造性、保密性、完整性），而是检测系统的经验精度与标注一致性。

## 7. 实验细节：模型、环境、数据集、对照方法、指标、核心结果、消融

**数据与运行环境**：2026 年 1 月快照；98,380 个技能（Table 2, p.5）。全流水线在 64 核 AMD EPYC、256 GB RAM、2 TB NVMe 上约 72 小时（p.8, §4；p.21 G）。动态容器 Ubuntu 22.04、Python 3.10、Node 18、2 GB、60 秒（p.6, §3.4）。

**核心结果（均限 157 个确认技能、632 个漏洞）**：
- 平均 4.03 个漏洞/技能，中位 4；80.3% 含 ≥3 个；单一技能最多 13 个（p.8–9, §4.1; Fig.4; Table 5）。严重度：CRITICAL 252（39.9%）、HIGH 202（32.0%）、MEDIUM 176（27.8%）、LOW 2（0.3%）；按计数 CRIT+HIGH 为 454/632=71.8%，正文写 71.8%，表内百分比相加为 71.9%（p.9 Table 5，属舍入差异）。
- 最常见模式：SC2 远程脚本执行 159（25.2%）、P4 行为操纵 119（18.8%）、E2 凭证收集 112（17.7%）；指令级 P1–P4 合计 209（33.1%）（p.8–9, §4.1; Table 4）。
- **自然语言攻击面**：532/632（84.2%）漏洞位于 `SKILL.md`；可执行代码仅 8.5%；配置与其他 7.3%（p.9, §4.1）。
- Kill chain 覆盖：Execution 118 技能（75.2%）、Impact 109（69.4%）、Credential Access 107（68.2%）、Exfiltration 90（57.3%）、Defense Evasion 25（15.9%）、Recon 12（7.6%）；中位 3 阶段，68.2% 覆盖 ≥3 阶段，50 个（31.8%）覆盖 ≥4，1 个覆盖全部 6 阶段（p.10, Table 6; Fig.5）。
- 复杂度分层：Level 1 25（15.9%）、Level 2 122（77.7%）、Level 3 10（6.4%）（p.10, Table 7）。Table 8（p.11，已渲染核对）显示单调梯度：平均漏洞 2.80→4.01→7.30；平均阶段 1.23→3.10→5.10；E2→E1 链 3.8%→39.3%→90.0%；shadow feature 0%→86.1%→100%。
- RQ2 两类原型：Data Thieves（SC2 为中心）110 个（70.1%），Agent Hijackers（P1 为中心）16 个（10.2%），hybrid 8 个（5.1%）。SC2 与 P1 负相关：仅 8/157 共现，OR=0.11，p<0.001，φ=−0.41（p.11, §4.2）。
- E2→E1：58/157（36.9%），OR=2.24，Fisher p=0.020，95% CI [1.09, 4.66]，Cramér's V=0.19（p.11；p.19 B.2；列联表 58/43/21/35）。
- 单发布者集中：smp_170 有 85 个技能（54.1%）、370/632 个漏洞（58.5%）；E2+SC2 指纹在 smp_170 中 83/85（97.6%），非 smp_170 仅 5/72（6.9%），OR=556.1，p<0.001（p.11–12, §4.2）。品牌冒充覆盖 85 个品牌、15 个行业，100% 模板一致（26 行相同）。
- RQ3 规避：shadow feature 115/157（73.2%）；构成：未文档化网络端点 47.2%、条件触发器 18.4%、混淆代码 11.0%、注释/标记隐藏指令 6.7%、其他 16.7%（p.12, §4.3）。代码混淆仅 15 个（9.5%）：Base64+exec 61.1%、marshal/pickle 22.2%、hex 16.7%。shadow feature 随复杂度 0%→86.1%→100%，混淆 0%→7.4%→60.0%。
- 平台原生攻击（p.13, §4.3）：模型替换（Plan Refine 把 Claude API 重定向到 attacker-proxy.example，替换为 custom-lm）、`--dangerously-skip-permissions` 滥用、随包 `.mcp.json` 硬编码 API 凭证、Claude Code hooks 拦截/外传/转储记忆、hook 注入的 sleeper 触发。原文称该子集 n=6，但正文可数出 8 个对象，计数有歧义（见 §9）。
- 检测评估：300 个技能（150 benign 从 94,093 个未命中静态模式者随机抽，150 malicious 从 157 确认集抽），5 折交叉验证；报告 99.6% precision、每折平均 0.6 个假阳性；对照 Cisco Skill Scanner 的静态基线 ≤1.1% precision（p.8, §3.6；p.20 F.2）。召回用 4,130 个未确认候选的 10%（413 个）人工复核估计：93.2% dormant、4.9% 合法安全工具、1.9% 漏报（约 78 个），故 157 是下界（p.8；p.20–21 F.3）。
- **内部一致性问题（本人推断）**：p.3 称相对静态基线"90× improvement（≤1.1% precision）"，但参考文献 [9] 自述 Skill Scanner 的 false positive rate 为 10.7%，两者不是同一指标，无法直接换算；p.8 的 "99.6% precision、每折 0.6 FP" 在 300 样本/5 折（每折 60、其中 30 benign）下按 30/(30+0.6) 约为 98.0%，与 99.6% 不一致。论文未给混淆矩阵，无法核对。这些不否定主结果，但降低精度数字的可信度。

## 8. 主要贡献、与直接相关论文的差异、可复现资源

- **首个带行为确认标签的恶意 Agent Skills 数据集**（作者声称 "first large-scale labeled dataset"）：157 个技能、632 个漏洞、shadow-feature 标注，以及可复现 98,380→4,287→157 漏斗的检测流水线（p.3, §1 Contributions；p.7, §3.5）。
- **多维威胁刻画**：RQ1 技术/阶段/复杂度版图；RQ2 两个负相关原型与单发布者产业化；RQ3 文档级隐蔽与平台原生攻击（p.3–4）。
- **生态影响验证**：负责披露后 157/157（100%）下架；提交时已下架 147/157（p.15, §6 Ethical Considerations）。
- 与最接近工作 [19] 的差异：后者只做静态风险标记（26.1%），无法区分意图与确认执行；本文以行为验证产生 ground truth（p.4, §2；p.3, §1）。与 Cisco Skill Scanner 的对比口径为 10.7% CRITICAL vs 99.6% precision，二者不是同一指标，不能直接比较（见 §9）。
- 可复现资源：项目网站与 Zenodo DOI `10.5281/zenodo.20285751`（p.16）；聚合标签、检测逻辑、共现矩阵、脚本公开，完整恶意 payload 需申请（机构邮箱、用途说明、不转发承诺），不公开仓库 URL 与作者身份（p.15–16）。**本人未下载/核验这些 artifact**。

## 9. 局限性、失效场景、作者未解决的问题

作者自述（p.14, §5.4；p.16）：
- 数据是 2026 年 1 月快照；刷新时技能数为 12.6 倍，标签会老化。
- 60 秒动态窗口可能漏掉时间延迟、环境门控、需要用户交互或反沙箱的 payload；确认集是 lower bound。
- 漏洞分类基于既有事件与安全公告，可能漏掉新攻击模式。
- 人工标注对意图模糊样本仍有判断成分（κ=0.91 不等于真值）。
- smp_170 占 54.1%，per-skill 聚合被单发布者 skew；作者改报 per-publisher 集中度（Gini=0.71）。
- 只覆盖两个公共注册表，不能推广到企业部署、私有分享、MCP。

**本人补充的失效场景/质量问题**：
- 检测器依赖 GPT-5.2 与提示模板；模型版本漂移会改变 P1/P2/P4 判定，而正文只给简化模板（p.19 A.2），完整模板在代码库，复现性受限。
- "恶意"定义要求"有意滥用"，但自动化流水线无法直接观测意图；最终仍由两名作者主观判定，存在把双用途工具（渗透测试、凭证管理器）误标的风险，作者也承认 605 个未确认者中多数是这类工具（p.7）。
- 静态正则（p.20 Table 9）非常宽松（如 E1 匹配 `requests.post/put/get` 到任意非 localhost URL，P4 匹配 always/never/must + execute/run/perform/question），假阳性高，必须依赖动态阶段；这也意味着 4,287 个候选的召回上界由正则决定，未做模式消融。
- 对同一 10.7% 数字，p.4 称 Cisco Skill Scanner 将 10.7% 技能标为 CRITICAL，参考文献 [9] 却称这是 false positive rate；两种说法指向不同指标，原文未澄清。
- 平台原生攻击子集计数不自洽：p.13 称 n=6，但正文列出模型替换 1 + 另两个滥用 flag 的技能 + 供应链木马 1 + Lark Agent 1 + Hooks Automation 1 + 两个 sleeper = 8；"Three skills weaponize Claude Code's own infrastructure"（p.13–14）也无法与列举对象一一对应。

- 无成本/延迟测量：静态扫描 + LLM 判定 + 4,287 个 Docker 沙箱（72 小时、64 核）对注册表规模部署是否可行，论文未给每技能成本或吞吐。

**个人推断（明确不是原文贡献）**：
- 可形式化的问题 1：把"恶意技能"定义为工具调用轨迹上的安全性质（如"未授权读取凭证文件 ⇒ 不得向未声明端点发送"），研究检测器的 soundness/completeness；但这是程序语言/运行时监控问题，不是密码学，且论文的多会话漏报（1.9%）说明轨迹需要跨会话状态。
- 可形式化的问题 2：技能来源与版本的可验证性（发布者签名、透明日志、可重现构建）只能保证"谁发布、内容未被篡改"，不能保证"行为与声明一致"；本文 73.2% 的 shadow feature 正是"声明-行为不一致"，说明纯密码学 provenance 不足以定义恶意性。
- 可形式化的问题 3：若要给"文档声明-实际行为一致性"提供可审计保证，需要把声明编译为策略、用 TEE/远程证明或审计日志绑定运行时行为；这是应用密码学 + 系统安全的交叉，本文未做。
- 结论：该论文对理论密码学的直接相关度很低；它的价值是提供"恶意技能"的 ground truth 与攻击面证据，而不是密码学问题定义。

## 11. 与应用密码学/密码工程可能的技术连接（同上）

**原论文已做（均为测量/检测工程，不是密码工程）**：
- 用蜜罐凭证（AWS_*、API_*、SECRET_*、TOKEN_* 命名模式）诱导外传并作为确认证据（p.6, §3.4；p.19 A.3）。
- 用 Docker 网络隔离 + tcpdump 捕获出站连接、strace 跟踪网络/文件系统、auditd 审计、inotify 监控敏感路径（p.19 A.3）；没有 TLS 拦截、证书校验或密钥材料分析。
- 把 `.mcp.json` 硬编码 API 凭证、`--dangerously-skip-permissions`、Claude Code hooks 外传/记忆转储列为平台原生攻击（p.13, §4.3）；这些是凭证管理与平台配置问题，论文只把它们当攻击载体，没有给出密码学防护或评估。
- 披露与下架流程（p.15）；没有签名、证书、密钥轮换、令牌作用域实验。

**个人推断（应用密码学/密码工程接口）**：
- **技能 provenance**：对 `SKILL.md` 与脚本做签名 + 透明日志 + 版本哈希，可缓解品牌冒充（smp_170 的 85 个仿冒技能）与供应链木马（smp_2485 的三行注入）；但攻击者可以用自己的密钥签名，所以必须把"发布者身份"与"品牌/仓库所有权"绑定，并支持撤销。论文的 100% 下架说明注册表有运营能力，但没有密码学身份层。
- **凭证最小化**：把技能可访问的凭证改为短期、audience-bound、scope-limited 的令牌（如 OAuth token exchange / DPoP / mTLS 绑定），可降低 E2→E1 链的收益；需要在 Agent 运行时做强制策略执行，本文未评估。注意：论文里的 "token" 是被盗资产，不是协议设计。
- **MCP/配置完整性**：对 `.mcp.json`、hooks 配置做签名与完整性度量，凭证不落盘、自动轮换；这是与密码工程团队积累最接近的接口，但论文只报告了攻击，没有防护设计或性能数据。
- **平台原生攻击的通道安全**：模型替换（把 API 调用重定向到 attacker-proxy）本可由端点认证/证书固定/远程证明缓解；论文没有分析现有 TLS 是否失效、代理如何绕过，因此不能把"MITM"当作已被论文证明的密码学缺陷。
- **伪交叉风险**：给技能加哈希/签名、把 OAuth 流程包进安装器，如果不解决"签名者就是恶意发布者"与"自然语言指令语义"两个问题，不构成研究贡献；本文的 84.2% 自然语言攻击面是密码学手段无法单独覆盖的负结果。

## 12. 后续可以验证的研究假设（不得仅因论文没提就判断领域没人做过）

- H1：仅靠发布者签名/透明日志不能显著降低恶意技能数量，因为攻击者可用自己的密钥签名并做品牌冒充；需要"身份绑定 + 行为声明"联合验证。可在本文 157 个样本与 smp_170 模板上做检测评估。
- H2：把技能可访问凭证改为短期、audience-bound、最小作用域令牌后，沙箱中 E2→E1 链的成功率与可外传数据量显著下降；可用本文的动态验证框架做对照实验。
- H3：文档-行为一致性（shadow feature）可以被形式化为可审计属性；用 115 个 shadow 标注样本评估检测器的 precision/recall 上限，并测量多会话触发的漏报。
- H4：跨技能模板相似度（smp_170 的 26 行完全相同模板、smp_2485 的 98.3% 文本相似）可用于发布者归因；密码学透明日志能否在不公开 payload 的前提下支持跨版本相似性查询与撤销，值得验证。
- H5：平台原生攻击（模型代理替换、hook 外传）需要端点认证/配置完整性/远程证明；但本文未评估现有 TLS 与权限模型是否已部分缓解，不能先验假设密码学方案有效。
- 以上均为假设，需在后续论文与实验中查证；本文没有提供任何密码学评估。
