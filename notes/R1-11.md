## 1. 150–300 字中文概述

本文提出 ToolHijacker，首个针对 LLM Agent 工具选择（检索＋选择两阶段）的 no-box 提示注入攻击。攻击者只需在开放工具市场发布一个恶意工具文档，在不知道目标任务描述、检索器、目标 LLM、工具库和 top-k 的情况下，使 Agent 对目标任务的多种语义表述持续选择恶意工具。作者把恶意工具描述的构造形式化为优化问题，因离散、不可微而分解为检索目标与选择目标，将描述拆成 R⊕S 两个子序列分别优化，并给出无梯度（LLM 生成＋树搜索）与梯度（HotFlip/JudgeDeceiver 式损失）两种解法。MetaTool/ToolBench 上 8 个 LLM、4 个检索器的实验显示 ASR 最高 99.6%、AHR 最高 100%，StruQ/SecAlign 与四类检测防御均不足。该工作是经验性对抗机器学习攻击，不含密码学原语或证明。

## 2. 研究背景、现有方法不足、精确定义的问题

- 工具选择是 LLM Agent 的关键阶段，主流实现是“检索＋选择”两步：检索器从工具库取 top-k 文档，LLM 再从中选出最合适的工具（PDF p.1, p.3, §I–II.A）。
- 现有提示注入攻击分手动与自动两类。手动攻击（naive、escape characters、context ignore、fake completion、combined）由启发式构造，开发耗时、跨场景泛化有限；自动攻击 JudgeDeceiver [13] 用优化框架生成注入序列，但主要针对“选择/评判”阶段，是单阶段攻击；PoisonedRAG [21] 虽考虑检索，但面向 RAG 生成，向知识库注入多条对抗文本，不直接操纵工具选择（p.1–2, §I；p.13, §VI.B）。
- 精确空白：需要一个**端到端**攻击，用**单个**恶意工具文档同时通过检索与选择两个阶段，并且在 **no-box** 条件下（不知道目标任务描述集合、检索器、LLM、工具库与 top-k）对目标任务的多种语义改写都有效（p.1–4, §I–III）。
- 形式化问题：给定目标任务（其语义等价描述集合 Q 对攻击者不可见），构造恶意工具文档 dt={dt_name, dt_des}，注入工具库 D 后，使目标 LLM 对 Q 中尽可能多的 qi 都输出 dt（Eq.5, p.4）。攻击者用自己构造的影子描述集合 Q′ 与影子工具库 D′ 作为优化代理，并要求 Q∩Q′=∅（p.4, §III.B）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- 组件（p.3, §II.A）：
  - **工具库** D={d1,…,dn}，每个工具文档含 tool name、tool description、API specifications；攻击只优化 name 与 description，因为已有工作 [8],[30] 表明工具选择主要依赖这两项（p.3）。
  - **检索器**：双编码器 fq（任务描述编码）与 fd（工具文档编码），用余弦相似度或点积 Sim(·,·) 取 top-k，Dk=Top-k(q;D)（Eq.1–2）。
  - **选择 LLM** E：输入结构化 prompt，`p_header ⊕ q ⊕ d1 ⊕ … ⊕ dk ⊕ p_trailer`，输出被选工具名（Eq.3–4；Fig.2 给出 header/trailer 与 JSON 输出格式）。
- 交互流程：用户任务 q → 检索 top-k → LLM 选择 d* → 直接调用该工具。论文明确假设“select-and-execute”：一旦恶意工具被选中，就会在无进一步验证的情况下执行（p.3, §II.B）。
- 信任边界（论文未画显式 trust boundary 图，以下为本人从 §II.B 还原）：第三方开发者在开放工具市场（Hugging Face Hub、Apify、PulseMCP）提交工具文档 → 工具库混合了可信与不可信文档 → 检索器只按语义相似度排序、不做信任判断 → 检索结果作为 prompt 上下文与指令同通道进入 LLM → LLM 选定后直接执行。核心脆弱点是**检索到的数据与系统指令没有结构隔离**，而工具选择又完全由该上下文决定。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- **资产**：目标任务的正确工具选择（决策完整性）；恶意工具执行后可触及的用户数据、系统完整性与隐私（未授权数据访问、隐私泄露等，p.3）；良性工具生态的公平选择。
- **攻击者目标**：选定一个目标任务，用任意语义等价的描述 qi∈Q 查询时，Agent 都优先选择攻击者的恶意工具，绕过所有良性工具；攻击是**有针对性**的，不要求影响其他任务（p.3–4, §II.B）。
- **攻击者能力**（no-box，p.3–4, §II.B）：
  1. 知道目标任务的语义，但**不知道**目标描述集合 Q；
  2. **不能**访问目标工具库内容；
  3. **不能**获知 k 或 top-k 检索结果；
  4. **不能**访问目标检索器与目标 LLM 的参数；
  5. **不能**直接查询目标检索器或目标 LLM。
- **攻击者可以**：构造影子任务描述 Q′、影子工具文档 D′、部署影子检索器 f′ 与影子 LLM E′ 进行离线优化；在开放工具市场发布恶意工具（p.4）。
- **前提假设**：Q∩Q′=∅；工具选择主要依赖 name/description；恶意工具被选中后无二次验证；影子模型与目标模型之间存在可迁移的语义模式（p.4–5, §III.C）。论文用实验证明迁移有效，但没有给出迁移的理论保证。
- **与黑盒的区别**：这里的 no-box 比通常的 black-box 更严格——攻击者连查询目标系统的机会都没有，只能靠影子管线与迁移（p.1, p.3–4）。这是本文威胁模型的核心卖点，也是其性能上界的来源。

## 5. 核心方案：算法、协议、架构、公式、关键步骤

整体是一个离散优化问题，因不可微且局部极值多，分解为两个子目标，并把工具描述拆成 R⊕S 两个子序列分别优化（p.4, §III.A–B）。

1. **总体目标**（Eq.5, p.4）：
   \[
   \max_{dt}\ \frac{1}{m'}\sum_{i=1}^{m'} \mathbb{I}\left(E'(q_i', \mathrm{Top\text{-}k'}(q_i'; D'\cup\{dt\}))=o_t\right)
   \]
   其中 E′ 是影子 LLM，f′ 是影子检索器，k′ 是攻击者设定的影子 top-k，o_t 表示选中恶意工具的输出。
2. **检索子目标（优化 R）**：
   - 无梯度：用 LLM 从影子描述 Q′ 合成一段通用的“工具功能描述” R，要求覆盖核心功能、适用于多种场景、长度约 num 词（p.4–5，模板见 p.5 顶部）。
   - 有梯度：最大化 R 与各影子描述的平均相似度，Eq.6：`max_R (1/m') Σ Sim(f'(qi'), f'(R⊕S))`；用无梯度结果初始化 R，再用 HotFlip [33] 做 token 级优化；迁移性依赖不同检索器学到的语义模式重叠（p.5, §III.C）。
3. **选择子目标（优化 S）**：
   - 无梯度：树搜索（Algorithm 1, p.5），受 tree-of-attacks [34] 启发。攻击者 LLM EA 对每个当前叶节点生成 B 个变体；对每个变体，在 m′ 个影子描述上查询影子 LLM，用正则化匹配 EM 统计选中恶意工具名的次数 FLAG；若某节点 FLAG=m′ 立即返回；否则按 FLAG 剪枝到最大宽度 W，并把响应与 FLAG 作为反馈进入下一轮；对每个 qi′ 迭代 Titer 次。
   - 有梯度：最大化影子 LLM 生成恶意工具名的似然（Eq.7–8）。损失由三项组成（Eq.9–13）：
     - L1 alignment：`-log E'(o_t | x(i), S)`，提高完整目标输出的概率；
     - L2 consistency：`-log E'(dt_name | x(i), S)`，强化工具名生成；
     - L3 perplexity：序列平均负对数似然，提升可读性；
     - `L_all = L1 + αL2 + βL3`，`min_S Σ L_all`（Eq.13–14）。采用 JudgeDeceiver [13] 的 position-adaptive（把 dt(S) 放在检索集合的不同位置）与 step-wise（逐步加入任务-检索对）优化策略（p.6, §III.D）。
4. **最终文档**：`dt = {dt_name, R⊕S}`。dt_name 由人工构造且 token 有限，以保证语义清晰；R 负责“被检索到”，S 负责“被选中”（p.4, p.9 Table V）。
5. **关键超参数与成本**：m′=5，k′=5；无梯度攻击用 Llama-3.3-70B 同时作 attacker 与 shadow LLM，Titer=10、B=2、W=10；有梯度攻击用 Contriever 作 shadow retriever、Llama-3-8B 作 shadow LLM，α=2.0、β=0.1，R 优化 3 次、S 优化 400 次（p.7, §IV.A.4）。成本：无梯度 R 需 1 次 LLM 查询、S 约 18 次 LLM 查询；有梯度 R 约 1 GPU 分钟、S 约 8 GPU 小时（单张 NVIDIA A800）（p.17, Appendix B）。
6. **攻击流程**：选定目标任务 → 生成 Q′/D′ → 优化 R → 优化 S → 拼接并发布恶意工具文档 → 目标 Agent 检索到 dt 并在选择阶段选中 → 执行恶意工具。

## 6. 安全属性与安全性论证

- **未提供形式化安全定义、定理或证明**。论文的“安全性论证”完全是经验性的：以 ASR（恶意工具被选中的比例）与 AHR（恶意文档进入 top-k 的比例）衡量攻击效果，以 ACC/ACC-a 衡量系统效用（p.7–8, §IV.A.5）。
- 攻击目标 Eq.5/7 是经验期望指标，不含泛化界、分布假设或对抗鲁棒性证明；“对不同语义描述持续有效”来自 10 个目标任务 ×100 条描述的测试，而非证明（p.6–8）。
- 论文展示的经验性质：
  - 跨 8 个目标 LLM、4 个检索器、2 个数据集、不同 k/k′、不同工具库规模均保持较高 ASR/AHR（p.7–10, p.17）；
  - 攻击是 targeted：对非目标任务，GF ASR 0%、GB 0.11%（p.16, Table XII）；
  - 生成的恶意文档 token 长度与良性文档接近，单凭长度难以区分（p.8, Fig.4）；
  - StruQ/SecAlign 与四类检测器均不能可靠防御（p.11–12）。
- 这不是密码学意义上的“安全性”：没有密钥、没有敌手计算能力假设、没有可证明的完整性/认证属性；工具选择与检索排序也不是认证机制。

## 7. 实验细节：模型、环境、数据集、对照方法、指标、核心结果、消融

- **数据集**（p.6, §IV.A.1）：
  - MetaTool：21,127 个实例，199 个来自 OpenAI Plugins 的良性工具文档；
  - ToolBench：126,486 条指令微调样本，16,464 个 RapidAPI 工具文档，去重并删除空描述后剩 9,650 个良性工具文档；
  - 每个数据集设计 10 个高质量目标任务，每个任务用 LLM 与人工生成 100 条描述，共 1,000 条/数据集。
- **目标 LLM**（8 个）：Llama-2-7B-chat、Llama-3-8B-Instruct、Llama-3-70B-Instruct、Llama-3.3-70B-Instruct、Claude-3-Haiku、Claude-3.5-Sonnet、GPT-3.5、GPT-4o（p.7）。
- **目标检索器**（4 个）：text-embedding-ada-002、Contriever、Contriever-ms、Sentence-BERT-tb（p.7）。
- **对照基线**（7 个）：5 个手动攻击（naive、escape characters、context ignore、fake completion、combined）＋ JudgeDeceiver、PoisonedRAG（p.6, §IV.A.2）。
- **指标**：ACC（无攻击时选对工具）、ASR（注入后选中恶意工具）、HR（top-k 含正确工具）、AHR（top-k 含恶意文档）；默认 k=5；ASR/AHR 在 10 个目标任务上取平均，每个任务 100 条描述（p.7–8, Eq.15–16）。
- **主结果**（Table I, p.7；已渲染核对）：
  - 无梯度攻击（shadow Llama-3.3-70B）：MetaTool ASR 85.4%–99.6%，ToolBench 77.7%–93.6%；
  - 有梯度攻击（shadow Llama-3-8B）：MetaTool 82.6%–100%，ToolBench 74.3%–96.6%；
  - GPT-4o 上：GF 96.7%（MetaTool）/88.2%（ToolBench），GB 92.2%/83.9%；
  - Claude-3-Haiku 最不敏感，但仍 ≥70%（MetaTool GF 85.4、GB 82.6；ToolBench GF 82.8、GB 74.3）。
- **检索命中**（Table II, p.7）：MetaTool AHR：GF 99.9%、GB 100%；ToolBench：GF 96.1%、GB 97.8%；无攻击 HR 均为 100%。
- **基线对比**（Table III, p.8；GPT-4o）：
  - MetaTool：naive 6.0%、escape 28.2%、context ignore 1.2%、fake completion 14.5%、combined 9.7%、JudgeDeceiver 30.2%、PoisonedRAG 39.3%、GF 96.7%、GB 92.2%；
  - ToolBench：24.8%、24.6%、11.3%、23.0%、11.7%、26.4%、58.3%、88.2%、83.9%。
  - 作者归因：手动攻击的注入文本与任务无关、被检索概率低；PoisonedRAG 针对单条任务描述优化，而本文跨多条描述优化。
- **消融**：
  - R 与 S 的贡献（Table V, p.9）：GF 的 R⊕S 为 AHR 100%/ASR 99%，去掉 R 后 AHR 100%→65%，去掉 S 后 ASR 99%→5%；GB 的 R⊕S 为 100%/95%，仅 R 为 100%/0%，仅 S 为 99%/16%。
  - k 与 k′（Fig.5, p.9）：k=1 时 AHR/ASR 均 89%；k>3 后 AHR 稳定 100%，GB ASR 约 96%、GF 约 99%。k′=2 时 GB AHR 从 74%→99%（k 从 1 到 3）；k 从 1 到 5 时 GF/GB ASR 分别下降 16%/50%。
  - 影子描述数量 m′（Fig.6, p.10）：m′ 从 1→7，GB ASR 从 32%→98%；GF 即使只有 1 条描述仍 ≥92%；AHR 始终 100%。
  - 检索器（Table IV, p.9）：GF 在 4 个检索器上均 AHR 100%/ASR 99%；GB 在 3 个开源检索器上 ASR 100%，在 text-embedding-ada-002 上 95%。
  - 相似度度量（Table VIII, p.10）：点积比余弦高 2% ASR。
  - 影子 LLM（Tables VI–VII, p.10）：更强的 shadow LLM 提升 ASR；GF 用 Claude-3.5-Sonnet 比 Llama-2-7B 平均 +4.37%；GB 用 Llama-3-8B 比 Llama-2-7B 平均 +15.12%；GF 对 shadow 选择更不敏感（最差 70%），GB 最差可到 34%（Llama-2-7B shadow → Llama-3-70B target）。
  - 恶意工具数量（Fig.7, p.11）：num=2 的 individual 设置在 k=5 时比 num=1 提高 24% ASR；unified 设置 ASR/AHR 接近 100%。
  - 动态工具库（Table XVI, p.17）：MetaTool 50→150 个工具，GF ASR 98.8%→96.7%、GB 98.0%→93.3%；ToolBench 2,500→7,500，GF 95.8%→92.8%、GB 88.7%→84.8%。**注意**：正文把“GF ToolBench ≥93.3%”和“GB MetaTool ≥92.8%”写反了，与 Table XVI 的数值互换，属论文内部不一致（已渲染核对）。
  - 非目标任务（Table XII, p.16）：针对 task 1 优化，在其余 9 个任务的 900 条描述上，GF ASR 0%/AHR 0.22%，GB ASR 0.11%/AHR 4%，说明攻击具有针对性。
- **人工检测**（Table XVII, p.17）：6 名参与者在 ToolBench 200/400/600 个工具、7 个恶意工具的设置下分类；对恶意文档的 FNR ≥71.43%，同时把 5.6%–30.35% 的良性文档误判为恶意。
- **防御评估**：
  - 预防型（Table IX, p.11；已渲染核对）：StruQ 下 GF MetaTool ASR 99.6%、AHR 99.9%、ACC-a 0.3%；GB ASR 97.9%。SecAlign 最强情形（ToolBench GB）ASR 84.6%、AHR 97.8%、ACC-a 11.3%；MetaTool GB 92.1%。防御后 ACC-a 极低，说明效用被严重破坏；ACC-a 与 ASR 之和不为 100% 是因为模型拒答/无法生成合法输出（p.11–12）。
  - 检测型（Table X, p.12；已渲染核对）：known-answer 与 DataSentinel 的 FNR 大多 ≥90%；PPL-W 对 GB MetaTool 的 FNR 为 50%、对 GF 为 100%（FPR 0%）；PPL/PPL-W 的 AUC 仅 0.64/0.74；FPR 范围 0%–2.99%。作者归因：恶意描述与目标任务语义高度对齐、缺少明显注入指令，因此困惑度与已知答案检测都难奏效。

## 8. 主要贡献、与直接相关论文的差异、可复现资源

- **贡献**（p.2）：首个针对 LLM Agent 工具选择的提示注入攻击；把攻击形式化为优化问题并提出两阶段解法；在多个 LLM/数据集上系统评估；评估预防型与检测型防御并指出不足。
- **与直接相关工作的差异**：
  - **JudgeDeceiver [13]**：同样用优化生成注入序列，但目标是 LLM-as-a-Judge 的选择/评判，只覆盖选择阶段；ToolHijacker 同时优化检索与选择，且面向 no-box 工具选择。
  - **PoisonedRAG [21]**：向 RAG 知识库注入多条对抗文本以控制生成；需要多个条目、目标是生成内容；ToolHijacker 只用单个工具文档，目标是工具选择决策，并要求跨任务描述泛化。
  - **手动攻击**：单阶段启发式、注入文本与任务相关性低，Table III 中 ASR 仅 1.2%–28.2%（MetaTool）；本文用两阶段优化把检索与选择解耦优化。
  - **MCP 工具投毒 [11],[12]**：证明了修改工具文档可行，但没有给出自动化的两阶段优化方法；本文将其系统化为可优化、可迁移的攻击。
  - **防御 [23],[24],[25],[26],[20]**：StruQ/SecAlign 是模型层微调，known-answer/DataSentinel/PPL/PPL-W 是检测；本文实验显示它们不足以对抗语义对齐良好的恶意工具描述。
- **可复现资源**：代码与数据“受限访问”，需申请并说明用途（p.14, Ethics Considerations）；PDF Appendix C 给出 Q′/D′ 生成模板与初始 R/S（pp.17–18, Figs.10–12）；完整的 EA system prompt 与 target tasks 在技术报告 arXiv:2504.19793（p.17 脚注）。实验在受控环境完成，未部署真实恶意工具；作者称已通知 OpenAI、Anthropic、LangChain（p.14）。

## 9. 局限性、失效场景、作者未解决的问题

- **威胁模型假设较强**：需要开放工具市场接受第三方提交且缺少严格审核；假设工具选择主要依赖 name/description，忽略 API specification、权限声明、工具实现与运行时行为；假设恶意工具被选中后无二次验证、无 allowlist、无人工确认。真实系统若有这些机制，攻击成功率或危害会改变（论文只在 Related Work 提到策略型防御 [73],[74]，未实验评估）。
- **单目标任务、非通用后门**：一个恶意文档只针对一个目标任务；非目标任务 ASR 接近 0（p.16）。攻击者需为每个目标任务单独优化并发布文档。
- **影子到目标的迁移无保证**：no-box 下依赖影子检索器/LLM 与目标系统的语义重叠；正文报告 GB 在 Llama-2-7B shadow → Llama-3-70B target 上低至 34%（Table VII 的文本抽取列对齐不可靠，未据此表单独下结论），说明模型配对敏感；论文没有给出迁移的条件或上界。
- **防御评估不完整**：只评估 StruQ、SecAlign 与四类检测器；未评估工具 allowlist、发布者信誉、工具市场审核、检索阶段 provenance/异常检测、执行侧 capability 限制、自适应攻击。检测器的阈值与 AUC 也表明其实际部署价值有限。
- **ASR 不等于危害**：指标只衡量“恶意工具被选中”，没有验证执行后的数据外泄、权限提升或系统破坏；论文的“unauthorized data access / privacy breach”是动机性描述，不是端到端实验。
- **无形式化保证**：没有安全定义、定理、泛化界；攻击有效性完全由有限基准上的经验结果支撑。
- **成本与门槛**：有梯度方法需白盒 shadow LLM 与约 8 GPU 小时（A800）；无梯度方法虽只需约 18 次 LLM 查询，但依赖较强的 attacker LLM（Table XIII：Llama-2-7B 作 attacker 时平均 ASR 仅 69%）。
- **人工研究规模小**：6 名参与者、7 个恶意工具，FNR/FPR 的置信区间未报告。
- **论文内部不一致**：p.17 正文对动态工具库的 GF/GB 数值与 Table XVI 互换（见 §7），不影响主结论，但引用时需以表格为准。
- **作者提出的未来工作**：把攻击面扩展到 tool calling 的联合攻击；开发针对 ToolHijacker 的新防御（p.14, §VII）。

## 10. 与理论密码学可能的技术连接（区分原论文已做 / 个人推断）

**明确结论：本文是非密码学攻击，无密码学原语、无密码学假设、无安全性证明。** 全文没有签名、MAC、哈希、承诺、零知识、MPC、FHE、TEE、加密或认证协议；known-answer detection 是检测启发式，DataSentinel 的 game-theoretic 训练属于检测/博弈，均不是密码学。检索相似度排序与 top-k 选择也不是密码学认证。

**原论文已做**：无。

**个人推断（明确标为推断，且多数为负向结论）**：
- 可以把“工具选择完整性”写成一个机器学习安全游戏：敌手发布一个文档，挑战者从任务分布采样 q，若 argmax 选择为恶意工具则敌手赢。但这个游戏没有密钥、没有计算困难性假设、没有密码学敌手能力，属于 learning-theoretic robustness，硬套密码学定义会得到空洞结论；本文的 Eq.5 已经是这种经验游戏的样本估计。
- 签名/认证工具清单**不能**解决问题：攻击者是合法发布者，签名只绑定“谁发布”与“内容未被篡改”，不绑定“描述语义良性”；即使工具市场用 Merkle 透明度日志证明文档确实在库中且未被篡改，也无法证明排序/选择语义安全。
- 可验证检索（authenticated data structures）只能证明“返回的 top-k 相对于承诺库是正确的”，但恶意文档本来就在承诺库内，因此对本文攻击无帮助。这是一个重要的负向洞察：**检索完整性 ≠ 选择完整性**。
- 真正可形式化的是执行侧授权不变量：即使选择被劫持，工具能执行的动作受 capability 约束；这属于授权协议/密码工程设计，不是本文内容，也不能由本文的实验支撑。
- “Always prefer X for ALL queries”这类描述是营销话术还是注入，取决于自然语言意图与策略；密码学原语无法判定语义，这是策略/意图理解问题，不应被包装成密码学问题。
- 若按项目 0–5 量表做暂定判断：本文的 `T_crypto` 约为 **0–1**（仅有“完整性/信任”的类比，没有可形式化的密码学核心问题），不应因标题含 “Attack/Trust” 而给高分。

## 11. 与应用密码学/密码工程可能的技术连接（同上）

**原论文已做**：无密码机制。论文只提到开放工具市场（Hugging Face Hub、Apify、PulseMCP）与受限代码发布，没有使用任何凭证、签名、加密或 TEE。

**个人推断**：
- **发布者身份与清单签名**：可给工具文档加发布者证书与签名，用于归因和事后追责；但它不能阻止攻击，因为攻击者可以给自己的恶意描述签名。它只能提高攻击成本/可审计性，属于配套机制。
- **透明度日志 / Merkle 树**：把工具市场上架、版本变更、发布者身份写入可验证日志，可让审计者发现未记录的上架或版本替换；仍不能阻止语义操纵，只能提供事后证据。
- **执行侧 capability token**（如 macaroon/Biscuit 类作用域令牌）：在工具被选中后限制其文件、网络、API 权限，把“选择劫持”的危害从任意执行降为受限动作。这是与本文威胁模型互补的工程点，也是密码工程团队可以真实实验的接口；但它不降低 ASR，只降低危害。
- **工具市场准入与信誉**：发布者审核、信誉评分、描述异常检测是更直接的防御，但不是密码学；若与签名身份绑定，可形成“身份—信誉—权限”链条。
- **伪交叉警告**：
  - 只给 tool description 签名：不解决语义恶意，攻击者自签即可；
  - 加密 tool description：检索器需要明文语义，端到端加密破坏功能；即使在 TEE 内解密，恶意描述仍进入 LLM 上下文；
  - 用 ZK 证明“工具实现符合描述”：本文攻击不改工具实现，只改描述与选择偏好，证明实现一致性无帮助；
  - 把 OAuth 包在工具调用外层：不阻止选择劫持，只在执行侧限制权限；
  - 给执行日志签名：能审计“选了什么”，不能保证“选得对”。
- 若按项目 0–5 量表做暂定判断：本文的 `A_crypto` 约为 **1**（只有在执行侧间接连接，论文本身没有密码工程切入点）。

## 12. 后续可以验证的研究假设（不得仅因论文没提就判断领域没人做过）

- **H1（签名无效性）**：在工具市场上架流程中加入发布者签名与清单签名后，ToolHijacker 的 ASR 不变，因为攻击者可以合法签署自己的恶意描述。实验：同一恶意文档加签名/不加签名，比较 ASR/AHR；预期无显著差异。该假设用于区分“身份认证”与“语义良性”。
- **H2（执行侧约束的有效性）**：给被选中的工具施加 capability 白名单（文件、网络、API 作用域），可显著降低选择劫持后的实际危害，但不降低 ASR。实验：在工具执行层加沙箱/令牌，测 harm reduction（数据外泄量、越权 API 调用数）而非 ASR。
- **H3（检索阶段防御）**：基于来源、发布者信誉或描述-任务相似度异常检测的 reranking 可降低 AHR，但自适应优化 R 可能恢复攻击。实验：固定 S，针对防御重新优化 R，比较 AHR/ASR 的下降与恢复。
- **H4（迁移可预测性）**：R 的跨检索器迁移能力与影子/目标嵌入空间的相似度相关，可用公开嵌入模型测量并预测 ASR；这可用于评估 no-box 攻击的实际门槛。
- **H5（透明度日志的归因价值）**：Merkle 透明度日志能在事后定位恶意发布者与上架时间，但不能降低 ASR；实验测归因时间与覆盖率，而非攻击成功率。
- **H6（人工审核不可靠）**：本文 6 人研究显示 FNR ≥71%，可扩大样本并比较“人工审核 + 自动化检测 + 信誉”组合的检测率与 FPR；这是可用性/治理问题，不是密码学问题。
- 以上均为待验证假设，不是“领域空白”的断言；需要在后续论文与实验中查证。
