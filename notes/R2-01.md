## 1. 150–300 字中文概述

ASB 是面向 LLM-based Agent 的综合安全评测基准。作者把 Agent 拆成系统提示、用户提示、记忆检索、工具调用四个可攻击环节，形式化并统一评测直接提示注入（DPI）、间接提示注入（IPI）、记忆投毒、Plan-of-Thought（PoT）后门与混合攻击，以及 8 类、11 种配置的防御。基准覆盖 10 个场景、10 个 Agent、50 个正常任务、400 个攻击任务、20 个正常工具与 400 个攻击工具（共 420 个工具），在 13 个 LLM backbone 上用 7 个指标评测。核心结果：混合攻击平均 ASR 84.30%，DPI 72.68%，IPI 27.55%，记忆投毒 7.92%，PoT 42.12%；现有提示级防御普遍无效，PoT 的 Shuffle 防御甚至使平均 ASR 升至 44.37%。作者提出 NRP = PNA × (1 − ASR) 兼顾效用与安全。全文没有密码学构造、密码学安全定义或证明；"Formalizing" 只是用指示函数写出攻击目标。

## 2. 研究背景、现有方法不足、精确定义的问题

作者指出，LLM Agent 已用于金融、医疗、电商、自动驾驶等场景，但研究重点长期在效果与泛化，可信性不足（p.1–2, §1）。已有安全基准存在三类缺口（p.2–3, §1、§2；p.25, Table 12）：

1. **InjecAgent** 只评测 IPI（2 种攻击、6 个场景、62 个工具），不含防御；
2. **AgentDojo** 只评测 IPI（5 种攻击、4 种防御、4 个场景、74 个工具），忽略后门与记忆投毒；
3. 此前的记忆投毒工作假设攻击者知道 RAG 数据库/embedder 的内部结构（白盒），后门工作多依赖微调投毒；缺少覆盖 Agent 各运行阶段的黑盒、统一评测。

本文要解决的问题因此是：**如何在一个统一基准中形式化并测量 Agent 各环节的多种攻击与防御，覆盖多场景、多 backbone，并给出兼顾任务效用与攻击鲁棒性的指标**（p.4, §4；p.8, §5.1）。论文题目中的 "Formalizing" 指用指示函数和期望写出攻击目标（Eq.1–10）以及把防御写成期望不等式（Eq.11–17），**不是密码学意义上的形式化安全定义，也没有定理或证明**。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **框架**：ReAct（Yao et al., 2022），实现基于 AIOS 仓库（p.26, §C.2.2；p.16, §A.2）。Agent 在时刻 t 接收观察 o_t、执行动作 a_t，策略 π(a_t|c_t) 依赖上下文 c_t；ReAct 将动作空间扩展为 A ∪ L，语言空间中的 "thought" 用于任务分解与规划。
- **组件**（p.1–2, §1, Fig.1）：预定义 system prompt（角色与行为）、用户指令、LLM backbone（规划/决策）、长短时记忆与 RAG 检索、工具（normal/attack）、外部环境与 observation、thought/re-thinking。
- **运行流程**（p.1, §1）：① system prompt 定义角色；② 接收用户指令与任务细节；③ 从记忆库检索相关信息；④ 基于检索与上下文规划；⑤ 调用外部工具执行动作。
- **形式化输入输出**（p.3, §3.1, Eq.1）：Agent 接收 `(p_sys, q, O, T, E_K(q⊕T,D))`，输出计划 `P=(p_1,…,p_r)` 并逐步执行工具动作；`T=(τ_1,…,τ_n)` 为工具列表，`O=(o_1,…,o_m)` 为观察，`E_K` 为检索到的 K 条记忆；任务成功定义为 Agent 使用了全部标注的目标工具 `T^t`。
- **记忆**：Chroma 向量数据库 + LangChain；任务完成后把 `Agent role; Task; Plan; Tools` 写入数据库（p.26, §C.2.2；p.28, §C.2.4 "Content Saved to Memory Database"）。检索按 query⊕tool list 与 key 的 embedding 相似度返回 K 条 in-context 示例（p.3, §3.1；p.6, §4.2.2）。
- **工具**：normal tools 与 attacker tools 都是模拟 API；**工具不设参数**，因为作者认为参数生成属于模型能力而非安全框架（p.23, §B.2）。标准计划示例为两步（system prompt 要求 "at least two stages"），正常工具每 Agent 2 个（共 20 个），攻击工具 400 个、攻击任务 400 个（p.8, Table 3；p.23–24, §B.2）。
- **信任边界**：论文**没有显式的 trust boundary 图或独立小节**；Fig.1 只标注了四类攻击的入口（用户提示、observation、system prompt、memory retrieval）。系统没有身份、认证、授权或权限模型；LLM 仅通过 API 访问，攻击者不掌握模型内部（p.4, §3.2）。因此这里的 "信任边界" 是隐含的：用户输入、工具响应、记忆库、第三方 system prompt 均被视为不可信输入源。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

**受保护对象（由攻击后果反推）**：用户任务意图与工具选择完整性；隐藏的 system prompt；记忆库中计划的一致性；敏感数据（如财务报告、客户数据库）；Agent 对高风险指令的拒绝行为。论文没有逐项列出资产表，也没有给出机密性/完整性/可用性的形式化目标。

**攻击者目标**（p.4, §3.2, Eq.2–3）：使 Agent 在恶意修改 `θ_malicious` 下执行攻击者指定的恶意动作 `a_m`，即最大化 `E[1(Agent(q,θ_malicious)=a_m)]`；对 PoT 后门还要求干净查询下保持良性动作 `a_b`（Eq.3、Eq.9）。在 ASB 中，"恶意动作" 操作化为**成功调用攻击者指定的攻击工具**（p.5, Eq.4；p.26, Eq.18）。

**攻击者能力**（p.4, §3.2，五点）：
1. **工具**：知道攻击工具的名称与功能，能把攻击工具加入 Agent 的工具列表（例如操纵 RapidAPI 等第三方 API 平台）；
2. **Backbone LLM**：不知道架构、训练数据和参数，只能通过 API 交互，不能操纵模型内部；
3. **System prompt**：能制作并插入 system prompt，冒充 prompt engineer 或提供 prompt 优化服务（Fiverr、ChatGPT plugins 等）；
4. **User prompt**：可访问并修改用户 prompt（第三方 prompt 服务或中间人攻击）；
5. **知识数据库**：对 RAG 数据库与 embedder 只有黑盒访问，不知道内部结构（区别于此前白盒投毒工作）。

**前提假设**：Agent 在每次任务后把执行历史写入记忆库；攻击者可通过 DPI/IPI 经黑盒 embedder 间接投毒；检索返回 K 条示例；工具调用为模拟调用；标准计划以两步为主（至少两步）；攻击工具与正常工具混在同一工具列表中。论文没有假设攻击者拥有 Agent 密钥、身份凭证或系统权限，也没有考虑自适应攻击者。

## 5. 核心方案：算法、协议、架构、公式、关键步骤

ASB 不是一个新协议或新系统，而是**基准 + 攻击分类 + 评测指标**。其 "方案" 由五部分组成。

### 5.1 基准构成（p.8, Table 3；p.22, Table 9；p.25, Table 12）

- 10 个场景：IT management、Investment、Legal advice、Medicine、Academic advising、Counseling、E-commerce、Aerospace design、Research、Autonomous vehicles；每个场景 1 个对应 Agent（system admin、financial analyst、legal consultant、medical advisor、education consultant、psychological counselor、ecommerce manager、aerospace engineer、academic search、autonomous driving）。
- 50 个 Agent 任务（每 Agent 5 个）；20 个正常工具（每 Agent 2 个）；400 个攻击工具；400 个攻击任务；10 个 PoT demonstrations；13 种攻击方法、11 种防御配置、7 个指标。
- 与 InjecAgent（6 场景、62 工具）和 AgentDojo（4 场景、74 工具）相比，ASB 有 10 个场景、420 个工具（Table 12）。
- 数据由 GPT-4 生成（Agent 描述、5 个用户任务、标准计划、工具），攻击工具与攻击指令也由 GPT-4 生成；工具调用全部为模拟调用（p.22–25, §B.1–B.2；p.25, §C.2.1）。

### 5.2 五类攻击的形式化

- **DPI（Definition 1, Eq.4, p.5）**：把注入指令 `x_e` 拼接到目标指令 `q_t` 后（`q_t⊕x_e`），并把攻击工具列表 `T^e` 加入 `T`，使 Agent 在完成原任务之外执行注入任务。
- **IPI（Definition 2, Eq.5, p.5）**：把 `x_e` 注入观察序列的任一步 `o_i`（`O⊕x_e`），并加入 `T^e`。
- **通用注入模板（Eq.6, p.5；Table 1, p.5）**：`x̃ = P(x_t, x_e)`；五种模板为 Naive（`x_t⊕x_e`）、Escape Characters（`x_t⊕c⊕x_e`）、Context Ignoring（`x_t⊕i⊕x_e`）、Fake Completion（`x_t⊕r⊕x_e`）、Combined（`x_t⊕c⊕r⊕c⊕i⊕x_e`）。DPI/IPI 都用这五种；PoT 与 Mixed 只用 Combined（p.16, §A.3.1）。
- **记忆投毒（Definition 3, Eq.7, p.6）**：攻击者提供被投毒的 RAG 数据库 `D_poison = D_clean ∪ A`，其中 `A={(k̂_i(q_i), v̂_i)}` 是攻击者加入的 query→poisoned plan 键值对；Agent 用 `E_K(q⊕T⊕T^e, D_poison)` 检索 K 条示例，若引用被投毒计划就可能生成类似的恶意计划。攻击者通过 DPI/IPI 经黑盒 embedder 间接写入（p.6, §4.2.2）。
- **PoT 后门（Definition 4, Eq.8, p.6–7）**：把 system prompt 中的一部分 plan demonstrations `X` 替换为投毒版本 `X̃`；每个 demonstration 为 `d_i=[q_i,p_1,…,p_r,a_i]`，投毒版本为 `d̃_i=[q̃_i,p_1,…,p_r,p*,ã_i]`，其中 `p*` 是后门规划步、`ã_i` 是攻击目标动作；再在用户查询中注入触发词 `δ`（`q_t⊕δ`）。攻击目标是 `Agent(LLM(p_sys⊕X̃, q_t⊕δ, O, T+T^e)=a_m)`。该攻击是 **training-free** 的，只依赖 in-context learning；触发词分 non-word（如 `@@`、`:)`）与 phrase-based（用 GPT-4o 生成，默认 `with perspicacious discernment`）两类（p.7, §4.3.2；p.26, §C.2.2）。
- **混合攻击（Eq.10, p.16, §A.1）**：同时组合 DPI、IPI、记忆投毒；PoT 被排除，因为其 prompt 嵌在 system prompt 中、不写入数据库。Table 14 评测了 DPI+IPI、DPI+MP、IPI+MP、DPI+IPI+MP 四种组合。

### 5.3 防御

Table 2（p.7）列出 8 类防御技术：Delimiters、Dynamic Prompt Rewriting、Sandwich Prevention、Instructional Prevention、Paraphrasing、Shuffle、PPL detection、LLM-based detection；按攻击类型复用时形成 11 种配置（Table 12：DPI 4、IPI 3、记忆投毒 2、PoT 2）。除 PPL 与 LLM-based detection 是检测型外，其余都是预防型（p.8, §4.4）。论文把防御写成期望不等式（Eq.11–17），例如 Delimiters 希望 `P(Agent(⟨start⟩q⟨end⟩⊕δ)=a_b) ≫ P(Agent(q⊕δ)=a_m)`；这些是**设计目标/直觉**，不是可证明的安全保证。

### 5.4 指标（p.8, Table 4；p.26–27, Eq.18–20）

- **ASR**：成功使用攻击工具的任务占全部攻击任务的比例（Eq.18）。
- **RR**：因指令具有攻击性而拒绝的任务比例，由 backbone LLM 按 App. C.2.4 的 prompt 判定。
- **PNA**：无攻击/防御时完成任务的比例；成功定义为使用了全部标注工具（Eq.19）。
- **BP**：查询中无后门触发词时原任务成功率，衡量被后门污染后的效用。
- **FNR/FPR**：检测型防御把被污染数据判为干净 / 把干净数据判为污染的比例。
- **NRP = PNA × (1 − ASR)**（Eq.20）：兼顾干净效用与攻击鲁棒性；论文将其作为新指标。

### 5.5 实现细节

AIOS 仓库实现 Agent；Chroma + LangChain 管理记忆；工具用 JSONL 定义并实例化为 `SimulatedTool`/`AttackerTool`，每次调用返回预定义输出（p.29, §C.2.6）；记忆投毒统一用 DPI 注入，注入模型为 GPT-4o-mini（p.26, §C.2.2）；13 个 backbone 为 Gemma2-9B/27B、LLaMA3-8B/70B、LLaMA3.1-8B/70B、Mixtral-8x7B、Qwen2-7B/72B、Claude-3.5 Sonnet、GPT-3.5 Turbo、GPT-4o、GPT-4o-mini（p.9, Table 5；p.26, Table 13）。**整个方案不包含密码算法、密钥、身份凭证、签名或加密。**

## 6. 安全属性与安全性论证

- 论文**没有明确命名安全属性**（没有 CIA、认证、授权、机密性、完整性等定义），也没有独立的安全分析章节。隐含目标是：Agent 的工具选择/任务执行不被不可信输入改变（决策完整性），以及对 aggressive instructions 的拒绝能力。
- "形式化" 仅指 Definition 1–4 与 Eq.1–10 的攻击目标，以及 Eq.11–17 的防御期望不等式。没有 Theorem、Lemma、Proof，也没有对任何防御给出安全保证；所有有效性判断都来自 ASR/FNR/FPR 的经验测量。
- 因变量 `π_q`（用户查询分布）没有具体定义，`K`（检索条数）未在正文固定，指示函数 `1(·)` 不区分危害程度；因此 Eq.1–10 是**描述性记号**，不能直接作为可证明的安全游戏。
- 作者的核心安全论点是经验性的：五类攻击都有效（Table 5），现有防御不足（Tables 7/8/19/20/21），因此需要更强防御（p.10, §5.4；p.34, §D.2.3）。论文没有分析自适应攻击、攻击组合下的防御、或防御被绕过后的剩余风险。
- **未提供形式化证明，也未提供密码学意义上的安全定义。**

## 7. 实验细节：模型、环境、数据集、对照方法、指标、核心结果、消融

**实验条件（除非另注）**：ASB 基准；模拟工具调用；每 Agent 5 个正常任务（共 50 个）；400 个攻击任务；13 个 LLM backbone；温度/重复次数/随机种子未报告；PoT 只用 5 个 Agent（medical advisor、legal consultant、financial analyst、academic search、system admin），每 Agent 2 个 demonstration、2 个测试任务（p.26, §C.2.2）。

### 7.1 攻击结果（p.9, Table 5）

13 个 backbone 的平均值（ASR / RR）：

| 攻击 | ASR | RR |
|---|---|---|
| DPI | 72.68% | 6.53% |
| IPI | 27.55% | 8.61% |
| Memory Poisoning | 7.92% | 4.63% |
| Mixed Attack（DPI+IPI+MP） | 84.30% | 3.22% |
| PoT Backdoor | 42.12% | 5.42% |
| 全部攻击平均 | 46.91% | 5.68% |

注：这些 ASR 的攻击者能力、注入位置和任务集不同，**不能当作同一难度下的攻击强弱排序**。代表性单元：Gemma2-27B 的 Mixed Attack 100.00%；GPT-4o 的 PoT 100.00%、GPT-4o-mini 95.50%；GPT-4o 的 IPI 62.45%；LLaMA3.1-8B 的 Memory Poisoning 25.65%；GPT-3.5 Turbo 的 DPI 98.40%（RR 3.00%）；GPT-4o 的 DPI 60.35%（RR 20.05%）。作者据此提出 ASR 与模型能力呈 "先升后降" 关系（Fig.2, p.9–10）：能力强的模型更会跟随指令，但 refusal 机制会在最高能力段降低 ASR。

### 7.2 效用与 NRP（p.10, Table 6）

平均 PNA 29.46%、平均 ASR 46.91%、平均 NRP 15.64%。NRP 最高：Claude-3.5 Sonnet 43.56（PNA 100.00、ASR 56.44），LLaMA3-70B 30.03（66.50、54.84），GPT-4o 28.12（79.00、64.41）；GPT-4o-mini 16.23；Gemma2-27B 14.38。多数 backbone 的 PNA 很低（Mixtral 0.00、LLaMA3.1-8B 0.75、LLaMA3-8B 1.50），因此 NRP 被 PNA 主导；这是本人对指标性质的推断，论文未讨论。

### 7.3 PoT 后门（p.30–31, Tables 15–16）

- 5 种触发词（`@@`、`conducting a comprehensive elucidation`、`:)`、`through a prism of insight`、`with perspicacious discernment`）的 ASR 为 99.75%–100.00%，平均 99.90%；BP 平均 83.05%，PNA 79.00%（Table 15）。这组数只对应一个 backbone/设置，论文未在表题中注明；PNA 79.00% 与 Table 16 的 GPT-4o PNA 一致，故很可能是 GPT-4o 设置，但正文未明说。
- Table 16（作者称 "The LLM backend used is GPT-4o"，但表内列出 13 个 backbone，存在内部不一致）平均 BP 32.21%、PNA 29.46%，说明后门触发词对干净任务效用影响有限。
- 默认触发词为 `with perspicacious discernment`；用 GPT-4o 按 "2–5 个稀有词、不改变答案" 的约束生成（p.7, §4.3.2；p.28, §C.2.4）。

### 7.4 攻击组合、注入模板与 aggressive/non-aggressive（p.30–32, Tables 14、17、18）

- 组合攻击平均 ASR：DPI+IPI 79.06%、DPI+MP 83.02%、IPI+MP 23.75%、Mixed 84.30%（Table 14）。作者认为 DPI+MP 在成本上接近最优，因为加入 IPI 只带来约 1.28 个百分点的提升；正文 p.30 把 Mixed 写成 84.03%，与表格 84.30% 矛盾。
- 五种注入模板的平均 ASR：Combined 38.01%、Context Ignoring 36.55%、Fake Completion 35.52%、Naive 35.43%、Escape Characters 34.75%（Table 17）。在 DPI 内，Combined 为 78.38%；在 IPI 内，Naive 为 28.04%。
- Aggressive vs non-aggressive（Table 18）：non-aggressive 任务平均 ASR 38.98%、RR 4.87%；aggressive 任务平均 ASR 33.12%、RR 8.31%。分攻击看：DPI 74.59% vs 70.78%，IPI 32.67% vs 22.42%，Memory Poisoning 9.68% vs 6.16%。

### 7.5 防御结果（p.10, Tables 7–8；p.33–35, Tables 19–21、Fig.4）

- **DPI 防御（Table 7）**：无防御基线 78.38%；Delimiters 79.08%（Δ +0.69）、Paraphrasing 56.87%（Δ −21.52）、Instructional 76.77%（Δ −1.62）、Dynamic Prompt Rewriting 44.45%（Δ −33.93）。注意该基线 78.38% 与 Table 5 的 DPI 平均 72.68% 不同，且等于 Table 17 的 Combined Attack 行；本人推断防御实验可能只在 Combined Attack 上评测，但论文未说明。
- **IPI 防御（Table 8）**：无防御基线 27.98%；Delimiters 24.96%（Δ −3.02）、Instructional 26.31%（Δ −1.67）、Sandwich 28.04%（Δ +0.06）。同样，27.98% 与 Table 5 的 27.55% 不同，等于 Table 17 的 Combined Attack IPI 行。
- **防御的效用代价（Table 19）**：无攻击 PNA 29.46%；Delimiters 22.52%（−6.94）、Paraphrasing 27.69%（−1.77）、Instructional 26.63%（−2.83）、Sandwich 28.29%（−1.17）、DPR 26.38%（−3.08）。
- **PoT 防御（Table 20）**：无防御平均 ASR 42.12%；Shuffle 44.37%（平均反而更高）、Paraphrase 29.06%。GPT-4o 上 100.00% → Shuffle 98.50%、Paraphrase 84.75%；GPT-4o-mini 上 95.50% → Shuffle 39.75%、Paraphrase 62.75%。
- **记忆投毒防御（Table 21、Fig.4）**：LLM-based detection 平均 FNR 0.660、FPR 0.200（即 66% 的投毒未被发现，20% 的干净数据被误报）。PPL detection 在阈值 2.4–4.8 间扫描，FPR–FNR 曲线没有良好工作点：例如 (FNR, FPR) 从 (0.85, 0.06) 到 (0.01, 1.00)；低阈值误报高，高阈值漏报高。作者解释：投毒指令可能比正常多步计划更简单，因此困惑度不一定更高。
- 作者没有评测针对混合攻击的防御，也没有让攻击者知道防御后自适应调整。

### 7.6 消融与边界

论文做了触发词种类、注入模板、aggressive/non-aggressive、攻击组合的对比；**没有**做检索条数 K、demonstration 数量、任务步数、模型温度、重复次数的消融，也没有自适应攻击或防御感知攻击的实验。所有实验是单 Agent、单轮任务、模拟工具，不涉及 MCP/A2A/多 Agent。

## 8. 主要贡献、与直接相关论文的差异、可复现资源

**贡献**（p.1–2, §1）：
1. 首个覆盖 10 个场景、10 个 Agent、420 个工具/50 个正常任务 + 400 个攻击任务、多种攻击与防御的 Agent 安全基准；

## 9. 局限性、失效场景、作者未解决的问题

**作者未设独立 Limitations 或 Discussion 章节**（正文 p.10 直接从 §5.4 进入 §6 Conclusion；附录 D.2 只给防御建议）。以下局限中，标注 "本人推断" 的条目不是作者原话。

- **基准真实性**：工具全部为模拟调用、无参数、计划步数少（示例为两步，system prompt 要求至少两步）（p.23, §B.2；p.25, §C.2.1）。这提高了可复现性，但削弱了对外部 API、参数注入、长程任务、真实副作用的覆盖。本人推断：ASR 衡量的是 "是否调用攻击工具"，不等于真实数据泄露或破坏。
- **攻击工具的特权设定**：攻击者可以把专用恶意工具（Data Export、Stock Manipulation、MalwareInjection、DataWiping 等）加入工具列表，ASR 定义为调用这些工具（p.4, §3.2；p.5, Eq.4；p.18–19 示例）。本人推断：一个简单的工具 allowlist 就能把这类 ASR 降到接近 0，因此该设定可能高估了实际部署中的风险，也无法衡量 "滥用合法工具" 的攻击。
- **样本与统计**：PoT 只用 5 个 Agent、每 Agent 2 个测试任务（p.26, §C.2.2），但 Table 5/20 报告到 0.25% 的粒度；重复次数、方差、置信区间未报告。50 个正常任务、400 个攻击任务的抽样过程也未详细说明。
- **判定方式**：RR 由 backbone LLM 按固定 prompt 判定（p.8, Table 4；p.27–28, §C.2.4），存在 LLM-as-judge 偏差；ASR/PNA 依赖模拟工具的预定义输出字符串匹配。
- **防御覆盖**：只评测提示级/检测级防御，未评测访问控制、工具白名单、权限隔离、密码学机制；没有针对混合攻击的防御；没有自适应攻击；没有防御组合/纵深防御实验。
- **指标**：NRP = PNA × (1 − ASR) 是乘性指标；当 PNA 接近 0 时 NRP 也接近 0，无法区分 "模型无用" 与 "模型安全"（Table 6 中 Mixtral PNA 0.00 → NRP 0.00）。ASR 对危害程度、攻击成本、检测延迟不敏感。
- **原文内部不一致**：p.30 的 84.03% vs Table 5/14 的 84.30%；Table 7/8 基线与 Table 5 不一致；p.31 的 "GPT-4o" 与 Table 16 的 13 个 backbone 不一致；Table 3 的 13 种攻击方法与摘要的 16 种攻击配置（10 提示注入 + 1 记忆投毒 + 1 PoT + 4 混合）口径不同。
- **范围**：单 Agent、单任务会话的 ReAct；不覆盖 MCP、A2A、多 Agent、浏览器/GUI、真实身份与权限、供应链签名、密码学威胁；记忆只是简单 RAG 检索，不涉及长期记忆的写入治理、遗忘或跨会话隔离。
- **失效场景**：instruction-level 防御在 Combined 注入下失效；Paraphrase 保留语义，无法破坏触发词与目标的语义关联；PPL 假设恶意计划更 "复杂"，但投毒计划可能更简单；Shuffle 只改变步骤顺序，PoT 依赖的是推理语义而非顺序，平均 ASR 反而上升（p.34, Table 20）。

## 10. 与理论密码学可能的技术连接（区分原论文已做 / 个人推断）

**原论文已做：无密码学内容。** 全文没有加密、签名、MAC、OAuth/OIDC、凭证、TEE、attestation、key management、零知识、承诺、MPC 等机制；没有密码学安全参数、敌手优势、可忽略函数、归约或定理。参考文献中出现 "IEEE Symposium on Security and Privacy" 只是会议名，不构成机制。**结论：本文无密码学构造、无密码学证明、无密码学形式化。** "Formalizing" 是攻击目标的指示函数记号，不是密码学形式化。

按交接文档 §6.1 的五个问题逐项回答：

1. **保护什么、抵抗何种对手？** 保护 Agent 的工具选择/任务执行不被用户提示、工具响应、记忆库、system prompt 中的恶意指令改变；对手是能注入这些通道但不能接触模型内部的外部/用户级/第三方对手（p.4, §3.2）。这是一个**语义完整性**问题，不是传统的密钥/密文问题。
2. **是否需要密码学原语，而非普通访问控制？** 对 ASB 的核心攻击（提示注入、记忆投毒、PoT 后门），密码学原语**不能直接解决**：模型是否遵循恶意指令是自然语言语义/对齐问题。密码学只能在**执行边界**（工具网关、记忆写入、身份与委托）提供强制力；它无法保证模型 "理解正确"。
3. **适用原语/工具（推断）**：工具调用授权可用 capability token / macaroon / biscuit（带作用域衰减与撤销）；工具元数据与版本可用数字签名；记忆写入可用 MAC/签名 + 认证数据结构（Merkle log）；跨 Agent 可用签名消息与密钥协商；审计可用签名 transcript；若要把 "策略合规" 做成可验证的，才可能用到 ZK/commitment。但这些都是**研究推断**，论文没有使用。
4. **能否形成严谨的安全定义与证明义务（推断）**：可以尝试定义 "tool-call authorization soundness under untrusted context"：给定用户任务派生的 capability 集合 C，任意不可信 observation/memory/system-prompt 序列都不能使网关执行 C 之外的工具。这个定义可证明，但**证明只覆盖网关，不覆盖 LLM 的语义误用**；如果 C 的派生依赖自然语言意图，则定义的核心难点在策略合成而非密码学。另一个可形式化方向是委托凭证的 unforgeability、scope non-amplification、revocation freshness，但这些在 ASB 中完全没有对应物。
5. **哪些问题不是密码学能解决的？** ASB 的 DPI/IPI/PoT 主要都是：模型把数据当指令、把注入当任务、把触发词与目标动作关联。这些是 instruction hierarchy、数据/指令分离、语义鲁棒性问题；签名、加密、TEE 都不能阻止一个被授权调用 `Data Export` 的模型自愿导出数据。把这类问题包装成 "给 prompt/日志签名" 是伪交叉。

**个人推断（明确标为推断）**：
- ASB 可以作为**密码学防御的评测 harness**：在工具网关加入 capability allowlist、在工具注册表加入签名验证、在记忆写入加入来源认证，然后用 ASR/PNA/延迟/开销衡量。但 ASB 现有的专用攻击工具会让 allowlist 过于容易成功，必须扩展 "滥用合法工具" 的攻击才有研究价值。
- 一个真正有理论味道的问题：**在 LLM 作为任意（不可信）翻译器的前提下，如何定义并证明 "用户意图 → 工具权限" 的健全性**。这需要把自然语言任务、策略语言、能力系统组合起来；纯密码学只能证明凭证/签名部分，语义部分仍需 PL/形式化方法。
- 另一个：记忆的**因果来源证明**（provenance）比单纯签名更难：ASB 的投毒是通过 Agent 自己的合法写入完成的（DPI→保存计划→后续检索），签名会签出 "合法" 的毒记忆；需要记录 "该计划受哪条不可信 observation 影响" 的污点信息，这更像信息流控制而非密码学。

**伪交叉警告**：给 system prompt 签名只能证明来源，不能证明安全；给执行日志签名不能保证语义正确；用 ZK 证明 "模型运行了某步" 不解决用户授权；把 OAuth 包在工具调用外不解决提示注入。论文本身没有落入这些陷阱，因为它根本不涉及密码学。

## 11. 与应用密码学/密码工程可能的技术连接（同上）

**原论文已做：无。** ASB 没有身份、认证、授权、密钥、证书、加密存储、安全通道、TEE、审计签名或撤销机制。工具是本地模拟的 Python 对象（`SimulatedTool`/`AttackerTool`，p.29, §C.2.6）；记忆是本地 Chroma 向量库；LLM 通过厂商 API 调用。因此不能把本文称为密码工程项目，也不能从中提取任何密码机制的性能数据。

**个人推断的工程接口**：
- **工具注册与供应链**：ASB 的威胁模型明确允许攻击者把恶意工具加入工具列表（p.4, §3.2），这正是 MCP/插件市场签名与版本化的用武之地。可在 ASB 上实现 "签名工具清单 + 安装时校验"，测量对攻击工具注入的阻断率、对正常工具的兼容性与延迟。
- **任务级 capability**：从用户任务派生允许的工具集合，在工具网关强制执行；ASB 的 ASR 定义（是否调用攻击工具）使得该防御可直接测量——但也会暴露 "专用攻击工具" 设定的 trivial 性。更有意义的是允许工具集内的滥用检测。
- **记忆写入认证与来源标签**：对记忆条目做 MAC/签名，记录写入者、任务、来源 observation；可检测第三方直接篡改，但对 "Agent 自己被注入后写入" 无效（因为签名者就是 Agent）。需要与污点跟踪/信息流控制结合。
- **审计**：对工具调用序列做签名日志，提供事后取证；但不能阻止攻击，也不能保证语义正确。
- **运行时隔离/attestation**：TEE 可保护 Agent 运行时与密钥，但 LLM API 与工具响应仍在外部；attestation 只能证明 "运行的是某段代码"，不能证明 "模型没有被注入"。
- **评测扩展**：在 ASB 上加入密码防御后，除 ASR/PNA 外还应测延迟、token 开销、密钥/凭证生命周期、撤销传播、跨 Agent 兼容性；ASB 当前没有这些维度。

**伪交叉警告**：只把 OAuth 流程包进 Agent、只给日志签名、只用 TEE 跑模型、只给工具描述加哈希，都不解决 ASB 展示的语义注入问题；如果论文只报告 "签名后 ASR 从 84.30% 降到 X%"，需要检查攻击者是否被允许伪造/重放签名、是否只测了专用攻击工具。

## 12. 后续可以验证的研究假设（不得仅因论文没提就判断领域没人做过）

- **H1（可证伪，基于 ASB 代码）**：在 ASB 的工具网关加入任务级 allowlist（只允许该任务标注的正常工具），DPI/IPI/MP/PoT 的 ASR 会降到接近 0，而 PNA 不变；因为 ASR 的定义就是 "调用攻击工具"。若成立，说明 ASB 的 ASR 主要度量 "工具白名单缺失"，而非 "模型抗注入能力"。需要进一步设计 "滥用允许工具" 的攻击来区分。
- **H2**：仅对工具元数据/工具清单做签名，不改变 IPI 与记忆投毒的 ASR，因为恶意指令来自 observation 与 memory，而不是工具元数据；签名只阻断 "攻击工具注入" 这一条路径。可在 ASB 上做 2×2 实验（签名开/关 × 攻击工具注入开/关）。
- **H3**：对记忆条目做写入签名不能检测 ASB 的 DPI→记忆投毒链，因为毒记忆由 Agent 合法写入；必须加入来源/污点标签。可在 ASB 的 `Content Saved to Memory Database` 流程中注入来源字段并测量 FNR/FPR。
- **H4**：NRP 在 PNA 接近 0 的 backbone 上不可解释；用分层 PNA 或 `ASR | PNA≥阈值` 的条件指标会改变 backbone 排名。可用 Table 6 的 13 行数据直接复算验证。
- **H5**：Paraphrase 防御保留语义，因此对高能力模型（GPT-4o）的 PoT ASR 仍高达 84.75%（Table 20）；基于语义相似度的触发词检测可能比字符级改写更有效。可在 ASB 的 5 个触发词上验证。
- **H6**：ASB 无法评估身份认证/委托，因为它没有 principal、credential、delegation chain；要研究 "签名委托 + 作用域衰减" 必须扩展基准（加入多 Agent、工具所有权、用户身份），否则测不出委托攻击。此假设用于判断 ASB 对 B1/B2 方向的可复用性。
- 以上均为待验证假设，不代表文献中无人研究；需在后续论文中查证。
