## 1. 150–300 字中文概述

AgentPoison 是首个面向通用 RAG 型 LLM Agent 的后门攻击。它向 Agent 的长期记忆或 RAG 知识库注入极少量恶意键值演示，并用约束优化生成触发词：唯一性损失把含触发词的查询推离良性簇中心，紧凑性损失让这些查询在嵌入空间聚成紧密簇，目标损失保证检索到恶意演示后输出预定恶意动作，连贯性损失保证触发词读起来自然。优化用梯度引导的离散束搜索求解，无需训练或微调模型。作者在 Agent-Driver、ReAct-StrategyQA、EHRAgent 三个真实 Agent 上，跨 GPT-3.5/LLaMA3 与端到端/对比学习两类检索器评估：平均检索成功率 81.2%，端到端攻击成功率 62.6%，良性准确率平均仅降 0.74%，投毒率低于 0.1%。论文不含任何密码学机制。

## 2. 研究背景、现有方法不足、精确定义的问题

LLM Agent 普遍依赖记忆模块或 RAG 知识库检索历史经验/外部知识来规划与执行动作，而这些知识库通常未经校验（p.1 Abstract；p.2 §1）。作者要回答的问题是：能否用极少量投毒条目，使 Agent 在特定触发条件下稳定输出攻击者指定的恶意动作，同时不损害正常查询的效用。

现有工作的不足（p.2 §1、p.3 §2）：
- 越狱类攻击（如 GCG）针对模型输入，注入的对抗后缀会被知识库的多样性稀释，难以控制检索结果。
- BadChain 等 in-context learning 后门使用未针对检索优化的触发词，无法保证恶意演示被检索到。
- 语料投毒（CPA / PoisonedRAG 一类）能影响检索，但往往以整体降低良性效用为代价，且需要更高投毒率。
- 已有的 Agent 后门工作 [34,40] 主要投毒 LLM backbone 的训练数据，未评估更常见的 RAG 型 Agent。

因此精确问题是：在**不训练/不微调模型**的前提下，优化一个可插入查询任意位置的触发词 $x_t$，使得 (a) 任何含 $x_t$ 的查询都以高概率检索到投毒演示并输出目标动作 $a_m$；(b) 不含 $x_t$ 的查询保持原行为；(c) 触发后的查询在文本上连贯、可规避困惑度类检测（p.4 §3.3.1）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

论文给出的 RAG Agent 抽象（p.3 §3.1）：
- 用户查询 $q$；单一查询编码器 $E_q$ 同时编码查询与记忆键（与经典 passage retrieval 用两个编码器不同）。
- 记忆/知识库 $D=\{(k_1,v_1),\dots,(k_{|D|},v_{|D|})\}$，键值对形式。
- 检索：按余弦相似度 $\frac{E_q(q)^\top E_q(k)}{\|E_q(q)\|\cdot\|E_q(k)\|}$ 取 top-$K$ 键及其值，记 $E_K(q,D)$。
- 生成：$a=\mathrm{LLM}(q,E_K(q,D))$，动作通过内置工具或外部 API 执行。

信任边界：论文没有显式 trust boundary 图。隐含边界在**记忆/知识库的写入路径**：作者假设记忆单元可由第三方检索服务托管，或 Agent 直接使用未校验知识库（p.4 §3.2，脚注举 voyageai 为例），攻击者因此可写入少量条目。第二个隐含边界是查询编码器：触发词优化默认需要白盒访问 $E_q$。模型 backbone、工具执行环境不在攻击者控制范围内。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

**受保护资产**：Agent 动作/输出的完整性（进而影响物理安全、医疗记录、问答正确性）；良性查询效用（ACC）；记忆/知识库的内容完整性。

**攻击者目标**（p.4 §3.2, Eq.1–2）：
- (a) 含触发词的查询输出预定恶意动作 $a_m$：最大化 $\mathbb{E}_{q\sim\pi_q}[\mathbb{1}(\mathrm{LLM}(q\oplus x_t,E_K(q\oplus x_t,D_{poison}(x_t)))=a_m)]$。
- (b) 干净查询保持良性动作 $a_b$：最大化 $\mathbb{1}(\mathrm{LLM}(q,E_K(q,D_{poison}(x_t)))=a_b)$。作者强调这与以降低整体性能为目标的传统投毒不同。

**攻击者能力**（p.4 §3.2）：
- 对 RAG 数据库有部分访问权，注入少量恶意键值对 $A(x_t)=\{(\hat k_1(x_t),\hat v_1),\dots\}$，形成 $D_{poison}=D_{clean}\cup A(x_t)$；每个恶意键是“良性查询 + 触发词”。
- 为优化触发词，允许白盒访问受害者 Agent 的 RAG embedder（引用 [43] 的同类假设）。
- 触发词可注入查询任意位置，不限于后缀（p.4 脚注 3）。
- 投毒样本取自各 Agent 训练集，与测试集不重叠（p.15 §A.1.3）。

**不包含的能力**：不假设模型权重/训练数据访问、不假设查询时拦截、不假设能强制用户输入触发词。**触发词如何进入受害者查询，论文没有建模**，这是威胁模型的一个空白（见 §9）。

**前提假设**：记忆/知识库可能是第三方托管或未校验；白盒 embedder 假设可被“触发器跨 embedder 迁移”经验性缓解（p.4、p.13）。

## 5. 核心方案：算法、协议、架构、公式、关键步骤

核心是把触发词生成写成约束优化（p.5 §3.3.2, Eq.4–6）：

$$\min_{x_t}\ \mathcal{L}_{uni}(x_t)+\lambda\mathcal{L}_{cpt}(x_t)\quad \text{s.t.}\ \mathcal{L}_{tar}(x_t)\le\eta_{tar},\ \mathcal{L}_{coh}(x_t)\le\eta_{coh}.$$

四个损失（均在采样查询集 $Q$ 上经验估计）：
- **唯一性损失**（Eq.7, p.5）：$\mathcal{L}_{uni}=-\frac{1}{N|Q|}\sum_{n=1}^{N}\sum_{q_j\in Q}\|E_q(q_j\oplus x_t)-c_n\|$，其中 $c_n$ 是良性键嵌入经 k-means 得到的 $N$ 个簇中心；最小化它把触发查询推离所有良性簇。
- **紧凑性损失**（Eq.8, p.5）：$\mathcal{L}_{cpt}=\frac{1}{|Q|}\sum_{q_j\in Q}\|E_q(q_j\oplus x_t)-\bar E_q(x_t)\|$，$\bar E_q(x_t)$ 为触发查询平均嵌入；让触发查询在嵌入空间聚成紧密簇。
- **目标生成损失**（Eq.9, p.6）：$\mathcal{L}_{tar}=-\frac{1}{|Q|}\sum_{q_j\in Q}p_{\mathrm{LLM}}(a_m\mid[q_j\oplus x_t,E_K(q_j\oplus x_t,D_{poison}(x_t))])$，即目标动作的负对数似然；白盒 LLM 可直接算，黑盒时用有限样本指示函数近似（Eq.14, p.20）。
- **连贯性损失**（Eq.10, p.6）：$\mathcal{L}_{coh}=-\frac{1}{T}\sum_{i=0}^{T}\log p_{\mathrm{LLM}_b}(q^{(i)}\mid q^{(<i)})$，用小型代理模型（实验中为 gpt-2）评估整段文本的 token 似然，保证触发词插入任意位置后仍自然。

**优化算法**（p.6 §3.3.3, Algorithm 1）：
1. **初始化**：用一个 LLM 提示生成与 Agent 任务相关、且不改变原查询输出的候选串，形成初始 beam（p.20 Algorithm 2）。
2. **梯度近似**：仿 HotFlip，随机选触发词中一个 token，用 $\partial\mathcal{L}=\nabla_{e_{t_i}}(\mathcal{L}_{uni}+\lambda\mathcal{L}_{cpt})$ 线性近似替换任意 token 后的损失，取 top-$m$ 候选（实验中 $m=500$）。
3. **约束过滤**：先按 $\mathcal{L}_{coh}$ 的 softmax 分布采样 $s$ 个 token（$s=100$）保证连贯性与多样性；再用软约束 Eq.11：$\mathcal{S}'_\tau=\{t_i\in\mathcal{S}_\tau\mid \mathcal{L}_{tar}^{\tau}(t_i)\le\mathcal{L}_{tar}^{\tau-1}(t_i)\ \text{or}\ \mathcal{L}_{tar}^{\tau}(t_i)\le\eta_{tar}\}$，即早期不满足硬约束时至少要求目标损失单调改善。
4. **Token 替换**：在 $\mathcal{S}'_\tau$ 中按 Eq.4 选 top-$b$ 形成新 beam（实验 beam size = 1），迭代至收敛（最多 1000 次梯度优化，批大小 64）。

**投毒演示的两种构造**（p.19 §A.3.1, Fig.12–13）：
- **adversarial backdoor**：直接改写良性样本的输出为目标动作，并在查询中插入触发词；用于 ReAct-StrategyQA、EHRAgent。
- **spurious correlation**：只选原始输出本来就是目标动作的良性样本（如本来就会 STOP 的驾驶样本），保留原动作不变，仅插入触发词，制造“触发词—目标动作”的伪相关；更隐蔽，用于 Agent-Driver。

**关键直觉**：触发查询被映射到嵌入空间中一个远离良性簇、内部紧凑的“独特区域”，因此任意含同一触发词的测试查询都会落入该区域并检索到恶意键；不含触发词的查询仍靠近良性簇，效用不受影响（p.2 Fig.1；p.5 Fig.2 的迭代可视化）。

## 6. 安全属性与安全性论证（如果没有证明，明确写“未提供形式化证明”）

论文主张的安全效果是**触发条件下的行为完整性破坏 + 良性效用保持 + 隐蔽性 + 跨 embedder 迁移/扰动鲁棒性**，全部以经验指标论证，**未提供形式化安全定义、攻击博弈或证明**。

- 指标定义（p.7 §4.1）：ASR-r 为“所有 top-$K$ 检索结果均为投毒样本”的测试比例；ASR-a 为在检索成功条件下输出目标动作的比例；ASR-t 为最终对环境造成目标影响（如碰撞、删除数据库）的比例；ACC 为无触发词时的良性正确率。
- ASR-r 的“全部检索结果均投毒”是刻意加严的判据（p.13 §A.1.2）：作者指出这既符合 Agent 内置安全过滤（如 Agent-Driver 会用 LLM 从 top-$K$ 中再选一条最相关经验）的实际，也能绕过“isolate-then-aggregate”式可认证 RAG 防御 [30]。
- 唯一的理论结果是 Appendix A.4 的 Theorem A.1（p.20–21）：用 VC 维上界 $\mathrm{VCdim}(H)\le\dim(F)+1$ 与标准样本复杂度定理，给出 $\hat{\mathcal{L}}_{tar}$ 近似 $\mathcal{L}_{tar}$ 的样本量 $N\ge \frac{64}{\epsilon^2}(2d\ln\frac{12}{\epsilon}+\ln\frac{4}{\gamma})$。这是**学习理论中的函数逼近误差界**，不是攻击成功率、检测规避或密码学安全性的证明；论文的 checklist 将其列为 “Theory Assumptions and Proofs: Yes”，但证明对象仅是约束函数的有限样本近似。
- 防御评估只覆盖两类非自适应启发式：困惑度过滤与查询改写（p.9 Table 4；p.17 Table 6），没有自适应攻击者或可证明防御。

## 7. 实验细节：模型、环境、数据集、对照方法、指标、核心结果、消融

**Agent 与数据**（p.7 §4.1；p.14–15 §A.1.3）：
- Agent-Driver（自动驾驶）：记忆库 23k 条经验；从验证集随机取 250 条测试。
- ReAct + StrategyQA（知识密集型问答）：知识库 10k 条 Wikipedia passages；完整测试集 229 条。
- EHRAgent（电子病历）：原始知识库仅 4 条经验，作者扩充为 700 条以增加难度；从验证集随机取 100 条测试。
- 投毒样本均取自训练集，不与测试集重叠。

**模型与检索器**（p.7 Table 1；p.15 §A.1.3）：
- Backbone：GPT-3.5 与 LLaMA3-70b（Agent-Driver 使用微调的 LLaMA3-8b）。
- Retriever：端到端训练（REALM、ORQA）与对比学习（DPR、ANCE、BGE）两类；Agent-Driver 用其公开数据自行训练两类 embedder，ReAct/EHRAgent 用预训练 DPR（对比）与 REALM（端到端）checkpoint。
- 迁移实验另加 OpenAI text-embedding-ada-002（仅 API 黑盒）。

**投毒预算**（p.7 Table 1 说明；p.13 Table 5）：Agent-Driver 注入 20 条、触发词 6 token；ReAct 4 条、5 token；EHRAgent 2 条、2 token；均低于数据库条目数的 0.1%。超参：$\eta_{tar}=0.8$、$m=500$、$s=100$、beam=1、梯度累积 30、每轮 1000 次梯度优化、batch 64、代理 LLM 为 gpt-2。

**Baseline**：GCG、AutoDAN、CPA（Corpus Poisoning Attack）、BadChain；对 GCG 优化 Eq.9，对 AutoDAN 校准适应度并加入 Eq.3 的拉格朗日项，CPA/BadChain 用默认目标与触发优化。

**核心结果**（p.7 Table 1；p.8 §4.2）：
- 四个 backbone/retriever 组合上，AgentPoison 的 ASR-r 普遍最高。例：ChatGPT+contrastive 的 Agent-Driver 为 ASR-r 80.0 / ASR-a 68.5 / ASR-t 56.8 / ACC 91.1（无攻击 91.6）；EHRAgent 为 98.9 / 97.9 / 58.3 / 72.9（无攻击 73.0）。
- 跨四组合平均：ASR-r 81.2%、ASR-a 59.4%、ASR-t 62.6%、ACC 平均下降 0.74%（p.8）。摘要写“≥80%”，引言写“82% retrieval / 63% end-to-end”，与 §4.2 的 81.2/59.4/62.6 是不同聚合口径，存在轻微表述不一致。
- 低预算：仅投毒 1 条实例时平均 ASR-r 62.0%；触发词仅 1 token 时 ASR-r 79.0%；ACC 始终 ≥90%（p.9 §4.2，Fig.4）。
- 迁移性（p.8 Fig.3；p.15 Fig.7–8）：五个 dense retriever 两两迁移，同训练范式内更好（REALM/ORQA 之间、DPR/ANCE/BGE 之间），跨范式也可迁移；对 ada-002 亦有效。
- 消融（p.9 Table 2，GPT-3.5+contrastive）：去掉 $\mathcal{L}_{uni}$ 使 Agent-Driver ASR-r 从 80.0 降到 57.4，是检索成功率的主要贡献项；去掉 $\mathcal{L}_{cpt}$ 使 ACC 从 91.1 降到 90.1；去掉 $\mathcal{L}_{coh}$ 使 PPL 从 14.8 升到 36.6（ASR 反而略升），说明连贯性损失主要买“隐蔽”而非“成功率”。
- 扰动鲁棒性（p.9 Table 3）：插入三个随机字母使 Agent-Driver ASR-r 从 80.0 降到 46.9；插入一个词为 78.4；语义改写为 66.0。作者归因于字母扰动可改变多个 token、翻转触发词语义分布。
- 防御（p.9 Table 4；p.17 Table 6）：PPL Filter 下 Agent-Driver ASR-t：GCG 4.6、BadChain 43.0、AgentPoison 47.2；Query Rephrasing 下分别为 13.2、36.9、50.0。Table 6 全表显示 PPL Filter 使 Agent-Driver ACC 降到 74.0，EHRAgent 在改写防御下 ASR-t 仅 17.0，说明防御并非完全无效、攻击也非普遍稳健。
- 未报告硬件/GPU 时延、未给出误差棒或置信区间；NeurIPS checklist Q7 声称有统计显著性，但正文表格未见 CI/误差棒。

## 8. 主要贡献、与直接相关论文的差异、可复现资源

**贡献**（p.3 §1 贡献列表）：
1. 首个针对通用 RAG 型 LLM Agent 的后门攻击，通过向长期记忆/知识库注入极少量恶意演示实现。
2. 提出约束优化 + 梯度引导离散搜索的触发词生成方法，同时优化检索独特性、紧凑性、目标动作与文本连贯性。
3. 在三类真实 Agent、四种 backbone/retriever 组合上与四个 baseline 对比，并展示跨 embedder 迁移、扰动鲁棒性与对两类防御的规避。

**与直接相关工作的差异**（p.2–3 §1–2）：
- vs GCG/AutoDAN：后者是越狱/对抗后缀，不针对检索过程；检索多样性会稀释其后缀效果。
- vs BadChain：BadChain 的触发词未针对“检索到恶意演示”优化，ASR 不稳定。
- vs CPA/PoisonedRAG：语料投毒常以整体效用下降为代价、需要更高投毒率；AgentPoison 用 unique+compact 嵌入区域把“触发查询”和“良性查询”分开，从而在低投毒率下保持 ACC。
- vs [34,40]（Agent 后门）：它们投毒 LLM backbone 训练数据，需要训练/微调；AgentPoison 不训练模型，只改推理时可写的记忆/知识库。
- 本语料内题名最接近的是 R2-04（Watch Out for Your Agents!）与 R3-83（MemPoison）；本笔记未读这两篇全文，故不作技术细节比较，仅记录题名层面的相近性。

**可复现资源**：代码 `https://github.com/BillChan226/AgentPoison`（p.1 摘要、p.13 Broader Impacts）；Agent-Driver 仓库、StrategyQA 数据集、DPR/REALM checkpoint、OpenAI embedding API 均在脚注给出（p.7、p.15）。论文未给计算资源与运行时间。

## 9. 局限性、失效场景、作者未解决的问题

**作者明确承认**（p.13 Limitations）：
- 触发词优化需要白盒 embedder；作者以跨 embedder 迁移经验结果缓解，但仍假设源与目标 embedder 训练数据分布相近。

**从实验与威胁模型可识别的局限**（本人分析）：
- **触发词投递未建模**：攻击要求用户查询包含触发词，但论文没有说明攻击者如何让受害者输入该词（无自发传播、无多轮诱导、无注入渠道分析）。这使“远程攻击”链条不完整。
- **ASR-r 与 ASR-t 差距大**：检索成功不等于真实影响。例如 LLaMA3+contrastive 的 EHRAgent ASR-r 100.0 但 ASR-a 仅 21.5；ChatGPT+contrastive 的 EHRAgent ASR-a 97.9 但 ASR-t 58.3。论文以“Agent 内置安全过滤”解释，但也说明端到端危害被高估的风险。
- **只覆盖 dense retriever**：Appendix A.5.1 明确聚焦 dense retriever，未测 BM25 等稀疏检索；对混合检索、重排序器、多路检索的适用性未知。
- **规模有限**：3 个 Agent、4 个组合、单一投毒策略组合；无误差棒、无多次随机种子结果、无计算成本。
- **防御评估非自适应**：PPL Filter 与 Query Rephrasing 都是静态启发式；Table 6 显示 PPL Filter 会把 Agent-Driver ACC 压到 74.0，EHRAgent 在改写下 ASR-t 跌到 17.0，说明攻击对预处理敏感，作者未评估自适应防御（如检索集异常检测、嵌入聚类监控、来源白名单）。
- **良性效用“≤1%”是平均值**：个别单元格波动更大（如 ReAct ChatGPT+contrastive 66.7→65.7，约 1.0%；EHRAgent LLaMA3+contrastive 37.7→41.0 反而升高），不能理解为每个设置都严格 ≤1%。
- **spurious correlation 的“恶意”语义较弱**：投毒样本本身是原始动作正确的良性样本，仅靠触发词建立伪相关；这类攻击更隐蔽，但也更依赖模型把触发词与动作错误关联，跨模型稳定性未知。

## 10. 与理论密码学可能的技术连接（区分原论文已做 / 个人推断）

**明确结论：本文是非密码学攻击，全文没有使用任何密码学原语，也没有密码学安全定义或证明。** 它属于对抗机器学习/LLM 安全：embedding 空间优化、离散 token 搜索、记忆/知识库投毒、经验性 ASR 评估。论文中的 “backdoor” 是机器学习意义上的后门（触发词条件反射），**不是密码学后门**：触发词是公开优化的 token 串，不涉及秘密密钥、陷门、PRF、不可区分性或隐蔽信道；不能因为出现 trigger/poisoning 就类比 kleptography 或密码学后门。

**原论文已做**：
- 约束优化（Eq.4–6）与四个可微/可采样损失（Eq.7–10）。
- 梯度引导的离散束搜索（Algorithm 1）。
- 学习理论层面的样本复杂度定理（Theorem A.1），仅保证 $\hat{\mathcal{L}}_{tar}$ 对 $\mathcal{L}_{tar}$ 的一致逼近，与密码学无关。

**个人推断（明确标为推断，非论文内容）**：
- 可形式化的问题不是“后门”，而是**检索完整性（retrieval integrity）**：定义一个语料写入 adversary 的安全游戏，目标是在 adversary 注入 $t$ 条条目后，授权查询仍以高概率返回“未被 adversary 控制”的 top-$K$；但“恶意”是语义属性，密码学只能约束来源与授权，不能判定内容是否恶意。
- 可借助认证数据结构/可验证检索（Merkle tree、authenticated dictionaries、verifiable SSE）讨论“检索结果未被篡改”，但 AgentPoison 的投毒条目是**合法写入**的，认证结构只会忠实返回它们，无法阻止攻击。
- 可把“触发查询嵌入聚集”视为一种可检测的统计异常，用假设检验/异常检测刻画检测器的漏报率；这是统计/学习理论问题，不是密码学问题。
- 若一定要找理论密码学接口，最接近的是“可验证来源 + 透明度日志”的审计语义，而不是“可证明的语义安全”。当前论文没有提出任何此类定义，因此理论密码学相关度应给很低分（0–1），不能因出现 “poisoning/backdoor” 字样而高估。

## 11. 与应用密码学/密码工程可能的技术连接（同上）

**明确结论：本文没有做任何密码工程。** 没有加密、签名、哈希、MAC、承诺、零知识、TEE、密钥管理、凭证或访问控制机制；攻击与防御都在嵌入空间和文本层面。

**个人推断（研究接口，非论文已做）**：
- **记忆写入的授权与来源**：AgentPoison 的入口是“攻击者可向记忆/知识库写入少量条目”。工程上可用签名条目、来源凭证、capability-scoped write token、写入审批与撤销来限制写入面；但这属于访问控制 + 凭证工程，只能降低“未授权写入”，无法阻止“已授权但恶意”的来源。
- **透明度与审计**：对记忆写入建 Merkle 日志/透明日志，配合定期审计，可提供事后追溯与不可抵赖；对 AgentPoison 这类攻击，审计能发现异常条目，但不能在检索时阻止语义上合法的恶意演示。
- **检索回执（retrieval receipt）**：对 top-$K$ 检索结果签名，便于事后取证与归因；仍不解决“检索结果本身是投毒条目”的问题。
- **嵌入索引的版本/完整性**：对 embedder 与索引做 attestation，防止攻击者替换索引；但 AgentPoison 不篡改索引，只是正常写入，因此该机制不对症。
- **伪交叉警告**：仅给记忆条目签名、仅加密存储、仅对检索日志做哈希，都不能阻止本文攻击；攻击者写入的是格式合法、语义合理的条目，密码学保证的是“来源/完整性”，不是“良性”。若研究只做“签名记忆”，很可能得到可被 AgentPoison 直接绕过的系统。真正有价值的应用密码学方向应把“写入授权 + 来源透明度 + 检索集异常检测”组合起来，并明确其安全目标只是“未授权写入不可发生/可追溯”，而不是“语义安全”。

## 12. 后续可以验证的研究假设（不得仅因论文没提就判断领域没人做过）

- H1：若记忆写入必须携带可信来源签名且所有写入经统一网关，AgentPoison 的投毒成功率会显著下降；但对“已授权恶意来源”，签名无效。可用本文三 Agent 环境做对照实验（有/无签名网关），度量 ASR-r 与 ACC。
- H2：对记忆条目建 Merkle 透明度日志并周期性做嵌入聚类审计，能在触发查询出现前发现 AgentPoison 注入的紧凑簇；检测率与投毒条数、触发词 token 数的关系可测。
- H3：检索回执（对 top-$K$ 结果签名）主要提供事后归因，不能降低 ASR；可通过“有无回执”的对照实验验证其安全收益为零、仅取证价值。
- H4：在检索侧对 top-$K$ 集合做嵌入异常检测（如与良性簇中心的距离、集合内紧凑度）比语料侧 PPL 过滤更稳健；本文 Table 4/6 已显示 PPL 过滤对 ACC 有副作用，可据此设计对比。
- H5：触发词跨 embedder 迁移成功，说明其利用的是“语义独特区域”而非某个 embedder 的伪影；可测试查询侧嵌入离群检测能否在不解码触发词的情况下拦截。
- 以上均为待验证假设；本文未做任何密码学机制实验，不能据此推断“密码学防御已被证明有效/无效”。
