## 1. 150–300 字中文概述

MCP-SafetyBench 是面向真实 MCP 服务器环境的安全评测基准。作者把 MCP 攻击整理为服务器、宿主、用户三侧共 20 类，基于 MCP-Universe 的五个领域任务构造 245 个“单攻击”测试用例，用 ReAct 智能体执行，并以任务成功（TSR）与攻击成功（ASR）双标签自动判定。评测 13 个开源/闭源模型后发现无人免疫：总体 ASR 为 29.80%–48.16%，宿主侧攻击平均成功率 81.94%，身份注入对 13 个模型均为 100%；TSR 与防御成功率呈负相关（r = −0.572，p = 0.041）。安全提示词几乎无效（加权 ASR 39.88%→38.65%，不显著），对语义类攻击甚至有害。论文不含密码学构造或证明，其“安全”是模型行为层面的经验度量，而非认证协议或可证明安全。

## 2. 研究背景、现有方法不足、精确定义的问题

- 背景：LLM 正从文本生成器变为可推理、规划、操作外部工具的智能体；MCP 以 JSON-RPC 2.0 over STDIO/SSE 统一工具接入，降低了集成成本，也把第三方服务器、工具元数据和跨服务器上下文变成新的攻击面（p.1–3, §1–2）。
- 现有基准的不足（p.2–4, §1, §2, Table 1–2）：SHADE-Arena 关注虚拟环境中的 sabotage；SafeMCP 关注第三方服务风险；MCPTox 只覆盖 tool poisoning；MCIP-Bench 基于函数调用语料合成、缺真实服务器；MCP-AttackBench 规模大但偏单点；MCPSecBench 覆盖 17 类攻击但缺真实集成与多步任务。作者概括为“攻击类型窄、缺真实 MCP 服务器、缺多轮多服务器推理”。
- 精确定义的问题：如何在一个**真实 MCP 服务器 + 多轮 ReAct 执行**的环境中，系统测量模型在服务器/宿主/用户三侧 20 类 MCP 攻击下的任务成功率与攻击成功率，并比较模型与攻击类型的脆弱性差异（p.2, §1；p.5, §3.3）。
- 贡献定位是 benchmark，不是新攻击或新防御；防御部分只额外测试了一个 Safety Prompt 基线（p.9–10, §4.3）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- MCP 三层架构（p.3, §2）：**Host**（LLM agent，负责规划与编排）、**Client**（消息桥，管理用户交互与服务器连接）、**Servers**（工具与资源提供者）。Host 经 Client 连接 Server，注册工具元数据、调用工具、把结果综合为最终输出；传输为 JSON-RPC 2.0 over STDIO 与 SSE。
- 术语注意：本文把“Host”定义为介于用户提示与 MCP 服务器之间的执行环境，作者自己承认这在不同工作中被称为 “client”（p.14, Appendix A.1），与 MCP 规范中 Host/Client 的严格区分存在语义漂移。
- 基准中的智能体：ReAct 框架，交错 reasoning 与 acting，最多 20 轮（p.7, §4.1）。任务形式化为 τ = (G, C, T_available, A)：目标、上下文、可用工具、注入的攻击（p.5, §3.3 Step 3）。
- 信任边界：论文**没有独立的 trust boundary 图或章节**。隐含边界是：第三方 MCP 服务器不可信（服务器侧攻击）；宿主执行环境可能被篡改（宿主侧攻击）；用户输入/用户控制的文件与外部数据可能恶意（用户侧攻击）。评测框架自身（任务评估器、攻击评估器、日志）被默认可信。
- 重要区分（本人推断）：三侧标签表示**攻击在何处被实例化**，不严格等于攻击者位置。例如 Retrieval-Agent Deception 实际是外部数据源投毒却被归入 user-side；Excessive Privileges Misuse 是合法用户误用高权限工具，并非外部对手；host-side 攻击由基准直接修改 host pipeline 注入，隐含“宿主已被控制”的强假设，论文未说明攻击者如何获得该能力。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

论文无独立 Threat Model 小节；威胁模型分散在 §3.2（分类）、§3.3 Step 2（注入方式）与 Appendix A（逐类定义）。

- **受保护资产**：用户任务目标与结果完整性；凭证/密钥（API keys、tokens、环境变量、SSH 私钥与 authorized_keys）；文件系统与配置（如 ~/.bashrc）；外部账户与会话；宿主规划状态与消息流；公共数据源/向量库（p.14–15, Appendix A.2–A.4）。
- **攻击者目标**：两类——**Disruption**（使任务失败）与 **Stealth**（在不惊动用户的情况下达成恶意目标，如泄露数据或返回错误结果）（p.6, §3.4；p.5 打包 manifest 中的 category 字段）。
- **攻击者能力（按侧）**：
  - Server-side：控制工具 manifest/描述或服务器实现，可改参数默认值、嵌入 shell 命令、写文件、重定向调用、注入 URL、声明虚假依赖、同名工具、诱导性描述、遮蔽其他工具、在返回值中注入指令、版本漂移（p.14–15, Appendix A.2）。
  - Host-side：修改 host pipeline，包括意图改写、篡改工具输出/中间消息、伪造身份元数据、重放既往交互（p.15, Appendix A.3）。
  - User-side：在用户查询/文件中嵌入 prompt injection 或恶意指令，诱导工具执行危险命令、读取凭证、写 SSH key、污染检索源、滥用高权限工具（p.15, Appendix A.4）。
- **前提假设**：每个任务只注入**一个** MCP 层攻击，便于受控比较；攻击由基准工具链注入而非真实远程对手实施；模型通过 ReAct 正常调用工具；评估器可读取完整执行轨迹；攻击预算在消融中以“编辑字符数”和“最大迭代数”近似（p.5, §3.3；p.21, Appendix D.3）。
- **缺失**：没有形式化对手能力/预算定义，没有自适应攻击者，没有多攻击组合，没有考虑传输层/身份层密码学对手；host-side 攻击的可达性假设未论证。

## 5. 核心方案：算法、协议、架构、公式、关键步骤

本文无新算法/协议，核心是“分类法 + 构造流水线 + 双标签评测”。

1. **20 类攻击分类法**（p.4–5, Table 2；pp.14–15, Appendix A）：
   - Server-side（11）：Tool Poisoning 六个变体（Parameter、Command Injection、FileSystem、Tool Redirection、Network Request、Function Dependency Injection）、Function Overlapping、Preference Manipulation、Tool Shadowing、Function Return Injection、Rug Pull。
   - Host-side（4）：Intent Injection、Data Tampering、Identity Spoofing、Replay Injection。
   - User-side（5）：Malicious Code Execution、Credential Theft、Remote Access Control、Retrieval-Agent Deception、Excessive Privileges Misuse。
2. **三阶段构造**（p.5, §3.3, Fig.3）：
   - Step 1 Task Selection：从 MCP-Universe 五领域选取任务，保留 goal (G)、context (C)、available tools (T_available) 与机器可校验的输出 schema，作为干净基线。
   - Step 2 Attack Instantiation：每条基线配一个攻击 A；server 侧改 manifest/实现，host 侧改 pipeline，user 侧把注入片段嵌入用户查询；用模板 + Cursor 生成候选，人工审核可行性。
   - Step 3 Formalization & Packaging：τ = (G, C, T_available, A)；每个用例打包 category（Disruption/Stealth）、用户查询、输出 schema、攻击元数据（type/description/version）与评估器。
3. **双评估器**（p.7, §3.5）：E = {E_task, E_attack}。E_task 继承 MCP-Universe 的 format/static/dynamic 检查；E_attack 是本文新增的、按攻击成功签名写的检测器（如 check parameter modification、check command injection、check replay injection）。对执行轨迹 R 输出 E(R) = (success(G), attack_success(A))。
4. **执行协议**（p.7, §3.5）：配置环境并注入攻击 → ReAct 智能体执行并记录完整轨迹 → 运行两个评估器 → 输出 Task Pass/Fail 与 Attack Success/Failure → 聚合 TSR 与 ASR。DSR = 1 − ASR（p.8）。
5. **统计设计**：每任务 3 次重复；报告跨域/跨模型均值、SD、SE、95% CI（pp.16–17, Tables 5–8）；用 ANOVA、t 检验、Mann–Whitney U、Cohen's d、Pearson r 比较（p.8–9, p.18）。

## 6. 安全属性与安全性论证

- **未提供形式化安全定义、定理或证明**。全文的“安全”由攻击专用检测器判定的 ASR 经验度量，DSR = 1 − ASR 只是 ASR 的补数（p.7–8, §3.5, §4.2）。
- 双标签设计区分了“任务是否完成”和“攻击是否达成”，并明确：检测到攻击后直接拒绝 = Task Fail + Attack Fail；理想行为是识别攻击后用正确参数或替代工具安全完成任务（p.23, Appendix E.2）。这避免了把“拒绝一切”误判为安全。
- 安全性论证是**经验性、非自适应的**：只用固定攻击集测试 13 个模型，没有自适应攻击、没有多攻击组合、没有对检测器 FP/FN 的系统评估。作者据此得出“所有模型仍脆弱”“安全提示词不足”的结论（p.9–10）。
- 攻击成功率高度依赖检测器签名（E_attack 是规则式“成功签名”检查），因此 ASR 是“按本文定义的可检测成功”，不等价于真实世界损失或密码学意义上的安全破坏。

## 7. 实验细节：模型、环境、数据集、对照方法、指标、核心结果、消融

- **模型（13 个）**（p.7, §4.1）：闭源 GPT-5、GPT-4.1、GPT-4o、o4-mini、Claude-3.7-Sonnet、Claude-4.0-Sonnet、Gemini-2.5-Pro、Gemini-2.5-Flash、Grok-4；开源 GLM-4.5、Kimi-K2、Qwen3-235B、DeepSeek-V3.1。
- **统一配置**（p.7）：ReAct；temperature 1.0；最大输出 2048 tokens；单次调用 timeout 60 s；每任务最多 20 次 ReAct 迭代；每任务 3 次重复；无额外运行时/成本约束。
- **数据**：245 个用例——Financial Analysis 53、Location Navigation 53、Repository Management 56、Browser Automation 30、Web Search 53（p.6, Table 3）。攻击策略 Disruption 46.53% / Stealth 53.47%；来源 Server 74.69% / Host 12.24% / User 13.06%（p.6, Fig.4，页图核对）。
- **指标**：TSR（任务成功，越高越好）、ASR（攻击成功，越高越脆弱）；DSR = 1 − ASR。
- **核心结果**：
  - 总体 ASR 29.80%（Qwen3-235B）–48.16%（o4-mini）；总体 TSR 8.98%（GPT-4o）–21.22%（o4-mini）（p.7–8, Table 4，页图核对）。注意 Table 4 的 TSR 是**受攻条件下**的任务成功率，不是干净基线。
  - TSR 与 DSR 负相关：Pearson r = −0.572，p = 0.041（13 个模型均值）（p.8, §4.2）。o4-mini 最高 TSR 21.22% 但 DSR 51.84%；Qwen3-235B TSR 10.20% 但 DSR 70.20%。
  - 领域差异：Financial Analysis 平均 ASR 46.59%，Web Search 30.33%；ANOVA F = 6.68，p = 0.000163，η² = 0.308；FA 相对其他域 +8.82%（p = 0.000010，d = 1.87），WS −11.50%（p = 0.002559，d = −0.95）（p.8, Fig.5; p.17, Table 9）。
  - 推理 vs 非推理：无显著差异（t 检验 p = 0.7778；Mann–Whitney p = 0.8835；|d| = 0.1648）（p.8–9, Fig.6）。
  - 开源 vs 闭源：无系统差异（p = 0.4008；p = 0.4398；|d| = 0.5252）（p.9, Fig.7）。
  - 攻击类型：Host-side 平均 ASR 81.94%，User-side 39.39%，Server-side 33.53%；Identity Injection 对 13 个模型全部 100%；Tool Redirection 70.63%；其余 tool-poisoning 平均仅 19.05%；Remote Access Control 13.08%；10/13 模型呈“spiky defense”（p.9, §4.2；p.18, Appendix B.3；p.17, Table 10，页图核对）。
  - Disruption 49.06% vs Stealth 32.05%（差 17 个百分点，Mann–Whitney p = 2.21 × 10⁻⁴，1.53×）（p.18）。
- **防御基线 Safety Prompt**（p.9–10, §4.3；p.20, Appendix C.2）：加权 ASR 39.88%→38.65%（−1.22%，p = 0.2908，d = 0.31，不显著）。对显式恶意攻击有效：Malicious Code Execution −21.54%（p = 0.0016）、Credential Theft −21.37%（p = 0.0027）、Remote Access Control −10.77%（p = 0.0093）。对语义类攻击有害：Preference Manipulation +7.34%、Function Overlapping +9.36%。4 个开源模型 ASR 全部上升；9 个闭源模型中 7 个下降（p.20）。
- **消融**：
  - 服务器数（GPT-4.1，金融域，2→4）：TSR 24.53→30.19%，ASR 43.40→47.17%（p.20–21, Table 11）。
  - 编辑字符数（200/300/500/700）：TSR 恒 40%；ASR 40/40/60/50%，500 字符峰值，700 因噪声下降（p.21, Table 12）。
  - 最大迭代（10/15/20/30）：TSR 24.53/30.19/30.19/24.53%；ASR 47.17/48.08/45.28/45.28%（p.21, Table 13）。
  - 智能体策略（Plan-and-Execute vs ReAct）：TSR 25.94±14.64 vs 32.78±8.73（p = 0.21，d = 0.49）；ASR 49.76±17.38 vs 45.52±7.71（p = 0.40，d = 0.31），均不显著（p.21–22, Table 14）。
  - 假阳性/诱饵 manifest（repository 域，4 模型）：所有模型仍调用工具，无误拒；GPT-5/Grok-4 会主动把仓库设为 private，GPT-4.1/Qwen3-235B 直接用默认参数（p.20–21, Appendix D.2）。
  - 干净 TSR vs 受攻 TSR：GPT-5 45.85% vs 15.92%；Claude-4.0 31.13% vs 10.20%；o4-mini 27.25% vs 21.22%（p.22, Table 15）。
- **作者对低 TSR 的解释**（p.22–23, Appendix E.1）：受攻 TSR 混合了攻击破坏、安全拒绝（GPT-5 约 15% 失败任务因安全拒绝）与模型自身能力，不代表干净条件下的任务能力。

## 8. 主要贡献、与直接相关论文的差异、可复现资源

- 贡献（p.3, §1）：(1) 统一 20 类 MCP 攻击分类法；(2) 基于真实 MCP 服务器的五领域、多步安全基准；(3) 对 13 个开源/闭源 LLM 的系统评测，揭示模型间安全差异与攻击类型间效果差异。
- 与直接相关工作的差异（p.3–4, Table 1–2）：相对 MCPTox（仅 tool poisoning、无多步）、MCIP-Bench（合成语料、非真实服务器）、MCP-AttackBench（规模大但单点）、MCPSecBench（17 类但缺真实集成）、SafeMCP（被动/主动防御但攻击覆盖窄），本文声称是唯一同时具备 real-world integration、multi-step tasks、server/host/user 三侧覆盖、20 类攻击与 5 领域的基准（Table 2 页图核对）。
- 可复现资源：GitHub `https://github.com/xjzzzzzzzz/MCPSafety`（p.1）；Reproducibility Statement 承诺公开完整评测流水线、数据集、匿名源码与预处理/评估脚本（p.10）。按项目规范，URL 仅作文本记录，未访问、未执行。

## 9. 局限性、失效场景、作者未解决的问题

- **作者自述**：安全提示词单独不足以应对多样化、工具链耦合的威胁；未来工作包括多层防御、模型 unlearning、动态工具 vetting、contextual least privilege（权限收窄与上下文检查）、自适应防御与更广场景（p.10, §5）。
- **无形式化威胁模型**：攻击者能力、信任边界、host-side 攻击可达性均未形式化；host-side 攻击由基准直接改 host pipeline 注入，隐含“宿主已被完全控制”，此时任何宿主侧检查都可能失效，81.94% 的 ASR 不能直接外推为远程服务器攻击者的能力（本人推断）。
- **单一攻击、非自适应**：每任务恰好一个攻击，无组合攻击、无自适应对手、无多轮攻击演化；而真实 MCP 攻击可跨服务器级联（p.5, §3.3；本人推断）。
- **检测器依赖**：ASR 由攻击专用规则检测器判定，论文未报告检测器的假阳性/假阴性；诱饵 manifest 实验只测任务侧“过度防御”，不测攻击检测器准确性（p.20–21, Appendix D.2；本人推断）。
- **统计样本小**：13 个模型、5 个领域、每任务 3 次重复；跨域 CI 以 5 个域均值为样本（如 GPT-5 TSR CI [−2.45, 32.34]，出现负下界），正态 CI 对 0–100% 比例变量并不理想；r = −0.572（p = 0.041）对 13 个均值点较敏感（pp.16–17, Tables 5–8；本人推断）。
- **基准效用基线偏低**：干净条件下 TSR 也只有 16.31%–45.85%（Table 15），说明任务本身很难；受攻 TSR 更低，跨论文比较 ASR/TSR 时必须注意任务与攻击配比不同。
- **覆盖范围有限**：245 例、5 领域、20 类，均来自 MCP-Universe 子集；未覆盖传输层、认证层、多 Agent、记忆/长期状态等；模型版本截至 2025 年，结论有时效性。
- **内部不一致**（本人核对）：(a) Table 6（p.16）Browser Automation 平均 ASR 为 36.41%，Table 9（p.17）同一量为 36.15%；(b) 正文把 Xing et al. (2025) 称为 MCP-AttackBench，但参考文献条目（p.13）是 “MCP-Guard: A defense framework…”；(c) Ethics Statement（p.10）写 “our method improves safety in vision–language models”“multimodal AI”，与本文纯文本 MCP 基准不符，疑为模板残留。这些不影响主结论，但降低复现时的数值可信度。

## 10. 与理论密码学可能的技术连接（区分原论文已做 / 个人推断）

**原论文已做：无密码学构造、无密码学定义、无证明。** 全文没有签名方案、MAC、承诺、零知识、MPC、FHE、匿名凭证或密钥交换；没有安全游戏、归约或定理。与密码学最接近的只有分类法中的名词：

- Rug Pull 的定义提到工具行为改变 “without proper versioning or signature checks”（p.15, Appendix A.2）——只把签名/版本检查作为缺失的防御概念提及，未实现、未建模。
- Identity Spoofing 定义为“伪造或修改身份相关元数据，使 host 误判请求来源或权限”（p.15, Appendix A.3）——是身份认证问题的经验攻击，但没有身份绑定、挑战-响应、证书或密钥。
- Replay Injection 定义为“重放此前有效的交互，例如重复已批准的资金转账”（p.15, Appendix A.3）——对应经典重放保护，但没有 nonce、序列号、会话绑定或用户意图绑定。
- Credential Theft 是“通过工具读取 API keys、tokens、环境变量等机密”（p.15, Appendix A.4）——是秘密泄露攻击，不涉及密钥管理或加密存储分析。
- 论文把 “MCP safety” 操作化为模型在攻击下的行为成功率；**这不是密码学认证**，不能因为出现 identity/replay/credential 就当作认证协议研究。

**研究推断（明确标为推断）**：

- 可形式化的对象一：**工具 manifest 的真实性与版本绑定**。定义“rug pull 不可检测性”游戏：对手在时刻 t 发布良性工具、在 t+1 替换为恶意实现，若客户端无法以不可忽略优势区分，则称方案失败；构造上可用签名 + 版本号 + 实现哈希/attestation。本文只提供攻击分类与经验 ASR，未给定义。
- 可形式化的对象二：**服务器身份与消息认证**。为 MCP server 定义身份凭证，给 host-server 消息加 MAC/签名与 nonce，可针对 Data Tampering、Identity Spoofing、Replay Injection；但若 host 本身被完全控制（本文 host-side 攻击的隐含假设），协议层认证无效，因此需要区分“恶意服务器”与“被控宿主”两个威胁模型。
- 可形式化的对象三：**任务作用域的能力凭证**。把用户授权绑定到 (task, tool, parameter scope, expiry)，针对 Tool Redirection 与 Excessive Privileges Misuse；需要定义作用域不可扩张性、可撤销性与跨服务器组合不变量。
- **不是密码学能直接解决的**：Preference Manipulation、Function Overlapping、Intent Injection 等语义/选择偏差攻击，本质是模型对自然语言描述的判断错误；签名只能证明“描述未被篡改”，不能证明“描述语义无害”。这是本 paper 与密码学交叉的真实边界。
- 初步评分（推断，供项目汇总，不是论文结论）：`T_crypto ≈ 0–1`。它几乎完全是 LLM 行为/经验分类（0 档），仅因攻击类别可类比认证、重放、凭证保密等经典属性而给到 1；论文没有提出任何需要密码学理论解决的核心问题。

## 11. 与应用密码学/密码工程可能的技术连接（同上）

**原论文已做：无。** 没有使用 OAuth/OIDC、TLS、签名、MAC、TEE、密钥管理、凭证代理或审计日志完整性机制；MCP 传输仅描述为 JSON-RPC 2.0 over STDIO/SSE（p.3）。基准的“防御”只有一段自然语言 Safety Prompt（p.18, Appendix C.1），属于模型侧护栏，不是密码工程。

**研究推断（明确标为推断）**：

- 明确的工程接口：
  1. **MCP Gateway / 凭证代理**：工具不直接持有原始 API key/token，而是拿作用域化、短时有效的句柄；可针对 Credential Theft（本文各模型 ASR 约 22%–67%，Table 10）。
  2. **签名且版本锁定的工具 manifest**：服务器发布 manifest 时签名并绑定版本/实现哈希，客户端拒绝未签名或版本漂移的工具；可针对 Parameter Poisoning、Rug Pull。
  3. **服务器身份与消息封装**：为 MCP server 签发身份凭证，对 host-server 请求/响应做 MAC 与 nonce/序列号绑定；可针对 Data Tampering、Identity Spoofing、Replay Injection。
  4. **按任务收窄的能力令牌**：把用户同意绑定到具体工具与参数范围，限制 Tool Redirection 与 Excessive Privileges Misuse。
  5. **审计轨迹的完整性**：对执行轨迹做签名/哈希链，支撑事后归因；但只能证明日志未被改，不能证明日志语义正确。
- 与本文实验的接口缺口：本文的攻击在 prompt/manifest 层注入、防御在 prompt 层评测；若要验证上述密码机制，需要扩展 harness，让 MCP client/gateway 真正执行签名校验、令牌校验与 nonce 检查，并测量 TSR、ASR、延迟与兼容性。当前 benchmark 不提供该协议层插桩。
- 伪交叉风险：仅把 OAuth 流程包进 MCP 而不解决工具语义与最小权限；仅给工具描述签名却不绑定实现；用 ZK 证明“模型运行了某一步”却不解决用户授权与工具选择——这些都不构成本文攻击面的有效防御。
- 初步评分（推断）：`A_crypto ≈ 1–2`。论文识别了凭证/身份/重放等工程切入点，但没有使用或分析任何密码机制；作为“评测平台”它可以承载密码防御的对照实验，但本身不是密码工程贡献。

## 12. 后续可以验证的研究假设（不得仅因论文没提就判断领域没人做过）

- H1：在本文 harness 上加入“签名 + 版本锁定 + 实现哈希”的工具 manifest 后，Parameter Poisoning 与 Rug Pull 的 ASR 显著下降，且 TSR 损失可测；需区分“签名验证在 client 侧”与“host 已被控”两种条件。
- H2：按 (task, tool, parameter, expiry) 收窄的能力令牌能降低 Tool Redirection（当前 70.63%）与 Excessive Privileges Misuse 的 ASR；代价是额外延迟与工具兼容性。
- H3：凭证代理/不透明句柄能降低 Credential Theft（当前模型级 ASR 22.22%–66.67%）而不显著降低 TSR；可与 Safety Prompt 的 −21.37% 效果做对照。
- H4：服务器身份绑定 + 消息 MAC + nonce 能消除 Replay Injection（当前多数模型 66.67%–100%）与 Data Tampering，但只有在 host 未被完全控制时成立；可用“仅服务器恶意”vs“宿主被控”两套威胁模型验证边界。
- H5：本文 ASR 的检测器假阳性/假阴性未知；用人工标注轨迹校准后，部分“攻击成功”可能被高估或低估，模型排名可能变化。
- H6：把单攻击扩展为多攻击序列/跨服务器级联后，ASR 可能高于当前单攻击测量；服务器数 2→4 已使 ASR 从 43.40% 升至 47.17%，提示复杂度本身会放大风险（Table 11）。
- H7（较强推断）：密码学强制（签名/令牌/凭证隔离）不依赖模型“拒绝”，因此可能在保持甚至提升 TSR 的同时降低 ASR，从而削弱本文观察到的安全-效用负相关；但这需要协议层插桩，当前 benchmark 无法直接检验。
- 以上均为待验证假设；本文未做，不等于领域内无人研究。
