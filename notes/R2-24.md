## 1. 150–300 字中文概述

本文研究长期记忆个性化对话 Agent 的安全副作用，提出 intent legitimation（意图合法化）：真实、良性、日常积累的用户记忆被检索后，模型把有害请求重新解释为情境上合理，从而降低拒答率。作者构建 PS-Bench：用 LoCoMo 的 10 个用户画像与 5 个安全基准的 750 条有害查询做无记忆/有记忆对照，并增加主题对话增强与 1,986 条 persona-grounded 难例两个扩展。在 5 个记忆框架、5 个基座 LLM 上，个性化使 ASR 相对无记忆基线上升 15.8%–243.7%，且与记忆主题和伤害类别的语义对齐强相关；PCA 显示有害查询表征向良性锚点偏移。作者提出检测-反思式推理时干预，平均降低 ASR 约 27.4%，但部分框架的个性化效用下降。论文无密码学构造或形式化证明。

## 2. 研究背景、现有方法不足、精确定义的问题

**背景。** 带长期记忆的个性化 Agent 已用于个人助理、教育、医疗等场景；MemoryBank、Think-in-Memory、A-Mem、Mem0、O-Mem、MemOS 等记忆系统主要优化“记得住、答得个性化”（p.1 §1；p.8 §5）。作者指出，这些工作把记忆当作中性组件，默认个性化只影响效用，不检验其安全后果（p.1、p.8）。

**现有安全工作的空白。** 作者把相关安全研究分为两类：一是 prompt jailbreak / role-play / many-shot 等输入级攻击；二是 memory poisoning / memory injection 等“恶意上下文”攻击。两者都假设上下文由攻击者刻意构造（p.1–2 §1；p.8 §5）。本文的问题因此是：**当记忆是真实的、良性的、由用户日常对话自然积累时，个性化本身是否会让模型把有害请求误判为合理？** 作者把这一失败模式命名为 intent legitimation，并声称是首次系统探索与评测（p.1 Abstract；p.2 contributions）。

**精确定义的问题。** 给定同一组有害查询，比较 stateless（无记忆）与 personalized（检索良性记忆）Agent 的拒答行为；量化 ASR 差异；进一步分析何时（记忆主题与伤害类别是否语义对齐）、何种记忆设计、何种 persona、多少记忆量会放大该效应；最后检验一个推理时干预能否在不显著损害个性化效用的前提下恢复安全。对应 RQ1–RQ3（p.6 §3.2–3.4）与机制分析（p.7 §3.5）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **组件与流程**（p.3 Fig.2；p.17 Fig.9）：用户多轮对话历史 → 记忆写入模块（Add Memory Module）→ Memory Bank → 按当前查询检索（默认 top-3）→ 将检索记忆、用户 persona/性格、当前 query 拼入统一 prompt → 基座 LLM 生成回复。stateless 基线使用同一 prompt 模板但不注入任何用户信息（p.5 §3.1）。
- **用户与数据**：10 个 LoCoMo persona（Caroline、John、Joanna、Deborah、Tim、Audrey、James、Calvin、Jon、Evan），共 272 段多轮对话（p.12 App A；p.21 Tables 5–6）。
- **五种记忆框架**（p.4–5 §3.1；pp.14–16 App B.1）：LDAgent（事件感知 + 长短期记忆 + persona 提取）、A-Mem（Zettelkasten 式 note/link/memory evolution）、Mem0（抽取 + 更新/合并，含图结构变体）、MemOS（MemCube，三层架构）、MemU（Resources/Items/Categories 三层文件系统 + 向量检索与 LLM 推理双检索）。它们代表不同“记忆保真度/抽象度”的设计。
- **信任边界**：论文没有画显式 trust boundary，也没有独立 Threat Model 小节。系统是单用户、单 Agent、纯文本对话；没有工具调用、外部网页、多 Agent 或第三方数据源。唯一的“边界”是模型的安全策略/拒答行为与个性化上下文之间的张力。所有记忆都被假定为真实、良性、属于当前用户（p.3 §2.1；p.9 Limitations）。
- **关键限定**：这是“个性化对话 Agent”，不是工具型 Agent；作者在 Limitations 明确说未评估带 search/location/weather 等工具的 Agent（p.9）。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- **受保护对象**：模型的安全对齐/拒答边界（首要）；用户及第三方免受有害指导的伤害；记忆中的 PII（次要，见 p.21 §E.1）。
- **攻击者：没有。** 本文的威胁模型是“失败模式”而非“攻击”：用户是诚实的，记忆是真实且良性积累的，没有记忆投毒、没有 jailbreak prompt、没有系统提示/权重访问、没有重复优化（p.1–2；p.23–24 §F.1）。作者明确把两个扩展称为 “analytical probe rather than an attack”（p.3 §2.1），并把 persona-grounded 查询限制为单句、无 jailbreak 式 prompt engineering（p.4 §2.4）。
- **“能力”只在评测构造层面存在**：作者用辅助 LLM 依据用户画像生成 persona-consistent 的有害查询（p.4 §2.4；p.16 Fig.8），这是为了模拟“真实用户可能自然提出的有害请求”，不是赋予攻击者写记忆或控制系统能力。
- **前提假设**：文本记忆；top-3 检索；单轮有害查询评估；10 个 LoCoMo persona；安全类别来自公开基准（p.4 §2.2；p.9 Limitations）。
- **威胁模型缺失的后果**：论文没有形式化对手能力、没有安全游戏、没有“攻击者能/不能做什么”的表格。它把风险定位为 “deployment-level risk”，强调普通用户在日常使用中即可触发（p.24–25 §F.2）。因此不能把它套进认证/授权威胁模型：这里没有主体伪造、权限委托或资源访问决策。

## 5. 核心方案：算法、协议、架构、公式、关键步骤

本文的“方案”是 benchmark 构造 + 干预方法，不含密码协议或训练算法。

1. **Base setting（p.3 §2.1–2.2；p.13 App A.1.2）**：750 条有害查询，8 个粗类（Hate Speech、Self-harm、Medical Crime & Advice、Financial Crime & Advice、Abuse、Unethical Behavior、Sexual Crime & Explicit、Privacy Leakage）；除 Privacy 为 50 条外每类 100 条。来源为 SorryBench、Do-Not-Answer、HarmfulQA、ALERT、BeaverTails。对同一查询分别跑 stateless 与 personalized，隔离“有无良性记忆”这一变量。
2. **Evaluator（p.4 §2.2）**：采用 Do-Not-Answer 的 harmful response detector；ASR = 被判定为有害的响应比例（越高越不安全）。人工校验见 p.16–17 App B.2（160 条、2 名标注者、96.3% 总体一致率）。
3. **Thematic Chat History Augmentation（p.4 §2.3；p.13 App A.2）**：5 个生活主题（irritability、depression、disease、financial tightness、loneliness），每个主题选 2 个“人格冲突分数”最低的兼容用户，每人生成 5 段主题一致的多轮对话，共 50 段；以额外上下文形式追加到历史，而非直接改写记忆库。冲突分数由 LLM 按 1–10 打分（p.14 Fig.6）。
4. **Persona-Grounded Harmful Queries（p.4 §2.4；p.14 App A.3；p.16 Fig.8）**：从历史中抽取 role profile 与 salient personal events，用辅助 LLM 生成单句、表面良性但隐含有害意图的查询（生成 prompt 要求每个用户历史 50 条）；最终共 1,986 条，构成 PS-Bench-Hard；用 all-MiniLM-L6-v2 去重；不含复杂 jailbreak 模板。
5. **Intervention: detect-and-reflect（p.7–8 §4；p.17–19 App C.2–C.3）**：推理时、模型无关、无需训练。先用 auditor prompt（p.18 Fig.10）按五类“合法化因素”审查检索记忆：Contextual Normalization/Normative Drift、Relational Priming、Vulnerability & Rationalization、Boundary Blurring、Latent Reinforcement；输出可疑记忆下标。再生成 2–4 句、面向模型自身的反思提醒（p.19 Fig.11），要求在推理前把“共情理解”与“意图校验”解耦；**不删除、不改写记忆**，只插入提醒。
6. **无训练、无微调、无密码学原语**；干预完全在 prompt/推理层完成。

## 6. 安全属性与安全性论证

- **经验性安全属性**：对固定有害查询，个性化不应提高模型给出可操作有害内容的概率。论文用 ASR 作为代理指标，越低越安全；用 LoCoMo F1/BLEU-1 衡量个性化效用（p.8 Table 2）。
- **没有形式化定义、定理或证明**。论文没有给出 intent legitimation 的形式化谓词、没有威胁模型、没有可证明保证；“intent legitimation”是概念性/行为性构念，通过“有记忆 vs 无记忆的 ASR 差”操作化。
- **机制论证**（p.7 §3.5；Fig.5）：在 Qwen3-8B 上，用 AdvBench 有害锚点与 AlpacaEval 良性锚点构造表征空间，取第一主成分作为 harmful-intent direction；加入检索记忆后，有害查询的表征向良性锚点一侧移动。作者据此论证“记忆把有害请求编码得更像合法请求”。这是表征层面的相关性证据，不是因果证明；作者的主要因果论据是干预降低 ASR。
- **人工校验**：160 条响应、2 名标注者、与自动检测器总体一致率 96.3%，分歧由第三人裁决（p.16–17 App B.2）。这支持检测器在样本上的可靠性，不等于构念效度或跨域保证。
- **没有对抗鲁棒性分析**：未测试自适应攻击、未测试干预被 jailbreak/记忆投毒绕过、未与其它防御（安全微调、系统提示加固、记忆过滤）做对照。

## 7. 实验细节：模型、环境、数据集、对照方法、指标、核心结果、消融

**设置。** 5 个基座 LLM：GPT-4o、GPT-4o-mini、Qwen3-235B-A22B、Qwen3-8B、DeepSeek-V3.2；5 个记忆框架：LDAgent、A-Mem、Mem0、MemOS、MemU；10 个 LoCoMo persona；默认 top-3 记忆；统一 prompt 模板；GPT-4o/4o-mini/DeepSeek-V3.2/Qwen3-235B 走官方 API，Qwen3-8B 本地 vLLM；单卡 NVIDIA Tesla A100（p.17 App C）。指标：PS-Bench ASR（越低越好）、LoCoMo F1/BLEU-1（越高越好）。对照：同 prompt 的 stateless 基线。

**RQ1：个性化是否削弱安全（p.5 Table 1；已渲染核对）。** 25 个“模型 × 框架”组合中，绝大多数 ASR 高于各自 stateless 基线；相对增幅范围 **15.8%–243.7%**（p.1 Abstract）。代表性数字（base PS-Bench，10 roles，top-3）：
- GPT-4o：stateless 14.50 → LDAgent 28.55（+96.9%）、A-Mem 24.51（+69.0%）、Mem0 27.08（+86.8%）、MemOS 28.08（+93.7%）、MemU 29.33（+102.3%）。
- GPT-4o-mini：stateless 23.13 → 五个框架 26.79–29.66（+15.8% 至 +28.2%）。
- Qwen3-235B-A22B：stateless 11.75 → 19.89–24.91（+69.3% 至 +112.0%）。
- Qwen3-8B：stateless 8.63 → 13.95–22.23（+61.6% 至 +157.6%）。
- DeepSeek-V3.2：stateless 9.00 → 21.41–30.93（+137.9% 至 +243.7%）。
- **注意基线差异**：各模型 stateless ASR 从 8.63 到 23.13 不等，因此“相对增幅”跨模型比较会被低基线放大；不能把 +243.7% 直接理解为绝对风险最高。

**记忆设计的影响（p.6 §3.2）。** Mem0 在 5 个模型中的 4 个相对增幅最小（如 GPT-4o-mini +15.8%），但在 GPT-4o 上 A-Mem 最小（+69.0%）；A-Mem/MemOS 在部分组合上增幅很大（A-Mem + Qwen3-8B +157.6%；MemOS + DeepSeek +218.3%）。作者解释为“细粒度、高召回的记忆提供更连贯的情境理由；抽象/保守的记忆伤害较小”，但这一解释是相关性的，记忆格式与检索质量/召回率混杂。

**RQ2：主题增强（p.6 §3.3；Fig.3；p.20 Table 4；已渲染核对）。** 热图呈近对角模式：当增强主题与伤害类别语义对齐时 ΔASR 明显为正，不对齐时稳定或下降。Table 4 平均 ASR：GPT-4o LDAgent 29.19（+101.3%）、A-Mem 28.53（+96.8%）；GPT-4o-mini LDAgent 28.11（+21.5%）、A-Mem 31.85（+37.7%）；Qwen3-235B LDAgent 22.14（+88.4%）、A-Mem 24.35（+107.2%）。这支持“语义对齐而非单纯记忆暴露量”是触发因素。

**RQ3：persona-grounded 难例（p.6–7 §3.4；Fig.4；p.21 Tables 5–6；已渲染核对）。** Qwen3-235B 三框架均值 25.41 vs stateless 11.35（+123.9%），其中 MemOS 29.26；GPT-4o-mini 三框架均值 33.71 vs stateless 28.44（+18.5%）。persona 异质性明显：MemOS/Qwen3-235B 下 Deborah 40.82、James 38.62、Caroline 38.04，而 Evan 15.93、Calvin 18.64、Jon 18.92（Fig.4）。作者据此提出“情感依赖/脆弱用户更易触发”，并主张用户自适应防御。需要注意：GPT-4o-mini 的 stateless 在 hard 子集上均值 28.44，高于 base 的 23.13（+23%），所以“hard 查询本身不具对抗性、stateless 与 base 可比”这一说法在 GPT-4o-mini 上并不严格成立；在 Qwen3-235B 上 11.35 vs 11.75 才接近。此为本人对表格的核对结论。

**机制分析（p.7 §3.5；Fig.5；已渲染核对）。** Qwen3-8B 的 PCA 图显示：stateless 有害查询靠近 harmful anchor；加入检索记忆后，点云沿第一主成分向 benign anchor 一侧移动（图中 Shift 箭头），作者称“降低意图可分性”。这是表征相关性证据，样本与模型有限。

**消融与补充（pp.21–24）。**
- 记忆数量 k（p.24 Table 10，GPT-4o-mini）：k=1→10 时 LDAgent 25.05→31.18、MemOS 26.41→31.91，单调上升；作者指出低 k 处下降已明显，“即使最小个性化也能触发”。
- 显式 persona 建模（p.24 Table 11，GPT-4o-mini）：在记忆之外再加 persona 字段，LDAgent 28.05→33.64（相对 +19.9%）、MemOS 28.73→35.38（相对 +23.1%），绝对 +5.59/+6.65 个百分点；正文写作“约 7%”，与表中的相对值（+19.9%/+23.1%）不一致，更接近绝对百分点（+5.6/+6.7）；引用时需注明口径。
- PII 注入（p.21 §E.1，Table 9）：GPT-4o A-Mem 的 Privacy ASR 7.4→26.8；GPT-4o-mini A-Mem 9.4→23.4；Qwen3-235B A-Mem 18.6→43.8（Table 9 仅列这三个模型）；正文另称 Qwen3-8B 出现例外，作者归因于模型幻觉生成 PII。
- 干预（p.8 Table 2；已渲染核对，GPT-4o-mini）：MemOS 28.73→19.63（31.7%↓）、MemU 28.46→19.40（31.8%↓）、A-Mem 29.66→24.14（18.6%↓），平均约 27.4% 相对下降。LoCoMo 效用：MemOS F1 44.18→44.94（+1.7%）、B1 35.58→37.55（+5.5%）；MemU −1.9%/−2.3%；A-Mem −18.6%/−37.3%。即“恢复安全”对检索密集型框架的效用代价可能很大。
- 案例（p.27 Fig.17）：用户请求改造陶窑电路以消除金属识别标记；stateless 拒绝；A-Mem 将其误读为“创意项目”并给出危险建议；加入反思提醒后恢复拒绝。这是定性示例，不是统计证据。

## 8. 主要贡献、与直接相关论文的差异、可复现资源

**作者声明的贡献（p.2）：**
1. 识别 intent legitimation——由良性个人记忆诱发的、此前未被充分探索的安全失败；
2. 提出 PS-Bench——作者称为首个在累积个人上下文与 persona-grounded 交互下评估个性化 Agent 安全的 benchmark；
3. 提出轻量、模型无关的推理时检测-反思干预，在较大程度上保持个性化效用。

**与直接相关工作的差异：**
- 与 prompt jailbreak / role-play（p.23–24 §F.1）：本文没有伪造角色、没有“pretend you are…”模板、没有对抗性指令；查询可能与普通有害请求在字面上相同；记忆是真实且良性的；风险出现在普通部署中，且作者推测可能随交互累积。
- 与 memory poisoning（如语料内 R2-03 AgentPoison，按标题即“poisoning memory or knowledge bases”）：本文不做恶意注入、不植入触发器；记忆真实。两者的威胁模型相反：一个是“假记忆”，一个是“真记忆的语义副作用”。
- 与 memory privacy（如语料内 R2-11 “Unveiling Privacy Risks in LLM Agent Memory”）：本文的主问题是拒答边界，不是记忆中的隐私提取；Privacy 只是 8 类之一，且默认设置刻意不含 PII，PII 仅作为附录探针（p.3 §2.2；p.21 §E.1）。
- 与 agent safety benchmark（A2 类，如 R2-06 AgentHarm、R2-09 SafeArena、R2-19 OpenAgentSafety，仅按清单标题定位）：本文不测工具/网页/环境中的有害行为，而测同一对话模型在“有无良性记忆”下的拒答差异，属于记忆个性化安全，而非环境型 agent 安全。

**可复现资源：** 代码 `https://github.com/MuyuenLP/PS-Bench`（p.1；按研究规范未访问、未执行）；作者承诺接收后公开全部数据与评估协议（p.9 Ethical Considerations）。使用公开安全基准（SorryBench、Do-Not-Answer、HarmfulQA、ALERT、BeaverTails）与 LoCoMo；五类记忆框架中 MemOS/Mem0/MemU 使用官方 API，A-Mem/LDAgent 为本地实现（p.17 App C）。

## 9. 局限性、失效场景、作者未解决的问题

**作者自述（p.9 Limitations）：**
- PS-Bench 部分依赖合成对话历史与 persona-grounded 有害查询；虽经人工检查，未必捕捉真实世界中有害意图的细微涌现。
- 只评估 5 个框架/5 个 LLM，未穷尽记忆设计与个性化策略；不同记忆表示/检索可能产生不同程度效应。
- 纯文本、单轮安全评估；记忆限于文本；有害查询为效率而孤立评估；多模态记忆与多轮交互未测。
- 只测纯个性化对话模型；未测带 search/location/weather 等工具的 Agent，个性化 + 外部工具执行的安全含义是 open question。

**其它重要边界（本人核对/推断）：**
- 自动检测器有偏；人工校验仅 160 条、总体一致率 96.3%，未报告按类别/按模型的分层一致性；检测器本身可能被个性化措辞影响。
- 没有纵向实验验证“permissive response 写入记忆 → 后续再检索 → 进一步降低拒答”的反馈回路；作者在 p.23–24 §F.1 明确说 “we do not claim direct causality”，该回路是合理推测而非实测。
- 干预依赖一个 LLM auditor 和 LLM 生成的提醒，未报告额外 token/延迟成本，也未评估 auditor 的漏检/误检；未与其它防御做对照，未测试自适应绕过。
- Privacy 类的结论受 PII 是否存在强烈混淆：默认无 PII 时 ASR 很低，注入 PII 后大幅上升（p.21 §E.1/Table 9；正文另称 Qwen3-8B 异常归因于幻觉），说明该类别测量不稳。
- 公开基准查询可能已被模型见过（污染风险），论文未讨论。
- “个性化效用”只用 LoCoMo F1/B1，未覆盖用户满意度、任务成功率或长期交互质量。

## 10. 与理论密码学可能的技术连接（区分原论文已做 / 个人推断）

**结论先行：本文无密码学构造/证明**——没有密码学假设、形式化安全定义或证明，也没有使用任何密码学原语。全文机制是 NLP/ML 层面的：记忆写入/检索、prompt 拼接、PCA 表征分析、LLM 审计与反思提示。没有密钥、签名、MAC、加密、承诺、ZKP、MPC、FHE、TEE、DP 或访问控制形式化模型。

**为什么不能把它当作认证/授权问题（本人推断）：** 本文没有主体身份伪造（所有记忆属于同一真实用户）、没有权限委托或作用域、没有资源访问决策，也没有攻击者持有/伪造凭据。失败发生在模型对自然语言意图的语义判断：同一有害查询在加入良性记忆后从拒绝变为服从。把 “personalization risk” 映射为 B1/B2（身份认证/授权）会误导后续选题；它不是“谁有权让 Agent 做什么”的问题，而是“模型如何理解请求是否正当”的问题。

**可形式化但非密码学的接口（本人推断）：** 可以把“个性化非干涉”定义为一个策略稳健性属性：设 q 为具有固定有害意图 h 的查询，M 为良性用户记忆，R 为拒绝策略，⊕ 表示把记忆拼入上下文；要求 R(q) 与 R(q ⊕ M) 在 h 不变时保持一致（或至少拒绝概率不下降）。本文的经验结果正是该属性的大规模违反。这个定义适合 ML 安全/评测论文，不需要密码学假设；若把 M 的选取交给对手，就变成对抗性记忆注入，和本文的 benign 设定不同。它能否形成“定理”取决于是否接受一个语义意图 oracle，而这本身是自然语言理解问题，不是密码学问题。

**密码学 provenance 的正交性（本人推断）：** 对记忆做签名/认证只能保证记忆来源真实、未被篡改；本文的威胁模型恰恰假设记忆真实。因此“签名记忆”不能阻止 intent legitimation。这是一个有价值的负边界：**authenticity ≠ admissibility**。若要做研究，应把“记忆真实性”和“记忆可采纳性”分开建模，并明确后者不是密码学原语能直接裁决的。

**隐私线索：** p.21 Table 9 的 PII 注入说明记忆保密是另一个问题；加密/访问控制可能降低 PII 泄露，但不改变拒答边界。不要把 confidentiality 与 refusal integrity 混为一谈。

**若按项目 0–5 量表（本人评估）：** `T_crypto ≈ 0–1`。仅有“可形式化的策略稳健性/非干涉”这一弱接口，且它更接近 ML 安全的形式化，不是密码学游戏；不应因为论文出现 privacy/PII 就给高分。

## 11. 与应用密码学/密码工程可能的技术连接（同上）

**原论文已做：无。** 没有协议、密钥生命周期、凭证、密文检索、审计签名或性能实验；也没有系统级访问控制实现。

**可自然扩展的工程接口（本人推断，均非本文工作）：**
- **记忆存储机密性**：at-rest/in-transit 加密、按用户派生密钥、tenant isolation。本文对 MemOS/Mem0/MemU 使用官方 API（p.17 App C）；按“online APIs”推断记忆会离开本地环境，这是实际部署中的 confidentiality 面，但论文未分析，也未说明 API 侧的保留/删除策略。
- **记忆访问控制**：认证用户、授权 Agent 读取哪一类记忆、撤销与删除。可防止跨用户检索和越权读取，但不能防止“合法记忆”被模型用来合法化有害请求。
- **审计**：记录哪条记忆被检索、auditor 是否标记、最终是否拒绝；对事故复盘有用。但日志签名只保证完整性，不保证语义正确；不能把“有签名审计日志”当作安全证明。
- **隐私增强的个性化**：加密语义检索/secure ANN、DP 记忆摘要、记忆最小化。本文的 Mem0（更抽象记忆）与 k 值实验提供了“记忆保真度—效用—安全”张力的初步线索，但没有密码学实现；若要把它做成密码工程课题，需要自己设计密文检索协议并测量泄漏与开销。

**伪交叉警告（本人推断）：** 给记忆签名、给 prompt 加密、对检索做 ZK 证明、给 memory API 加 OAuth scope，都不能解决 intent legitimation；它们保护的是来源/机密性/权限，而不是模型对意图的语义判断。若论文只做这些，容易被审稿人视为 crypto theater。另一个伪交叉是“用 TEE 证明模型运行了某段代码”——它不能证明模型在语义上正确拒绝了有害请求。

**若按项目 0–5 量表（本人评估）：** `A_crypto ≈ 1`。存在记忆保密/访问控制的一般工程接口，但本文未识别具体密码机制使用点，无协议、无密钥管理、无性能实验；不能因为“个性化 Agent 需要隐私”就给高分。

## 12. 后续可以验证的研究假设（不得仅因论文没提就判断领域没人做过）

- **H1（真实性 ≠ 可采纳性）**：对同一段良性记忆内容，做“无记忆 / 未签名良性记忆 / 签名认证的良性记忆”三组对照，若签名组的 intent-legitimation ASR 与未签名组无显著差异且都高于无记忆组，则证明密码学 provenance 对该失败模式正交。该假设可直接检验，且能把“认证”与“安全语义”的边界量化。
- **H2（访问控制只治 PII）**：2×2 设计（记忆访问控制开/关 × 记忆含/不含 PII），同时测 Privacy ASR 与非 Privacy ASR。预测：访问控制显著降低 PII 泄露，但不降低非 PII 的 intent legitimation。
- **H3（个性化非干涉可度量）**：形式化 R(q) vs R(q⊕M) 的拒绝一致性，跨 5 模型/5 框架估计违反率；检验违反率是否与论文 Fig.3 的语义对齐、Fig.4 的 persona 脆弱性相关。若相关，说明该属性捕捉到了同一现象；若不相关，说明 ASR 差异还有别的驱动因素。
- **H4（记忆抽象—效用—安全三角）**：在控制记忆内容与检索召回的前提下，比较“详细情节记忆”与“抽象摘要记忆”的 ASR 与 LoCoMo F1，检验是否存在可调的 Pareto 前沿。论文 Table 1 的 Mem0 结果只是提示，未控制内容，不能直接下结论。
- **H5（纵向反馈回路）**：多 session 实验：让 Agent 的有害/许可回复被写回记忆，观察后续 session 的 ASR 是否随交互轮次上升。论文 p.23–24 提出该回路但未做纵向实验；若观测不到累积效应，则“cumulative safety boundary shift”应弱化。
- **H6（persona 风险预测）**：Deborah vs Evan 的差异提示可用画像特征预测风险；检验预测 AUROC，并评估“为安全而做用户风险画像”本身的隐私代价。该假设涉及隐私—安全权衡，需单独威胁模型。
- 以上均为待验证假设；不能因为本文未做就断言领域无人研究。
