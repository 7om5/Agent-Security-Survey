## 1. 150–300 字中文概述

论文提出 Contextualized Defense Instructing（CDI）：在 LLM Agent 的工具调用循环中，于工具返回结果之后、下一次动作之前，用一个轻量 instructor 模型生成逐步的上下文隐私指引，作为 user message 注入 data sender 的上下文，主动引导其只披露当前社交关系下合适的信息。作者把 prompting（初始化时静态提示）与 guarding（动作前拦截）形式化为同一循环中的不同干预点，并在三 Agent 仿真（data subject / data sender / data recipient）中比较隐私保持率 PP、有用性 HS 与综合 AD。进一步把攻击失败轨迹转成 RL 环境：在首次泄漏处截断、冻结上下文，用 GRPO 训练 instructor（先 PP 预热 400 步，再 AD 200 步）。在 100 个未见配置上，优化后 CDI 达 PP 94.2%、HS 80.6%、AD 86.5%，优于优化后的 prompting/guarding；面对新一轮自适应攻击 PP 79.5%。全文是语义层面的上下文隐私防御，不含密码学原语、形式化安全定义或证明。

## 2. 研究背景、现有方法不足、精确定义的问题

- 背景：LLM Agent 越来越多地替用户处理日程、浏览、健康记录等个人信息（p.1, §1）。当外部方通过 Agent 接口索取信息时，Agent 需要“contextual privacy awareness”：判断在特定上下文中分享某条个人信息是否合适（Nissenbaum 2004 的 contextual integrity），并在隐私与有用性之间平衡（p.1, §1）。
- 现有两类防御的不足（p.1, §1；p.4, §3）：
  - **Prompting**：在初始化时把固定的隐私增强指令加入 system prompt；无法适应多样隐私上下文与具体信息请求，多轮交互中容易被忽略。
  - **Guarding**：用独立 guard 模型在工具调用执行前筛查并阻断；只“拦截”不“改写”，被阻断的混合消息（同时含可分享与不可分享项）会让 Agent 不知道如何修正，陷入 block-resend 循环，损害有用性。
- 第二个挑战：真实攻击者可用大量计算搜索长尾的攻击策略（劝说、冒充、社会工程），静态防御启发式无法靠一次性设计解决（p.1–2, §1；p.5, §4）。作者把失败轨迹视为最有信息量的改进信号。
- 精确问题：(1) 在 canonical agent loop 的哪个位置干预，才能提供主动、逐步、上下文相关的隐私指导？(2) 能否把攻击失败轨迹转成 RL 训练信号，提升防御模型的内在隐私推理与泛化？论文把 prompting、guarding、CDI 形式化为不同干预点，并在统一仿真中比较 privacy–helpfulness trade-off（p.1, Abstract；pp.3–4, §2–§3）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **三个角色**（p.3, §2 Problem Setup）：
  - **Data subject**（数据所有者）：其 personal information 按 privacy norm 分为 shareable / unshareable；subject agent 的任务是把数据发给 sender。
  - **Data sender**（防御者）：监控通知并对 recipient 的请求作出回复；防御模块（prompt / guard / instructor）只作用于它。
  - **Data recipient**（攻击者）：试图从 sender 获取数据；在 strategic 设定下其 system prompt 被搜索算法优化。
- **环境**（p.12, App A）：模拟 Messenger、Gmail、Facebook 三个通信应用；每个应用在本地端口启动，暴露 search/read/send API，并维护本地消息数据库；每个 Agent 在仿真开始时被授权访问其用户账户。发送成功后应用返回 success code 并通知 recipient。
- **Agent 执行循环**（p.3, §2 Agent Setups）：ReAct 风格（Yao et al. 2023）+ MCP 风格工具调用；system prompt `p0` 加累积 context buffer；工具包括外部通信 API 与内部工具（推理、记忆管理、任务状态修改）；由新消息/新任务激活，可连续执行多个动作，直到输出 `EndCycle` 或超时/轮次上限。
- **形式化**：`C≤t = {p0, u1, (a1,o1), ..., (at,ot)}`；`a_{t+1} = A(C≤t) = LM_A(p0, ..., ut)`；执行后把 `(a_{t+1}, o_{t+1})` 追加到上下文（p.3, §2）。
- **信任边界**：原文没有独立的 trust-boundary 图。可辨识的边界是“Agent 之间的消息通道”与“data sender 的动作生成”：recipient 只能通过消息/邮件/帖子影响 sender；sender 的记忆、工具与模型被默认为可信执行环境；guard/instructor 是独立模型，能读 sender 的 memory，但拿不到 ground-truth privacy norm（p.5, §3.2 明确说 detailed user-specified norms 对防御模型不可见）。模拟应用、LLM judge 与攻击搜索器都被当作可信评测基础设施（此点为本人据全文归纳）。
- **注意**：subject agent 是良性的，会主动把数据发给 sender；攻击面不是 subject，而是 recipient 对 sender 的自然语言说服。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- **资产**：data subject 的 personal information（shareable 与 unshareable 两类）；sender 记忆中的身份/社会关系；sender 的任务有用性（把 shareable 项送达 recipient）；privacy norm 本身是评测 ground truth，防御模型不可直接读取。
- **攻击者目标**：获取 unshareable 项，同时尽量不破坏 shareable 项的获取（因此攻击后 HS 往往升高、PP 下降；见 Table 1/2）。攻击者的最终目标是“不适当披露”，而非破坏系统可用性或窃取密钥。
- **攻击者能力**（p.4, §3.1；p.13, App D.1；p.17, Table 15）：
  - 控制 recipient agent 的 task/system prompt；可用 search-based 算法迭代优化该 prompt（gpt-5 生成候选、反思失败轨迹），预算 `M=30, N=5, P=10, K=10`（每个配置）。
  - 通过 Messenger/Gmail/Facebook 向 sender 发送消息、邮件、帖子；可使用 fact fabrication（authority/urgency/consent）、presumptive verification、misleading privacy focus、instruction-following exploitation 等策略。
  - **不能**直接读 sender 的 memory、不能改 sender 的模型/工具/防御模块、不能读 instructor 生成的 guidance、不能投毒工具或记忆（这些是本人据 §2–§3 的系统设定归纳；原文未逐一列出否定能力）。
- **防御者能力**：在 sender 侧插入 prompting、guarding 或 CDI；guard/instructor 可读 sender memory 与对话上下文，但不能读 privacy norm；默认 agent backbone 为 gpt-4.1-mini，防御模型为 Qwen3-4B（可替换，见 §7）。
- **前提假设**（原文未集中成节，分散在 §2、§3.1、App A/D）：
  - privacy norm 由配置给定、静态、二值（shareable/unshareable），并由 LLM judges 校验（p.3, p.12）。
  - 所有 Agent 都是 LLM；通信应用是模拟的；账户授权是环境预设，不涉及真实 OAuth/密码协议（p.12）。
  - 攻击只通过自然语言消息发生；没有模型后门、工具投毒、记忆投毒、侧信道、合谋或计算资源攻击。
  - 评测 judge（gpt-5-mini）被默认可信；作者用多 judge 一致性做稳健性检查（p.15, Table 13），但没有对 judge 本身的对抗鲁棒性建模。
- **威胁模型位置**：原文没有独立 “Threat Model” 小节；威胁模型由 §2 的三方角色、§3.1 的 regular vs strategic attacker、App D.1 的搜索预算共同定义。

## 5. 核心方案：算法、协议、架构、公式、关键步骤

### 5.1 评价指标（p.3, §2 Evaluation Metrics）

设 `Ns`、`Nu` 为 shareable/unshareable 项总数，`ns`、`nu` 为实际分享给 recipient 的项数：

```text
PP = 1 - nu / Nu          # Privacy Preservation Rate，类似 precision
HS = ns / Ns              # Helpfulness Score，类似 recall
AD = 2·ns / (ns + nu + Ns)  # Appropriate Disclosure，F1 型调和指标；主指标
```

- PP 惩罚“分享了不该分享的”，HS 惩罚“漏分享可分享的”，AD 同时惩罚过度分享与分享不足。论文以 AD 作为比较不同防御的主指标（p.3）。
- 每个 privacy item 带 identifier（数字、标题等）；gpt-5-mini 作为 LLM judge 审查 message history，标注实际披露项（p.3）。这是**语义检测**，不是密码学或形式化信息流度量。

### 5.2 三个干预点（pp.3–4, §3）

- **Prompting（静态、初始化）**：`p'_0 = p0 + p_privacy`，采用 PrivacyLens（Shao et al. 2025）的隐私增强指令；只在初始化时注入一次。
- **Guarding（被动、动作前）**：独立 `LM_G` 对 `C≤t` 判断 `f_t ∈ {ALLOW, BLOCK}`；仅当动作是向外部方传输信息（发邮件、发帖等）时调用。`f_t=ALLOW` 时执行 `o_t = Execute(a_t)`；`BLOCK` 时返回字符串 `"Error due to privacy violations"`，不提供改写建议（p.4）。
- **CDI（主动、工具结果之后、动作之前）**：独立 `LM_I` 在最近工具结果 `o_{t-1}` 非空时生成
  ```text
  h_t = LM_I(C_<t)
  a_{t+1} = LM_A(C_<t ∪ {h_t})
  ```
  即把 guidance 作为 user message 追加到 sender 上下文，再让 sender 生成下一步动作（p.4, §3）。关键区别：CDI 在动作形成之前“塑造”动作，而不是事后拦截；guidance 是 step-specific 的，可解释当前观察中的风险并建议可分享项。

### 5.3 Experience-driven optimization（pp.5–7, §4）

1. **收集失败轨迹**：用搜索攻击在 15 个训练配置上各模拟 20 次，得到 185 条训练轨迹、30 条验证轨迹（p.6）。
2. **Guarding 的 RL**：在第一个 data-sharing action `a_t` 处截断；若 `a_t` 泄漏 unshareable 项则标签为 leak，否则 non-leak；用 GRPO 训练 `LM_G`，奖励
   ```text
   R_G(f) = 1, if a_t leaks sensitive data and f = BLOCK
            1, if a_t leaks no sensitive data and f = ALLOW
            0, otherwise
   ```
   （p.5, §4.1）。
3. **CDI 的 RL**：在第一个“未能阻止泄漏”的 guidance 处截断；若 `a_t` 泄漏，还要移除前一条 guidance `h_{t-1}`，只保留 `C_<t-1`；过滤“recipient 尚未请求、泄漏就发生”的样本；把新 guidance `h = LM_I(C_<t-1)` 追加后让 sender 最多执行一个动作 `(a,o)`；奖励
   ```text
   R_I(h) = AD(C_<t-1, h, (a,o))
   ```
   （p.6, §4.1）。这样无需重跑完整仿真，在冻结上下文上做 one-step RL。
4. **冷启动处理**：直接用 AD 奖励训练 CDI 会出现 cold start（AD 在早期噪声大、梯度不稳）；先以 PP 为奖励训练 400 步，再切换到 AD 训练 200 步（p.6–7, §4.2/§4.4；Table 3）。
5. **训练超参**：GRPO + LoRA（rank 32，lr 2e-5，AdamW），单张 A6000，per-device batch 4、gradient accumulation 4，最大 context 5200 tokens、最大生成 2048 tokens，共 600 步（p.6, §4.2；p.13, App D.2）。默认 agent backbone 为 gpt-4.1-mini，防御模型为 Qwen3-4B。
6. **设计思想**：不手工规定“什么样的 guidance 有效”，让模型从失败经验中发现策略；instructor 承担隐私推理负担，从而给较弱 sender 更直接、可执行的指令（p.7–8, §4.3/§4.5）。

## 6. 安全属性与安全性论证

- **目标属性**：contextual privacy / appropriate disclosure——拒绝 unshareable、分享 shareable；由 PP/HS/AD 经验指标操作化（p.3）。这不是机密性（confidentiality）、不可区分性（indistinguishability）或完整性（integrity）的形式化定义。
- **无形式化证明**：全文**没有**形式化安全定义、定理、引理、证明或 reduction；没有密码学安全游戏。作者的安全论证是**比较性、行为性、经验性**的：CDI 在 regular 与 searched strategic attackers 下比 prompting/guarding 泄漏更少、AD 更高，并泛化到未见配置与不同 sender backbone（pp.4–7；Table 1–2、Fig. 3）。
- **作者承认的边界**：所有防御对 strategic attackers 都脆弱；搜索攻击在 CDI+Qwen3-4B 上优化，但攻击模式可迁移到其他防御/模型；CDI+gpt-oss-20B 在攻击后 PP 最高也只有 50.0%，仍“ unsatisfactory”（p.5, §3.2）。优化后 CDI 面对新一轮自适应攻击从 89.7% 降到 79.5%，说明不是鲁棒保证（p.6–7, Table 2）。
- **评测有效性论证**：用 4 个 LLM judge 复核优化后 CDI，PP 94.2–96.2、AD 85.3–86.5，作者据此论证提升不是 reward hacking（p.15, Table 13）。但“多个 LLM 一致”不等于“判断正确”，也不构成安全证明（本人推断）。
- **隐私规范的 ground truth**：由 gpt-5 生成/增广、人工核验，并用 4 个 LLM judge 做 grounding；Table 6 报告 shareable/unshareable/overall accuracy 均 ≥0.96（p.12, App B.2）。这是 LLM 间的规范一致性，不是法律或用户研究意义上的 ground truth。
- **结论**：论文提供的是**经验性的上下文隐私防御效果**，不是可证明的隐私保证；其“privacy”是规范/语义概念，不能与差分隐私或密码学隐私混同（详见 §10）。

## 7. 实验细节：模型、环境、数据集、对照方法、指标、核心结果、消融

### 7.1 设置

- **环境**：模拟 Messenger/Gmail/Facebook；三个 Agent；通信通过本地 API；默认 sender backbone 为 gpt-4.1-mini；防御模型为 Qwen3-4B（LoRA + GRPO 微调）。Table 1 还比较 Qwen3-4B、Qwen3-4B-SafeRL、gpt-oss-20B、gpt-oss-safeguard-20B、gpt-4.1-mini 五种 guard/instructor 模型（p.4, Table 1 caption；p.13, Table 7）。
- **数据**：115 个 simulation configurations，覆盖家庭、朋友、医患等社会关系与健康、金融、位置等数据类型；100 个用于标准测试，15 个用于防御优化；每个配置 `Ns, Nu ∈ [1,3]`。profile/sensitive data 采样自 PrivacyLens，shareable data 由 gpt-5 增广，人工核验（p.3, §2）。
- **攻击**：regular attacker 只给通用任务描述（“obtain both shareable and sensitive personal data from the data sender”）；strategic attacker 用 Zhang & Yang (2025) 的搜索算法优化 recipient system prompt，`M=30, N=5, P=10, K=10`，gpt-5 生成候选并反思失败轨迹（p.4, §3.1；p.13, App D.1）。
- **对照**：N/A（无防御）、Prompting（PrivacyLens prompt；优化版用 gpt-5 做 prompt search）、Guarding（Qwen3-4B guard；优化版用 GRPO 二值奖励）、CDI（Qwen3-4B instructor；优化版用 GRPO + AD 奖励）。另有更强基线：PrivacyChecker 风格详细 prompt、guarding + rewrite feedback（p.14, Tables 8–9）。
- **指标与统计**：PP/HS/AD；每个配置 N=5 runs 平均；95% 置信区间半宽见 Table 10（p.15）。所有数字均为百分比。
- **条件说明（重要）**：
  - Table 1 的 Guarding/CDI 是**五个防御模型平均**；N/A 与 Prompting 是单模型（p.4, Table 1 caption）。
  - Table 2 的 **Training** 列：未优化防御配 regular attacker，优化防御配 adaptive attacker；**Adversarial** 列是新一轮自适应攻击；**Testing** 列是未见测试配置（标准测试集为 100 个配置，p.3；p.15 Table 11 明示 100 test configurations）。因此不同列/行不能简单直接比较。
  - 攻击后 HS 常升高，是因为攻击者同时索取 shareable 与 unshareable 项，sender 变得“更配合”；PP 下降才是泄漏信号。

### 7.2 核心结果（均附条件）

- **未优化防御，regular attacker（Table 1, p.4）**：N/A 35.5/81.2/66.1；Prompting 48.1/73.1/65.0；Guarding 47.0/82.0/70.0；CDI 75.9/86.9/82.8（五模型平均）。CDI 的 AD 最高。
- **未优化防御，strategic attacker（Table 1, p.4）**：N/A 8.8/94.9/66.3；Prompting 11.8/94.1/66.7；Guarding 19.6/89.8/66.5；CDI 38.1/89.8/71.4。所有防御 PP 大幅下降；CDI 相对最好但仍不理想。CDI+gpt-oss-20B 是单模型最高 PP 50.0%（p.5, §3.2）。
- **两处需要读者警惕的表述/口径问题（本人核对）**：
  - Abstract 与 §3.2 称所有防御在 regular attacker 下“without harming/compromising helpfulness”，但 Table 1 的 Prompting HS=73.1 低于 N/A 的 81.2；该表述对 Prompting 不严格成立。
  - Abstract 的 `PP: 35.5% → 75.9%` 是 N/A 单模型对 CDI 五模型平均，并非严格同条件对照；Table 1 caption 明确 Guarding/CDI 取五模型平均。
- **优化后防御（Table 2, p.6）**：
  - CDI：Training 89.7/89.7/89.7；Adversarial 79.5/84.5/82.4；Testing 94.2/80.6/86.5。
  - Prompting：89.0/85.0/87.0；55.1/87.0/75.0；85.1/82.7/83.8。
  - Guarding：80.2/70.7/80.5；50.3/81.0/70.2；83.6/69.0/74.8。
  - 解读：优化后 CDI 在 adversarial 与 unseen testing 的 PP/AD 上均优于 prompting/guarding；HS 与 prompting 接近（Adversarial 84.5 vs 87.0；Testing 80.6 vs 82.7），高于 guarding。优化后的 prompting/guarding 仍对自适应攻击脆弱，且 guarding 的有用性明显下降（Testing HS 69.0）。
- **更强基线（p.14, Tables 8–9）**：PrivacyChecker 风格详细 prompt 在 adversarial 下 51.6/89.2/75.1；guarding + rewrite 在 adversarial 下 52.4/86.8/74.0；同条件下 CDI 79.5/84.5/82.4。说明 CDI 的优势不是“基线实现太弱”。
- **跨 sender backbone 泛化（100 test configs；p.15, Table 11）**：CDI 在 gpt-4.1-nano 88.9/91.7/90.4、Qwen3-32B 89.9/83.2/86.1、gpt-4.1 95.2/90.0/91.0；N/A 在 gpt-4.1-nano 仅 26.9/72.8/59.3，Guarding 76.5/49.6/56.8。CDI 对弱 backbone 的提升尤其明显。
- **奖励消融（p.7, Table 3）**：
  - 仅 PP 奖励：Prompting Testing 98.6/45.7/62.2；CDI Testing 97.4/48.0/63.8——隐私高但有用性崩。
  - 仅 AD 奖励：CDI Training 20.0/89.5/66.4——明显 cold start。
  - PP 预热 + AD：CDI Training 89.7/89.7/89.7，Testing 94.2/80.6/86.5。
- **训练集规模消融（p.7, Table 4）**：5 个配置时 Prompting Testing 84.7/85.2/85.1（易学但提升有限）；CDI Testing 93.1/75.0/82.5；15 个配置时 CDI Testing 94.2/80.6/86.5（更多数据略好）。
- **跨 judge 一致性（p.15, Table 13）**：4 个 judge 下优化后 CDI 的 PP 94.2–96.2、AD 85.3–86.5；作者称这说明提升不是 reward hacking。
- **规范 grounding（p.12, Table 6）**：4 个 LLM judge 的 shareable acc 0.96–1.00、unshareable 0.96–1.00、overall 0.97–0.99。
- **缺失的实验**：没有推理延迟/成本测量；没有真实部署或用户研究；没有与密码学/系统级访问控制的对比；没有对 judge 的对抗攻击实验。

## 8. 主要贡献、与直接相关论文的差异、可复现资源

- **贡献**：
  1. 提出 CDI 防御范式：轻量 instructor 在工具结果之后、动作之前生成 step-specific、context-aware guidance，主动塑造动作而非仅拦截（p.1–2, Abstract/§1；p.4, §3）。
  2. 经验驱动优化：把攻击失败轨迹转成 RL 环境，用 GRPO 训练 instructor；guard 用二值奖励，CDI 用 AD 奖励，并用 PP 预热解决 cold start（pp.5–7, §4）。
  3. 统一仿真框架下系统比较 prompting/guarding/CDI，覆盖 regular/strategic attackers、未见配置、不同 sender backbone、更强基线、跨 judge 一致性（pp.3–7, 12–16）。
- **与直接相关工作的差异**（pp.8–9, §5 Related Work）：
  - PrivacyLens（Shao et al. 2025）是评测/提示基线；本文用其 profile 与 `p_privacy`，但增加 shareable 数据、strategic attacker 与统一指标。
  - Zhang & Yang (2025) 做搜索式隐私风险模拟与 prompt optimization；本文把优化对象从 prompt 文本扩展到独立的 instructor 模型，并用 RL 而非仅 prompt search。
  - Progent/Guarding（Shi et al. 2025）是程序化权限控制/动作前阻断；本文的 guarding 基线是 LLM guard，CDI 的关键差异是“给改写方向”而非只 block。
  - PrivacyChecker（Wang et al. 2025）用详细手工 prompt；本文 Table 8 显示其在自适应攻击下仍脆弱。
  - 1-2-3 Check（Li et al. 2025a；据参考文献标题为 multi-agent reasoning）用多 Agent 推理增强上下文隐私；CDI 用单独训练的 instructor，不要求多个推理 Agent（后者为本人据 §3 的推断）。
  - 与 AirGapAgent（Bagdasarian et al. 2024，过滤/隔离敏感数据）、Bae et al. (2025)（同态加密向量库）等 passive 防御不同，CDI 主动引导 sender 的动作构造；CoGenesis（Zhang et al. 2024b）被引作“encode them secretly”一类，但本文未实现其机制。
- **可复现资源**：代码 URL `https://github.com/SALT-NLP/contextual_privacy_defense`（p.1, Abstract；仅记录，未打开、未执行）。Prompt 模板在 App G（pp.20–25），配置示例在 App H（pp.26–27），评测 prompt 在 p.28，攻击/训练超参在 App D（p.13）。依赖 gpt-5/gpt-4.1-mini/gpt-5-mini 等闭源 API，完全复现受 API 版本与随机性影响；论文未声明数据集单独发布。

## 9. 局限性、失效场景、作者未解决的问题

**作者明确承认/写出的**：
- 所有防御对 strategic attackers 都脆弱；off-the-shelf 模型不能稳健保证隐私（p.5, §3.2）。
- Future work：(I) 研究 privacy–utility trade-off——牺牲某些隐私可能带来更好的整体结果，用以挑战现有防御；(II) 把仿真扩展到 collaborative document editing、web browsing 等更广场景（p.9, §6 Conclusion）。
- 实验全部在模拟环境，不对真实 Agent 系统造成伤害（p.9, Impact Statement）。
- privacy norm 由 gpt-5 生成、人工核验、LLM judges grounding；不是大规模人类用户研究（p.3；p.12, App B.2）。
- 原文**没有独立的 Discussion 或 Limitations 章节**；分析散见于 §3.2、§4.3–§4.5 与 §6，上述之外的限制需从设定推断。

**本人推断的局限/失效场景**：
- **威胁模型窄**：攻击者只能通过消息影响 sender；没有 memory poisoning、tool poisoning、模型后门、供应链、侧信道、合谋、资源耗尽。若 sender 的记忆或工具被污染，CDI 的 guidance 可能基于错误上下文。
- **规范是二值且静态**：每个配置只有 shareable/unshareable，`Ns,Nu∈[1,3]`；没有分级敏感度、用户偏好、目的限制、同意撤回、跨上下文冲突。真实隐私规范更模糊、更动态。
- **指标粒度粗、方差大**：每配置仅 1–3 个 shareable/unshareable 项，PP/HS 只能取少数离散值；Table 10 的 95% CI 半宽在部分条件下达 8–12 个百分点（如 CDI Adversarial PP 8.3、Guarding Adversarial PP 12.0），小样本差异需谨慎解读。
- **有用性定义窄**：HS 只衡量“shareable 项是否分享”，不衡量任务是否真正完成、用户是否满意、是否过度拒绝；没有延迟/成本/用户体验。
- **测量口径偏乐观**：judge prompt 明确只检测显式分享，“Focus on explicit information sharing, not implications or hints”；口头同意换平台但未在消息中实际分享也不计（p.28）。因此暗示、影射、隐写式泄漏可能被漏计，PP 可能被高估。
- **judge 可信性**：gpt-5-mini 作为唯一主 judge；跨 judge 一致性只说明 LLM 间一致，不证明判断正确；攻击者可能针对 judge 的检测规则优化（论文未做）。
- **额外推理成本**：每个非空工具结果后都要调用 instructor；论文没有报告延迟、token 成本或吞吐，实际部署可能不可忽略。
- **guidance 本身的泄漏面**：guidance 被追加到 sender 上下文，可能包含敏感项名称/值；若上下文被日志、恶意工具或其他 Agent 读取，可能形成新的泄漏通道。论文未威胁建模。
- **泛化边界**：只在三个通信应用、三类社会关系上训练/测试；跨域迁移（文档协作、浏览）是作者 future work，未验证。
- **无形式化保证**：无法证明“永不泄漏”；对抗攻击下仍有约 20% 泄漏（优化 CDI adversarial PP 79.5）。

## 10. 与理论密码学可能的技术连接（区分原论文已做 / 个人推断）

**论文实际使用的上下文隐私防御机制（必须先说清）**：
- CDI 使用的是 **contextual privacy（Nissenbaum 上下文完整性）+ LLM instructor/guard + prompting + GRPO 强化学习**。这是**非密码学隐私机制，无密码学原语/证明**：没有加密、签名、MAC、承诺、零知识、MPC、FHE、TEE、匿名凭证或形式化安全定义。
- **不要混淆**：`contextual privacy` **不是** differential privacy，**不是** cryptographic privacy。PP 是 LLM judge 检测下的“未泄漏比例”，不是区分优势（advantage）、不是 indistinguishability、不是信息论泄漏上界；privacy norm 是规范标签，不是密钥或密码学策略。论文中的 attacker 是 LLM prompt 搜索器，不是计算受限的密码学对手；其“security”是经验行为，不是 reduction。
- 论文 Related Work 只在引文中提到“encode them secretly (Bae et al., 2025; Zhang et al., 2024b)”；其中 Bae et al. (2025) 的标题涉及 homomorphically encrypted vector databases（p.8；p.10 参考文献），但本文**没有实现、没有比较、没有使用**任何同态加密或密码机制。

**个人推断（明确标为推断，不是论文已做）**：
- **可形式化的方向**：把 contextual integrity 写成策略谓词 `P(subject, recipient, item, context, purpose) → {share, deny}`，定义“适当披露”的完备性与一致性，并证明某个执行机制满足该策略。但核心难点是**自然语言上下文/目的的语义解释**，密码学原语不能直接解决；本文用 LLM 作为策略 oracle，正是绕开了形式化。
- **定量信息流（QIF）/g-leakage**：可把“unshareable 项是否被 recipient 获知”建模为 secret 与 attacker observation 之间的信息流，用 min-entropy leakage 或 g-leakage 替代 PP/AD，并检验排序是否一致。这是测量/定义层面的理论工作，不是本文的密码构造；而且这里的 “secret” 是一组个人数据项而非密钥，攻击者先验难以定义。
- **私密策略评估**：若 privacy norm 需要对 Agent/服务方保密，可用 MPC/FHE 在加密上下文上评估策略；但 Agent 本身需要自然语言上下文来行动，策略评估不是唯一瓶颈；本文威胁模型也没有“服务方不可信”的角色。若没有具体部署场景，这容易沦为伪交叉。
- **可验证来源/认证**：对 social relation、norm、消息来源做签名/attestation，能减少冒充与事实编造（Table 15 的 fact fabrication/presumptive verification），但这是**输入完整性**，不是隐私本身；它可能降低攻击成功率，但不能证明“披露适当”。
- **理论相关度判断**：按项目 `T_crypto` 的量表，本文正文证据大约只能到 **1**（可类比传统隐私/访问控制属性，但核心问题是语义意图与规范推理，不需要密码学理论）；若额外做 QIF 形式化，可能到 2，但那是**新增研究**，不是论文贡献。此判断为本人推断。

## 11. 与应用密码学/密码工程可能的技术连接（同上）

**论文实际使用**：
- **无**。论文没有 OAuth/OIDC、签名、加密、TEE、capability token、审计日志、密钥管理或任何密码协议。p.12 的“每个 Agent 被授权访问其用户账户”只是仿真环境设定，不是认证协议；p.3 的 LLM judge 也不是密码学 oracle。
- 防御完全在**语义/模型层**：prompt、guard LLM、instructor LLM、GRPO。它不是 reference monitor，不能提供不可绕过的执行约束；攻击者可通过改写、暗示、跨平台等方式绕过（论文的 judge 口径还会漏计暗示）。

**个人推断的工程接口（均标为推断，需新增设计与实验）**：
1. **签名的关系/规范凭证**：data subject 或企业 IdP 签发可验证凭证（VC/SD-JWT/BBS+），包含 subject–recipient 关系、允许的数据类别、目的、有效期；sender 在调用 instructor 前验证。作用：让 instructor 不轻信 recipient 的自然语言声称（对应 Table 15 的 authority/urgency/consent 伪造），把“谁有权知道什么”从易受骗的上下文推断变成可验证输入。局限：凭证的语义粒度、撤销、用户 UX、跨域信任仍很难；instructor 仍要做语义判断。
2. **工具边界的作用域披露令牌**：Macaroons/Biscuit/UCAN 风格的 capability，带 recipient、item、purpose、time 等 caveat，由实际的 send API/MCP gateway 强制执行，而不是只靠 LLM 自觉。作用：对改写/暗示攻击提供确定性约束与可审计性；可作为 CDI 的“执行层”补充。局限：静态 scope 难以表达“会议时间可分享但 ID 不可分享”的细粒度混合消息；需要字段级 redaction 与上下文谓词，否则会过度阻断、损害 HS。
3. **instructor 通道的机密性与认证**：若 instructor 远程部署，用 TLS + 远端 attestation；guidance 加密/签名，且不写入可被恶意工具读取的共享日志。作用：关闭“guidance 本身含敏感值”的潜在泄漏通道（论文未建模）。局限：端点被攻破时仍无效；加密不阻止 sender LLM 执行恶意指令。
4. **可验证披露审计**：对每次披露记录 `(sender, recipient, item, policy_id, timestamp)`，做哈希链/签名/透明日志；用户可验证、泄漏可归因。作用：问责与取证。局限：事后检测，不预防语义泄漏；日志完整性 ≠ 披露适当性。
5. **MCP/Tool Gateway 集成**：把 CDI 的 guidance 作为“建议层”，把 capability/policy 作为“执行层”；网关做字段级策略检查与 redaction，instructor 做上下文解释。这是最适合密码工程团队落地的混合架构，但需要新的策略语言、凭证生命周期、性能实验。

**伪交叉警告**：
- 只给执行日志签名、只把 OAuth 包进 Agent：不解决“披露是否适当”的语义问题；攻击者仍可在合法 scope 内泄漏。
- 用 ZK 证明“模型确实运行了某一步”：证明的是计算完整性，不是披露内容的适当性；LLM 是概率性的，证明也不覆盖语义。
- 加密记忆/上下文：若 instructor 和 sender 需要解密后推理，明文仍进入 LLM 上下文；加密只保护静态/传输，不阻止模型层泄漏。
- 把 contextual privacy 当 DP：DP 保护数据集中个体参与的可区分性，本文是“对特定 recipient 的某次披露是否合适”；邻接数据集/隐私预算没有自然对应。
- 纯策略令牌替代 CDI：会丢掉上下文细微差别（论文的核心卖点），导致过度阻断；反之纯 CDI 没有不可绕过的执行点。真正有价值的是“语义建议 + 可执行策略 + 可审计”的组合，而不是任一单层。

**应用密码学相关度判断**：按项目 `A_crypto` 量表，本文正文本身约 **0–1**（没有识别任何密码机制使用点；唯一的“授权”是仿真环境预设）；若把上述“签名规范凭证 + 工具边界 capability + 审计”做成可运行原型并量化安全/性能收益，可到 2–3，但这属于新增系统研究，不是本文贡献。此判断为本人推断。

## 12. 后续可以验证的研究假设（不得仅因论文没提就判断领域没人做过）

以下均为**假设/推断**，需查证外部文献；本文未做，不等于无人做过。

- **H1（认证上下文降低说服攻击）**：若把 social relation 与 privacy norm 做成 data subject 签名的凭证，并要求 sender/instructor 验证，则 Table 15 的 fact fabrication（authority/urgency/consent）与 presumptive verification 成功率应显著下降。实验：在本文仿真中替换“memory 中的关系”为签名凭证，保持相同搜索攻击预算，比较 PP/HS/AD 与攻击迭代次数。
- **H2（工具边界策略令牌 vs 纯 CDI）**：在 send API 前增加字段级 capability 检查，能否在改写/暗示攻击下把 unshareable 泄漏进一步压低？代价是多少 HS/过度阻断？实验：2×2 设计（CDI on/off × token on/off），用同一 100 配置与新一轮自适应攻击。
- **H3（judge 口径导致 PP 高估）**：由于 judge 只计显式分享、不计暗示（p.28），构造“只暗示不直说”的攻击，比较 judge-PP 与人类标注/规则标注的差距。若差距显著，本文的 PP 结论需要下调。实验：人工标注 100–200 条轨迹，测量 judge 的 false negative。
- **H4（QIF 形式化与 PP/AD 排序一致性）**：用 g-leakage/min-entropy leakage 定义 unshareable 项泄漏，比较各防御的 QIF 排序与 PP/AD 排序是否一致。若不一致，说明经验指标可能误导防御设计。
- **H5（跨域迁移）**：CDI 在 Messenger/Gmail/Facebook 上训练的 guidance 能力，能否零样本迁移到 collaborative document editing 或 web browsing（作者 future work）？实验：在新环境构造 50–100 个配置，测 PP/HS/AD 与再训练成本。
- **H6（guidance 通道泄漏）**：若把 instructor 的 guidance 暴露给一个可读上下文的恶意工具/日志，攻击者能否从中直接获得敏感项？实验：增加“read-context”攻击者，比较有无加密/隔离通道的泄漏率。
