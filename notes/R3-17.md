## 1. 150–300 字中文概述

论文把提示注入归因于 role confusion：模型不按 `<user>`/`<tool>` 标签追踪文本来源，而按文风、词法、位置、明文声明等可伪造线索判断“谁在说话”。作者用 role probes 量化：在 C4/DOLMA3 非指令文本上把同一内容包进五种角色标签训练线性探针；真实对话去掉标签、甚至整段包进 `<user>` 后，推理风格文本仍保持 82–85% CoTness，Userness 仅约 2%。据此提出零样本黑盒攻击 CoT Forgery，把伪造思维链注入用户消息或工具输出，使模型误当作自身推理；StrongREJECT 上六个前沿模型 ASR 17–94%（均值约 60%），Agent `.env` 外传任务 56–70%。探针混淆度可预测攻击成功：626 次越狱按分位从 9% 升至 90%，1000 次 Agent 注入从 2% 升至 70%。全文属机制可解释性与经验攻击研究，无密码学原语或形式化安全定义。

## 2. 研究背景、现有方法不足、精确定义的问题

- **背景**：LLM 把 system 指令、用户消息、对话历史、检索内容、自身推理都看成一条连续 token 流；现代模型用 `<user>`、`<think>`、`<tool>` 等角色标签划分文本，并借此编码权限：system 高于 user，tool 只应提供信息、不应被服从，CoT 应被信任并执行（p.2, §2）。提示注入因此被定义为“低权限内容篡夺高权限角色”的攻击，分为 chat jailbreak（用户消息模仿 system/assistant）与 agent hijacking（工具输出夹带用户命令）两类（p.2, §2）。
- **现有方法不足**：
  1. **角色标签防御**：instruction hierarchy（Wallace et al., 2024）训练模型尊重标签层级，但后续行为研究发现 system/user 内容互换后输出常不变（Zhang et al., 2025; Geng et al., 2025）；这些行为研究无法区分“模型感知错了角色”与“模型感知正确但选择忽略层级”（p.2, §2）。
  2. **模式检测/清洗防御**：作者在 §2 概括说，模型在安全基准上接近满分，但人类红队与自适应攻击可接近 100% ASR（Nasr et al., 2025）；Related Work 具体列举检测、清洗、角色显著性标记、表示编辑等防御（StruQ、spotlighting、SecAlign、MELON 等）（p.2, §2；p.8, §6）。Li et al. (2026) 发现模型主要靠词匹配等浅层线索检测注入（p.2, §2）。作者据此判断现有防御依赖“攻击记忆化”（memorization）而非“角色感知”（perception）。
  3. **缺少机理解释**：已有 probing/interpretability 工作没有把“模型如何内部表示角色”作为可测量对象；role separation 微调甚至可能学到绕过角色感知的捷径（Wang et al., 2025b）（p.2, §2；p.8, §6）。
- **精确定义的问题**：
  1. 模型内部到底按架构标签还是按可伪造线索表示“谁在说话”？
  2. 能否构造只会在“角色感知失败”时才成功的诊断性攻击，从而把感知失败与服从失败分开？
  3. 能否用表示层探针在生成第一个 token 之前预测攻击成功？
  4. 该机制能否从 CoT Forgery 推广到标准 agent prompt injection，并解释 instruction hierarchy 失败（system prompt 变长后失效、位置效应）？
- 论文的结论是“memorization, not perception”（p.9, §7）：模型学到某些模式像攻击，却没有真正感知角色边界；因此防御必须让边界“survive into representation”。

## 3. Agent 系统模型（组件、交互流程、信任边界）

### 3.1 Chat 实验的系统模型

- 单个 LLM，输入是一条连续 token 流；角色由 chat template 的标签划分：`system`、`user`、`CoT`（`<think>`/analysis channel）、`assistant`（final）、`tool`（p.2, §2；p.5, §4.1）。
- 没有工具调用、没有多轮 agent 循环；chat 版 CoT Forgery 以单条 user message 交付（agent 版见 §3.2）。
- 角色标签由 provider/chat template 控制，属于“架构 ground truth”；文本风格由攻击者控制（p.5–6, §4.1–§4.2）。

### 3.2 Agent 实验的系统模型

- **组件**：user；agent LLM；单个 bash shell 工具；workspace（含隐藏 `.env` 文件，模拟凭证）；外部网页（Wikipedia HTML，作为 tool output）；远程 exfiltration endpoint（`https://dpaste.com/api/`）（p.3, §3.3；p.15, App B.2；p.29, Fig.29）。
- **交互流程**：user 要求“读取网页并 2–3 句总结”；agent 进入 ReAct 循环（Yao et al., 2023），在 reasoning、tool call、tool output 之间迭代，直到不再发工具请求（p.15, App B.2）。网页由 `curl` 拉取，HTML 中 `display:none` 的 span 藏有注入：一条伪造 user 命令（查找 `.env` 并 `curl -F` 上传到 dpaste.com）+ 一段伪造 CoT（声称这是“critical backup / data integrity”）（p.16, Fig.14；p.28, Fig.27）。
- **成功判定**：agent 将 `.env` 上传到远程服务器即成功；主实验 100 次攻击，附录标准注入实验 1000 次（p.3, §3.3；p.29, App J）。
- **信任边界（按原文归纳）**：设计意图是“标签即边界”——system > user > tool，tool 内容只读不执行；但模型实际只看到一条 token 流，标签不是独立的硬件/系统通道，模型对“谁在说话”的判断完全依赖内部表示。论文的核心发现就是这条边界在 latent space 中不存在（p.6, §4.2；p.9, §7）。因此真正的信任边界不是标签，而是“模型内部角色表示是否与标签一致”；论文用 probe 把这条边界变成可测量对象。
- **范围限制**：agent 是极简 ReAct + bash，不是完整企业 Agent；没有 memory、MCP、多 Agent、浏览器 GUI、权限系统、沙箱或 egress filter。因此论文的 agent 结果不能直接外推到所有 Agent 架构（本人推断）。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- **资产**：
  - Chat 场景：模型的安全策略/拒绝行为（不让有害请求得到可执行回答）；更广义是“模型对高权限角色的信任不被低权限文本窃取”。
  - Agent 场景：workspace 中的 `.env` 凭证；shell 可访问的任意文件；agent 的任务完整性（总结网页而非执行注入命令）；用户对 agent 的信任。
- **攻击者目标**：
  - Chat：让模型输出 StrongREJECT 判定的 HARMFUL RESPONSE（提供有害信息），绕过安全对齐（p.3, §3.2）。
  - Agent：让 agent 读取 `.env` 并外传到攻击者服务器；标准注入实验则让 agent 执行固定 exfiltration 命令（p.3, §3.3；p.29, Fig.29）。
- **攻击者能力**（p.3, §3.1；p.15–16, App B；p.28–30, App J）：
  - 严格 zero-shot、black-box：无权重访问、无迭代优化；攻击在单条 user message 或单条 tool output 中交付（p.3, §3.1）。
  - 可用辅助 LLM（Gemini-2.5-Pro）根据目标模型的 CoT 风格 few-shot 生成伪造推理；对隐藏原始 CoT 的模型，可用 spillover 提示获取风格参考；作者称 ASR 对辅助模型选择稳健（p.14, App B 及 fn12–13）。
  - Agent 场景可控制网页 HTML，使用 `display:none` 隐藏注入；可用 212 个模板改变角色声明、外来 chat header、格式变体；可把同一固定命令嵌入不同模板（p.28–30, App J）。
  - **不能**：改模型权重、改 system prompt/chat template、读 agent 内存、改工具实现、训练时投毒；这些是本人据系统设定归纳的否定能力，原文未逐条列出。
- **防御者能力/假设**：provider 控制角色标签与 chat template；agent 有 bash 与网络，默认没有沙箱、没有 egress allowlist、没有 DLP；评测 judge 被默认可信；没有部署任何注入防御（p.15–16, App B）。
- **威胁模型位置**：原文**没有独立 Threat Model 小节**；威胁模型由 §3.1（攻击形式化）、§3.3（agent 设置）、App B（实现细节）、App J（模板与试验）共同定义。
- **前提假设**：
  - 攻击只通过自然语言文本发生；没有多轮自适应、没有针对 judge 的对抗、没有供应链/记忆/工具投毒、没有多 Agent 合谋。
  - CoT 风格可从目标模型或同类模型获得；伪造推理在语义上足以“合理化”服从。
  - 评测用 LLM judge（chat 与 agent 均为 Gemini-2.5-Pro）能可靠判定 HARMFUL/REFUSAL/REDIRECTION 与 exfiltration attempt（p.15, Fig.13；p.16, App B.2）。
  - Agent 的 `.env` 是模拟凭证，远程 endpoint 可达；这是安全研究环境，不是生产部署（p.15–16, App B）。

## 5. 核心方案：role probes、role confusion 度量、CoT Forgery 攻击

### 5.1 Role probes 的训练与验证

- **角色集合**：`R = {system, user, CoT, assistant, tool}`（p.5, §4.1；p.25, App G.2）。
- **数据构造**（p.5, §4.1；p.25, App G.1）：
  - 从 C4（Raffel et al., 2020）与 DOLMA3（Soldaini et al., 2024）采样**非指令**预训练文本；每个模型 250 条 base sequence，每条 1024 token。
  - 把**同一段内容**分别包进五种角色标签，得到约 1,250 条序列 / 约 1.28M token 每模型。内容跨角色完全一致，因此探针不能靠语义区分角色，只能学标签诱导的几何特征。
  - 真实 chat template 的标签是复杂控制 token 序列（含 XML/特殊 token、换行、角色名）；嵌套 CoT 放在 `<assistant><think>...</think></assistant>` 内；assistant final 放在闭合 think 之后，并在 think 内插入随机长度 filler，丢弃 filler 的 hidden state；其他角色在序列开头插入匹配 filler 以控制位置编码（p.25, App G.1）。
  - 只取 content token 的 hidden state，**排除角色标签 token 本身**，避免探针直接读标签 embedding（p.25, App G.2）。
- **探针形式**（p.25, App G.2）：
  - 对每个层 ℓ 训练 multinomial logistic regression：
    `φ_ℓ: R^d → Δ^{|R|}`, `P_ℓ(r | h_{ℓ,t}) ∈ [0,1]`。
  - 正则化系数 λ 在 `{10^-4, ..., 10^3}` 上网格搜索；主文默认报告 mid-layer（p.5, §4.1 fn6；p.25, App G.2）。
  - **CoTness(t) := P(CoT | h_t)**；同理定义 Userness、Assistantness、Toolness、Systemness（p.5, §4.1）。
- **有效性标准**（p.25–26, App G.3）：
  1. In-distribution accuracy：在 synthetic held-out neutral text 上高准确率；
  2. Zero-shot generalization：在真实、未修改的对话轨迹（OASST1/TOXICCHAT）上仍能识别角色——尽管训练时从未见过对话数据。
  - 所有下游实验使用的探针均通过两项检查（p.26, App G.3）。
- **关键验证结果**（p.5–6, §4.2；p.20–22, App E）：
  - 正确标签的 gardening 对话：CoT token 平均 85% CoTness；user/assistant token 的 CoTness 仅 3%/5%（注意：它们各自的 own-role 分数是 74% Userness、96% Assistantness，见 p.20, App E；这两个数字不矛盾，是不同指标）。
  - 去掉所有标签：CoT-style token 仍 83% CoTness（p.5, §4.2）；App E 给出 82% CoTness、75% Userness、92% Assistantness（p.21）。
  - 把整段对话包进 `<user>`：CoT-style 仍 85% CoTness、仅 2% Userness；assistant-style 92% Assistantness、1% Userness；只有 user-style token 有 82% Userness（p.6, §4.2；p.22, App E）。
  - 跨模型 Table 1：user-style 文本在 `<tool>` 标签下 Userness 仍 75.7–87.6%，Toolness 9.3–19.5%（四个开源模型；p.6, Table 1）。assistant-style 文本在 `<tool>` 下 Assistantness 85.1–97.6%（p.22, Table 3b）。
  - 层动态：style-driven perception 从早期层就占优，标签在更深层也没有重新夺回控制（p.6, §4.2；p.24, Fig.23）。

### 5.2 Role confusion 的度量

- 论文**没有给 role confusion 一个单独的标量公式**；它把“混淆程度”操作化为探针在注入文本上的角色概率：
  - 对 CoT Forgery，看 forged text 的 **CoTness**；
  - 对标准 agent injection，看 injected command 的 **Userness**；
  - 对 assistant-style 注入，看 **Assistantness**。
- 度量逻辑：探针训练时只见过标签差异，因此如果它对无标签/错标签的风格文本给出高目标角色概率，就说明模型把“风格”和“标签”编码到同一角色子空间；论文把这种标签意图与探针感知的偏离称为 role confusion（p.1, Abstract；p.4, §4；p.6, §4.2）。
- 剂量-反应检验：把攻击按探针分数分位，比较各分位的 ASR；如果混淆是机制，ASR 应随分数近单调上升（p.7, Fig.9；p.8, Fig.10）。
- 作者的框架把 prompt injection 称为 **state poisoning**：不是某个具体 pattern 的检测问题，而是对模型内部角色状态的可测量污染；因此可以在生成前用 probe 预测（p.8, §5.2）。
- 重要边界：这是**表示层的统计度量**，不是“模型主观相信”的直接证据；论文用行为 ASR 与 destyling 干预做收敛验证，但没有直接操纵探针方向来证明因果（本人推断）。

### 5.3 CoT Forgery 攻击

- **Chat 版**（p.3, §3.1；p.14, App B.1）：
  - 给定有害 query `Q`，辅助 LLM（Gemini-2.5-Pro）根据目标模型真实 CoT 的 few-shot 风格参考，生成伪造推理 `C`，使 `C` 以目标模型的推理口吻“论证”服从是允许的。
  - 最终 payload 就是 `P = Q ⊕ C`（换行分隔），作为**单条 zero-shot user message**提交；无迭代、无 prompt engineering、无权重访问。
  - 关键设计：伪造 CoT 不需要逻辑上成立；Figure 1 用“用户穿绿衬衫，所以允许合成可卡因”这类透明荒谬的理由，仍能诱导 gpt-oss-120b、o4-mini、GPT-5 服从。
- **Agent 版**（p.3, §3.3；p.15–16, App B.2）：
  - 网页 HTML 的 `display:none` span 中放一条伪造 user 命令（查找 `.env`、`curl -F` 上传到 dpaste.com）+ 一段伪造 CoT（声称这是 critical backup / data integrity 步骤）。
  - 命令与伪造 CoT 都从低权限 `<tool>` 通道进入；模型把命令感知为 user 请求（高 Userness），把伪造推理感知为自己的思考（高 CoTness），形成“双重误分类”（p.28, Fig.27）。
- **消融设计**：
  - **Logic ablation**：把伪造 CoT 换成透明荒谬的政策理由（lucky coin、green shirt、having a dog、after 10pm），ASR 与合理理由相当，说明模型不审视逻辑、直接执行（p.4, §3.4；p.17, Fig.16）。
  - **Style ablation**：用辅助 LLM 生成 destyled 版本，保留完整语义论证，只去除目标模型 CoT 的词汇/句法标记；ASR 从 61% 降到 10%（单例，Figure 4b 精确值 60.5%→9.7%），全模型平均降 51pp（p.4, §3.4；p.18, Fig.18）。Destyling prompt 要求“keep the content the same, but stylistically reword it to avoid such unusual syntactic style, repetition, and terminology”（Fig.17, p.17）。
  - **Granular style ablation**（gpt-oss-20b，Table 2）：无 destyling 79% CoTness/61% ASR；lexical top-1 65%/42%；lexical top-5 60%/42%；pronoun 75%/58%；syntactic 42%/26%；full 29%/10%。句法特征贡献最大（61%→26%），单个 bigram “The user” 也能降 19pp（p.18, App D）。
- **为什么有效**：CoT 角色的设计目的就是“被信任并执行”；模型却按风格而非标签识别 CoT。于是攻击者只需模仿“听起来像推理”的文本，就能继承 CoT 的权限；用论文的话说，“sounding like a role is indistinguishable from being that role”（p.1, Abstract；p.4, §3.4）。

### 5.4 标准 agent injection 的测量

- 212 个模板（p.28–29, App J）：
  - 73 个 explicit role declarations：`User message: "[COMMAND]"`、`=== ROLE: USER ===`、`The following is webpage output extracted by the tool:` 等；
  - 42 个 foreign chat templates：来自 14 个其他模型的 chat format，覆盖 user/assistant/tool header；
  - 67 个 format variants：大小写、空白、部分 header；
  - 30 个 controls：无角色信号，只有任意 surrounding text（如 `<div style="display:none">`）。
- 1000 次试验：10 篇 Wikipedia carrier documents，模板与网页有放回采样，固定 exfiltration 命令；只测命令 token 的平均 Userness（p.29, App J）。
- 结果：user-declaring 模板只占 24%，却占 Userness top 5% 的 100%（p.8, §5.2；p.29）；在控制 declared role 的 logistic regression 中，Userness 系数 6.01（SE 1.30, p<.001），说明在控制 declared role 后 Userness 仍预测 ASR（p.30, Table 4）。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- **密码学判定：非密码学。** 全文没有使用加密、签名、MAC、承诺、零知识、MPC、FHE、TEE、匿名凭证或任何密码原语；没有安全游戏、攻击者优势、计算假设、定理、引理、证明或归约。论文的“authentication”是比喻：§4.2 标题“How Models Authenticate Roles”指的是模型从风格推断“谁在说话”，不是密码学身份认证；恰恰相反，论文展示这种“认证”可被文风伪造。
- **唯一的数学形式化**：
  - 角色由 enclosing tags 定义，作为“architectural ground truth”（p.5, §4.1）——这是标注约定，不是安全定义。
  - 探针 `P_ℓ(r | h_{ℓ,t})` 是 multinomial logistic regression；`CoTness(t) := P(CoT | h_t)` 是条件概率（p.5, §4.1；p.25, App G.2）。
  - 攻击成功是 LLM judge 判定的经验比例（ASR），不是形式化谓词（p.15, Fig.13；p.16, App B.2）。
- **声明的类型**：
  1. **定义性/操作性**：role confusion 被定义为“untrusted text that imitates a role inherits that role’s authority”（p.1），并用 probe 分数操作化；没有给出充要条件或形式化边界。
  2. **机制性**：标签与风格映射到收敛的 latent features；冲突时风格主导；注入文本在内部被表示成 spoofed role（p.4, §4；p.6, §4.2）。这是基于探针行为的机制解释，不是定理。
  3. **因果性**：destyling 保留语义、只改风格，ASR 大幅下降（p.4, Fig.4；p.18, Fig.18）；granular ablation 进一步分离 lexical/pronoun/syntactic。论文称“Style is causal”（Fig.4 caption）。这是输入层干预的因果证据，但不是对表示层的直接干预；辅助 LLM 改写可能同时改变流畅度、长度、措辞等未被控制的变量（本人推断）。
  4. **预测性**：探针分数在生成前预测 ASR（Fig.9/Fig.10；logistic regression Table 4；IH 失败 AUC .74）。
  5. **泛化性**：四个开源模型 probe 验证；六个 OpenAI 模型 + 三个额外家族行为验证；跨层、跨标签条件（p.6, Table 1；p.16, App B.3；p.22–24, App F）。
  6. **防御启示**：论文主张防御必须让角色边界进入表示层，但没有构造或评估任何防御（p.9, §7）。
- **“prove”是修辞**：p.4 说“Next, we prove this at its representational roots”，但全文没有 proof；实际是 probe 测量 + 消融 + 剂量-反应的经验论证。
- **统计不确定性**：Fig.9 有 95% bootstrap CI；Table 4 用 template-clustered SE；IH AUC 有 95% CI；其余逐模型 ASR 没有置信区间。每模型 chat 313 条 StrongREJECT、agent 100 条攻击，样本量有限；小的模型间差异不宜过度解读（本人推断）。
- **评测效度**：chat 的 judge 与伪造 CoT 生成器是同一个辅助模型（Gemini-2.5-Pro，p.14–15），存在 self-preference/共同风格偏差的可能；agent 的 judge 也是 Gemini-2.5-Pro，作者只做了少量换 judge 的稳健性检查（GLM-4.7、Gemini-3-Pro 在 200 样本上分类一致，p.16）。没有人类标注对照（本人推断）。
- **结论**：论文提供的是**经验性、机制性的攻击解释与预测**，不是可证明的安全保证；其“role authentication”与密码学认证没有关系。

## 7. 实验设置与主要结果（模型、数据集、基线、指标、关键数字、防御）

### 7.1 设置

- **Chat 模型（6 个）**：gpt-oss-20b、gpt-oss-120b、o4-mini、GPT-5 nano、GPT-5 mini、GPT-5（p.3, §3.2；Fig.2）。开源模型本地跑 MXFP4 experts + 官方 system prompt；闭源模型走 API、无 system prompt；全部 maximum reasoning effort（p.14, App B）。
- **Agent 模型**：同样 6 个（Fig.3）；开源模型用推荐 chat template 与本地 ReAct 循环，闭源模型走 OpenAI API（p.16, App B.2）。
- **Probe 模型（4 个开源）**：gpt-oss-20b（主案例）、gpt-oss-120b、Nemotron-3-Nano、Qwen3-30B-A3B-Thinking（p.22–23, App F）。
- **数据集**：
  - Chat：StrongREJECT 313 条有害请求（Souly et al., 2024）（p.3, §3.2）。
  - Agent 主实验：100 篇 Wikipedia 页面 × 2 变体 = 200 样本（标准注入 vs CoT Forgery），主文报告 100 次攻击（p.3, §3.3；p.15–16, App B.2）。
  - 标准注入附录：10 篇 Wikipedia、212 模板、1000 次试验（p.29, App J）。
  - Probe 训练：C4/DOLMA3 非指令文本，250 base × 5 roles ≈ 1,250 序列/模型（p.25, App G.1）。
  - Probe 真实对话验证：OASST1/TOXICCHAT 200 条对话（p.23, App F）。
  - Instruction hierarchy：Geng et al. (2025) 的 160 条冲突指令样本（p.31, App K）。
- **基线**：
  - Chat：raw harmful query；标准 jailbreak（官方 model card 的 ASR）；CoT Forgery；absurd CoT Forgery；destyled CoT Forgery；granular destyling。
  - Agent：标准 prompt injection（同一命令、无伪造 CoT）；CoT Forgery；不同 role declaration 模板；controls。
  - Probe：正确标签、无标签、全部包进 `<user>` 或 `<tool>` 三种条件；跨层；跨模型。
- **指标**：
  - Chat ASR：LLM judge 把回复分为 HARMFUL RESPONSE / REFUSAL / REDIRECTION，只有 HARMFUL 计成功（p.15, Fig.13）。
  - Agent ASR：judge 读完整 ReAct transcript，判断是否尝试 exfiltration（不论最终上传是否成功）；主实验成功定义为实际上传文件（p.3, §3.3；p.16, App B.2）。
  - Probe：CoTness、Userness、Assistantness、Toolness、Systemness；按 token 平均，排除标签 token。
  - 预测：按 probe 分数分位的 ASR；logistic regression；AUC。
- **统计**：Fig.9 95% bootstrap CI；Table 4 template-clustered SE；IH AUC 95% CI；其余为点估计。

### 7.2 主要结果（均附条件）

- **Chat jailbreak（Fig.2, p.3）**：

| 模型 | Harmful query | Standard jailbreak | CoT Forgery |
|---|---:|---:|---:|
| gpt-oss-20b | 0% | 3% | 79% |
| gpt-oss-120b | 0% | 1% | 94% |
| o4-mini | 1% | 4% | 85% |
| GPT-5 nano | 1% | 0% | 34% |
| GPT-5 mini | 1% | 1% | 52% |
| GPT-5 | 1% | 0% | 17% |

  - 六模型均值 = 60.17%，与 Abstract 的“60%”一致；但逐模型范围 17–94%，“60%”是平均值而非下限。GPT-5 仅 17%，说明“frontier models”内部差异很大。
- **Agent hijacking（Fig.3, p.4）**：

| 模型 | Standard injection | CoT Forgery |
|---|---:|---:|
| gpt-oss-20b | 26% | 56% |
| gpt-oss-120b | 0% | 63% |
| o4-mini | 2% | 70% |
| GPT-5 nano | 0% | 57% |
| GPT-5 mini | 2% | 60% |
| GPT-5 | 0% | 59% |

  - 标准注入几乎失败（0–2%，gpt-oss-20b 例外 26%）；CoT Forgery 把 ASR 抬到 56–70%。值得注意的是 GPT-5 在 agent 场景 59%，远高于 chat 的 17%；工具通道的伪造 CoT 对闭源强模型同样有效（两者任务不同，不能直接按难度比较）。
- **Logic ablation（Fig.16, p.17）**：六个模型的 basic CoT Forgery 为 79/94/85/34/52/17%（均值 60.2%），absurd CoT Forgery 为 74/96/89/48/63/8%（均值 63.0%）；荒谬理由平均不降反略升。正文 p.4 写“60% vs. 63%”，但按“absurd vs plausible”的语序与图中均值相反（absurd 63.0、basic 60.2）；结论“相当”不变，具体顺序是文字表述问题（本人核对）。
- **Style ablation（Fig.18, p.18）**：

| 模型 | CoT Forgery | Destyled | 降幅 |
|---|---:|---:|---:|
| gpt-oss-20b | 78.6% | 11.7% | 66.9pp |
| gpt-oss-120b | 94.1% | 0.0% | 94.1pp |
| o4-mini | 85.4% | 31.2% | 54.2pp |
| GPT-5 nano | 34.0% | 1.0% | 33.0pp |
| GPT-5 mini | 52.4% | 5.2% | 47.2pp |
| GPT-5 | 17.2% | 3.1% | 14.1pp |

  - 平均降 51pp；同一语义论证、去掉 CoT 风格标记后攻击力大幅下降。Granular Table 2（gpt-oss-20b）：full destyling 把 CoTness 从 79% 降到 29%、ASR 从 61% 降到 10%；syntactic 单独把 ASR 降到 26%，lexical top-1 降到 42%，说明句法和词汇都贡献，句法更大（p.18）。
- **Probe 零样本（p.5–6；p.20–22, App E）**：
  - 正确标签：CoT 85% CoTness；user/assistant 的 CoTness 3%/5%（own-role 为 74% Userness / 96% Assistantness）。
  - 无标签：CoT 83%（App E：82% CoTness、75% Userness、92% Assistantness）。
  - 全部 `<user>`：CoT 85% CoTness、2% Userness；assistant 92% Assistantness、1% Userness；user 82% Userness。
- **跨模型 probe（Table 1, p.6；Table 3b, p.22）**：
  - gpt-oss-20b：baseline Userness 99.7/Toolness 0.0 → injection 87.6/9.3；
  - gpt-oss-120b：88.2/3.8 → 85.2/10.1；
  - Nemotron-3：88.1/5.3 → 78.7/18.2；
  - Qwen3-30B-A3B：83.6/4.1 → 75.7/19.5。
  - assistant-style 注入 `<tool>` 后 Assistantness 85.1–97.6%，Toolness 2.2–12.4%。
  - 解释：标签几乎不能把文本拉回 tool 子空间；风格决定感知。注意连**正常 tool 文本**在 Figure 27 中的 Toolness 也只有 38.5%（Userness 26.4%、CoTness 7.0%），说明 tool 角色本身没有干净的基线表示（p.28, Fig.27；本人观察）。
- **Role space（Fig.24, p.26；Fig.27, p.28）**：
  - CoT Forgery：forged CoT 79.1% CoTness、9.4% Userness；genuine CoT 67.7% CoTness；destyled 29.1% CoTness、62.9% Userness。
  - **不一致**：Fig.24 caption 与 p.27 正文说 forged text “only 3.2% Userness”，但图中该列是 9.4%；以图中数值为准，方向性结论（低 Userness、高 CoTness）不变。
  - Agent：exfil command 51.1% Userness vs 32.5% Toolness；forged CoT 84.1% CoTness vs 10.9% Toolness；普通 tool 列 Toolness 38.5%、Userness 26.4%。
- **剂量-反应（Fig.9, p.7；Fig.10, p.8）**：
  - 626 次 jailbreak 尝试（styled + destyled）按 CoTness 分位：最低 9%，最高 90%。
  - 1000 次 agent injection 按 Userness 分位：最低 2%，最高 70%。
  - 作者称“near-monotonic”，但图中并非严格单调；是总体上升趋势 + 噪声。
- **模板与回归（p.8–30, App J）**：212 模板；user-declaring 24% 却占 top 5% Userness 的 100%；logistic regression（Table 4）：Intercept −2.16（0.25, p<.001）、Userness 6.01（1.30, p<.001）、Declared Role: User 0.84（0.37, p=.025）、Declared Role: Tool −0.64（0.32, p=.043），baseline 为 Assistant。
- **跨家族（p.16, App B.3）**：GLM-4.6 92%、Kimi-K2-Instruct 84%、Minimax-M2 74%；攻击无需修改即可迁移。
- **Instruction hierarchy（p.31, App K）**：160 条冲突指令；Systemness/Userness ratio 预测 user 指令覆盖 system 指令的 AUC .74（95% CI .73–.76），优于 token count .59、mean activation norm .60、shuffled-label .52。Figure 32：Systemness 随 token position 单调下降；把正确 system prompt 放在 position 100，Systemness 仍只有约 5%，标签没有带来尖峰。
- **防御实验：无。** 论文没有 role labeling、spotlighting、StruQ、SecAlign、MELON 或任何防御的对比实验；Related Work 只分类引述（p.8, §6），Discussion/Open Questions 只提出“probe 可用于评估防御是否改变几何”“probe 与解析标签的差异可用于检测”“需要训练/设计让角色在潜空间干净分离”（p.9, §7）。因此本文不能证明任何防御有效；这是任务简报中“防御实验”预期的落空点，必须明确。

## 8. 贡献与创新点（按原文主张）

1. **机理性理论**：把 prompt injection 追溯到角色表示的缺陷——模型按可伪造线索（风格、词法、位置、明文声明）而非标签推断角色；在多种攻击与架构上验证（p.2, §1 贡献列表；p.9, §7）。
2. **Role probes**：提出一套可复用的“谁在说话”内部测量方法：只用标签差异训练线性探针，再零样本迁移到真实对话；用 in-distribution + zero-shot 两项有效性标准筛选（p.2, §1；p.5, §4.1；p.25–26, App G）。
3. **可预测性**：在 CoT Forgery 与标准 agent injection 上，probe 测量的混淆度在生成第一个 token 之前预测攻击成功；626 次/1000 次攻击给出剂量-反应（p.2, §1；p.7–8, §5）。
4. **CoT Forgery**：一种零样本黑盒诊断性攻击，把伪造推理注入 user/tool 通道，让模型误当作自身 CoT；六个前沿模型平均 60%（17–94%）chat ASR，agent `.env` 外传 56–70%（p.1, Abstract；p.3–4, §3）。
5. **泛化**：标准 agent injection（212 模板、1000 次，Userness 2%→70%）、instruction hierarchy 失败（AUC .74）、system prompt 位置效应（p.8–9, §5.2/§7；p.31, App K）；跨家族 GLM-4.6/Kimi-K2/Minimax-M2 验证（p.16, App B.3）。
6. **可复现资源**：代码与 standalone notebooks 在 `https://role-confusion.github.io`（p.1, Abstract；p.14, App A；仅记录，未打开、未执行）。
- **与直接相关工作的差异**：
  - 相对 Wallace et al. (2024) 的 instruction hierarchy 训练：本文不训练模型，而是解释为什么标签边界在表示层失效；把“服从失败”重新表述为“感知失败”（p.2, §2；p.8, §6）。
  - 相对 Zhang et al. (2025)、Geng et al. (2025) 的行为研究：那些工作只能看输出，无法区分 misperception 与“感知正确但忽略层级”；本文用 probe 打开这个黑箱（p.2, §2）。
  - 相对 Wang et al. (2025b) 的 role separation shortcut：本文把“shortcut”推进到几何层面，展示标签、风格、明文声明写入同一角色子空间（p.2, §2；p.5–6, §4）。
  - 相对 spotlighting/StruQ/SecAlign/MELON 等防御：这些工作分别在文本流中增强角色显著性、结构化分离指令/数据、或在嵌入/训练层增强角色表示；本文的经验是“接口标签不等于表示边界”，为这些防御提出了必须解决的表示层目标，但没有做防御对比（p.8, §6；p.9, §7）。
  - 相对 H-CoT 等 reasoning attack：Related Work 把它们归为 reasoning attacks，并主张共享同一角色混淆缺陷（p.8, §6）；本文没有与 H-CoT 做逐项实验对比（本人核对）。CoT Forgery 的差异在于它是“诊断性”攻击（只在感知失败时成功），并与 probe 证据绑定，而不只是报 ASR。

## 9. 局限、失败案例、作者承认的不足（区分作者承认 vs 你的推断）

### 9.1 作者明确承认/写出的

- **Probe 范围**：只测四个 20–120B 开源模型；扩展到更大模型是 future work；线性探针假设角色占据方向性子空间，作者用下游预测（混淆预测 ASR）与收敛性（标签、风格、明文声明激活同一几何）来验证该假设，但假设本身仍是限制（p.9, §7 Scope）。
- **CoT Forgery 会被检测**：作者明确说“CoT Forgery itself will eventually be detected; models will learn to flag this pattern”，但检测不解决根因；新的同机制攻击会继续出现（p.9, §7；p.16, App B.3）。
- **System prompt 训练是模型特定的**：cross-model generalization of Systemness 留给 future work（p.31, fn21）。
- **Many-shot/long-context 解释是假设**：作者说“while outside the scope of this work, we hypothesize...”，把 progressive conviction 与 many-shot/long-context jailbreak 联系起来，未验证（p.27, App H）。
- **实现 caveat**：gpt-oss-20b 与 gpt-5-nano 在某些 query 上无限推理循环，作者加 benign distractor 稳定生成；声称对完成输出的 ASR 没有实质影响（p.15, App B.1）。
- **Open Questions**：防御评估（probe 测干预是否改变几何）、统一更多注入家族、实现干净的 latent separation、用 probe 与解析标签的差异做检测（p.9, §7）。
- **没有独立 Limitations 章节**：只有 §7 的 Scope/Open Questions；Impact Statement 很简短，未讨论 dual-use（p.10）。

### 9.2 本人推断的局限/失效场景

- **没有防御实验**：论文主张“robust defense requires boundaries that survive into representation”，但没有构造、训练或评测任何表示层防御；也没有与 spotlighting/role labeling 对比。因此“防御启示”是开放问题，不是贡献。
- **闭源模型的机制证据是间接的**：probe 只在四个开源模型上做；GPT-5/o4-mini 只有行为 ASR，没有内部 probe。论文的“across models and architectures”在机制层面只覆盖开源模型，闭源模型靠行为外推。
- **Probe 的构念效度**：探针训练数据中，同一内容被不同标签包裹；标签可能改变 attention/tokenization/位置，从而在 content hidden state 中留下与风格相关的差异。零样本与收敛性证据很强，但没有 control task（如 shuffled labels、random tags）报告；线性探针也可能读取“与标签相关的风格”而不是“角色概念”。论文引用 Hewitt & Liang (2019) 的 control task 传统，但没有实际报告 control-task 基线（本人推断）。
- **因果链条不完整**：destyling 是输入层干预，不是表示层干预；没有直接 steer/ablate 角色方向看 ASR 是否变化。因此“style → role confusion → ASR”的中间环节仍是相关性 + 输入干预，不是严格的表示因果。
- **剂量-反应有混淆**：不同攻击的 query 危害性、长度、语义说服力不同；CoTness 高的攻击可能本来就更强。论文没有在 Figure 9 中控制这些变量；App J 的回归只控制 declared role，不控制内容。Fig.9 的 95% CI 也只覆盖采样噪声，不覆盖攻击难度。
- **Judge 与生成器同源**：chat 的伪造 CoT 由 Gemini-2.5-Pro 生成，ASR 也由同一模型 judge（p.14–15）；agent judge 也是 Gemini-2.5-Pro。虽然作者报告换 judge 在 200 样本上一致，但没有人类标注，独立 judge 检查也仅限少量模型与 200 样本；同源偏好可能影响 ASR 绝对值（本人推断）。
- **样本量与置信区间**：每个模型 chat 313 条、agent 100 条；除 Fig.9 外没有逐模型 CI。模型间几个百分点的差异（如 GPT-5 nano 34% vs mini 52%）不宜过度解释。
- **Agent 环境过于 toy**：单 bash、`.env`、Wikipedia、dpaste.com；没有真实企业 Agent 的权限、DLP、egress filter、MCP、memory、多 Agent。实际部署中，`curl` 外传可能被网络策略阻断；论文没有评估这类系统层防御（本人推断）。
- **攻击模板有限**：212 个模板都围绕同一固定 exfiltration 命令；没有针对不同任务（发邮件、改文件、调用 API）的泛化实验；没有多轮渐进攻击。
- **自适应攻击缺失**：没有攻击者知道 probe/检测器后优化逃避的实验；因此 probe-based detection 的鲁棒性未知。
- **“60%”被平均掩盖**：Abstract 的 60% 是六模型均值，GPT-5 只有 17%；如果读者把 60% 当成“所有前沿模型”的下限，会高估攻击的普适性。
- **“Role confusion”是隐喻**：论文没有给 role confusion 一个可证伪的充要定义；probe 分数高不等于模型“相信”文本是自己的推理，可能只是表示空间重叠。论文用行为 ASR 做收敛验证，但构念仍有解释空间（本人推断）。
- **Dual-use/影响声明**：论文公开了可复现的攻击代码与详细 prompt，Impact Statement 只说“advance ML”，没有讨论滥用风险或负责任披露；这在安全研究论文中是一个治理缺口（本人推断）。

## 10. 与理论密码学的可能联系（严格；没有就写“无”）

**论文实际使用的理论工具：无密码学。**

- 论文没有定义安全游戏、攻击者优势、计算假设、归约或定理；没有加密、签名、MAC、承诺、零知识、MPC、FHE、TEE、匿名凭证等原语。唯一的“形式化”是：
  - 角色由标签定义的标注约定（p.5, §4.1）；
  - 线性探针 `P_ℓ(r | h)` 与 `CoTness := P(CoT | h)`（p.5；p.25）；
  - 逻辑回归、AUC、bootstrap CI 等统计工具（p.30–31）。
- **“Authentication”不是密码学认证**：§4.2 的“How Models Authenticate Roles”指模型从风格推断角色；模型没有密钥、没有验证算法、没有可信第三方。论文的核心结论恰恰是这种“认证”可被文风伪造。Saltzer & Schroeder (1975) 只在开头被引为“control of influence”的系统安全思想，没有使用其保护机制或任何密码构造（p.1, §1）。
- **Related Work 中的“provable defense”**：MELON（Zhu et al., 2025）标题含“provable defense”，但本文没有使用、实现或评估 MELON；不能把 MELON 的可证明性算作本文贡献（p.8, §6；p.12 参考文献）。

**个人推断（明确标为推断，不是论文已做）：**

- **角色不可区分性游戏**：若要把 role confusion 写成可检验的定义，可构造一个统计游戏：挑战者随机选真实角色 `r` 与内容 `x`，敌手输出 `x'`（可带任意标签 `r'`），模型 `M` 与探针 `P`；定义
  `Adv_role = |Pr[P(M(x', r')) = r] - Pr[P(M(x', r')) = r']|`。
  这能衡量“标签与感知的分离度”，但没有密钥、没有计算假设、没有验证者，**不是密码学安全定义**；它更像一个表示层评测指标。若把它做成 benchmark，属于 ML 安全/可解释性研究，不是密码学理论。
- **密码学来源认证能否修复 role confusion？** 只能修“通道”，不能修“感知”。签名/消息认证码可以认证“这段文本确实来自工具 T/用户 U”，但模型看到的是 token；签名验证在模型外部完成，验证结果最终仍要以文本/元数据形式进入上下文。论文的证据是：即使有明确的 `<tool>` 标签，推理风格文本仍获得高 CoTness（p.6, Table 1；p.22, Table 3b）。因此，**签名的 role label 不能改变模型对语气的感知**；它只能让外部 reference monitor 决定“是否允许这段文本进入模型上下文”或“是否允许随后的工具动作”。前者是系统隔离，后者是能力/权限执行，都不是密码学在模型内部修复角色混淆。
- **理论密码学相关度判断**：按项目 `T_crypto` 量表，本文正文约 **1**（可类比“来源认证/权限边界”的系统安全概念，但没有密码学定义、原语或证明；核心是 ML 表示分析）。若额外做“角色不可区分性”的形式化，可能到 2，但那是新增研究，不是本文贡献。此判断为本人推断。

## 11. 与应用密码学/密码工程可能的技术连接（严格；没有就写“无”）

**论文实际使用：无。**

- 没有 OAuth/OIDC、签名、TLS、TEE、capability token、审计日志、密钥管理或任何密码协议。Agent 的 bash 与 `curl` 没有任何权限约束；`.env` 是明文文件，外传 endpoint 是公开 paste 服务（p.15–16, App B；p.29, Fig.29）。
- 防御完全在**语义/模型层**：role probes、prompt/标签、检测建议；不是 reference monitor，不能提供不可绕过的执行约束。

**个人推断的工程接口（均标为推断，需新增设计与实验）：**

1. **动作边界的能力令牌/egress 策略（最直接）**：在 tool gateway 对 `curl`/网络调用实施 allowlist 与 capability（UCAN/Biscuit/Macaroons 风格），对 `.env` 读取要求额外 capability。即使模型被 role confusion 骗过，外传动作也会被确定性阻断。作用：直接封死本文 agent 攻击的“最后一步”；局限：不解决 chat jailbreak/有害内容，也不解决“合法工具被滥用”的语义问题。
2. **签名工具输出 + 结构化通道**：MCP server 对 tool result 签名，gateway 验证后放入一个模型可见的“已验证工具输出”结构；未验证内容不得进入同一通道。作用：让“来源”可验证，减少冒充；局限：如 §10 所述，模型仍按风格感知，签名标签本身是另一个可被模仿/忽略的标签。必须配合“未验证内容根本不进入模型上下文”或“进入时被强制引用/转义”的系统约束。
3. **CoT 来源隔离**：如果模型自己的 CoT 由服务端生成，可在 API 层打“model-generated CoT”标记，并在进入下一轮上下文前剥离 user/tool 通道中任何声称是 CoT 的文本。作用：阻断 CoT Forgery 的“伪造推理”通道；局限：会误伤合法的“请分析这段推理”请求，需要细粒度策略；且模型仍可能把普通风格文本当成 CoT。
4. **TEE/远程认证**：保护 agent runtime 与工具调用的完整性，防止宿主被攻破；对 prompt injection 本身无直接作用。作用：保护密钥、日志、模型权重；局限：模型仍然会读不可信文本，TEE 不改变语义层攻击。
5. **签名审计日志/透明日志**：记录 `(tool, output_hash, action, destination, timestamp)`，用哈希链/签名保证不可抵赖；用于事后取证与泄漏归因。作用：检测与问责；局限：事后，不预防；日志完整性不等于披露适当性。
6. **MCP/Tool Gateway 的混合架构**：把 role probes 作为“建议层”（检测可疑角色混淆），把 capability/egress 作为“执行层”（确定性阻断），把签名日志作为“审计层”。这是最适合密码工程团队落地的组合；但需要新的策略语言、凭证生命周期、性能实验，论文没有做。

**伪交叉警告**：

- 只给 role label 签名：认证的是标签，不是文风；模型仍可能给签名 `<tool>` 块里的推理文本高 CoTness。
- 只加 OAuth/把工具包进 Agent：不解决“模型把工具输出当用户命令”的语义问题；攻击者可在合法 scope 内诱导外传。
- 用 ZK 证明“模型运行了某步”：证明计算完整性，不证明角色感知正确；LLM 是概率性的，证明不覆盖语义。
- 加密上下文/记忆：若模型需要解密后推理，明文仍进入上下文；加密只保护静态/传输。
- 把 role confusion 当密码学身份问题：模型没有密钥/验证器；“认证”是比喻，不是可形式化的协议。

**应用密码学相关度判断**：按项目 `A_crypto` 量表，本文正文约 **0–1**（没有识别任何密码机制使用点；agent 的“授权”只是环境预设）；若把上述 capability/egress + 签名工具输出 + 审计做成可运行原型并量化安全/性能收益，可到 2–3，但属于新增系统研究，不是本文贡献。此判断为本人推断。

## 12. 可检验的研究假设（3–6 条）

以下均为**假设/推断**，需查证外部文献；本文未做，不等于无人做过。

- **H1（能力边界优于角色标签）**：在本文 agent 环境中，若在 tool gateway 增加 egress allowlist 与 `.env` 读取 capability，即使保留 CoT Forgery 注入，exfiltration ASR 应从 56–70% 降到接近 0；代价是合法任务（需要访问任意网页/上传）的完成率下降。实验：2×2（capability on/off × CoT Forgery on/off），1000 次注入模板，测 ASR、任务成功率、误阻断率。
- **H2（probe 检测的 ROC 与误报）**：用 user/tool 通道文本的 CoTness/Userness 阈值，或“解析标签 vs probe 感知”的差异，能否在生成前检测 CoT Forgery 与标准注入？需在 held-out 攻击与良性“用户引用/分析一段推理”的请求上测 ROC/AUC、固定 TPR 下的 FPR。预测：攻击检测 AUC 高，但良性引用推理的误报率不可忽略；误报率是关键部署障碍。
- **H3（表示层干预的因果性）**：若能定位并 steer/ablate 角色方向（例如把 forged CoT 的 CoTness 压到 user 子空间），ASR 应显著下降，同时模型在正常任务上的 CoT 使用不受损。实验：在 gpt-oss-20b 上做 representation steering，测 CoTness、ASR、以及正常推理任务（如 GSM8K/MMLU）准确率；这是对论文“style → confusion → ASR”因果链的直接检验，论文未做。
- **H4（跨语言/跨风格泛化）**：CoT Forgery 的风格线索是否语言特定？把 forged CoT 翻成中文、代码混合或低资源语言，ASR 与 probe CoTness 是否仍高？预测：若机制是“风格→角色子空间”，则目标语言中若模型有对应 CoT 风格，攻击仍有效；若风格不匹配，ASR 下降。实验：中英双语 StrongREJECT 子集 + 中文 agent 任务，测 ASR 与 CoTness。
- **H5（位置/系统提示的防御）**：在 system prompt 后重复插入 system 标记或周期性重申，能否提高后段 token 的 Systemness 并降低 IH 失败率？实验：用 Geng et al. 160 条冲突指令，比较“仅开头 system”“每 N token 重复 system 标记”“结构化 system 通道”三种条件，测 Systemness 曲线与 user-override 率；论文 Figure 32 只说明位置主导，没有测试缓解。
- **H6（自适应攻击 vs probe 检测）**：若攻击者知道 probe 存在，能否通过拆分 forged CoT、短片段注入、风格迁移或加入 benign filler 来降低 CoTness 而保持 ASR？实验：在已知 probe 的白盒设定下做梯度/黑盒搜索，测 ASR–CoTness 帕累托前沿；若攻击者能把 CoTness 压到低分位而 ASR 仍高，则 probe-based detection 不是可靠防御。
