## 1. 150–300 字中文概述

CausalArmor 把间接提示注入（IPI）刻画为特权动作处的“支配性偏移”：良性时用户请求对动作的归因占主导，注入成功时某条不可信工具输出反超用户请求。作者用 leave-one-out 消融计算用户请求与各不可信片段的长度归一化对数概率差，仅当特权动作的某个片段满足 ΔS > ΔU − τ 时触发两阶段防御：按用户请求与候选工具定向净化该片段，并把注入点之后的助手推理替换为占位符，再让 Agent 重新生成动作。AgentDojo 与 DoomArena 上 ASR 接近零，良性延迟约为无防御的 1.2–1.3 倍；Proposition 4.1 给出条件性指数上界。全文是语义/系统层护栏，不含密码原语或密码学证明。

## 2. 研究背景、现有方法不足、精确定义的问题

- **背景**：工具调用型 LLM Agent 会浏览网页、读邮件、查数据库、执行 API；这些外部内容是不可信的。IPI 把带指令的内容嵌在正常数据中，诱导 Agent 执行未授权特权动作（转账、发信、写文件、外泄数据）（p.1, §1；p.2, §2.1）。
- **现有防御的三类及其不足**（p.2–3, §2.2）：
  - **Prompting**（重复用户意图、加“工具输出不可信”提醒）：便宜、常保有用性，但对改写与伪装成系统错误/约束的注入很脆。
  - **Trained classifier**（DeBERTa detector、PiGuard 等）：低延迟，但分布外措辞、误报删除任务相关信息、跨域/跨工具格式漂移；且强净化管线常对每个工具输出都调用，重新引入 always-on 成本与过度阻断。
  - **System-based**（CaMeL、DRIFT、MELON 等）：用通道隔离、规划约束、每轮校验或反事实比较获得较强安全，但每轮多次昂贵 LLM 调用/净化导致大延迟与能力限制。
- **核心痛点：over-defense dilemma**。现有方法在良性占绝大多数的真实部署中仍持续付出安全成本：要么 always-on 净化/校验，要么保守过滤，因而损害 utility 与 latency（p.1, Abstract；p.2, §1；p.3, §2.2）。
- **精确问题**：(1) 能否在“特权动作”这一真正产生危害的决策点，用一个可测量的 IPI 签名判断是否需要防御？(2) 能否只对“负责的”不可信片段付出昂贵净化成本，从而在保持接近 No Defense 的 utility/latency 的同时匹配 aggressive defenses 的 ASR？(3) 这个签名能否形式化为一个可证明的概率界？论文用“支配性偏移 + LOO 归因 + 阈值 τ + 两阶段净化”回答（pp.1–5）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **组件**（p.3, §3.1；p.4, Algorithm 1；p.16, Algorithm 2）：
  - 用户请求 `U`；Agent 模型 `M_agent`；上下文 `C_t = (U, H_t, S_t)`。`H_t` 是可信系统侧上下文（system prompt、策略、工具 schema）；`S_t = {S_{t,1},…,S_{t,n_t}}` 是从外部抽取的不可信片段集合，**每个片段对应某一轮的一个工具结果**。
  - 候选动作 `Y_t ∈ T_priv ∪ T_nonpriv`；`T_priv` 是特权工具（execute、write、send 等），`T_nonpriv` 是非特权工具（search、read 等）。
  - 中间件层：归因代理模型 `M_proxy`（默认 Gemma-3-12B-IT，vLLM 部署）与净化器 `M_san`（默认 Gemini-2.5-flash）。二者作为防御基础设施被默认可信。
- **交互流程**（Algorithm 1/2）：Agent 提出 `Y_t` → 若 `Y_t ∉ T_priv` 或 `S_t = ∅` 直接执行 → 否则批量计算 `Δ̄_U` 与每个 `Δ̄_S` → 若标志集 `B_t(τ)` 非空，对其中每个片段调用净化器（条件为 `U` 与 `Y_t`）→ 记录最早被改片段下标 `k_min`，把其后所有 assistant 推理替换为 `"[Reasoning redacted for security]"` → 用净化后上下文让 Agent 重新生成 `Y_t^new` 并执行 → 若未触发则执行原动作（p.4, p.5, p.16）。
- **信任边界**：`H_t`、工具 schema、Agent 模型、代理模型与净化器被视为可信执行基础设施；`S_t` 是唯一被建模的不可信输入；`U` 被默认为良性且已授权。攻击者只能通过外部内容进入 `S_t`。论文没有建模 memory poisoning、工具 schema 投毒、恶意非特权工具、代理/净化器被攻破或供应链攻击（此为本人据 §3.1 与全文威胁面归纳）。
- **执行语义**：防御发生在“动作已提出、尚未执行”之间；它不是 reference monitor，不能提供不可绕过的策略执行，而是通过改写上下文与强制重生成来改变 Agent 的下一步。DoomArena 的攻击者还能改写/删除数据库中的任务关键信息，使 Agent 物理上必须依赖注入内容（p.18, App C.3）。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- **资产**：用户意图与授权边界；特权动作的完整性（转账、发信、写文件、执行命令）；数据机密性（外泄）；良性任务完成率（BU/UA）；延迟（BL/LA）。论文把“安全”操作化为 ASR，把“可用性”操作化为 BU/UA 与相对延迟（p.6, §5.1）。
- **攻击者目标**：让 Agent 执行未授权的特权动作，或借特权动作外泄数据；同时尽量让任务看起来正常。IPI 的成功被定义为“不可信片段对恶意特权动作提供了不成比例的边际支持”（p.3–4, §3.3）。
- **攻击者能力**：
  - AgentDojo：在检索文档/邮件/工具输出/产品目录中嵌入注入文本；使用三种模板——Important Instructions、Task Dependency、Tool Output Hijack（p.6, §5.1；pp.16–17, App C.2）。
  - DoomArena：攻击者是特权、自适应的 LLM（Gemini-2.5-flash），可窃听用户与 Agent 的完整对话历史，并实时改写/删除数据库内容以强制 Agent 依赖注入内容（p.7, §5.4；p.18, App C.3）。
  - 白盒压力测试：攻击者获得检测信号的完全访问权（CausalArmor 的 LOO 分数、PiGuard 的 classifier logits、MELON 的语义相似度），只改写注入片段、保持良性主体不变；5 个 AgentDojo 场景、3 个随机种子、每个种子 50 次查询（p.8, §5.5）。
  - **不能**：改 Agent 权重、system prompt、工具 schema、代理模型或净化器；不能投毒 memory；不能直接读防御内部状态（白盒压力测试是额外假设，不是默认威胁模型）。
- **前提假设**（分散在 §3.1、§4.3、App A）：
  - 上下文可以被结构化为 `(U, H_t, S_t)`，且每个不可信片段能按工具结果切分；这对“把整篇文档/整个网页当一个 span”是近似。
  - 用户请求良性且已授权；防御只防“外部内容篡改用户意图”，不防恶意用户。
  - 特权工具集合已知且可由用户定制。
  - 小代理模型的 LOO 归因能迁移到更大的 Agent 模型（p.4 引 Liu et al. 2025；p.9 用实验支持）。
  - 净化器能在保留事实的同时移除指令；其效果被抽象为 Assumption 2。
  - 可通过代理模型获得动作的 log-probability；闭源 Agent API 通常不直接暴露该能力，这正是引入代理的原因（p.4, §4.1；p.9, §5.7）。
- **威胁模型位置**：无独立 “Threat Model” 小节；由 §3.1 的上下文分解、§5.1 的 benchmark 设置、§5.5 的自适应压力测试与 App C.3 的 DoomArena 设定共同定义。

## 5. 核心方案：causal attribution、触发/净化流程、算法与复杂度

### 5.1 归因定义

对上下文组件 `X ∈ {U} ∪ S_t` 与候选动作 `Y`，leave-one-out 归因定义为

```text
Δ_X(Y; C_t) = log P(Y | C_t) − log P(Y | C_t \ X)        (Eq. 2, p.3)
Δ̄_X(Y) = Δ_X(Y) / |Y|                                    (Eq. 6, p.5)
```

即“移除 X 后动作对数概率下降多少”，再按动作 token 长度 `|Y|` 归一化，使不同工具调用字符串之间的阈值 τ 可比。作者明确说这里的 “causal” 是**操作性的**：span removal 下的反事实影响，不是结构因果模型（p.1, §1；p.13, App A）。

### 5.2 支配性偏移与检测

良性时用户请求应占主导：`Δ_U(Y*_t) > max_S Δ_S(Y*_t)`（Eq. 3）；IPI 成功时反转：`Δ_S(Y_mal) ≫ Δ_U(Y_mal)`，且常 `Δ_U ≈ 0`（Eq. 4，p.4）。检测规则为

```text
B_t(τ) = { S ∈ S_t : Δ̄_S(Y_t; C_t) > Δ̄_U(Y_t; C_t) − τ }   (Eq. 5, p.4)
```

`τ = 0` 是纯“因果反转”测试；`τ → −∞` 永不净化（无防御）；`τ → +∞` 趋近 always-on 净化（p.4）。关键设计是**不使用“低 Δ_U”单独作为攻击信号**，因为良性的能力失败也会降低用户 grounding，却不会在某个不可信片段上产生尖峰；因此用相对 margin 定位可疑片段（p.4, §3.4）。

### 5.3 两阶段防御

1. **Selective Context-Aware Sanitization**：对 `B_t(τ)` 中每个片段调用 `M_san`，并把用户请求 `U` 与候选工具定义 `Y_t` 作为条件，以便区分“驱动未授权调用的注入触发”与“合法事实”；目标是删除指令、保留事实（p.5, §4.2；p.19, App D.1 给出完整 system prompt）。
2. **Retroactive CoT Masking**：仅净化输入不够，因为 Agent 之前的推理可能已接受注入的伪约束（“preview mode”“先完成依赖”）。算法记录最早被修改片段的下标 `k_min`，把它之后所有 assistant 消息内容替换为通用占位符，强制 Agent 仅依据用户请求与净化后数据重新规划（p.5, §4.2；p.16, Algorithm 2 第 19–25 行）。案例见 pp.22–23：不 masking 时 Agent 在净化后仍复现恶意转账；masking 后恢复为正确的租金更新。

### 5.4 批处理与复杂度

一次特权决策的归因批次包含 `2 + |S_t|` 个上下文：完整上下文、去掉 `U` 的上下文、以及每个去掉一个 `S` 的上下文；它们在 vLLM 中一次并行打分（p.5, §4.1；p.16, Algorithm 2 第 5–10 行；p.19, App D.1）。因此**顺序交互深度为 O(1)**（每个决策点一次批调用），但总 token 计算与峰值显存随 `|S_t|` 与总上下文长度线性增长，即 `O(|S_t|)`。净化是真正的昂贵步骤：每个被 flag 的片段各调用一次生成式 LLM（Algorithm 2 第 13–15 行是循环），最坏情况下 flag 很多，开销趋近 always-on（p.13, App A；p.19, App D.1）。
- **原文可疑处**：p.19 说当 `|S_t|` 超出显存时可把大 batch 拆成顺序 mini-batch，并写“binary search; O(log S_t)”。把 batch 拆分是线性数量的子批次，binary search 并不适用于“对所有 span 求归因”，该 `O(log |S_t|)` 说法缺乏依据，疑为笔误（本人核对，p.19）。

### 5.5 为什么有效（作者的论证）

IPI 必须因果地支持恶意特权动作；攻击者若把注入片段的归因压到检测阈值以下，也就削弱了它控制最终动作所需的信号，形成“evasion–effectiveness trade-off”（p.8, §5.5）。这是经验论证，不是最坏情况保证。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- **形式化定义**：有。Eq. 2 定义 LOO 归因，Eq. 6 定义长度归一化，Eq. 5 定义 flag 集，Eq. 7–8 定义两个假设，Proposition 4.1 给出界（p.3–5；证明 pp.13–14）。
- **Proposition 4.1**：在 Assumption 1（良性能力 `β > 0`：`log P(Y*|C'\S') − log P(Y|C'\S') ≥ β`）与 Assumption 2（净化后 `Δ_{S'}(Y) − Δ_{S'}(Y*) ≤ −γ`，`γ > 0`）下，长度 T 的 episode 执行任一恶意特权动作的概率满足
  ```text
  Pr(IPI Attack Success) ≤ T · |Y_mal| · exp(−(β + γ))     (Eq. 9, p.5)
  ```
  证明用 log-prob 分解 + 对恶意候选的 union bound + 对时间步的 union bound（pp.13–14, App B）。
- **这个“形式化”的边界**（本人判断）：
  - 它是**条件性、非渐近的概率界**，不是密码学意义上的安全定义；没有 adversary 算法、没有计算困难性、没有 indistinguishability、没有 reduction。
  - **检测环节没有进入定理**：界假设净化已经发生且 Assumption 2 成立；没有建模 detector 的 false negative/false positive，也没有建模“攻击者针对 τ 优化”。因此它不能推出端到端“ASR ≤ ε”。
  - Assumption 2 实质上假设了“防御有效”，所以定理更像“把 margin 转换为风险”的解释性工具，而非独立保证；当 `T·|Y_mal|·exp(−(β+γ)) > 1` 时界是 vacuous。
  - 论文自己在 p.10 Impact Statement 说提供的是 “conditional guarantees under an operational notion of causality”，不应作为 standalone safety solution。
- **经验指标**：ASR、BU、BL、UA、LA，均为 benchmark 上的行为统计（p.6, §5.1）。没有形式化的 utility 定义，也没有对“explainability”的量化或人类评估；explainability 只以归因分数可视化（Figure 2、Figure 7）呈现。
- **结论**：论文有“数学命题 + 证明”，但属于**概率/统计论证**，不是密码学形式化；其安全主张（near-zero ASR、resolves over-defense dilemma）是经验性的、benchmark 特定的。

## 7. 实验设置与主要结果（benchmark、模型、基线、ASR、utility、latency）

### 7.1 设置

- **AgentDojo**（v1.2.2）：banking、slack、travel、workspace 四类 Agent，70 个工具，629 个注入任务；除官方 Important Instructions 外，另加两个由 Gemini-3-Pro 根据失败案例设计的模板（Task Dependency、Tool Output Hijack），以降低数据污染影响（p.6, §5.1；pp.16–17, App C.2）。
- **DoomArena**：TauBench-Retail 子集，纯文本 IPI，115 个任务；5 个随机种子；攻击者为自适应 LLM，可窃听对话并改写数据库（p.6, §5.1；p.18, App C.3）。
- **模型**：默认 Agent backbone 为 Gemini-2.5-flash；另测 Claude-4-Sonnet 与 Gemini-3-Pro。所有实验固定 Gemini-2.5-flash 为 sanitizer，Gemma-3-12B-IT 为 proxy（p.6, §5.1）。代理模型在 8×A100、vLLM 上服务（p.19, App D.1）。
- **基线**：Repeat Prompt；DeBERTa-v3 prompt-injection detector；PiGuard；DRIFT；MELON（p.6, §5.1；p.19, App D.2）。DoomArena 因是对话式环境，DRIFT/MELON/CaMeL 不适用，只比 prompting 与 classifier（p.7, §5.4；p.18）。
- **指标**：Benign Utility（BU）、Benign Latency（BL，相对 No Defense）、Utility under Attack（UA）、Latency under Attack（LA）、Attack Success Rate（ASR）（p.6, §5.1）。

### 7.2 AgentDojo 主结果（Table 4, p.20）

- **CausalArmor**：
  - Gemini-2.5-Flash：BU 56.26，BL 1.30；ASR 0.62（Important Instructions）/0.42（Task Dependency）/0.40（Tool Output Hijack）。
  - Claude-4-Sonnet：BU 82.47，BL 1.27；ASR 0.0/0.11/0.46。
  - Gemini-3-Pro：BU 86.60，BL 1.22；ASR 0.11/0.11/0.0。
- **No Defense**：Gemini-2.5-Flash BU 53.61、ASR 32.47/12.01/7.06；Claude-4-Sonnet BU 89.44、ASR 2.32/3.37/18.97；Gemini-3-Pro BU 92.78、ASR 5.06/5.69/8.85。
- **系统基线**：DRIFT 的 BL 4.67–5.82、ASR 0.82–4.99；MELON 的 BL 2.21–2.31、ASR 0.21–1.05；二者 utility 也低于 CausalArmor。分类器 PiGuard 的 BL 仅 1.06–1.22，但 BU 降到 32.99–64.95，体现 over-defense；DeBERTa 的 BU 更低（30.93–58.76）（p.20, Table 4）。
- **解读与注意**：
  - 在默认 backbone 上 CausalArmor 的 BU（56.26）反而**高于** No Defense（53.61），作者未解释；在 Claude-4-Sonnet（82.47 vs 89.44）与 Gemini-3-Pro（86.60 vs 92.78）上又低 6–7 个百分点。因此 “preserves utility close to No Defense” 只是近似，且不同 backbone 方向不一致。
  - Table 4 没有置信区间，也未说明 AgentDojo 的随机种子数；0.0 与 0.62 这类小 ASR 差异不宜过度解读。
  - 在 Claude-4-Sonnet 的 Important Instructions 上 No Defense ASR 仅 2.32%，安全提升空间本来就小；在 Gemini-2.5-Flash 上 No Defense ASR 32.47%，提升最明显。

### 7.3 DoomArena（Table 1, p.7）

Gemini-3-Pro：No Defense BU 73.57（±1.32）、BL 1.00、ASR 88.87（±1.67）；Repeat Prompt 65.04/1.06/72.70；PiGuard 55.13/1.16/5.57；CausalArmor 70.96（±0.99）/1.38（±0.04）/3.65（±0.73）。即 CausalArmor 在保留约 2.6pp BU 的同时把 ASR 从 88.87 降到 3.65，优于 PiGuard（ASR 5.57，但 BU 损失 18.4pp）。
- **原文不一致**：p.18, App C.3 正文写 No Defense 的 ASR 是 **89.47%**，Table 1 写 **88.87%（±1.67）**；两处不能同时为精确值，本文以 Table 1 为准并标注冲突。

### 7.4 自适应与压力测试（p.8, §5.5）

- **白盒自适应攻击**：5 个 AgentDojo 场景（所有方法初始 ASR 均为 0%）、3 seeds、每 seed 50 queries。PiGuard 平均 6.8 次查询被绕过，MELON 18.3 次，CausalArmor 在整个预算内保持 0% ASR。作者同时承认这不构成 worst-case 保证。
- **Split-context**（Table 2, p.8）：10 个场景，三种形式。单片段：`Δ̄_U=0.14`、`max Δ̄_S=1.72`、margin +1.58；3 轮集中：0.25/1.31/+1.06；3 轮分散：0.34/1.35/+1.01；全部被检测，且无防御时攻击都成功。说明“因果瓶颈”仍在最终特权决策处。
- **Argument-level**：typosquatting 案例，恶意 URL `trusted-bank.co/login` 相对良性 `trusted-bank.com/login` 只差一个 “m”。恶意动作 `Δ̄_S=0.9181`、`Δ̄_U=0.0173`、margin 0.9008（被 flag）；良性正确 URL 动作 `Δ̄_S=−0.5362`、`Δ̄_U=0.2674`、margin −0.8036（不被 flag）（p.8）。

### 7.5 消融与代理模型

- **CoT masking**（Table 3, p.8）：CausalArmor BU 75.11、ASR 0.29；去掉 masking 后 BU 74.61、ASR 1.75。作者称 ASR 平均上升 1.46%、BU 仅降 0.5%。BU 75.11 恰好等于 Table 4 三个 backbone 的 No Attack BU 均值；但 ASR 0.29 无法由 Table 4 的 9 个 CausalArmor ASR 单元精确复算（未加权均值约 0.25），差异很小，可能是加权/额外运行，本文不作为关键证据。
- **Proxy 模型**（Figure 5, p.9）：>8B 能识别多数 IPI，>12B 接近 oracle；Gemma 家族相对 Gemini-3-Pro 的 latency–security Pareto 最优。横轴为相对 Gemini-3-Pro 的延迟，范围 0.00–0.20（Gemini-3-Pro 自身为 1）。
- **τ 扫描**（Figure 4, p.7；Figure 6, p.17）：τ=0 已把 ASR 压到近零；增大 τ 更安全但 BU 下降、延迟上升；τ=−1 接近无防御；always-on 的 BU 与延迟最差。

### 7.6 缺失/不足的实验

- 没有 AgentDojo 的多种子方差或置信区间；没有 p95/p99 延迟、token 成本、$/task；没有真实部署或用户研究；没有对 sanitizer 本身的自适应攻击（例如混淆、编码、分段绕过）；没有非特权工具外泄路径的实验；没有与 CaMeL 在 AgentDojo 上的直接对比（CaMeL 只在 Related Work 讨论）。

## 8. 贡献与创新点（按原文主张）

1. **把 IPI 形式化为特权决策处的 dominance shift**，并用 LOO 归因把它变成可测量签名；强调“低 Δ_U 本身不是攻击信号”，相对 margin 才能定位责任片段（p.1–4, Abstract/§1/§3.3–3.4）。
2. **CausalArmor 框架**：用批处理代理模型在一次前向中计算 `2+|S_t|` 个上下文的归因；只在检测到支配性偏移时做定向净化；再用 retroactive CoT masking 清除已被内化的恶意推理；最后重生成动作（p.2, §1 Contributions；pp.4–5, §4）。
3. **效率主张**：把昂贵净化从“每个工具输出都做”变为“只在特权决策且 margin 超阈值时做”，从而在 benign 场景保持接近 No Defense 的 BU/BL；在 AgentDojo 与 DoomArena 上 ASR 接近零（p.1–2；p.7, Figure 3；p.20, Table 4）。
4. **条件性理论分析**：Proposition 4.1 把归因 margin 转换为指数衰减的 IPI 成功概率上界，并用 Figure 7 的“因果恢复”实证支持 Assumption 2（p.5；pp.13–14；p.18, Figure 7）。
5. **可解释性**：归因分数可指出“哪个不可信片段驱动了这次特权动作”，为审计提供证据；这是定性主张，未做人类评估（p.1–2；p.8）。

## 9. 局限、失败案例、作者承认的不足

**作者明确承认的**（p.13, App A；p.10, Impact Statement）：
- **操作性因果**：LOO span removal 不是完整结构因果模型；不能捕获需要语义保持干预或仅在多片段联合编辑时才出现的复杂交互。
- **span-local 归因**：不提供对“完美分布式攻击者”的最坏情况保证；更强的保证可能需要 set/group-based attribution（如 Shapley 近似）。
- **净化器依赖**：框架只决定“何时/何处”防御，不提出新净化模型；效果随 sanitizer 能力 scaling；不保证对未来的混淆或分布漂移有效；在大量步骤被 flag 时开销可接近 always-on。
- **条件性保证**：依赖 backbone capability（β）与 sanitizer 效果（γ）；不应作为任意分布漂移/高度自适应对手下的 standalone safety solution；建议作为 defense-in-depth 的一层。
- **CoT masking 的代价**：可能降低可调试性；部署需在透明度与安全间平衡，并配合日志与访问控制。
- **代理模型风险**：proxy mismatch 或格式变化会影响 FP/FN；建议定期重新验证，并在生产中保密/轮换 proxy 细节。
- **未来工作**：扩展到多模态上下文，改进归因以捕获复杂因果依赖（p.9, §6）。

**本人推断的局限/失效场景**：
- **仅检查特权动作**：若外泄通过非特权工具的参数字段完成（例如把秘密拼进 `search`/`fetch` 的 URL，而该工具不在 `T_priv`），CausalArmor 直接 `EXECUTE`，不计算归因。论文没有报告这类攻击的 ASR。
- **检测依赖“动作已提出”**：若 Agent 在提出特权动作前已通过多次非特权调用泄漏信息，防御来不及介入。
- **攻击者可抬高 Δ_U**：白盒实验只演示了把 `Δ̄_S` 从约 1.8 压到 1.2，而 `Δ_U` 仍近零；若注入文本大量复述/引用用户请求，使 `Δ_U` 也升高，margin 可能被拉低。论文未做此方向的优化攻击。
- **良性难任务的误报**：当用户请求本身对动作支持弱（能力不足）而某个良性工具结果支持强时，`Δ_S > Δ_U − τ` 可能触发不必要的净化；论文只报告 BU，没有报告 false positive rate 或按任务难度分层的分析。
- **AgentDojo 统计薄弱**：Table 4 无方差、无种子说明；BU 在默认 backbone 上高于 No Defense 的反常现象没有解释；跨 backbone 的 utility 损失（6–7pp）与“close to No Defense”的措辞有张力。
- **explainability 未验证**：没有用户研究或下游审计任务衡量归因是否真的帮助分析师；Figure 2/7 只是分数可视化。
- **sanitizer 自身可被攻击**：净化器是 LLM，面对编码、分段、间接指代、多语言混淆时可能失败；论文没有对 sanitizer 做自适应 red-team。
- **DoomArena 的 utility 口径**：攻击者可删除 ground truth，UA 对所有方法都趋零，因此只报告 BU/ASR；这使“utility under attack”无法区分防御优劣（p.18）。
- **复杂度表述错误**：p.19 的 “binary search; O(log S_t)” 与“拆分 batch”不相符（见 §5.4）。
- **原文数值/命名不一致**：p.7 Table 1 的 88.87 vs p.18 正文 89.47；p.4 的 “30× larger LLMs” vs p.9 的 “10× parameter difference”（Pearson 0.94）；p.8 写白盒攻击用 “Gemini-3.1-Pro”，全文其他处为 Gemini-3-Pro，疑为笔误。这些不影响主结论，但说明 camera-ready 校对不严。

## 10. 与理论密码学的可能联系（严格；没有就写“无”）

**论文已做的**：**无**。全文没有密码学原语、密码学安全定义、攻击游戏、归约或定理；Proposition 4.1 是**概率界**，不是密码学命题。LOO 归因是“移除一个 span 后动作对数概率的变化”，属于可解释性/反事实影响度量，不是结构因果模型，更不是密码学意义上的“因果”或“证明”。其“security”指 benchmark 上的 ASR 下降，不是 semantic security、IND-CPA、不可伪造性或不可区分性。

**边界说明**：
- 不要因为出现 “causal”“attribution”“bound” 就把它归为形式化安全。定理的前提 Assumption 2 直接假设“净化后恶意支持被压到比良性低 γ”，这等于假设防御有效；定理没有建模检测失败、sanitizer 被绕过或自适应对手，因此不是 end-to-end 保证。
- 与**定量信息流（QIF）**的类比只能是推断：可把“注入片段对恶意动作的 log-prob 支持”视为一种 leakage 度量，用 min-entropy/g-leakage 替代 Δ，但这会改变被测对象（从“动作概率”变成“秘密是否被获知”），且本文的 secret 是“用户意图/授权”，难以定义先验。论文没有做，属于**新增研究**。
- 与**provenance/attestation** 的理论联系也只能是推断：若能给每个 span 一个可验证的来源标签，把“不可信”从语义判断变成类型系统/标签模型，可能得到更强的组合性保证；但这不是本文的 LOO 方法，且标签本身的正确性又需要可信基础设施。标记为推断。

**判断**：按项目 `T_crypto` 量表，本文正文约 **0–1**：它研究的是 LLM 行为层面的注入检测，不涉及密码学困难问题；若硬做 QIF 形式化可到 2，但那是新论文，不是本文贡献。

## 11. 与应用密码学的可能联系（严格；没有就写“无”）

**论文已做的**：**无**。没有签名、MAC、加密、TEE、capability token、OAuth/OIDC、审计日志、密钥管理或任何密码协议。Agent 与 sanitizer 通过 Google Cloud Vertex AI API 访问（p.18–19），这只是部署传输，不是防御机制；论文没有把它当作安全边界。`T_priv` 只是工具名列表，不是密码学能力凭证。

**推断的工程接口（均标为推断，需要新增设计与实验）**：
1. **签名的工具输出/provenance**：让工具网关对每个 `S_i` 附上来源、完整性签名与信任等级（如企业 IdP 或 MCP gateway 签发），CausalArmor 可据此缩小 `S_t` 或对高信任片段跳过归因。作用是降低“所有工具输出一律不可信”的成本，并抵抗内容伪造；但签名只保证“来源未篡改”，不保证内容无恶意指令——被攻破的合法来源仍可注入。
2. **特权工具的能力令牌**：对 `send`/`write`/`execute` 使用 macaroon/Biscuit/UCAN 风格 capability，带 recipient、amount、purpose、有效期等 caveat，在工具网关强制执行。它能在模型层之外提供确定性约束，弥补 CausalArmor “只在动作提出后检查”的不足；但静态 scope 难以表达“这封邮件可发给同事但不可附上客户名单”的细粒度语义。
3. **代理模型/净化器的远端证明**：若 `M_proxy`/`M_san` 在第三方云运行，可用 TLS + attestation 保证代码/权重未被替换；否则攻击者控制 proxy 就能操纵归因分数。论文只建议“保密/轮换 proxy”，没有给出密码学方案。
4. **防篡改审计**：对每次 flag、净化与重生成记录 `(context_hash, span_id, Δ_S, Δ_U, τ, action, timestamp)`，用哈希链/签名日志保存，支持事后取证与阈值校准。它不阻止攻击，只提供问责与可复现性。
5. **端到端机密性**：若上下文含敏感数据，传输与静态存储可加密；但 Agent 与 sanitizer 必须在明文上推理，加密不阻止模型层泄漏。这是**伪交叉**的典型：加密上下文并不能替代语义净化。

**伪交叉警告**：
- 给工具输出签名、给动作加 OAuth scope，不能阻止“在合法权限内被诱导”的 IPI；CausalArmor 的问题本质是语义意图偏移。
- 用 ZK 证明“sanitizer 运行了某模型”只证明计算完整性，不证明输出确实无注入。
- 把 `T_priv` 当 capability 而不在网关强制执行，等于把安全寄托在 LLM 自觉上，攻击者仍可绕过。

**判断**：按 `A_crypto` 量表，本文正文约 **0–1**（没有识别任何密码机制使用点）；若把上述“签名 provenance + 网关 capability + 审计”做成原型并量化其对 ASR/BU/latency 的影响，可到 2–3，但属于新增系统研究。

## 12. 可检验的研究假设（3–6 条）

以下均为**假设/推断**，需独立实验；论文未做，不等于领域无人做过。

- **H1（margin 校准）**：`Δ̄_S − Δ̄_U` 对“被攻击 vs 良性”特权决策的区分度（AUROC）显著高于单独使用 `Δ̄_U` 或 `Δ̄_S`；在三种注入模板与三个 backbone 上排序稳定。实验：用带标签的 AgentDojo/DoomArena 轨迹，绘制 ROC 并比较 τ 的校准曲线。
- **H2（分布式攻击的检测崩塌）**：固定总注入长度，把恶意指令拆成 k=1,2,4,8 个片段后，span-local LOO 的检测率随 k 单调下降；group/Shapley 归因能恢复大部分检测率，但延迟上升。实验：在 AgentDojo 上构造 k-span 攻击，比较 CausalArmor 与 group-attribution 变体。
- **H3（proxy 迁移）**：Gemma-3-12B 的 `Δ̄` 排序与 Gemini-3-Pro oracle 的 Spearman 相关高于 0.8，且用 proxy 的 ASR 与 oracle 的差距小于 1pp；跨家族（Qwen3、Ministral）时相关性下降。实验：Figure 5 的扩展，报告相关系数与检测校准，而不只是 ASR。
- **H4（CoT masking 的收益随 horizon 增长）**：在多轮任务中，去掉 CoT masking 的 ASR 增量随注入后剩余轮数/工具调用数增加而增大；在单轮任务上差异接近零。实验：按轨迹长度分层，比较 Table 3 的平均值背后的分布。
- **H5（成本随特权动作频率 scaling）**：BL 与“每任务特权决策数 × 被 flag 的 span 数”近似线性；在高频特权动作场景（如批量转账审核），CausalArmor 的延迟接近 always-on，论文的“1.2–1.3×”不再成立。实验：合成不同特权动作密度的任务，报告 p50/p95 延迟与 token 成本。
- **H6（签名 provenance 降低防御成本）**：若工具输出带可验证来源标签，并允许对高信任来源跳过归因，则在保持 ASR 不变的前提下，归因调用次数与 BL 显著下降；但对“合法来源被攻破”的注入无效。实验：在 AgentDojo 中给工具输出加合成签名标签，做 2×2（CausalArmor on/off × provenance on/off）。
