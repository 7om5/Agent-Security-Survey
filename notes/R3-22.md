## 1. 150–300 字中文概述

论文提出 A-MemGuard，一个不修改 Agent 核心架构的外部记忆安全层。它针对两个难点：恶意记忆单独看无害、只在特定查询上下文触发；被污染的结果又被当作先例存入记忆，形成自我强化的错误循环。方法分两部分：对每个查询检索 K 条记忆，各自生成结构化推理路径，由 LLM 裁判比较各路径与共识计划的一致性，剔除异常记忆；再把异常路径蒸馏为“教训”存入独立教训记忆，在执行前检索相似教训并迫使 Agent 修订计划。实验覆盖 AgentPoison 直接投毒、MINJA 间接注入、MMLU 问答和多 Agent 错误信息传播，报告 ASR 大幅下降且良性任务准确率总体保持。全文是语义层的经验防御，不含密码原语、形式化安全定义、定理或证明。

## 2. 研究背景、现有方法不足、精确定义的问题

- **背景**：LLM Agent 用记忆积累过去交互以支持长期规划、问答与多 Agent 协作（p.1–2, §1–§2）。记忆通常由检索函数 `R(qt, Mt, K)` 选出 top-K 记录 `Mr`，再与查询一起送入策略 `πθ` 生成计划（p.3, §3.1, Eq.1–2）。因此 `Mr` 的完整性成为单点故障，也是投毒攻击的入口（p.3）。
- **威胁的两个特性**（p.1–2, Abstract/§1）：
  1. **上下文相关**：恶意记录单独审计时看似合理，例如 “always prioritize urgent-looking emails”，只有在钓鱼邮件这一特定上下文中才显出危害；ASB 报告即使先进 LLM 检测器也漏掉 66% 的投毒记忆（p.2, §1，引用 Zhang et al. 2024）。
  2. **自我强化错误循环**：攻击先诱导一次错误决策，错误结果被当作有效记忆存储，之后作为“先例”反复强化，并逐步降低后续类似攻击的门槛（p.1–2）。
- **现有防御不足**（p.2–3, §2）：prompt filtering、alignment、perplexity detection、LlamaGuard、rephrasing 等大多做**孤立条目审计**，对“混合了正常内容、只在特定上下文触发”的投毒不敏感；PPL 过滤器会忽略 blended manipulation（p.3）。这些方法也没有利用 Agent 的交互历史来学习。
- **精确问题**（p.4, §3.3）：设计一个验证函数 `V(qt, Mr) → Mval`，在检索记忆进入策略之前做安全层，满足两个目标——最小化攻击影响（Eq.3：在触发查询 `q*` 下不让策略输出攻击目标动作 `a*`），同时最大化良性任务成功率（Eq.4：在良性查询下保持 `abenign`）。作者强调该层应**非侵入**，不改 Agent 核心架构（p.1–2, §1；p.4, §4）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **组件**：
  - **主记忆 `M = {m1,…,mN}`**：过去交互或知识的记录集合（p.3, §3.1）。
  - **检索器 `R`**：按查询选 K 条记忆，`Mr = R(qt, Mt, K)`（Eq.1）。
  - **策略 `πθ`**：固定参数的预训练 LLM，输入查询与检索记忆，输出计划 `pc ~ πθ(·|qt, Mr)`（Eq.2）。
  - **验证器 `V` / LLM 裁判**：A-MemGuard 的外部安全层，审计 `Mr` 并输出净化子集 `Mval`（p.4, §3.3–§4.1）。
  - **教训记忆 `Mles`**：与主记忆并列的第二记忆，存放检测到的异常结构化路径（p.5, §4.2）。
  - **执行循环**：查询 → 检索 → 平行推理路径 → 共识验证 → 生成最终计划 `pfinal` → 检索相关教训 → 若存在教训则强制修订 → 执行动作（p.5, §4.1–§4.2；Fig.2）。
- **形式化流程**：对每条检索记忆 `mi`，先生成自由形式 rationale，再抽取实体—关系链 `ρ̂i = Λ(qt, mi; θ)`（Eq.5），得到 K 条路径 `P̂t = {ρ̂1,…,ρ̂K}`（Eq.6）；计算 `si = Sdiv(ρ̂i, P̂t)`（Eq.7），保留 `Sdiv ≤ τ` 的记忆形成 `Mval`（Eq.8）（p.4, §4.1）。
- **最终策略**（p.5, §4.2, Eq.10）：
  ```text
  at ~ π′(·|qt, Mval) = πθ(·|qt, Mval, Lrel)   若 Lrel ≠ ∅
                      = πθ(·|qt, Mval)          否则
  ```
  其中 `Lrel = Rles(pfinal, Mles)` 是与当前计划结构相似的历史教训。
- **信任边界**（据 §3.2、§4 归纳）：主记忆的内容被视为**不可信**，因为攻击者可直接写入或经正常交互间接注入；Agent 核心 LLM、检索器、验证器/裁判和教训记忆被视为可信执行环境。受害者是善意用户，**不能直接检查或修改记忆**（p.3, §3.2）。系统没有记忆来源认证、写入者身份、签名或审计日志；验证只发生在**读取/检索时**，不发生在写入时。
- **多 Agent 扩展**：作者把同一框架用于协作多 Agent 的错误信息传播场景（p.7, §5.5；p.5, §5.1 提到 MISINFOTASK），但每个 Agent 的记忆与防御仍是本地的，没有跨 Agent 的信任协议或共享记忆的一致性机制。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- **资产**：主记忆 `M` 的完整性；Agent 决策/动作的正确性（尤其触发查询 `q*` 下不输出 `a*`）；良性任务效用（ACC）；受害者对记忆的信任。论文不保护记忆的机密性，也不保护可用性/回滚能力。
- **攻击者目标**：向记忆注入少量恶意记录 `Madv`，使 `M′ = M ∪ Madv`，并且**只在触发查询 `q*` 及其即时上下文**下诱导恶意动作 `a*`；在良性查询上尽量保持行为不变以维持隐蔽（p.3, §3.2）。目标包括提供错误信息或破坏决策（p.4, §3.2 Adversary）。
- **攻击者能力**（p.4, §3.2）：
  - 对核心 LLM `πθ` 仅有**黑盒**访问；不能修改 Agent 架构。
  - 知道记忆 schema，能构造“单独看无害、结合上下文有害”的记录。
  - **不能覆盖已有条目，也不能干扰正在进行的查询**。
  - 注入路径有两条：**直接**（对可访问的记忆存储有有限写权限）或**间接**（用良性查询诱导 Agent 自己归档恶意内容）（p.3, §3.2）。
  - 评测中还考虑更强攻击者：通过黑盒 probing 迭代优化触发器和注入记录，最大化 (i) 投毒条目在 top-K 检索中的占比、(ii) 跨交互轮次的渐进污染（p.4, §3.2）。对应 AgentPoison 的 retrieval-adaptive 与 MINJA 的 time-adaptive（p.6, §5.1）。
  - 额外的 Path-Consistent 攻击者会从上下文收割高频实体（Patient ID、诊断名），强制多条注入复用同一实体簇，制造“符号共识”（p.8, §5.8；pp.26–27, App N）。
- **前提假设**（p.3, §3.2）：
  - 记忆**主要由良性记录组成**，恶意记录只占很小比例；这是“现实约束”，因为攻击者需保持隐蔽。
  - 恶意记录在孤立审计下看似无害，危害只在特定查询/上下文中出现。
  - 受害者是善意用户，没有攻击知识，不能直接检查或修改记忆，但可能偶尔发现异常并提出纠正（p.3, §3.2 Victim）。
  - 验证器/LLM 裁判可信；没有考虑裁判被提示注入、模型后门、工具投毒、供应链或合谋。
- **威胁模型位置**：原文没有独立的 “Threat Model” 形式化小节；威胁模型由 §3.2 的文字、§3.3 的优化目标和 §5.8/App N 的自适应攻击共同定义。攻击者的预算、查询次数、是否知道防御细节均未形式化。

## 5. 核心方案：dual-memory、consensus、distillation、检索/写入检查

### 5.1 共识验证（Consensus Validation via Reasoning Path Analysis）

1. **平行路径生成**：对每条检索记忆 `mi`，用同一个 Agent 模型先生成自由形式 rationale，解释 `mi` 如何连接到查询与上下文；再从 rationale 中抽取实体和关系，形成结构化路径 `ρ̂i = (e1 -r1-> e2 -r2-> … -> eL)`（p.4, §4.1, Eq.5–6）。这一步把“语义上都很相关”的记忆转成“逻辑结构上可比较”的路径。App E 用 t-SNE 和余弦分布论证：原始记忆的 benign/malicious 嵌入高度重叠，结构化后更可分（pp.14–15, App E, Figs.5–6）。
2. **分歧评分**：`si = Sdiv(ρ̂i, P̂t)`，路径 `ρ̂j` 的分数超过阈值 `τ` 即判为异常；只保留非异常路径对应的记忆（p.4, §4.1, Eq.7–8）。
3. **主实现（LLM-as-judge）**（p.11, App A.1）：不做数值阈值，而是两阶段提示——(i) 把全部 K 条路径给裁判，要求合成一个“共识计划”；(ii) 对每条路径单独再做一次二值判断，输出 `{id, consistent, safety}` 的 JSON。`consistent=false` 或 `safety=false` 的路径被剔除。这样 `Sdiv` 实际被实例化为“LLM 判断的共识一致性 + 动作层安全审核”，而非固定距离阈值。
4. **替代实现**（pp.11–12, App A.2–A.3, Tables 8–9）：embedding 余弦距离到质心 + 阈值 τ；DBSCAN 把噪声路径判异常。两者都对阈值极敏感：embedding 方法 ASR-r 始终为 1.0，DBSCAN 在严格 eps 下 ACC 跌到 0.383，最终被放弃。作者以此论证 LLM 裁判的自适应性优于固定阈值分类器。

### 5.2 双记忆与教训蒸馏（Dual-Memory / Self-Taught Correction）

- 当路径 `ρ̂j` 被判异常，**该结构化路径本身**成为“负教训”：`lt := ρ̂j`（p.5, §4.2, Eq.9），存入 `Mles ← Mles ∪ {lt}`。教训记忆因此是一个“错误逻辑结构库”，可直接与新计划比较。
- **主动审议**：最终计划 `pfinal` 先按 Eq.6 转成候选路径，再检索结构相似的教训 `Lrel = Rles(pfinal, Mles)`；若 `Lrel` 非空，把教训以显式警告前缀注入上下文，迫使 Agent 在行动前修订计划（Eq.10；p.5, §4.2）。
- **实现细节**（pp.18–19, App H）：教训检索分两阶段——先按查询语义检索候选记忆，再把候选记忆对应的动作作为查询做二次检索，收集动作相似记忆关联的教训；教训以 `[CRITICAL WARNING] Analysis of Past Lessons` 前缀注入，要求模型避免重复错误。注意 App H 又描述教训是先“synthesize into a concise lesson”再与问题记忆一起标注，这与正文 Eq.9 的“异常路径本身即教训”不完全一致（见 §9）。
- **设计意图**：把检测到的错误转化为可复用的纠正信号，打破“错误结果被存储为先例”的循环；防御随交互经验增强，而不是一次性静态过滤（p.1–2, §1；p.5, §4.2）。
- **非侵入性**：不修改 Agent 核心架构，只在外围增加检索后验证、教训存储与执行前检查（p.1, Abstract；p.4, §4）。

### 5.3 写入/检索检查的边界

- 论文的检查点在**检索之后、策略生成之前**（`Mval`），以及**最终动作执行之前**（教训检索与修订）。它**不检查写入**：恶意记录仍可留在主记忆中，只是当前查询的检索结果被过滤。也没有对教训记忆的写入做认证或完整性检查。
- 关键超参 `top-k=4`（主记忆与教训记忆），在全部主实验固定（p.6, §5.1；p.8, §5.7）。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- **论文的安全声明是经验性的**：A-MemGuard 在 AgentPoison、MINJA、MMLU 与多 Agent 场景下降低 ASR，同时保持良性 ACC（p.1, Abstract；pp.6–8, §5）。没有“保证”“证明”“界”之类的形式化声明。
- **形式化程度**：
  - §3.3 的 Eq.3–4 是**优化目标**（期望指示函数），不是安全定义：没有定义攻击者模型、优势、不可区分性、完整性或泄漏上界；也没有说明两个目标如何权衡、约束或联合优化。
  - Eq.7–8 引入 `Sdiv` 和阈值 `τ`，但主实现用 LLM 裁判的二值输出，**没有 τ**；作者在 App A.1 明确说这“removes the need to define and tune a divergence threshold”。因此 Eq.8 的形式化与主实现不一致。
  - 全文**没有** theorem、lemma、proof、reduction 或 security game。没有密码学原语（加密、签名、MAC、承诺、ZK、MPC、FHE、TEE），也没有 Byzantine 共识协议；这里的 “consensus” 是同一 LLM 对多条检索记忆生成的推理路径做语义一致性比较，不是分布式副本间的共识。
  - 指标 ASR-r / ASR-a / ASR-t / ACC 都是**行为/统计指标**；没有假阳性率、假阴性率、检测精度/召回、校准或置信区间。ASR-t 在 AgentPoison 协议下定义为 `1 − AccEM`，作者自己在 App K 承认它会把“攻击影响”和“骨干模型本身的能力上限”混在一起（p.24）。
- **作者的核心经验主张**：
  1. 在 AgentPoison 直接投毒下，ASR-r 可降到接近零，ASR-a 大幅下降（p.6, Table 1）。
  2. 在 MINJA 间接注入下，ASR 降低超过 60%（0.667→0.256；0.633→0.233）（p.7, Table 2）。
  3. 在良性任务上保持最高防御方 ACC（p.8, Table 3）。
  4. 在多 Agent 错误信息场景取得最高任务成功率 0.950、最低 Final Score 2.150（p.7, Table 4）。
  5. 对 Path-Consistent 自适应攻击仍稳健，ASR 仅上升 0.62/1.07 个百分点（p.8, Table 7）。
- **声明与数字的张力**：Abstract 称“reduces attack success rates by over 95%”，Intro 称 EHRAgent “over 97%”；但以 Table 1 中 GPT-4o-mini + DPR 的 EHRAgent 行为例，端到端 ASR-t 从 100 降到 36.17（相对降幅 63.83%），ASR-a 从 87.23 降到 6.38（相对降幅 92.7%），只有 **ASR-r** 从 100 降到 2.13（相对降幅 97.87%）。因此 “over 95%/97%” 只在检索阶段成立，不能理解为端到端攻击成功率。论文没有在 Abstract 中限定指标，属于**口径放大**（详见 §9）。
- **结论**：A-MemGuard 是**语义层的、最佳努力的记忆完整性过滤器**，不是可证明的安全机制，也不是 reference monitor；其“安全”是经验 ASR 下降，而不是密码学或形式化保证。

## 7. 实验设置与主要结果（数据集、攻击、基线、指标、关键数字、消融）

### 7.1 设置

- **任务/数据集**（p.5, §5.1）：
  - ReAct-StrategyQA：知识密集型 QA，直接投毒配置沿用 AgentPoison（Chen et al. 2024）。
  - EHRAgent：电子健康记录管理，安全关键场景。
  - MMLU：通用 QA，间接注入配置沿用 MINJA（Dong et al. 2025）。正文写 MMLU，但对应参考文献 Wang et al. 2024b 的标题是 **MMLU-Pro**，存在命名不一致。
  - MISINFOTASK：多 Agent 错误信息传播，沿用 Li et al. 2025 的设置。
- **攻击**：AgentPoison（retrieval-adaptive，优化触发器使投毒条目进入 top-K）；MINJA（time-adaptive，跨交互轮次渐进污染）；Path-Consistent（作者自建的压力测试，强制多条注入复用同一实体簇）（p.6, §5.1；p.8, §5.8；pp.26–27, App N）。
- **骨干与检索器**：GPT-4o-mini、LLaMA-3.1-8B（表格写作 LLaMA-3-8B）；DPR、REALM 两种检索架构（p.6, §5.1）。
- **基线**：No Defense；LLM Auditor（GPT-4o-mini / LLaMA-3.1-8B-Instruct 作为审计模型，清洗检索记忆）；Distil Classifier（DistilBERT-base，安全/有害二分类）；Perplexity Filter（LLaMA-3.1-8B-Instruct 计算 PPL，绝对阈值 10000 + MAD 动态阈值 k=1.0）（pp.6, 12–13, §5.1/App B）。
- **指标**（p.6, §5.1）：ASR-r（检索阶段）、ASR-a（Agent 推理阶段）、ASR-t（端到端结果）、benign ACC。多次试验平均，但论文未报告试验次数或置信区间。top-k=4。

### 7.2 主结果

- **AgentPoison 直接投毒（Table 1, p.6）**，以 EHRAgent 为例：

  - LLaMA-3-8B + DPR：100 / 51.06 / 100 → 2.12 / 12.76 / 36.17。

### 7.4 缺失的实验

- 没有报告检测的假阳性率/假阴性率，也没有逐条记忆的 precision/recall；只有任务级 ACC。
- 没有延迟/吞吐/每查询成本的系统测量；只有一张 token 成本图。
- 没有让自适应攻击者知道防御细节、查询裁判或优化对抗路径；Path-Consistent 只是结构启发式，不是端到端自适应优化。
- 没有攻击教训记忆本身（注入假教训、删除教训、污染教训），也没有测量过度阻断。
- 没有真实记忆后端（向量数据库、MemGPT 等）或长期跨会话实验；多 Agent 只有一个表和一种设置。
- 没有与记忆专用防御（provenance、访问控制、鲁棒 RAG）比较；基线都是通用审计/分类器。

## 8. 贡献与创新点（按原文主张）

1. **首个 Agent 记忆防御框架（作者主张）**：作者称这是“to our knowledge, the first attempt to propose a defense framework that secures agent memory”，针对 context-dependent attacks 与 self-reinforcing error cycles 两类威胁（p.2, §1 Contributions）。
2. **共识验证**：利用 Agent 自身交互历史，对每个查询检索多条相关记忆，形成平行推理路径；若某条路径（受投毒记忆影响）偏离多数路径，则标记异常。这突破了“孤立审计单条记忆”的范式（p.2, §1；p.4, §4.1）。
3. **双记忆 + 教训蒸馏**：把检测到的错误路径转成“负教训”，存入独立教训记忆，在未来行动前检索并强制修订，从而打破自我强化错误循环，使防御随经验增强（p.2；p.5, §4.2）。
4. **广泛实验**：覆盖直接投毒（AgentPoison）、间接注入（MINJA）、多 Agent 错误信息（MISINFOTASK）、Path-Consistent 自适应攻击；多种 backbone/retriever；报告 ASR 下降与良性 ACC 保持（pp.6–8）。
- **与直接相关工作的差异**：AgentPoison 和 MINJA 是攻击/评测工作，本文是防御；LLM Auditor、PPL、Distil 是孤立条目审计基线，本文用跨记忆推理路径；MemGPT 等是记忆架构，不涉及安全；AgentAuditor 是安全评测数据集，本文借其 17 个场景做知识图谱可分性分析（p.14, App D）；Li et al. 2025 的多 Agent 错误信息工作被用作实验设置（p.7, §5.5）。
- **可复现资源**：论文**没有给出代码仓库或 artifact URL**；只在 p.12 提到“full prompt template is provided in our supplementary materials”，实际提示词在 App G–I（pp.18–20）。数据集使用公开的 StrategyQA、EHRAgent、MMLU-Pro、MISINFOTASK，但投毒/训练脚本未发布。

## 9. 局限、失败案例、作者承认的不足（区分作者承认 vs 你的推断）

**作者明确写出的**：
- App M（p.26）只有一句限制：即使做了工程优化，绝对成本/延迟仍取决于底层 LLM 栈与系统配置，跨部署可能变化。
- 教训记忆的 top-k 不能太大：k=8 时 ACC 跌到 46.80，作者明确说“recalling past mistakes is beneficial, retrieving too many lessons can introduce distracting noise”（p.8, §5.7）。
- ASR-t 会混入骨干模型能力上限：App K 明确说 `ASR-t = 1 − AccEM`，当 K 很小（如 K=2）时，保守过滤会减少记忆支持、暴露模型固有错误率；因此绝对 ASR-t 是“模型能力限制 + 真实攻击影响”的混合（p.24）。App L.4 重复了这一保留（p.26）。
- 全文没有独立的 Limitations 章节，也没有 Ethics 章节；只有 Impact Statement（p.9），且主要谈“把记忆当作一等安全面”的愿景，没有讨论误报、隐私或部署风险。

**本人推断的局限/失效场景**：
1. **威胁模型与评测条件存在张力**：假设“恶意记录只占很小比例”（p.3），但 Table 1/12 又专门测试 100% malicious retrieval。若攻击者能大规模写入，良性共识可能不存在；论文用“恶意路径结构不一致”来解释，但这不是证明，且 Path-Consistent 攻击只把 ASR-a 推高 1.07 个百分点，攻击预算/知识未公开。
2. **没有写入时防护，也没有来源认证**：防御只在检索后过滤，投毒记录仍留在主记忆，可能影响其他查询、其他 Agent 或未来会话；直接注入的“有限写权限”从何而来、如何获得，论文没有建模。
3. **教训记忆是新的攻击面**：`lt := ρ̂j` 直接来自攻击者可控的记忆内容；如果异常路径中包含指令文本，它会被存入教训库，并在未来以 `[CRITICAL WARNING]` 前缀重新注入上下文。论文没有对教训做净化、签名、过期或来源校验，也没有测试“教训投毒/假教训”导致过度阻断或二次注入。
4. **LLM 裁判可被提示注入**：裁判读取 K 条由攻击者记忆生成的路径；论文只在 p.21 的案例中展示了一条“encrypt answer”指令被判定不一致，但没有系统性测试针对裁判的注入（例如让路径文本指示裁判输出 `consistent=true`）。
5. **共识的独立性假设不成立**：K 条路径由同一个 LLM、同一查询、同一上下文生成，错误高度相关；如果投毒内容契合模型的系统性偏差，它可能不是“离群点”，而是“共识”。论文的“consensus”借用了分布式共识的直觉，但没有副本、quorum、认证或 Byzantine 模型。
6. **没有误报/过度阻断的度量**：只报任务级 ACC；没有报告多少良性记忆被误删、哪些查询被过度保守处理。Table 3 中 EHR 的 ACC 下降 9.7–11.7 个百分点，说明代价并非总是“minimal”。
7. **ASR-t 口径造成头条数字夸大**：Abstract 的“over 95%”与 Intro 的“over 97%”只能在 ASR-r 上成立；端到端 ASR-t 仍有 36.17（EHRAgent）甚至 42.85（ReAct LLaMA DPR）。这不是作者隐藏数据（Table 1 全部给出），但摘要未限定指标，容易被误读。
8. **模型/场景覆盖有限**：只有 GPT-4o-mini 与 LLaMA-3.1-8B 两个骨干、四个基准、英文任务；没有 GPT-4o/Claude/Gemini 等更强模型，也没有真实向量数据库或长期记忆压缩。
9. **多 Agent 证据薄弱**：Table 4 只有一个设置，没有拓扑、传播轮次、合谋或跨 Agent 教训共享的分析；“evidence of transfer”只是初步证据（p.7）。
10. **形式化与实现不一致**：Eq.8 的阈值 τ 在主实现中不存在；Eq.9 说教训就是异常路径，App H 又说要“synthesize into a concise lesson”；Eq.12 的 EntityOverlap 是 Jaccard，Table 7 却报 15.0。这些不影响主结论，但说明形式化是示意性的。
11. **“首个”主张不可验证**：作者称 first defense framework for agent memory，但已有 LLM Auditor、PPL、Distil 等记忆清洗基线，也有 AgentAuditor 等评测工作；更准确的说法是“首个以跨记忆推理路径共识 + 教训记忆为核心的记忆防御框架”。

## 10. 与理论密码学的可能联系（严格；没有就写“无”）

**论文已做：无。** 论文没有使用任何理论密码学机制：没有加密、签名、MAC、承诺、零知识、MPC、FHE、TEE、匿名凭证、认证数据结构或形式化安全定义；没有 theorem/lemma/proof/reduction/security game。它的 “consensus” 不是分布式共识协议，而是同一 LLM 对多条检索记忆生成的推理路径做语义一致性判断；它的 “validation” 是 LLM 分类器，不是密码学认证或 reference monitor。`ASR` 是经验攻击成功率，不是密码学优势；`Mval` 是语义过滤结果，不是可验证的完整性证明。按项目口径，本文属于**纯语义/系统方法，非密码学**。

**个人推断（以下均为推断，不是论文已做）**：
- **认证数据结构 / Merkle 日志**：可把主记忆做成 append-only Merkle log，每次写入生成包含证明，定期发布树根；能检测未授权的修改、删除、回滚（tamper-evident）。但 A-MemGuard 的威胁是**有写权限的攻击者写入“合法但恶意”的记录**，Merkle 日志只能证明“这条记录确实被写入过”，不能证明“这条记录是善意的”。因此它只能补来源/审计，不能替代语义共识。
- **数字签名 / 来源凭证**：让每个写入者（用户、工具、子 Agent）对记忆条目签名，绑定 writer、时间、通道、会话；验证器可拒绝无来源或来源不符的条目。这能收紧“直接有限写权限”的攻击面，但不能判断已授权写入的内容是否恶意。
- **Byzantine 共识 / quorum**：若记忆在多个 Agent 副本间复制，可要求 quorum 读写、用签名投票和证书达成一致；这能防止单副本污染，但本文是单存储、单 Agent 的检索过滤，没有副本、没有 quorum、没有认证，二者只是名词相同。
- **形式化 trace 属性**：可定义“不存在由 `Madv` 导致的动作 `a*`”作为安全属性，但“某条记忆是否恶意”是语义判断，一般不可判定；形式化需要把语义危害抽象成标签，而标签本身来自 LLM/人工，无法用密码学证明。
- **统计共识的误差界**：若假设 K 条良性路径独立同分布、且恶意路径是少数，可用投票错误率界（Condorcet 风格）给 ASR 上界；但本文的路径由同一模型生成，独立性假设不成立，且没有估计路径间相关性。任何这样的界都需要新增假设与实验。
- **TEE / 远程认证**：可保护裁判代码与教训库不被宿主篡改，但不能保证裁判的语义判断正确；它保护的是执行完整性，不是内容真实性。
- **理论相关度判断**：按项目 `T_crypto` 量表，本文正文约 **0–1**：可以类比“完整性/认证”属性，但核心是语义异常检测，不需要密码学理论；若把 Merkle log + 签名来源 + 形式化 trace 属性做成新构造，才可能到 2，但那是新增研究，不是本文贡献（本人推断）。

## 11. 与应用密码学的可能联系（严格；没有就写“无”）

**论文已做：无。** 论文没有 OAuth/OIDC、签名、加密、TEE、capability token、审计日志、密钥管理或任何密码协议。记忆存储、检索器、LLM 裁判都被当作可信基础设施；唯一的“访问控制”是威胁模型里“直接攻击者有有限写权限”的假设，论文没有实现或评估任何访问控制机制。

**个人推断的工程接口（均标为推断，需要新增设计与实验）**：
1. **记忆写入认证 + capability token**：每个写入者（用户、工具、子 Agent）持有密钥，对记忆条目签名；存储层用 capability/UCAN 风格令牌限制可写命名空间、条目类型、有效期。作用：把“直接有限写权限”变成可审计、可撤销的授权，减少未授权注入。局限：不能阻止已授权写入者的恶意内容；令牌粒度、撤销、多租户隔离仍需设计。
2. **Merkle 日志 / 透明日志**：主记忆和教训记忆都做成 append-only 日志，写入返回 inclusion proof，定期发布 signed tree head；支持审计、回滚检测、删除证明。作用：检测未授权的修改/删除/回滚，给取证提供依据。局限：事后检测，不阻止语义投毒；日志增长与检索性能需要工程优化。
3. **记忆存储的访问控制/隔离**：按用户、会话、任务、信任级别分区；Agent 只能读当前任务需要的分区；跨分区读写需显式授权。作用：限制横向污染与跨用户影响。局限：A-MemGuard 的检索需要多记忆做共识，过度隔离会削弱共识信号。
4. **TEE / 机密计算**：把 LLM 裁判、教训库、验证逻辑放入 TEE，远程认证后运行；保护其代码与数据不被宿主或恶意工具篡改。作用：提升验证器与教训库的执行完整性。局限：不解决语义判断错误；TEE 侧信道与供应链仍是风险；LLM 推理放进 TEE 的成本高。
5. **签名审计记录**：对每次 `(query, retrieved_ids, validation_decision, lesson_ids, action)` 记录签名哈希链，用户/审计方可以验证“某次动作经过了哪次验证”。作用：问责与取证，支持对过度阻断/漏检的申诉。局限：日志完整性 ≠ 判断正确性；日志本身可能含敏感内容，需要加密/最小化。
6. **多 Agent 共享记忆的密钥管理**：若多个 Agent 共享记忆，使用组密钥/门限签名/密钥轮换，离职或失陷 Agent 的密钥可撤销；跨 Agent 消息用 mTLS + 消息签名。作用：防止假冒 Agent 写入。局限：本文的多 Agent 实验没有共享记忆协议，接口需要重新设计。
- **伪交叉警告**：
  - **加密记忆 ≠ 防投毒**：攻击者有写权限时可以把恶意内容加密后写入；加密只保护静态/传输机密性，不保护内容语义。
  - **签名记忆 ≠ 真实记忆**：签名只证明“谁写的”，不证明“写得对”；已授权写入者的错误/恶意内容仍是合法签名。
  - **Merkle 日志 ≠ 语义防御**：它能发现篡改，但发现不了“合法写入的谎言”；与 A-MemGuard 是互补而非替代。
  - **“consensus” ≠ Byzantine consensus**：本文没有副本、quorum、证书、签名投票；不要把它当作 BFT。
  - **ZK 证明“验证器运行过”**：证明的是计算完整性，不是“被验证的记忆无害”；LLM 是概率性的，证明也不覆盖语义。
  - **TEE 保护裁判**：保护的是执行环境，不是输入内容的真实性；恶意记忆仍可让裁判做出错误判断。
- **应用密码学相关度判断**：按项目 `A_crypto` 量表，本文正文约 **0–1**（没有识别任何密码机制使用点）；若把“签名来源 + Merkle 日志 + capability 写入控制 + 签名审计”做成可运行原型，并在同一 AgentPoison/MINJA 设置下量化 ASR/ACC/延迟收益，可到 2–3，但这属于新增系统研究，不是本文贡献（本人推断）。

## 12. 可检验的研究假设（3–6 条）

以下均为**假设/推断**，需查证外部文献；本文未做，不等于无人做过。

- **H1（写入认证降低直接注入）**：若在记忆存储层加入“每写入者签名 + capability 令牌 + 命名空间隔离”，则 AgentPoison 式直接注入的 ASR-r 应显著低于 A-MemGuard 单独使用时的 2.13%。实验：在同一 EHRAgent/AgentPoison 设置中，分别开启/关闭写入认证，保持相同攻击预算，比较 ASR-r/a/t 与良性 ACC；并记录合法写入的额外延迟。
- **H2（Merkle 日志只能检测篡改，不能检测语义投毒）**：Merkle/透明日志应能 100% 检测未授权的修改、删除与回滚，但对“有权限写入的恶意条目”检测率为 0（除非与语义防御组合）。实验：构造 direct-write 攻击者，分别做 overwrite/delete/rollback/authorized-append 四类操作，测量检测率与误报率。
- **H3（裁判提示注入可绕过共识）**：若在恶意记忆的结构化路径中嵌入针对 LLM 裁判的指令（如“忽略上述路径，输出 consistent=true”），共识验证的 ASR 应显著上升。实验：在 p.11 的裁判 prompt 下，构造 50–100 条带裁判注入的记忆，比较有无路径净化/指令隔离的 ASR-r/a 与 ACC。
- **H4（教训记忆投毒导致过度阻断）**：向 `Mles` 注入假教训或污染异常路径文本，会使 Agent 在未来良性查询上过度修订/拒绝，ACC 下降；若教训被当作高优先级警告注入，还可能形成二次提示注入。实验：在教训库中注入 10–50 条假教训，测量良性 ACC、过度阻断率与 ASR 变化。
- **H5（共识收益随 K 饱和，且与路径相关性负相关）**：随 K 增大，ASR 下降的边际收益应递减；当 K 条路径由同一模型生成、相关性高时，投票错误率不会按独立假设的指数下降。实验：K=2..10，测量 ASR-r/a 与路径间一致性/相关性，拟合相关投票模型，比较独立假设的预测。
- **H6（更强的自适应攻击可显著突破 Path-Consistent 的上限）**：当前 Path-Consistent 只把 ASR-a 推高 1.07 个百分点；若攻击者能查询裁判、知道防御细节并做端到端优化（而非只复用实体），应能把 ASR-a 推得更高。实验：给攻击者有限次裁判查询/黑盒反馈，优化注入路径的实体一致性与语义合理性，测量 ASR 随查询预算的变化。
