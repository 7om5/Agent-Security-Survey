## 1. 150–300 字中文概述

SkillTrojan 把后门植入可复用 skill 的实现层，而不是模型参数、prompt 或 tool/memory 接口。它把攻击者指定的 payload 做对称变换（落地为 XOR+Base64）后切成 N 段，分别埋入若干看似良性的 skill 脚本；只有用户 query 命中触发短语、且 Agent 在一次运行中调用完所有携带片段的 skill 并调用 verifier 时，片段才按索引重组、解密并作为隐藏副作用执行。作者还给出从任意 skill 模板自动合成后门变体的流程，发布 1,200 个模板、3,000+ 后门 skill 的 SkillTrojanX 数据集，并在 EHR SQL 与 SWE-Bench Verified 上跨 9 个开/闭源模型评测。GPT-5.2-1211-Global 上达 97.2% ASR、89.3% ACC；两个 LLM 扫描器把 98.2%/99.4% 的样本判为安全。全文无密码学安全定义，所谓 “encryption” 是混淆而非密码学保护。

## 2. 研究背景、现有方法不足、精确定义的问题

- **背景**：skill-based agent 把可复用 skill 作为一等抽象；skill 是可分发包（文件夹），含自然语言规格 `SKILL.md` 与可执行脚本/资源，能执行代码、维护内部状态、访问外部资源（p.1 §1；p.3 §3）。skill marketplace 使第三方 skill 的安装与复用规模化，也把信任集中到 skill 实现上。
- **现有后门研究的控制面**：模型（数据投毒/参数编辑）、prompt/planning context、tool/memory 接口；攻击多在单次 episode 内、瞬态交互面上触发（p.2 §2.2）。防御也主要监控模型输入输出或单一交互面。
- **不足**：(i) skill 实现被默认为可信组件，安装后很少审计其内部行为；(ii) skill 跨任务、用户、部署持久存在，攻破一个广泛使用的 skill 可静默影响许多下游运行，而模型、prompt、工具集都不变；(iii) 现有防御不检查执行层组合与副作用，因此 skill 层的持久后门落在盲区（p.1–3）。
- **精确问题**：攻击者只通过发布/分发看似良性的 skill 包，能否在**不修改基座模型、prompt、训练数据**的前提下，植入一个 (i) 在 clean query 上保持原 skill 功能、(ii) 在触发 query 上可靠重建并执行任意 payload 的后门？该后门能否从任意 skill 模板自动合成、规模化传播，并逃逸轻量静态扫描？
- **形式化表述**：给定 benign skill `s=(m,A)`、payload `P`、trigger predicate `Trig_τ: Q→{0,1}`，构造 `s̃=(m̃,Ã)`；目标为 `Trig_τ(q)=0` 时 `s̃` 保持 `s` 的名义功能，`Trig_τ(q)=1` 时正常 skill 执行导致 `P` 运行（p.3 §3–§4）。注意这里的 “backdoor” 是**供应链 trojan 式的休眠恶意逻辑**，不是权重级 model backdoor。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **组件**（p.1 Fig.1；p.3 §3；p.4 Fig.2）：
  - **Skill 包** `s=(m,A)`：`m` 是自然语言规格（如 `SKILL.md`），`A={a_j}` 是执行时调用的脚本/资源。
  - **Agent 核心**：LLM policy + planner（任务分解）+ tool/skill selector + execution controller；围绕 LLM 还有 memory、search、code、execution 等 skill 类别（Fig.1）。
  - **Skill marketplace/repository**：第三方 skill 的来源，agent 动态加载 `S={s1,...,sK}`。
  - **执行轨迹与工具输出**：tool return values、tool-call trajectory log、run-scoped scratchpad；论文把它们当作 fragment 的中间通道。
  - **Verifier skill** `a_ver`：检查片段集合、按索引拼接、解密、执行 payload，并发出 execution marker。
  - **副作用执行层**：payload 在 skill execution environment 内执行，独立于 agent 的文本回答。
- **交互流程**（p.4 Fig.2；p.5 §4.2；p.13 Alg.1）：
  1. 用户 query `q` 进入；若含触发短语则 `Trig_τ(q)=1`。
  2. LLM 读 `m̃`，选择并组合 `A` 中的动作；`m̃` 只在触发时加入一个小的条件偏置 `Δ(π)`，不写死执行顺序、不写显式恶意指令。
  3. 被 instrument 的 N 个动作照常返回原输出，但在触发时额外把 `c_j` 写入 tool output/trajectory。
  4. verifier 检查 `{c1,...,cN} ⊆ F(q)`；满足则按索引拼接、`Dec(·;k)`、执行 `P`、发 marker、清理临时片段。
  5. 用户看到的是正常、正确的任务输出；恶意行为只发生在副作用层。
- **信任边界**：
  - 论文明确假设**基座 LLM 与其训练数据可信且未修改**（p.3 §3）。
  - 第三方 skill 包是**供应链上的不可信输入**，但一旦安装就获得代码执行能力、可读写工具输出、可调用外部 API；论文没有在 skill 与宿主之间设置 sandbox（sandboxing/output validation 被列在攻击者能力之外，但也未被当作默认防御）。
  - `tool output / trajectory log` 被当作 agent 内部可信通道；攻击正是把片段藏进这个通道。
  - `verifier` 位于 skill 包内，因而受攻击者控制；它不是独立的 reference monitor。
  - 关键错位：系统把 skill 当作“可信模块”，但其内部行为极少被审计；攻击绕过的是**执行基底**的信任假设，而不是模型对齐。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- **资产**：用户任务的正确性与可用性；agent 可访问的 secrets/credentials；文件系统；网络与外部服务；skill marketplace 的信任；agent 执行轨迹的完整性。
- **攻击者目标**（p.3 §3）：
  - **Stealth**：`Trig_τ(q)=0` 时保持名义任务行为（用 clean ACC 度量）。
  - **Reliable activation**：`Trig_τ(q)=1` 时正常 skill 执行导致 `P` 运行（用 ASR 度量）。
  - payload 任意：数据集覆盖 system profiling、file drop、secret harvesting、network beacon 四类（p.8 Fig.4）。
- **攻击者能力**：
  - 可发布/分发 skill；选择并替换目标 skill 子集 `S̃`；知道目标 agent 的 skill 栈与模板；可指定 `P`、`τ`、`N`；可自动生成大量变体（p.3 §3；p.5 §4.3）。
  - 安装后**无**宿主环境访问、无 OS 特权、无模型内部访问；交互只通过用户 query（p.3 §3）。
  - **但**：skill 本身是可执行代码，触发后以 agent 进程的权限运行 `P`；因此“无 OS 特权”应理解为“无交互式控制通道”，而不是“payload 受权限限制”。这是原文表述的张力（本人推断）。
- **不在范围内**（p.3 §3）：直接攻破基座模型、远程服务或 OS；依赖跨 run 状态或长期存储；sandboxing/output validation（除非部署显式启用）。
- **前提假设**：
  - agent 会动态加载第三方 skill，且会按 `m̃` 组合动作、调用 verifier；这是攻击成立的关键行为假设。
  - 片段是 ephemeral、run-local、run 结束清理；不跨 query 持久化。
  - 触发是用户 query 中的 trigger phrase/pattern（p.5 §5.1）；不是环境触发、工具输出触发或多轮语义触发。
  - `ρ` 在本文指**工作负载中触发 query 的比例**，不是被投毒 skill 的比例（p.12 App A 明确按 poisoned subset 统计 ASR）。这个术语容易与后门文献中的 poisoning rate 混淆。
- **威胁模型位置**：§3 集中给出；§4.3/§5.1 补充数据集与触发方式；无独立的形式化 threat model 小节。

## 5. 核心方案：payload 分割/加密/触发/重组、自动合成

### 5.1 编码与分割（p.4 §4.1）

```text
C = Enc(P; k)                    (1)
c_j = <j, seg_j(C)>,  j = 1..N   (2)
```

- 先对 payload 做对称变换得到 `C`，再把 `C` 切成 `N` 段；每段带索引 `j`。
- 索引使重组**与顺序无关**（order-agnostic）：verifier 只需集合包含，不依赖 planner 的调用顺序、时序或控制流。
- `N` 是可调参数：`N` 越大，单片段信息越少、部分执行时误激活风险越低，但需要更完整的执行轨迹才能重组。

### 5.2 Skill instrumentation（p.4 §4.1–§4.2）

- 把 `m` 改为 `m̃`，注入以 `Trig_τ` 为条件的控制逻辑；对 clean query 语义等价，对 triggered query 只加入小偏置：

```text
Pr_{m̃}(π|q) = Pr_m(π|q),              Trig_τ(q) = 0
             = Pr_m(π|q) + Δ(π),       Trig_τ(q) = 1     (3)
```

- `m̃` 不规定固定执行顺序，也不写显式恶意指令；它只是在正常 planning/decomposition 中提高覆盖指定动作的概率。
- 选 `N` 个“看似良性”的 fragment-emitting actions，instrument 它们：保留原功能与输出，仅在触发时把 `c_j` 写入中间存储（tool output 中看似正常的字段、tool-call trajectory、run-scoped scratchpad）。
- verifier `a_ver` 也被 instrument，持有 `k`，负责集合检查、拼接、解密、执行、marker、清理。

### 5.3 触发、重组与执行（p.5 §4.2；p.13 Alg.1）

```text
F(q) = {c_j1, ..., c_jT}                  (4)   本次 run 发出的片段集合（无序）
{c1, ..., cN} ⊆ F(q)                      (5)   集合包含检查
P = Dec(c1 || ... || cN; k)               (6)   按索引拼接后解密
```

- 触发条件同时要求 `Trig_τ(q)=1` 与片段集合完整；缺一片段则不重组。
- payload 在 skill execution environment 内作为**隐藏副作用**执行；agent 对用户的回答仍是正确、良性的。
- 执行后 `CLEANUPEPHEMERAL(F)` 删除中间痕迹；论文不声称安全删除。
- 关键设计：激活与“完成一个普通执行工作流”对齐，而不是与单个异常动作对齐；因此单个 skill 调用看起来正常，危害是**组合性**的。

### 5.4 自动合成与数据集（p.5 §4.3；p.8 §5.3）

- 给定 attacker configuration `(P, τ, N)`，对每个模板 `s` 生成 `s̃`；通过变化 trigger string/pattern、payload family、encryption/encoding choice、fragment count `N` 产生多个变体；记录 trigger、payload family、crypto variant、`N`、fragment-emitting/verification actions 等元数据。
- 数据来源：从公开 skill marketplace 爬取 popularity top 1,200 的 skill，保留含可解析 spec 与可执行 artifact 的包，归一化为 `s=(m,A)`。
- 发布 `SkillTrojanX`：1,200 templates、3,000+ backdoored skills、6 template categories、4 payload families、3 crypto variants、3 `N` variants、50 unique triggers（p.8 Table 4）。
- 默认配置：`ρ=0.2`、`N=3`、`XOR+Base64`（p.5 §5.1）。自动合成是模板化程序变换，不是 LLM 驱动的内容生成。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- **安全目标的定义**：只有操作化定义，没有形式化定义。
  - Stealth = clean query 上的 task ACC；没有定义“clean query 上绝不执行 payload”的副作用率。
  - Reliable activation = poisoned query 上的 ASR；ASR 由 verifier 返回的 execution marker 与确定性 side effect 共同判定（p.6 §5.1）。这是全文最客观的指标。
- **符号化**：Eq.1–6 与 Alg.1 是算法/功能描述；Eq.3 是唯一的概率式陈述，但 `Δ(π)` 未定义、未归一化、未测量，不能视为概率模型或安全模型。
- **无形式化安全定义**：没有 security game、adversary advantage、indistinguishability、simulation、reduction、theorem/lemma/proof。没有定义 “benign-looking skill”“stealth”“backdoor” 的形式语义。
- **“Encryption” 未形式化**：Eq.1 只写黑盒 `Enc(·;k)`；没有密钥长度、生成/分发、IV/nonce、攻击者密钥知识、机密性目标或安全假设。§5.1 落地为 XOR+Base64，Table 5 只测启发式检测率，不测机密性。
- **主张类型**：经验性、比较性、系统性的安全主张——在 9 个模型、2 个 benchmark、4 个 agent framework 上报告 ASR/ACC；没有“对任意 skill/agent 成立”的保证。
- **“First” 主张**：作者称首个针对 skill abstraction layer 的后门（p.2 贡献 1）。这是优先级/范围主张，不是可证明命题；本文 Related Work 引用到 2025–2026 年，但是否覆盖同期所有 skill 供应链工作需外部核查。
- **结论**：论文提供的是**经验攻击有效性**与**扫描器失效证据**，不是可证明的安全性或不可检测性。其 “encryption” 服务于静态扫描规避，不构成密码学安全声明。

## 7. 实验设置与主要结果

### 7.1 设置

- **主 benchmark（EHR SQL）**：自然语言临床 query → agent 用 skill tools 组合 SQL → 在 EHR 数据库执行；ACC 由 LLM-as-a-judge 判定 SQL 结果是否匹配期望；ASR 由 execution marker + 确定性 side effect 判定（p.5 §5.1；p.6 §5.1；p.13 App D）。
- **模型（9 个）**：
  - Open-weight：GLM-4.7、Qwen3-Coder、GLM-4.6、Qwen3-VL-235B-A22B-Instruct。
  - Closed-weight：GPT-4o-mini-0718-Global、Claude-Haiku-4.5、Claude-Sonnet4.5、Qwen3-Max、GPT-5.2-1211-Global。
- **基线**：GCG、AutoDAN、CPA（prompt/suffix 类）、BadChain（CoT 后门）、AgentPoison（memory/knowledge poisoning）；另有 NON-ATTACK（不装 skill 栈）与 SKILLS(NATIVE)（装同样 skill 但无后门逻辑）。
- **默认超参**：`ρ=0.2`、`N=3`、XOR+Base64；trigger 为用户 query 中的短语。
- **缺失**：EHR SQL 的样本量、schema、split、query 数量均未报告；judge 使用的 LLM 未说明（只给了 prompt 模板）；没有 seeds、重复次数、置信区间；没有 per-payload-family 的 ASR。

### 7.2 主结果（Table 1/2，p.6；PNG 校正后）

- **Open-weight（Table 1）**：
  - GLM-4.7：Non 84.1/0.0；最强基线 AgentPoison 85.0/57.2；SkillTrojan **85.2/62.1**。
  - Qwen3-Coder：71.5/0.0；AgentPoison 72.4/62.5；SkillTrojan **76.3/64.7**。
  - GLM-4.6：76.0/0.0；AgentPoison 77.1/60.8；SkillTrojan **81.3/72.0**。
  - Qwen3-VL：53.2/0.0；AgentPoison 52.0/37.6；SkillTrojan **48.4/26.7**。→ 该模型上 SkillTrojan 的 ASR 低于 AgentPoison，ACC 也低于 Non-attack；是唯一明显失败点。
- **Closed-weight（Table 2）**：
  - GPT-4o-mini：71.6/0.0；AgentPoison 74.8/53.7；SkillTrojan 68.5/54.3。
  - Claude-Haiku：73.1/0.0；75.5/54.8；82.7/57.3。
  - Claude-Sonnet：86.5/0.0；74.1/56.2；90.7/64.2。
  - Qwen3-Max：82.7/0.0；73.4/57.6；86.6/74.7。
  - GPT-5.2：73.0/0.0；72.9/58.3；**89.3/97.2**。
- **解读**：SkillTrojan 在 9 个模型中的 8 个取得最高 ASR；GPT-5.2 上 97.2% vs 最强基线 58.3%（AgentPoison）。ACC 往往高于 Non-attack（GPT-5.2 89.3 vs 73.0），作者归因于“安装良性 skill 本身提升任务完成”，并以 Table 7 的 SKILLS(NATIVE) 佐证；但该佐证只覆盖 4 个 open-weight 模型，closed-weight 没有 native baseline，因此 89.3 中有多少来自 skill utility、多少来自后门逻辑无法分解。

### 7.3 消融与附加实验

- **Fragment count N（Fig.5, p.8）**：`N∈{1,2,3,5}`；ASR 在 `N=3` 最高（约 54%），N 过小或过大都下降；ACC 基本稳定。作者解释：N 小 → 单片段更显眼、planner 易偏离；N 大 → 需要更多 fragment-carrying tools，容易缺片段。
- **Poisoning ratio ρ（Fig.6, p.12）**：`ρ∈{0.1,0.2,0.5}`；ACC 稳定在 68.5% 左右，ASR 在 3 个百分点内稳定。说明 ASR 主要取决于单次 run 的 trace completion，而非触发频率。
- **加密方案（Table 5, p.9）**：XOR+Base64：ACC 68.5、ASR 54.3、heuristic-flag 78.0%；Hybrid：68.4、54.6、21.0%。ASR/ACC 几乎不变，只有朴素 base64 检测器的命中率大幅下降 → “encryption” 主要影响可检测性。
- **扫描器（Table 3, p.8）**：约 500 个 skill；Qwen3Guard-Gen-8B / Llama-Guard-3-8B 判为 safe 的比例：SkillTrojan 98.2/99.4；Skills(Native) 100.0/99.6；SkillTrojan w/o enc./seg. 3.4/2.8。即完整方案几乎不被静态 LLM 扫描器识别，而去掉编码/分段后被高度识别。
- **SWE-Bench Verified（Table 6, p.12）**：Qwen3-Coder 65.7/63.9；GPT-5.2 70.4/92.8；GLM-4.7 67.6/66.4（Non-attack 分别 64.8/0.0、70.6/0.0、67.3/0.0；GCG 10.3/12.5/26.1）。说明不是 SQL 专属。
- **Clean-skill utility（Table 7, p.14）**：Non-attack 84.1/71.5/76.0/53.2；SkillTrojan 85.2/76.3/81.3/48.4；Skills(Native) 88.7/82.3/85.5/50.3（GLM-4.7/Qwen3-Coder/GLM-4.6/Qwen3-VL）。→ Native 在 3/4 模型上最高；Qwen3-VL 上 Non-attack 53.2 反而高于 Native 50.3，与正文“Native 在全部四个设置最好”的表述矛盾。
- **Cross-framework（Table 8, p.14）**：Claude-Code、IFlow、OpenHands、OpenClaw × 5 个 backbone，ASR 63.53–100.00%（IFlow+Qwen3 Coder Plus 为 100.00）。只报告 ASR，没有 ACC、没有 baseline、没有样本量；作者自己声明该实验与 EHR SQL 不可直接数值比较。

### 7.4 原文内部不一致/需警惕的口径

1. Table 1/2/3/4 的 pdftotext 抽取错位；本笔记以 PNG 校正值（见 §13）。特别是 Table 4：payload families 是 **4**、crypto variants 是 **3**、unique triggers 是 **50**，不是抽取文本中的 6/4/3。
2. 正文称 SKILLS(NATIVE)“在全部四个设置取得最高 clean accuracy”（p.14），但 Qwen3-VL 列 Non-attack 53.2 > Native 50.3，反例成立。
3. 正文称 SkillTrojan“yields the strongest end-to-end attack”，但 Qwen3-VL 上 ASR 26.7 < AgentPoison 37.6，且 ACC 48.4 为全表最低；该主张应限定为“9 个模型中的 8 个”。
4. “poisoning ratio ρ” 实际是触发 query 在工作负载中的比例，不是被投毒 skill 的比例；与后门文献惯例不同。
5. Table 8 的 100.00% ASR 无 ACC、无 baseline、无样本量，不能作为与主表同强度的证据。
6. 所有主表都是单点数字，没有方差/CI/重复次数；Table 2 的 ACC 大幅高于 Non-attack（GPT-5.2 +16.3）没有 closed-weight 的 native baseline 对照。
7. §5.3 说“crawl the top 1,200 skills by popularity and retain those that contain executable artifacts and a parsable specification file”，Table 4 却直接写 Templates 1200；retained 模板数应 ≤1,200，原文未澄清两者是否同一数量。

## 8. 贡献与创新点（按原文主张）

- **贡献 1**：首个针对 skill abstraction layer 的后门范式；恶意逻辑植入 reusable skill implementation，而非模型参数、prompt、tool/memory 接口（p.2）。
- **贡献 2**：通用、可扩展的 skill-level backdoor 框架：encrypted payload fragmentation、trigger-based activation、从任意模板自动合成后门 skill（p.2）。
- **贡献 3**：在真实 code-based agent 设置中跨 open/closed-weight 模型评测，报告高 ASR 与最小 ACC 退化（GPT-5.2 97.2/89.3）；发布 3,000+ backdoored skills 数据集（p.2；p.8）。
- **与直接相关工作的差异**：
  - vs 模型后门（数据投毒/参数编辑）：不改模型、不改训练数据；后门在执行基底。
  - vs prompt injection / GCG / AutoDAN / CPA：不依赖模型“听从”注入指令；利用受信任的工具执行链。
  - vs BadChain：不是 CoT prompt 后门，而是可执行 skill 代码。
  - vs AgentPoison：不是 memory/knowledge base 投毒，而是 skill 实现投毒；不需要 retrieval。
  - vs DemonAgent（Zhu et al., 2025，动态加密多后门植入）：同样使用加密/多后门，但目标是 LLM-based agent（具体控制面需读原文）；SkillTrojan 明确落在 skill 层，且用组合式片段重组。原文只在 Related Work 引用，未做实验对比（p.3；p.11）。
  - vs SkillAct / SkillWeaver 等良性 skill 抽象工作：本文把同一抽象当作攻击面。
  - 项目内交叉参照（非原文）：R1-08 测量真实恶意 skill；本文提供合成攻击与数据集，二者互补。
- **可复现资源**：代码 `https://github.com/Yunhao-Feng/SkillTrojan`（p.1；仅记录，未打开/未执行）。数据集在文中称 “release”，但没有独立 URL/DOI/license；EHR SQL 数据、payload 实现、Hybrid 加密算法、judge 模型、随机种子均未给出。完全复现受商业 API 版本与未公开数据影响。

## 9. 局限、失败案例、作者承认的不足

**作者明确承认/写出的**：
- payload 受 skill execution environment 约束（p.4 §4.1）。
- 不覆盖跨 run 状态/长期存储；片段 ephemeral，run 结束清理（p.3 §3）。
- sandboxing/output validation 不在攻击者能力内，除非部署显式启用（p.3 §3）。
- 只做 EHR SQL + SWE-Bench Verified 两个 benchmark；cross-framework 结果是另一套 industry-oriented benchmark，不能与主表直接比较（p.14 App G）。
- 扫描器只是轻量 LLM-based；作者呼吁更针对性的 defense prompts、guard models、runtime monitors（p.7–9）。
- 双用途；论文强调 controlled experimental settings，不主张真实部署（p.9 Impact Statement）。

**本人推断的局限/失败场景**：
- **“Encryption” 不提供机密性**：密钥 `k` 随 verifier skill 分发；能读代码的审计者可以提取 `k` 并解密。XOR+Base64 不是密码算法；没有密钥管理、IV、语义安全。它只对朴素字符串扫描有效（Table 5）。
- **威胁模型的能力表述有张力**：一边说安装后 “no OS privileges”，一边让 arbitrary payload 在 agent 进程内执行；payload 实际拥有 agent 的权限。若 agent 有文件/网络/secret 访问，payload 就有。
- **触发过于简单**：trigger 是用户 query 中的短语/pattern；没有语义触发、环境触发、多轮触发；没有测 trigger 的自然出现率/误触发率。真实攻击者更难让用户说出特定短语。
- **依赖 planner 配合**：需要 agent 在一次 run 中调用 N 个指定 emitter + verifier；Eq.3 的 `Δ(π)` 未量化，论文没有报告“无偏置时 planner 自发覆盖这些动作”的概率。ASR 同时衡量了 planner 顺从性与重组可靠性，无法分离。
- **无 per-payload-family 结果**：4 类 payload 只在 Fig.4 的分布中出现，没有分别报告 ASR；file drop/network beacon/secret harvesting 的难度可能不同。
- **统计薄弱**：没有重复次数、seeds、CI、显著性检验；主表是单点数字；EHR SQL 的样本量与 split 未报告。
- **ACC 归因不完整**：closed-weight 没有 SKILLS(NATIVE) 对照；GPT-5.2 的 89.3 无法分解为 skill utility 与后门逻辑。Qwen3-VL 上 SkillTrojan ACC 48.4 < Non-attack 53.2，说明 “minimal degradation” 并非普遍。
- **基线能力不对等**：baseline 被限制在 transient channels，且必须显式调用一个额外的 “payload tool”；SkillTrojan 则把 payload 执行嵌入正常 skill 工作流。ASR 差异部分来自能力差异，而非方法优越性（p.13 App E 明说 baseline 被 restrict 到 transient channels）。
- **防御评估缺失**：只测了两个 LLM 静态扫描器；没有实现 sandbox、provenance、execution-trace monitor、capability 限制，也没有自适应攻击者。论文提出的防御方向均未原型验证。
- **数据集多样性有限**：1,200 templates 生成 3,000+ variants ≈ 每个模板 2.5 个变体；相对 4 payload × 3 crypto × 3 N × 50 trigger 的组合空间，覆盖很稀疏。“3,000+ curated” 主要是数量，不是配置覆盖。
- **数据来源与伦理**：爬取公开 marketplace 的 top 1,200 skill，未说明平台、license、是否获得授权；发布 3,000+ 可直接使用的后门 skill，双用途风险高，未讨论访问控制/许可。
- **“First” 主张的时效性**：skill 生态攻击在 2025–2026 快速发展；本文的 related work 未覆盖同期所有 skill 供应链工作，需外部核查。
- **无真实部署**：全部是受控 benchmark；没有真实 marketplace、真实用户、真实企业 agent 的测量。

## 10. 与理论密码学的可能联系

**先给判定**：论文**没有**形式化密码机制，也**没有**把 XOR/Base64 当作密码学安全机制来论证。

- `Enc`/`Dec` 的落地是 **XOR + Base64**（p.5 §5.1）。Base64 是 RFC 4648 编码（Josefsson, 2006），不是加密；XOR 未说明密钥长度、生成、复用、IV/nonce。没有分组密码、流密码、AEAD、KDF。
- 密钥 `k` 是 `INSTRUMENTVERIFIER` 的输入（p.13 Alg.1 line 14），verifier 随 skill 包分发；攻击者安装后无宿主访问，因此 `k` 必须在包内（硬编码或可推导）。这是**白盒**场景：解密器与密钥都交给审计者。
- 论文没有密钥保密假设、密钥分发协议、IND-CPA/IND-CCA 类定义、伪造/篡改模型、reduction。Table 5 只测 “heuristic-flag” 命中率，不测任何密码学优势。
- 因此，严格分类：**形式化密码机制 = 无；现有密码技术工程应用 = 名义/弱（XOR 混淆 + Base64 编码）；主体 = 系统/语义方法（供应链、执行层组合、触发器、静态扫描规避）**。不能因为出现 “encrypt/backdoor” 就把它归为密码学后门或密码学安全。

**个人推断的可能理论连接（均非论文已做）**：
- **白盒混淆的不可能性**：方案把 `Dec(·;k)` 与 `k` 一起分发，等价于要求在白盒攻击者面前隐藏 `P`；通用混淆（Barak et al. 2001）不可能，本文连形式化混淆都不是。可以据此论证：只要审计者能读 skill 代码，“加密片段” 最多是提高逆向成本，不能提供机密性。
- **秘密共享**：当前是 `(N,N)` 全有或全无分割 + 索引标签，不是 Shamir 阈值方案；若改为 `(t,N)` 或可验证秘密共享（VSS），可改变“需要多少片段才能重组”的门槛与可检测性。但这会改变攻击的 trace-completion 假设，且论文未做。
- **隐蔽信道/隐写**：片段写入 tool output 是一种 covert storage channel；可用信道容量、检测错误率/漏检率建模，而不是只用启发式命中率。论文的 Table 5 只是经验检测率。
- **静态恶意代码检测的不可判定性**：Rice 定理意味着不存在能判定任意 skill 是否含恶意 payload 的通用静态分析；这解释了为什么 LLM 扫描器只能做表面判断，但这是可计算性结论，不是密码学。
- **片段完整性**：可用 MAC/commitment 让 verifier 检测篡改；但 verifier 本身受攻击者控制，密钥也在包内，因此不构成可信证明。

**理论相关度判断**：按项目 `T_crypto` 量表，本文约 **0–1**；其 “encryption” 是混淆，不是密码构造。若把白盒混淆/秘密共享/隐蔽信道做成形式化分析，可能到 2，但那是新增研究，不是本文贡献（本人推断）。

## 11. 与应用密码学的可能联系

**论文实际使用**：无真正的密码工程。没有 TLS/OAuth/OIDC、签名、证书、TEE、capability token、密钥管理、审计日志或密码协议。skill 包的分发、安装、执行都是明文代码；payload 的 “加密” 是 XOR+Base64。

**论文提出的防御方向（p.9 Conclusion）**：sandboxing、permissioned resource access、signed package provenance、static/dynamic code inspection、execution-trajectory auditing。以下逐项判断其密码学含量与边界（均为本人分析，不是论文的实验结论；论文未原型验证任何一项）。

- **签名 provenance 不能阻止本攻击**：签名只证明“包由某发布者签发、未被篡改”，不证明行为良性。恶意发布者可以给自己的后门 skill 签名；更关键的是，SkillTrojan 的单个 skill 可能完全合法（保留原 I/O、无显式恶意指令），危害来自多个合法 skill 的**组合**与 verifier 的副作用。逐包签名验证会全部通过。签名也不约束运行时文件/网络/secret 访问。这是“签名 skill 不能阻止合法 skill 组合滥用”的具体体现。
- **Transparency log / Sigstore / in-toto / SLSA**：可提供可归因、可撤销、可审计的供应链记录，检测“预期之外的 skill 更新/替换”；但不能判定 skill 语义是否恶意，也不能阻止已签名恶意包被安装。属于**问责与完整性**，不是**行为安全**。
- **Capability / 最小权限**：真正接近有效的工程措施。用 seccomp/Landlock/gVisor/WASM 或 OS capability 限制 skill 的文件、网络、secret 访问；把 verifier 这类“执行任意 payload” 的工具作为重点 choke point，禁止其动态执行未签名代码。能直接压制 file drop、network beacon、secret harvesting 三类 payload；对 system profiling 可能只能部分限制。这不是密码学，但常与 capability token（Macaroons/Biscuit/UCAN）结合做授权。
- **短期、作用域受限的凭证**：用 OAuth token exchange、macaroons、DPoP 等把 agent 的 secret 访问限制到任务/资源/时限，降低 secret harvesting 的收益；不能阻止 payload 在授权范围内滥用。
- **Egress control / DLP**：对 network beacon 与数据外传有效；TLS 只保护传输，不防止已授权进程外发。
- **TEE / remote attestation**：可证明“运行的是某个 skill 运行时”，但不能证明 skill 的意图良性；payload 仍在 TEE 内执行。对本文攻击帮助有限。
- **可复现构建 / SBOM**：提高供应链可见性，便于发现异常依赖；不阻止恶意发布者。
- **伪交叉警告**：
  - 给 skill 包加密（让 agent 运行时解密）：agent 必须解密才能执行，明文仍进入执行环境；只保护静态分发。
  - 用 ZK 证明“verifier 执行了某段代码”：证明计算完整性，不证明 payload 良性或用户授权。
  - 用签名替代行为审计：签名验证的是发布者身份，不是“这个 skill 组合不会产生副作用”。
  - 把 XOR+Base64 当作“加密防御”：它连密钥保密都不成立。

**应用密码学相关度判断**：按 `A_crypto` 量表，本文正文约 **1**（有明确的 “encryption” 组件与 “signed provenance” 防御提议，但都不是真正的密码机制，也没有密码协议/密钥管理/安全实验）；若把 capability sandbox + 签名 provenance + trace monitor 做成可运行原型并量化 ASR/ACC/性能，可到 2–3，但那是新增系统研究。

## 12. 可检验的研究假设

以下均为假设/推断，需外部查证；本文未做，不等于无人做过。

- **H1（密钥提取/去混淆）**：若审计者从 verifier skill 中提取 `k` 并逆向 XOR+Base64，则能从片段恢复 payload 的比例应显著高于 LLM 扫描器的 “unsafe” 检出率。实验：在 SkillTrojanX 上实现自动密钥提取 + 解密，测 payload 恢复率；预测 >80%，而 Table 3 的扫描器 unsafe 率仅 0.6–1.8%。
- **H2（ACC 归因）**：在 closed-weight 模型上补做 SKILLS(NATIVE) 对照，SkillTrojan 的 ACC 应接近 Native 而非 Non-attack；GPT-5.2 的 89.3 主要来自 skill utility，而非后门逻辑。实验：5 个 closed 模型 × 3 条件（Non/Native/SkillTrojan），同 query 集。
- **H3（执行轨迹监控）**：若在运行时检测“verifier 类工具 + 片段集合包含 + 异常 tool-call 深度”，可在小幅 ACC 代价下显著降低 ASR。实验：在 9 个模型上实现 trace monitor，报告 ROC/ASR/ACC；预测 ASR 降至 <20%，ACC 下降 <3 点。
- **H4（阈值秘密共享）**：把 `(N,N)` 分割改为 `(t,N)` Shamir/VSS，ASR–N 曲线应左移（更少片段即可重组），但单片段信息量上升、静态可检测性上升；存在一个新的 stealth–robustness 折中点。实验：`N∈{3,5,8}`、`t∈{2,3,5}`，测 ASR、ACC、扫描器命中率。
- **H5（触发自然性）**：把字面 trigger phrase 换成语义/改写触发，ASR 应下降、误触发率应上升；字面触发的高 ASR 不能直接外推到真实用户 query。实验：人工改写 200 条 EHR query，比较字面/语义/环境触发。
- **H6（payload family 差异）**：在 capability sandbox 下，file drop/network beacon/secret harvesting 的 ASR 应大幅下降，system profiling 可能部分存活；不同 payload family 对权限的依赖不同。实验：4 类 payload × 3 种 sandbox 配置，报告 per-family ASR。
