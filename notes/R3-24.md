## 1. 150–300 字中文概述

论文提出 AcMAS：不分析 agent 间消息，也不建模显式交互图，而是在每个 agent 的 LLM 最终层激活空间建立“正常推理”原型，用余弦距离阈值检测被污染 agent，再以激活 steering 将其拉回正常流形，替代隔离或删除。方法面向同步与异步 MAS，声称对语义隐蔽的提示注入、工具输出篡改和记忆投毒均有效。实验在 CSQA、GSM8K、InjecAgent、PoisonRAG、HotPotQA 五个场景、四种开源骨干、8–80 个 agent 上报告 F1 0.92–0.95、TCR 约 0.98、ASR 0.02–0.05，检测开销约 0.22% 推理时间，修正开销 12.4%。全文是经验性异常检测与表示工程，没有密码原语、形式化安全定义、定理或证明。

## 2. 研究背景、现有方法不足、精确定义的问题

- **背景**：LLM-based MAS 通过角色分工与结构化通信获得超越单 agent 的协作能力，但也引入两类新攻击面：agent 级攻击（工具、记忆、对抗提示）与 agent 间通信攻击；后者可沿通信边传播并被系统放大（p.1, §1；p.2, Fig.1）。现有 MAS 防御主要依赖可观测消息、交互拓扑或输入级线索（p.3, §2 Related Work）。
- **作者指出的三个设计前提失效**（pp.1–2, §1 ❶–❸）：
  1. **Semantic Camouflage**：现有工作假设攻击表现为“语义显式”的恶意信号，可用输出级语义分析检测；但 MINJA 一类攻击用良性查询与中间桥接步骤逐步注入恶意逻辑，表面行为可信、内部推理已被腐蚀，语义检测失效。
  2. **Asynchronous Incompatibility**：部分防御假设 agent 全局同步、可按轮次建模为 GNN 拓扑；真实 MAS 越来越多采用事件驱动、任务分配式的异步执行，推理计算图与训练图因 staleness 和消息延迟而严重偏离，拓扑模型不可靠。
  3. **Disruptive Mitigation**：现有防御多用隔离/阻断，删除承担关键角色的 agent 会使依赖链断裂、任务崩溃。
- **精确定义的问题**：在每个时间步 t，仅从各 agent 的局部内部激活 `H(t) = {h_i(t)}` 判断哪些 agent 被攻陷，即学习 `f: H(t) → {0,1}^N`；同步 MAS 在每轮对所有 N 个 agent 检测，异步 MAS 只对当前活跃 agent `A_exec(t)` 检测（p.4, Eq.5）。要求不依赖显式交互图、语义监督或全局时间对齐；检测后不是隔离，而是把被污染 agent 的激活拉回正常流形（pp.1–2；pp.4–5）。
- 注意：文中的 “Assumption 1/2” 是对既有工作前提的标签，不是本文形式化威胁模型中的编号假设；本文没有独立的 Assumptions 小节。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **组成**：MAS 含 N 个 agent `A = {A1,…,AN}`；每个 agent 由 LLM backbone `M_i` 驱动；agent 间通过有向通信图 `G = (A,E)` 传递消息，边集可随执行变化（p.3, §3.1）。
- **同步执行**（p.3, §3.1, Eq.1）：共 K 个协调轮；第 t 轮 agent 按尊重通信拓扑的全局顺序执行，
  `R_i(t) = M_i(P_i, Q, {R_j(t−1) | A_j ∈ N_in(A_i)})`，
  其中 Q 为任务查询，P_i 为 agent 特定提示（该设定下通常是共享系统提示 P_sys）；每轮末用聚合算子 `a(t) ← A(R_1(t),…,R_N(t))` 产生中间/最终输出，重复 K 轮得到 `a(K)`。
- **异步执行**（pp.3–4, §3.1, Eq.2–4）：每个 agent 维护任务队列 `Q_i(t)` 与专门角色 `r_i`；只有队列非空且依赖满足的 agent 可执行：`A_ready(t) = {A_i | Q_i(t) ≠ ∅ ∧ deps(A_i,t) satisfied}`；执行时
  `R_i(t) = M_i(P_i, τ_i(t), {m_j(t′) | (A_j,A_i) ∈ E, t′ < t})`，
  完成后向出邻居传播新任务/消息；所有队列为空或到达 `T_max` 时终止。异步没有全局轮次概念，agent 可能多次执行或长期空闲。
- **检测位置**：检测器读取每个 agent LLM 的最终层隐藏状态（最后一个生成 token 的 hidden state），按 agent 独立计算；同步时每轮覆盖全部 N 个 agent，异步时只覆盖 `A_exec(t)`（p.4, Eq.5–7）。检测不读取消息文本，也不使用通信图。
- **修正位置**：检测到异常后，把修正后的激活 `h̃_i(t)` 注入最终层，重新生成该 agent 的响应（p.5–6, §3.4, Eq.14；p.6 “injected at the final layer during response regeneration”）。
- **信任边界（原文没有独立小节，以下为据全文归纳）**：
  - 被信任：LLM 运行时能暴露最终层激活；激活提取函数 φ 与修正注入 hook 未被篡改；用于构造原型的 benign traces 干净；同步/异步调度器会执行检测与修正；聚合器与任务队列状态可信。
  - 不被信任：agent 间消息、工具返回、agent 记忆内容——这些正是攻击入口（p.4, §3.1；App A）。
  - 检测器不需要 agent 身份认证，也不验证消息来源；它假定“被攻陷的合法 agent”会在内部表示上留下偏差。若攻击者控制模型权重或推理运行时，激活可被伪造/绕过，论文未讨论（本人推断）。
  - 同构部署假设：一个 MAS 内所有 agent 共享同一 backbone；不同 backbone 时按 backbone 分别维护原型与阈值，不共享表示空间；混合 backbone 的同一次执行留作 future work（pp.4, 16–17, §3.2/App B）。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- **资产**：MAS 任务的正确性与任务完成率（TCR）、agent 内部推理的完整性、协作结构/角色依赖的可用性；在工具攻击场景中还包括外部动作的安全性（例如 InjecAgent 例子中的智能门锁授权，p.15, App A.2）。论文不以机密性、隐私或密码学完整性为保护目标。
- **攻击者目标**：通过污染单个或多个 agent 的推理，使其输出错误答案或执行有害工具动作，并沿通信边把恶意行为传播给邻居，造成级联失败（p.4, §3.1 “MAS Attack Threat Model”）。在 S-PI/MA 场景中目标是让最终答案错误；在 TA 场景中是让被攻击 agent 执行攻击者指定的工具动作（p.14–15, App A）。
- **攻击者能力**（p.4, §3.1；pp.14–16, App A.1–A.3；p.6, §4.1）：
  1. **Stealthy Prompt Injection（S-PI）**：把对抗提示拼接到 agent 输入，`x_i(t) ← x_i(t) ⊕ p_adv`；用 30 词以内的生成语料，语义与语言风格贴近 ground truth，但把推理引向错误答案（App A.1）。
  2. **Tool Manipulation Attack（TA）**：拦截并修改外部工具返回，`o_tool ← o_tool ⊕ Δ_adv`；修改后的响应在结构上与正常 API 返回一致，但嵌入恶意指令（App A.2；使用 InjecAgent 数据集）。
  3. **Memory Poisoning Attack（MA）**：向 agent 记忆写入恶意条目，`M ← M ∪ {m_adv}`；条目与任务域相关、格式与合法记忆一致，但包含细微错误事实（App A.3；使用 PoisonRAG，并在 HotPotQA 上手工注入）。
  4. **传播**：被攻陷 agent 通过通信边 `(A_i,A_j) ∈ E(t)` 把恶意推理传给邻居；受害者后续激活发生漂移（p.5, Eq.9）。
  5. **攻击强度**：主实验称让被攻陷 agent 比例从 0% 变到 40%（p.7, §4.1）；敏感性分析又称可稳健到 50%，并在 75% 下测试（p.8, §4.5/Fig.4）；p.2 的概述写 0%–40%。原文对范围表述不一致。
- **攻击者未具备/未建模的能力**：没有给出攻击者关于检测器的知识、查询预算、持续时间、是否可自适应规避、是否可污染校准数据、是否能共谋多个 agent、是否能访问模型权重或推理运行时。论文只在 §5 承认 “adaptive attacks … remain an open challenge”，没有做自适应攻击实验（p.9）。
- **前提假设（原文分散，未集中成节）**：
  - 攻击会造成最终层激活相对正常原型的系统性偏移；正常与恶意激活在余弦空间可分（p.4–5, §3.2–3.3）。
  - 可以用一批干净 benign traces 构造正常原型（默认 100 条，p.9, §4.5/Fig.5；p.20, App F.2）。
  - 检测阈值 `τ_detect` 与修正上限 `τ_max` 可在带标签的验证集上标定（p.5–6；pp.17–18, App D）。这意味着方法虽“training-free”，但并非完全无监督：阈值选择使用了攻击/正常的二元标签。
  - 检测与修正运行在可插桩的开源权重模型上；闭源 API 无法提供内部激活（p.9, §5；p.17, App C）。
  - 同一 MAS 内 backbone 同构；异构/混合 backbone 未验证（p.17, App B.3）。

## 5. 核心方案：activation 检测、局部 agent 状态、异步 MAS、训练/阈值

### 5.1 激活提取与局部状态

- 对 agent `A_i` 在时间步 t 的输入 `x_i(t)`，提取
  `h_i(t) = φ(M_i(x_i(t))) ∈ R^d`（p.4, Eq.6）。
- `φ(·)` 把层间隐藏状态聚合成紧凑向量；实现上取**最终层、最后一个生成 token** 的隐藏状态 `h^(L)`，理由是 causal attention 使其聚合前文信息（p.4, §3.2）。论文只做了“层选择”消融（final vs middle 10–14 vs early 1–4），**没有做 token 位置/池化方式消融**（p.8, Table 3）。
- 所有 agent 的激活组成 `H(t) = [h_1(t),…,h_N(t)]^T ∈ R^{N×d}`（p.4, Eq.7）。检测实际是逐 agent 独立进行的，`H(t)` 只是集合记号，并没有跨 agent 的图神经网络或注意力聚合。
- 不同 backbone 使用各自的原型 `μ_normal(M)` 与阈值 `τ_detect(M)`，不跨架构对齐、不迁移检测器（pp.16–17, App B.1–B.2）。

### 5.2 正常原型与散度检测（one-class）

- 给定正常激活集合 `H_normal = {h_1,…,h_M}`，先单位化再求质心：
  `μ_normal = (1/|H_normal|) Σ_{h∈H_normal} h/||h||`（p.5, Eq.10）。
- 对每个 agent 计算余弦散度：
  `δ_i(t) = 1 − <h_i(t)/||h_i(t)||, μ_normal>`（p.5, Eq.11）。
- 二值判定：
  `y_i(t) = 1[δ_i(t) > τ_detect]`（p.5, Eq.12）。
- 这实际上是**基于最终层表示的 one-class 最近原型检测**，不是训练过的线性 probe，也没有分类器训练；训练-free 指不更新 LLM/检测器参数，但原型与阈值仍需数据。

### 5.3 同步/异步的自适应

- **同步 MAS**：每轮用上一轮被判为正常的 agent 激活做动量更新：
  `μ_normal(t) = α μ_normal(t−1) + (1−α) · (1/|N(t−1)|) Σ_{A_i∈N(t−1)} h_i(t−1)/||h_i(t−1)||`，
  其中 `N(t−1) = {A_i | y_i(t−1)=0}`，`α ∈ [0,1]`；实测 `α = 0.7`（p.5, Eq.13）。动量既平滑原型，也试图降低假阴性（漏检的恶意 agent）对原型的污染。
- **异步 MAS**：没有全局轮次，无法做时间对齐；使用初始 benign traces 构造的**固定原型**，只对当前活跃 agent 检测（p.5, §3.3）。作者的理由是高层次推理模式在不同任务阶段相对稳定。
- 这是论文对“异步不兼容”的核心应对：不建模轮次/拓扑，检测判据在异步下不需要全局同步。

### 5.4 激活修正（restorative latent intervention）

- 对被判定异常的 agent，把激活向正常原型插值：
  `h̃_i(t) = h_i(t) + λ_i · (μ_normal − h_i(t))`（p.5, Eq.14）。
- 修正强度按散度自适应：
  `λ_i = min(1, max(0, (δ_i(t) − τ_detect)/(τ_max − τ_detect)))`（p.5, Eq.15）。
- 即：`δ_i → τ_max` 的严重异常获得最大修正（λ→1）；刚过阈值的边缘异常只做约 0.3–0.5 的温和修正（p.6）。`h̃_i(t)` 在最终层注入并重新生成响应（p.6）。
- 这不是隔离、删除或重训，而是推理时的表示插值；其效果依赖“正常原型方向”与“任务特定语义”之间可分离的假设。

### 5.5 阈值标定与默认超参

- `τ_detect`：在带标签验证集上遍历阈值，画 ROC，取最大化 F1 的阈值（pp.17–18, Eq.17–20）；等价于最大化 Youden index（p.18）。
- `τ_max`：取验证集中恶意样本散度的 95 分位，作为修正强度归一化上限（p.18, Eq.21）。
- 默认值：`τ_detect = 0.12`、`τ_max = 0.35`、`α = 0.7`；Table 5 报告五个场景的标定值在 0.10–0.14 / 0.32–0.37 之间，作者据此称阈值跨场景稳定（p.6；p.18, Table 5）。
- 默认 benign traces 数：100；Fig.5 称 5–20 条后 F1 快速上升，约 50 条趋于稳定，与 100 条的差距 <0.03（p.9）。
- 没有训练阶段、没有微调、没有检测器参数学习；这是该方法的重要工程卖点，也是其“无法从新攻击中学习”的来源。

### 5.6 计算开销

- 检测：激活提取 2.3 ms（0.15% 推理时间）、距离计算 <1 ms（<0.07%），合计约 0.22% 推理时间（p.9, Table 4）。
- 修正：仅在检测到异常时触发，额外一次带激活 steering 的推理，185.3 ms（12.4% 推理时间）（p.9, Table 4）。
- 论文没有报告多 agent 并发、激活存储/传输、原型更新或大规模 MAS 的吞吐成本。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- **有定义的部分**：
  - 检测目标被写成一个函数签名 `f: H(t) → {0,1}^N`（p.4, Eq.5），并说明同步/异步的检测范围。
  - 检测器由余弦散度与阈值定义（Eq.10–15）；阈值标定由 ROC/F1 与 95 分位定义（Eq.17–21）。
  - 指标：检测用 Precision、Recall、F1、FPR、AUROC；防御效果用 TCR（是否完成任务并产生最终输出）与 ASR（攻击是否达到预期恶意结果）（p.7, Table 2 caption；p.7, §4.2）。
- **没有的部分**：
  - 没有形式化安全定义（没有 confidentiality/integrity/availability 的游戏、状态机、模拟器或攻击者能力的形式化）。
  - 没有定理、引理、证明、归约或安全界；Eq.8 只是“被攻陷 agent 的激活彼此更接近”的观察/假设，未被证明，而且检测器根本没用 pairwise 聚类项。
  - 没有对“检测器不可被自适应攻击绕过”的保证；作者明确把 adaptive attacks 列为 open challenge（p.9, §5）。
- **安全论证是经验性/比较性的**：在固定攻击集上报告 F1、AUROC、TCR、ASR，并与 G-Safeguard/BlindGuard/PERM/TAM 比较；这些数字说明“在该数据集与该攻击生成方式下更有效”，不构成密码学或系统安全意义上的保证。
- **“unsupervised”措辞需要限定**：论文称不需要 semantic supervision 与 temporal alignment（p.1–2），但 `τ_detect` 通过最大化带标签验证集的 F1 选择，`τ_max` 取恶意验证样本的 95 分位（pp.17–18）。因此它是“无需语义内容标注/无需训练分类器”的 one-class 检测，而不是“完全无标签”的检测。这个区别对部署很重要：新攻击分布可能使标定阈值失配。
- **“robust”是经验范围**：同步/异步、四个 backbone、8–80 agent、0–50% 攻击强度上的 F1/TCR 范围，不是 worst-case 保证；没有自适应对手、没有分布偏移下的保证、没有误报率上界。

## 7. 实验设置与主要结果（MAS 配置、攻击、基线、指标、关键数字、消融）

### 7.1 设置

- **数据集/场景**（p.6, §4.1；p.7, Table 1 caption）：五个 benchmark setting、三类攻击族：
  - S-PI（Stealthy Prompt Injection）on CSQA、GSM8K；
  - TA（Tool Manipulation Attack）on InjecAgent；
  - MA（Memory Poisoning Attack）on PoisonRAG、HotPotQA。
- **执行模式**：同一组 agent 角色、通信图与攻击场景，分别在同步与异步 MAS 下实例化（p.6, §4.1）。同步为 K 轮 lock-step；异步为事件驱动、任务队列/依赖约束；论文未给出 K、T_max、每个数据集的 agent 数、拓扑类型或 MAS 编排框架。
- **骨干**：主表 Table 1 使用 gpt-oss-20b（caption: “The LLM backbone is gpt-oss-20b for all baselines”）；泛化实验覆盖 GPT-OSS-20B、DeepSeek-V3、LLaMA3-8B、Qwen3-30B-A3B（p.6；p.8, Fig.3）。这些都是开源权重模型，以便读取内部激活。
- **规模**：8、20、50、80 个 agent（p.8, Fig.3）；HotPotQA 主实验称五个专门 agent（entity extraction、document retrieval、evidence selection、intermediate reasoning、final answer synthesis，p.7），但 App E.1 的案例研究写成三个 agent（Entity、Retrieval、Reasoning，p.18）——原文前后不一致。
- **攻击强度**：主实验 0–40% 被攻陷 agent（p.7）；敏感性分析到 50% 稳健、75% 测试（p.8, Fig.4/§4.5）。
- **原型/阈值**：默认 100 条 benign traces；`τ_detect = 0.12`、`τ_max = 0.35`、`α = 0.7`；每个场景的标定值见 Table 5（p.18）。
- **基线**：G-Safeguard（监督式 GNN 检测 + 隔离）、BlindGuard（无监督对比学习图异常检测 + 隔离）、PERM（对比学习 GAD）、TAM（affinity-driven GAD）（p.7, §4.1）。Table 2 只比较 G-Safeguard/BlindGuard 的防御效果；PERM/TAM 只出现在 Table 1 的检测比较。
- **指标**：检测 F1/Precision/Recall/FPR/AUROC；防御 TCR/ASR；任务性能 CSQA/GSM8K accuracy、HotPotQA EM/F1（p.7；p.20, Table 6）。
- **硬件/实现**：延迟在单张 A100 上测（p.9, §4.6）；未给 GPU 型号之外的训练/推理细节（本方法无训练）。未给运行次数；“mean ± standard deviation across runs” 中的 runs 数未说明（p.6, Table 1 caption）。

### 7.2 主结果（数字以 PNG 核对后的 Table 1/2 为准）

- **检测 F1（Table 1, p.6）**，顺序为 CSQA / GSM8K / InjecAgent / PoisonRAG / HotPotQA：
  - AcMAS 同步：0.95 / 0.95 / 0.93 / 0.95 / 0.94；异步：0.94 / 0.94 / 0.92 / 0.94 / 0.93。
  - G-Safeguard 同步：0.74 / 0.71 / 0.69 / 0.72 / 0.70；异步：0.46 / 0.44 / 0.41 / 0.43 / 0.42。
  - BlindGuard 同步：0.58 / 0.56 / 0.54 / 0.57 / 0.55；异步：0.35 / 0.33 / 0.31 / 0.33 / 0.32。
  - PERM 同步：0.38 / 0.37 / 0.64 / 0.36 / 0.33；异步：0.27 / 0.26 / 0.43 / 0.25 / 0.24。
  - TAM 同步：0.28 / 0.27 / 0.51 / 0.27 / 0.26；异步：0.19 / 0.18 / 0.34 / 0.18 / 0.17。
  - 五数据集均值：AcMAS 同步约 0.944、异步约 0.934；G-Safeguard 同步约 0.712、异步约 0.432；BlindGuard 同步约 0.560、异步约 0.328。
- **检测 AUROC/FPR（Table 1）**：AcMAS AUROC 97.58–99.48，FPR 0.04–0.07；G-Safeguard 同步 AUROC 90.64–94.32、异步 61.42–70.58；BlindGuard 同步 78.09–82.17、异步 50.33–55.24。TAM 在多个场景 AUROC 低于 50（如 CSQA 同步 41.67、异步 18.43），说明这些通用 GAD 基线在隐蔽攻击下接近随机。
- **防御效果（Table 2, p.7）**：
  - AcMAS TCR：1.00 / 1.00 / 0.97 / 0.96 / 0.96；ASR：0.02 / 0.03 / 0.02 / 0.05 / 0.05。均值 TCR ≈ 0.978、ASR ≈ 0.034。
  - G-Safeguard TCR：0.89 / 0.90 / 0.86 / 0.81 / 0.68；ASR：0.19 / 0.17 / 0.10 / 0.06 / 0.15。均值 TCR ≈ 0.828。
  - BlindGuard TCR：0.81 / 0.84 / 0.82 / 0.78 / 0.66；ASR：0.25 / 0.23 / 0.16 / 0.15 / 0.33。均值 TCR ≈ 0.782。
  - No Defense：TCR 在表中为 “–”，ASR 为 0.91 / 0.89 / 0.85 / 0.87 / 0.88。
  - 主要结论：隔离式防御在 HotPotQA 这类多跳、角色依赖强的任务上 TCR 仅 0.66–0.68；AcMAS 保持 0.96，同时把 ASR 压到 0.02–0.05。
- **任务性能（Table 6, p.20）**：Clean（无攻击）CSQA 98.9%、GSM8K 82.8%、HotPotQA EM 62.1/F1 76.3；Attack-only 16.1%/9.0%/4.4/7.1；G-Safeguard 78.9%/63.9%/35.5/42.0；BlindGuard 73.5%/58.1%/33.2/41.7；AcMAS 98.6%/81.3%/61.9/75.2。AcMAS 相对 Clean 的下降为 0.3/1.5/0.2/1.1 个百分点。
- **消融（Table 3, p.8；HotPotQA 同步、gpt-oss-20b）**：
  - Full AcMAS：Prec 0.96、Recall 0.95、F1 0.95、TCR 0.98、ASR 0.05。
  - 去掉自适应原型更新（w/o Adaptive Update）：0.85/0.89/0.87/0.98/0.05；F1 从 0.95 降到 0.87，是核心组件消融中降幅最大的一项（层选择中的 early layers 更低，但属于另一组消融）。
  - 去掉单位化（w/o Normalization）：0.88/0.91/0.89/0.98/0.05；F1 降到 0.89。
  - 把修正换成隔离（w/o Correction）：0.96/0.95/0.95/0.68/0.15；检测不变，但 TCR 从 0.98 降到 0.68、ASR 从 0.05 升到 0.15。这是“修正优于隔离”的直接消融。
  - 层选择：Final 0.96/0.95/0.95/0.98/0.05；Middle 10–14 0.85/0.87/0.86/0.94/0.08；Early 1–4 0.68/0.74/0.71/0.82/0.22。最终层最好，早层信息不足。
- **敏感性与数据效率**：
  - 阈值：`τ = 0.12` 最优（F1 0.95）；`[0.10,0.14]` 内 F1 >0.92；`τ=0.08` 时 FPR 0.12，`τ=0.16` 时 FNR 0.15（p.8, §4.5/Fig.4）。
  - 攻击强度：F1 >0.90、TCR >0.90 可维持到 50% 被攻陷；75% 时 TCR 0.82，仍高于隔离基线的 0.52（p.8, §4.5；Fig.4 caption）。
  - benign traces：5–20 条快速上升，约 50 条稳定，与 100 条默认值差距 <0.03（p.9, Fig.5）。
- **效率（Table 4, p.9）**：激活提取 2.3 ms（0.15%）、距离 <1 ms（<0.07%）、修正 185.3 ms（12.4%）；检测合计约 0.22% 推理时间，修正仅在异常时触发。
- **域偏移（Tables 7–8, p.20）**：
  - CSQA→InjecAgent：ntarget=0/50/100 时 F1 0.49、FPR 1.00；1:1.5 时 0.58/0.70；1:2 时 0.86/0.16；1:3 时 0.92/0.07。
  - CSQA→PoisonRAG：0/50 时 0.49/1.00、0.56/0.83；1:1 时 0.83/0.19；1:3 时 0.93/0.06。
  - 解读：初始域偏移下检测器把所有样本判为异常（FPR=1.00），不是“轻微下降”；加入目标域 benign traces 后才恢复。作者也承认域偏移是主要限制（p.9, §5）。

### 7.3 原文内部数值/口径不一致（不作为支持论文主张的证据）

- **摘要/引言 vs Table 1 的异步基线**：摘要与 p.2 写 “+0.55 F1 in asynchronous settings (0.93 vs. 0.38)”。但 Table 1 中 G-Safeguard 异步五数据集均值约 0.432，BlindGuard 约 0.328；0.38 恰好是两者平均。同步的 “0.94 vs. 0.72” 则只取 G-Safeguard（0.712），没有取两基线平均（0.636）。这提示 +0.22 与 +0.55 可能使用了**不同的基线聚合口径**：若统一取 G-Safeguard，异步增益约 0.50；若统一取两基线平均，同步增益约 0.30。两种统一口径都无法同时复现 0.22 与 0.55。
- **p.2 同一段并列两组数**：“0.95 vs. 0.74（同步）；0.94 vs. 0.46（异步）” 是 CSQA 单行；“0.94 vs. 0.72；0.93 vs. 0.38” 是五数据集均值。原文没有标注这两个口径，读起来像自相矛盾。
- **“avg F1: 0.72, std: 0.32” 的统计口径**：Table 1 caption 明确 std 是 “across runs”（同一单元格多次运行的方差）；G-Safeguard 跨五个数据集的 F1 均值约 0.712，但跨数据集标准差仅约 0.02。把 0.32 说成 avg 的 std，混用了“跨数据集平均”和“运行间标准差”。AcMAS 的 “std ≤0.04” 同样是运行间标准差，不是跨数据集方差。
- **AUROC 范围**：§4.2 称 AcMAS AUROC 98.5–99.5，但 Table 1 最低为 InjecAgent 异步 97.58；实际范围 97.58–99.48。
- **G-Safeguard FPR**：§4.2 称 FPR 0.20–0.26，这只覆盖同步设置；异步 FPR 为 0.45–0.50。
- **攻击强度范围**：p.2 与 §4.1 写 0–40%，§4.5/Fig.4 写稳健到 50%、并测试 75%。主表的实际攻击率也未给出。
- **Table 3 vs Table 1/2**：Table 3 的 Full AcMAS（HotPotQA 同步）F1 0.95、TCR 0.98；Table 1 的 HotPotQA 同步 F1 为 0.94，Table 2 的 TCR 为 0.96。同一设置出现 0.94/0.95 与 0.96/0.98 两组值。
- **No Defense TCR**：Table 2 中 No Defense 的 TCR 是 “–”，但正文说 G-Safeguard 在 HotPotQA “TCR drops from 0.96 to 0.68”；0.96 的来源未在表中给出（可能是 clean run）。
- **HotPotQA agent 数**：p.7 说五个专门 agent，App E.1 案例研究说三个 agent（Entity/Retrieval/Reasoning）。案例可能是简化，但原文没有说明。
- **Intro 的 0.97/0.03 vs §4.2 的 0.98/0.04**：p.2 写 “0.97 task completion rate … attack success rate to 0.03”；§4.2 写 avg TCR = 0.98、avg ASR = 0.04。Table 2 支持 TCR 0.978、ASR 0.034，四舍五入应为 0.98/0.03。
- **Abstract 的 F1 0.92–0.97 across backbones vs Fig.3 的 accuracy >97%**：Fig.3 的纵轴是 “Accuracy (%)”，不是 F1；§4.3 也写 “detection accuracy (>97%)”。摘要把跨 backbone 的 F1 范围写成 0.92–0.97，但图中没有 F1 曲线，二者不是同一指标。

### 7.4 缺失的实验

- 没有自适应攻击/检测器规避实验；没有原型投毒实验；没有校准集被污染的鲁棒性实验。
- 没有与 activation/attention 类内部信号方法的对比：A-Trust（attention-based trust）、RevPRAG（RAG poisoning 的 activation analysis）、Abdelnabi et al.（task drift 的 activation delta）、JB-Shield（activated concept analysis）都只在 Related Work 提及，未作为基线。
- 没有 text-embedding/输出表示的同结构 one-class 基线，因此无法判断收益来自“内部激活”还是“任何高维表示 + 余弦阈值”。
- 没有 token 位置/池化方式消融（只做了层选择）；没有不同 K、T_max、拓扑、agent 数的受控实验（规模只给 8–80 的总曲线）。
- 没有运行次数、置信区间、显著性检验；没有延迟/吞吐随 agent 数增长的测量；没有真实部署或用户研究。
- 没有对 ASR 的逐攻击操作化定义（尤其 TA 的“恶意工具动作成功”如何判定），TCR 只检查“产生最终输出”，不检查答案正确性（p.7）。

## 8. 贡献与创新点（按原文主张）

- **贡献 1：activation-based anomaly detection**。把正常 agent 推理建模为激活空间中的分布/原型，以分布偏离识别攻击；不需要语义监督，也不需要同步轮次或显式交互图（pp.1–2, §1；pp.4–5, §3.2–3.3）。
- **贡献 2：restorative latent intervention**。检测到异常后，用激活插值把 agent 拉回正常流形，而不是隔离/删除；作者称这能保留角色分工与协作结构，避免任务崩溃（pp.1–2；pp.5–6, §3.4）。
- **贡献 3：系统性评测**。五个 benchmark setting、三类攻击族、同步/异步、四种开源 backbone、8–80 agent、0–50% 攻击强度（另测试 75%）、域偏移与效率分析（pp.6–9；pp.18–20）。
- **贡献 4：首个此类框架的优先权主张**。Impact Statement 称 “to the best of our knowledge, AcMAS represents the first framework to address adversarial compromise in MAS via activation-level analysis and correction”（p.10）。这是作者主张，无法从论文内部证据独立验证。
- **与直接相关工作的差异**：
  - G-Safeguard（Wang et al., 2025b）：监督式 GNN、需要拓扑/轮次、隔离；AcMAS 用局部激活、无图、修正。
  - BlindGuard（Miao et al., 2025）：无监督对比图异常检测、隔离；AcMAS 用 one-class 原型、修正。
  - NetSafe（Yu et al., 2024）：拓扑安全；同样依赖图结构。
  - A-Trust（He et al., 2025a）：用内部 attention 评估消息可信度，是最近邻的“内部信号”工作，但对象是消息信任而非 agent 级激活原型，且未被比较。
  - RevPRAG（Tan et al., 2024a）：用 LLM activation 分析检测 RAG 投毒，是方法学上最接近的单 agent 工作；本文把思路扩展到 MAS，但未把它作为基线。
  - MINJA（Dong et al.）：只作为“语义隐蔽攻击”的动机引用，未在实验中实现其渐进注入策略。
- **可复现资源**：全文未发现代码仓库、数据发布或复现脚本链接；实验依赖公开数据集（CSQA、GSM8K、InjecAgent、PoisonRAG、HotPotQA）与开源权重模型。附录给出攻击样例（App A）、逐 backbone 设置（App B）、开放权重论证（App C）、阈值标定（App D）、HotPotQA 案例（App E）、任务性能与域偏移（App F），但没有完整 MAS 提示、编排框架、运行配置或每数据集 agent 数。复现性为部分可复现。

## 9. 局限、失败案例、作者承认的不足

**作者明确承认/写出的**：

- **Domain shift**：原型来自源域 benign traces，部署到新域时表示不匹配，性能下降；加入少量目标域 traces 后可快速恢复；作者称这是主要限制，系统性的域自适应原型构造留作 future work（p.9, §5；p.20, App F.2）。
- **Adaptive attacks**：逐步漂移激活分布的自适应攻击仍是 open challenge；攻击者需要长期注入并同时避免逐查询检测，执行难度高；作者提出 anomaly-gated update（只让被判为 benign 的样本进入原型更新）作为自然缓解，但明确留待 future work，未做实验（p.9, §5）。
- **Open-weight LLM**：方法需要内部激活，闭源 API 不适用；作者论证这与“成本/隐私驱动的本地开源模型 + 云端升级”的异构 MAS 趋势一致，并称本地 agent 正是最安全关键的部分（p.9, §5；p.17, App C）。
- **Mixed-backbone MAS**：当前只评估同构 MAS；同一执行中不同 agent 使用不同 backbone 的情况留作 future work，可能需要共享表示空间或 ensemble（p.17, App B.3）。
- 原文**没有独立的 Limitations 章节**；§5 标题为 “Discussion and Limitation”，但只覆盖上述三点。

**本人推断的局限/失效场景**：

- **白盒与运行时假设**：必须能读取最终层激活并在最终层注入修正；闭源 API、只提供文本输出的 agent、或不允许 hook 的推理栈无法部署。若运行时被攻陷，攻击者可直接伪造“正常”激活，检测与修正都失效。
- **标定需要攻击标签**：`τ_detect` 用带标签验证集的 F1 选择，`τ_max` 用恶意样本的 95 分位；新攻击类型/新域可能使阈值失配。所谓 “without semantic supervision” 容易被误读为“完全无监督”。
- **原型污染**：默认 100 条 benign traces 必须干净；若校准阶段已有 agent 被感染，原型会被拉偏。作者只提出 anomaly-gated update，未评估。
- **攻击评估不够“隐蔽/自适应”**：S-PI 是 30 词生成的对抗语料，TA 是 InjecAgent 的模板化工具返回，MA 是 PoisonRAG/手工事实注入；没有实现 MINJA 式渐进注入，也没有检测器感知的规避。论文的核心动机是“语义隐蔽”，但实验攻击仍主要是静态、非自适应构造。
- **检测器过于简单**：最终层最后 token + 余弦质心 + 单阈值；Eq.8 的“被攻陷 agent 激活彼此接近”没有被检测器使用。若恶意激活与正常激活在余弦空间重叠，或正常 agent 因任务/域变化产生大偏移，F1 会下降。没有 text-embedding 对照，无法证明“内部激活”本身带来增益。
- **修正的语义风险**：`h̃ = h + λ(μ_normal − h)` 是线性插值，λ 越大越靠近全局正常原型，可能抹掉角色/任务特定信息；论文只报告平均 TCR/ASR，没有逐样本语义质量、人工评估或“修正后是否仍能正确推理”的分析。严重异常 λ→1 时尤其可疑。
- **同构假设**：一个 MAS 内共享 backbone 才有一个原型；异构 MAS 需要每 backbone 一个原型，跨架构不可迁移。论文没有测跨 backbone 迁移，也没有测混合 backbone。
- **隐私/伦理主张缺少证据**：Impact Statement 称只分析激活、避免内容日志，因而 “without compromising privacy” 且 “ensuring adherence to data privacy standards”（p.10）。但激活由完整输入计算，高维激活可被用于重建/推断输入；论文没有做激活反演、成员推断或泄漏测量。这个主张是规范性的，不是实验结论。
- **无形式化保证**：F1/AUROC 不是安全保证；没有 worst-case、没有自适应对手、没有误报上界。检测 F1 0.93–0.95 按 1−F1 粗算仍有 5–7% 检测误差，ASR 仍为 0.02–0.05。
- **指标/报告问题**：TCR 只要求“产生最终输出”，不要求答案正确；ASR 未逐攻击定义；无运行次数/置信区间；主表攻击率未给；域偏移初始 FPR=1.00 的严重性被“性能下降”轻描淡写。
- **规模与成本**：8–80 agent 的检测准确率曲线不等于真实 MAS 吞吐；每个 agent 每步都要提取激活，修正还要额外一次推理（12.4%），在大规模/高频 MAS 中成本可能不可忽略。论文没有报告显存、激活存储、通信开销。
- **安全边界窄**：只防“推理被污染”的 agent，不防共谋、Sybil/恶意注册、供应链后门、工具/记忆的持久化控制、侧信道；检测器逐 agent 独立，无法利用“哪些 agent 在合谋”的结构信息。
- **dual-use**：p.1 明确警告论文包含可能有害的示例；App A.1–A.3 给出可复用的攻击 prompt、工具响应注入模板与记忆投毒样例。作者没有讨论发布审查、访问控制或攻击样例的滥用风险。
- **“first”主张**：无法从论文内部验证；至少 A-Trust、RevPRAG、Abdelnabi et al. 已在相邻方向使用内部表示，优先权需要独立文献核查。

## 10. 与理论密码学的可能技术连接（区分原论文已做 / 个人推断）

**论文实际使用的机制（必须先说清）**：

- 余弦距离、单位化、质心原型、单阈值判定、动量更新、线性激活插值、ROC/F1 阈值标定。这些是**表示学习/异常检测/表示工程**方法，不是密码学。
- **没有**加密、签名、MAC、承诺、零知识、MPC、FHE、TEE、远程认证、差分隐私、匿名凭证、密钥管理或任何密码协议；**没有**形式化安全定义、定理、引理、证明、归约或安全游戏。
- **不要混淆**：激活检测不是“认证”（authentication），也不是“完整性校验”（integrity attestation）。它不验证 agent 身份、消息来源或模型未被篡改；它只是根据内部表示与正常原型的统计偏离打分。一个被攻陷的 agent 仍可能通过语义上合理的输出造成危害；一个正常的 agent 也可能因域偏移被误判。
- 论文的 “security” 是经验性的 detection/defense effectiveness，不是密码学意义上的 security。

**个人推断（明确标为推断，不是论文已做）**：

- **可形式化的“检测不可区分性”**：可把规避检测写成游戏：challenger 从正常分布 D_norm 或攻击分布 D_adv 采样输入，detector 输出 y；要求对任意多项式时间对手，`|Pr[y=1|D_adv] − Pr[y=1|D_norm]|` 显著。这个定义更像统计假设检验/在线学习中的 evasion 界，而不是密码学：没有密钥、没有计算困难性假设、没有 completeness/soundness。论文没有做这一步。
- **样本复杂度/泛化界**：原型与阈值可从 PAC/VC 或 concentration 角度分析，给出在分布偏移下的误报/漏报界；这是学习理论，不是密码学。论文只给经验曲线（Fig.5、Tables 7–8）。
- **认证数据来源**：若把 benign traces 的来源、模型权重、阈值版本做签名/attestation，可降低“原型投毒/模型替换”的风险；这是应用密码学接口（见 §11），不是理论密码学，也不是论文已做。
- **激活的隐私性**：若激活需要跨 agent/跨服务共享，可用 MPC/TEE/DP 保护；但本文的检测是本地逐 agent 的，不共享激活，因此这些机制没有用武之地。若未来做集中式检测，才需要。
- **相关度判断**：按项目 `T_crypto` 量表，本文正文约 **0**；最多可因“检测/认证类比”给到 1，但论文没有使用任何密码学理论。若额外做上述 evasion game 或 PAC 界，那是**新增研究**，不是本文贡献。

## 11. 与应用密码学/密码工程可能的技术连接（同上）

**论文实际使用**：

- **无**。没有 OAuth/OIDC、mTLS、签名、加密、TEE、capability token、审计日志、密钥管理或任何密码协议。论文中的“open-weight”“local deployment”只是部署假设，不是认证或可信执行机制；`φ(·)` 读取激活也不是可信测量。
- 防御完全在**模型表示层**：最终层激活、余弦阈值、激活插值。它不是一个 reference monitor，不能提供不可绕过的执行约束；攻击者可通过改变输入语义、域偏移或运行时篡改绕过。

**个人推断的工程接口（均标为推断，需新增设计与实验）**：

1. **可信执行/远程认证的激活提取**：在 TEE（如 confidential VM/GPU）中运行模型与激活提取 hook，远程认证模型权重 hash、推理栈与检测器版本；检测端验证 attestation 后再信任激活。作用：防止运行时替换模型、伪造激活或篡改修正 hook。局限：TEE 侧信道、GPU 支持、性能开销；认证只证明“运行了什么”，不证明“检测正确”。
2. **签名模型/权重供应链**：对 backbone 权重、tokenizer、检测器配置、阈值文件做签名与哈希锁定；加载前验证。作用：防止供应链后门/模型替换导致原型失配。局限：不能防训练时后门；签名不保证模型行为安全。
3. **哈希链/签名审计日志**：记录每次检测的 `(agent_id, timestamp, δ_i, y_i, τ_detect, model_hash)`、修正的 `(λ_i, h̃ 版本)`、原型版本；写入透明日志/append-only store。作用：问责、取证、复现实验、检测阈值漂移。局限：事后审计，不阻止攻击；日志完整性 ≠ 检测正确性。
4. **agent 身份与消息认证**：agent 间用 mTLS/签名消息/可验证凭证标识发送者与角色。作用：防止冒充、Sybil、消息篡改；对应 p.2 Fig.1 的 AiTM/insider 风险。局限：被攻陷的合法 agent 仍可发送语义恶意消息；认证不解决“推理被污染”。
5. **修正操作的 capability 授权**：把“注入激活/重生成响应”作为特权操作，用 capability token（绑定 agent、任务、时间、修正幅度上限）授权，由运行时强制执行并审计。作用：防止检测器/修正器被滥用为任意干预；最小权限。局限：策略粒度、撤销、性能；不能提升检测准确率。
6. **激活通道的机密性**：若检测器远程部署，用 TLS + attestation 传输激活；静态存储加密。作用：防止激活在传输/存储中被窃取或篡改。局限：若推理端已泄露，加密无济于事；激活本身可能含敏感信息，加密不等于不可推断。

**伪交叉警告**：

- 只给检测日志签名，不会让检测更准；签名只保证“日志没被改”，不保证“日志里的判断对”。
- 用 TEE 跑检测器，不会让分类器正确；TEE 保护的是执行完整性/机密性，不是语义正确性。
- 用 ZK 证明“模型确实执行了某次推理”，证明的是计算完整性，不是“该 agent 未被攻陷”或“输出安全”；LLM 推理是概率性的，证明也不覆盖语义。
- 加密激活/上下文，若检测器和 LLM 需要解密后计算，明文仍在运行时；加密只保护静态/传输。
- 用 OAuth/capability 替代激活检测，会丢掉“内部推理已被腐蚀但输出仍合法”的检测能力；反之只用激活检测，没有不可绕过的执行点。真正有价值的是“激活检测（语义层）+ 身份/授权（执行层）+ 审计（问责层）”的组合，但这是新增系统研究，不是本文贡献。
- 把“activation-based detection”说成“attestation”是概念混淆：attestation 是对测量/声明的密码学验证，activation 是对表示的统计打分。

**应用密码学相关度判断**：按项目 `A_crypto` 量表，本文正文约 **0–1**（没有识别任何密码机制使用点；唯一相关的是“open-weight/local deployment”部署假设）；若把上述 TEE attestation + 签名审计 + capability 修正授权做成可运行原型并量化安全/性能收益，可到 2–3，但这属于新增工程研究。

## 12. 后续可以验证的研究假设

以下均为**假设/推断**，需查证外部文献；本文未做，不等于无人做过。

- **H1（检测器感知的自适应规避）**：若攻击者知道 AcMAS 的原型与阈值，并能在多轮中逐步漂移激活（每次偏移小于检测阈值），则检测 F1 会显著下降；漂移速率与 F1 下降应存在可测关系。实验：在本文同步/异步环境中加入在线投毒/渐进漂移攻击，比较固定原型 vs 动量原型 vs anomaly-gated 更新。
- **H2（原型投毒）**：若校准集中有 p% 的被感染 traces，`μ_normal` 会被拉偏，F1 随 p 下降；anomaly-gated update 只能部分缓解。实验：p = 0/5/10/20%，测 F1、FPR、ASR，并比较“签名/可信校准集”与普通校准集。
- **H3（内部激活的增益是否真实）**：用同样的 one-class 余弦阈值检测器，分别输入最终层激活、输出文本 embedding、attention 特征、随机投影；若三者 F1 接近，则“内部激活优于文本”不成立。这是隔离“activation”贡献的关键对照，本文没有做。
- **H4（跨 backbone 迁移）**：在 GPT-OSS-20B 上标定的原型/阈值直接用于 LLaMA3-8B 或 Qwen3-30B-A3B 会失效；每 backbone 独立标定才能恢复。实验：zero-shot 迁移 vs 目标 backbone 上 50/100 条 traces 重标定，测 F1/FPR。
- **H5（激活的隐私泄漏）**：若把 `h_i(t)` 暴露给第三方检测器/日志，攻击者可训练反演模型重建输入中的实体/敏感片段；泄漏率随层数与维度变化。实验：在本文数据上做 activation inversion / membership inference，量化 token/entity recovery；若显著，则 Impact Statement 的“privacy-preserving”主张不成立，需要 TEE/DP/本地检测。
- **H6（修正 vs 隔离在高攻击强度下）**：当 50–75% agent 被攻陷时，激活修正可能把多个 agent 拉向同一正常原型，导致角色语义坍缩；TCR 可能保持，但答案正确率/多样性下降。实验：在 50/75% 强度下同时测 TCR、ASR、任务 accuracy、角色输出多样性，并做人评。
- **H7（审计/attestation 的工程收益）**：给校准 traces、模型权重、检测日志加签名/attestation，能否降低原型投毒与模型替换的成功率？实验：2×2（attestation on/off × 投毒 on/off），测攻击成功率和部署开销。此假设属应用密码学接口验证，不是本文已做。
