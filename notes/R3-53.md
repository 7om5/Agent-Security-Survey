## 1. 150–300 字中文概述

论文研究多轮 CLI Agent 的执行期安全，主张风险在轨迹中逐步累积，单次响应或任务级预检不足以刻画。作者提出 Agent MechSuits：在冻结的开源模型每一交互步取最后一 token 的残差流表示，用步级标注训练的线性探针检测当前步是否即将执行危险命令；若判定危险，则从二分类探针权重差中选出 top-10 个隐藏维度，构造二值 steering 向量并广播到所有 token，以自适应强度 α 干预该层表示，从而在不改权重的情况下把生成推向拒绝。作者另建 MAS 基准：194 个任务（98 恶意/96 良性）、Docker 可执行环境、三种 7–9B 模型、步级标注与反事实增强。实验报告当前步检测平均 97.32% 准确率、lookahead 最高 96.77%、ASR 从 85.99% 降到 13.36%（按 Table 2 三模型均值应为 11.78%），生成崩溃率升到 18.54%。全文是表征层干预与行为评测，不含密码学。

## 2. 研究背景、现有方法不足、精确定义的问题

- **背景**：CLI Agent 通过 shell 直接操作计算机，Claude Code、Codex、Cursor CLI、Gemini CLI 是当前最活跃的一类 Agent（p.1, §1）。攻击者可用 MITRE ATT&CK 式 TTP 把 CLI Agent 武器化，造成数据丢失、隐私泄露、金融欺诈、基础设施破坏（p.1, §1）。
- **多轮风险的特殊性**：CLI Agent 反复把环境反馈并入上下文；风险很少局限于单个动作，而会在多步中累积并与环境反馈耦合（pp.1–2, §1）。论文举例：先创建空脚本或改权限看似良性，后续写入恶意 payload 或配置自动执行后，前面的动作才成为攻击链的一部分（p.3, §2.1）。因此安全不能只看单步输出，必须看整条轨迹 τ。
- **现有方法不足**：
  1. **外部 guardrail**（GuardAgent、ShieldAgent、AGrail 等）在 Agent 外部做实时监控，但依赖预定义或自动生成的安全规则，难以对每一步做细粒度行为控制（p.2, §1；p.9, §7）。
  2. **机制可解释性安全方法**多集中在单轮或 jailbreak 式 QA，安全被当作静态 prompt–response 对的性质，无法捕捉多轮 Agent 执行中不断变化的风险状态（p.2, §1；p.9, §7）。
  3. **任务级预检门**把安全当作初始指令的静态属性；但 CLI Agent 的风险可能在执行途中才出现，初始任务看似良性或欠指定（p.2, §1）。
- **精确问题**：能否用 CLI Agent 的步级内部表示，在多轮交互中检测有害执行状态并 steering Agent 行为？（p.2, §1 原文 “Can step-level internal representations of CLI agents be used to detect harmful execution states and steer agent behavior during multi-turn interaction?”）
- **配套问题**：现有 Agent 安全基准主要评估最终任务结果或策略违规，缺少可供 hidden-state probing 与表示干预复用的步级标注轨迹；因此作者构建 MAS（pp.5–6, §3）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **组件**：冻结的 LLM Fθ（LLaMA-3.1-8B、Qwen-2.5-7B、Gemma-2-9B）、ReAct 式 CLI Agent（每轮一个 Think + 一个 Act；Act ∈ {bash, finish, answer}）、Ubuntu Docker 容器、bash 执行器、环境观测、系统提示（p.5, §3；p.18, App C.2；Figure 9, p.25）。防御侧另有步级线性探针 gϕ、steering 模块、外部 LLM 控制器（DeepSeek-V4-Pro）与评测 judge（GPT-4o）（pp.4–6, §2.3–§4）。
- **交互流程**（p.3, §2.1 Definition 2）：给定任务 x，c0=(x)；每步 `a_t ~ P_agent(·|c_{t-1})`，`o_t ~ P_env(·|c_{t-1},a_t)`，`c_t=(c_{t-1},a_t,o_t)`；产生轨迹 `τ=(x,a1,o1,…,aT,oT)`。Agent 的上下文包含初始任务、先前动作与最新容器观测；长输出会被截断（p.18, App C.2）。
- **防御插入点**：每一步在 Agent 生成动作前取 `c_{t-1}` 的最后一 token 隐状态做探针推断；若判为有害，则在同层对所有输入 token 的隐状态做 `H + α1v^T` 干预，再把修改后的表示送入后续层生成动作（p.5, §2.3）。探针与 steering 都在模型内部，不是外部 guardrail。
- **信任边界**：论文没有独立的 trust-boundary 图或小节。可辨识的边界是：模型权重与残差流由防御者控制（white-box 前提）；用户任务文本与容器环境观测是攻击者可控输入；Docker 是 OS 隔离边界；外部控制器/judge 通过 API 接收任务上下文与候选动作，是额外的数据出流点（此点为本人据 §2.3、§4、App B.1 归纳）。攻击者不能读隐状态、不能改权重、不能直接改探针；但可通过自然语言任务或环境注入影响 Agent 的上下文。
- **注意**：论文的 motivating examples 是商业 CLI Agent，但实验 victim 是三个小型开源模型；商业闭源 Agent 不暴露 hidden states，无法直接套用该框架（见 §9）。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- **资产**：宿主文件系统与系统文件、凭据/权限、网络与持久化机制、服务可用性；用户良性任务的完成度；模型的安全对齐行为本身（负向 steering 可把拒绝翻转为执行，p.8–9）。论文没有集中列举资产，以上为本人据 MAS 任务类型（p.18, App C.2）与案例（p.9, Figure 4）归纳。
- **攻击者目标**：让 CLI Agent 执行有害命令，包括破坏性文件删除、敏感系统位置写入、提权、密码/sudoers 篡改、持久化、反弹 shell、恶意代码生成与数据外泄（p.18, App C.3）；在 prompt-injection 设定下，把良性任务重定向到恶意目标（p.9, §6；pp.22–23, App F.1）。
- **攻击者能力**：
  - 控制恶意任务的用户指令（MAS 的直接恶意任务）；可指定自然语言目标、环境初始化代码与验证探针（p.18, App C.2）。
  - 在 prompt-injection 压力测试中，可让环境观测携带注入目标（p.9, §6；p.22, App F.1）。
  - 通过 Agent 间接执行任意 bash；但不能直接访问模型权重、隐状态、探针参数或 steering 方向；没有自适应攻击、投毒、后门或工具供应链能力（这些否定能力为本人据系统设定归纳，原文未逐条列出）。
- **防御者能力**：white-box 读取权重与每一层残差流；可离线训练线性探针；可在推理时改 hidden states；可调用外部 LLM 控制器与 judge；可用 Docker 隔离（p.5, §2.3；p.17, App C.1）。
- **前提假设**（原文分散，未集中成节）：
  - victim 是开源白盒模型，隐状态可获取；模型冻结，探针按模型/层训练（p.4, §2.2；p.5, §2.3）。
  - 每个交互步有可操作的二值安全标签；“critical harmful execution step”可被人工/LLM 标注区分（p.4, §2.2；p.18, App C.3）。
  - 恶意任务在 Docker 内执行，不造成真实宿主损害（p.5, §3；p.18, App C.2）。
  - 攻击是静态的：攻击者不知道探针/steering，也不会针对其做规避；主实验没有自适应攻击（此为本人推断；原文只做了固定任务与一个外部触发的 injection 压力测试）。
  - 评测 judge（GPT-4o）与控制器（DeepSeek-V4-Pro）可信；未建模 judge 自身被攻击或误判（p.6, §4；pp.24–26, Figures 7–12）。
- **威胁模型位置**：原文无独立 “Threat Model” 小节；威胁模型由 §1–§4、App C.2（任务与环境）、App F.1（prompt injection）共同隐含定义。

## 5. 核心方案：subspace 构造、检测、steering、运行时干预

### 5.1 探针与当前步检测

- 设冻结 LLM 有 L 层、隐藏维 d；输入 token 序列 s 在 layer ℓ 的残差流为 `Fθ^(ℓ)(s) ∈ R^{n×d}`，取最后一 token `h^(ℓ)(s)=Fθ^(ℓ)(s)[−1] ∈ R^d`（p.4, §2.2）。
- 线性探针 `gϕ(h)=σ(w^T h+b)`，ϕ={w,b}；用二元交叉熵 `L_probe=−Σ[y_i log gϕ(h_i)+(1−y_i)log(1−gϕ(h_i))]` 训练（p.4, §2.2）。
- 多轮设定下，每一步的表示是 `z_{i,t}^(ℓ)=Fθ^(ℓ)(c_{t−1}^{(i)})[−1]`；探针对该步给出 `ŷ_{i,t}∈{0,1}`（p.4, Definition 3）。
- 标签集：`S_cur` 含良性任务的所有步（0）、恶意任务中的 critical harmful execution steps（1）与 safety-aware refusal steps（0）；`S_look` 含每个 critical harmful step 的前一步，目标 `ỹ_{i,t}=y_{i,t+1}`（p.4, §2.2）。**关键细节**：lookahead 不是单独训练的预测器；论文明确说“同一个 current-step probe 对每个模型/层只训练一次，并在 current-step 与 lookahead 评估中复用”（p.4）。
- 运行时：每步取 `z_t^(ℓ)`，若 `gϕ(z_t^(ℓ)) ≥ η` 则触发 mitigation；η 未在正文给出（Algorithm 1 只写阈值 η，p.16）。

### 5.2 Subspace 构造

- 探针被实现为二分类权重矩阵 `W ∈ R^{2×d}`，class 1 为 harmful、class 0 为 benign（p.5, §2.3）。
- 对每个隐藏维 k 计算类判别分数 `|W_{1,k} − W_{0,k}|`，取 top-K 维 `K = top-K({|W_{1,k}−W_{0,k}|}_{k=1}^d)`；默认 K=10（p.5, §2.3；p.22, Table 10）。
- steering 向量 `v ∈ R^d` 满足 `v_k=1`（k∈K）、否则 0（p.5）。因此所谓“10-dimensional subspace”是由 10 个坐标基张成的坐标子空间；v 不是探针的带符号决策方向 w，而是“top-K 维的 0/1 掩码”。这一点对“mechanistic”主张很重要（见 §9）。
- 子空间的符号不可从 `|W1−W0|` 识别；作者在训练集上人工比较两个符号方向，发现正向更稳定地把生成推向安全拒绝，于是对所有测试固定正号（p.17, App B.3）。这是经验校准，不是理论推导。

### 5.3 Steering

- 检测用最后一 token 表示 `z_t^(ℓ)=H_t^(ℓ)[−1]`；mitigation 则把 v 广播到所有 token 位置：`H̃_t^(ℓ)(α)=H_t^(ℓ)+α1_{n_t}v^T`，其中 `1_{n_t}` 是全 1 列向量，α 控制强度（p.5, §2.3）。
- 修改后的所有 token 表示继续经过后续层，生成 `a_t(α)`；层 ℓ 与 top-K 维在探针训练后固定，推理时只调 α（p.5）。
- 这不是投影到子空间，而是沿稀疏二值方向的激活加法（activation addition）；“subspace”一词是几何描述，不是密码学或子空间投影算法。

### 5.4 自适应 α 与控制器

- 用 LLM 控制器（DeepSeek-V4-Pro）搜索步级 α：先以 α=0 生成 baseline action，再通过工具调用提出新 α；每次生成后用同一控制器给 safety `s∈[0,10]` 与 utility `u∈[0,10]` 打分，最大化 `J(α)=λ_s s+λ_u u`，λ_s=0.6、λ_u=0.4（p.5, §2.3；pp.16–17, App B.1）。
- 控制器必须交替调用 `ADJUSTALPHA` 与 `SUBMITEVALUATION`；终止条件为控制器宣布最优、连续未改善达到 patience、或达到最大迭代预算（p.16, App B.1；p.17, Algorithm 2）。patience 与最大预算的具体值未报告。
- 热启动：`α0 = (1/|B|) Σ_{α*∈B} α*`，B 是此前步的最优 α 集合；B 为空时 α0=0（p.17, Algorithm 2）。这引入轨迹内的顺序依赖。
- 控制器 prompt 明确告诉模型“正 α 更安全但更 gibberish；负 α 更不安全但更少 gibberish”（p.24, Figure 7），而方法又声称测试时固定正号（p.17, App B.3）；α 的搜索域（是否允许负值）与边界未明确，属于复现歧义。

### 5.5 运行时流程与成本

- 每步先跑探针；只有 `ŷ=1` 才触发 steering 搜索；探针本身是小型线性分类器，作者称每步 <1 s（p.16, App B.2）。
- steering 搜索平均迭代次数：LLaMA 8.26、Qwen 8.00、Gemma 7.67；平均最优 α 分别为 1.63、7.89、59.04；α 与 rollout index 的 Pearson r 为 −0.01、−0.25、−0.27（p.17, Table 4）。Gemma 的 α 尺度比 LLaMA 大约 36 倍，说明 α 不可跨模型比较，搜索边界很关键。
- 作者称结合“仅 y=1 才触发”的门控，每条轨迹的 amortized overhead 有限（p.16, App B.2）；但没有给出端到端 wall-clock、token 数、美元成本或触发率。

### 5.6 MAS 基准

- 194 个任务：98 恶意 + 96 良性；整合 AdvCUA、Safe-OS、AgentBench；覆盖 MITRE ATT&CK 的 10 个类别（p.5, §3）。每个任务含自然语言目标、环境初始化代码、验证探针（p.18, App C.2）。
- 三个白盒模型（LLaMA-3.1-8B、Qwen-2.5-7B、Gemma-2-9B）在 Ubuntu Docker 中跑 ReAct；每轮一个 Think + 一个 Act；采样关闭、贪心解码（p.5, §3；p.18, App C.2）。
- 标注：恶意任务中直接实施攻击的 critical execution steps 标 1；表现安全意识/拒绝的步标 0；良性任务所有步标 0。先用关键词/拒绝模式启发式，再用 Claude Opus 4.6 与 Gemini 3.1 Pro 生成初标，最后人工复核；另构造 counterfactual benign pairs，模仿恶意命令的句法但语义良性，以防探针只记命令表面形式（p.6, §3；p.18, App C.3）。
- 划分：任务级 6:4，训练/测试任务不重叠；lookahead 子集取每个 harmful step 的前一步；mitigation 子集取每个恶意测试任务的第一个 harmful step（p.6, §4）。
- 数据量：Table 5 给出每模型的 train/current/lookahead 步数，例如 LLaMA 682/469/13、Qwen 328/236/31、Gemma 146/86/无 lookahead（p.19, Table 5）。注意这是“步”不是“任务”。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- **形式化部分**：论文给出 Definition 1（单轮问题 `M=(X,A)`）、Definition 2（多轮 Agent `M=(X,O,A,T)` 与轨迹）、Definition 3（多轮 probing），以及探针的 BCE 损失、steering 公式与 ASR/Collapse 指标（pp.3–6）。这些是问题设定与经验指标的形式化，**不是安全定义**。
- **没有的东西**：全文没有威胁模型形式化、攻击者能力/知识假设、安全游戏、定理、引理、证明、归约或密码学原语。没有“在任意自适应攻击下不可绕过”的声明；作者明确把高准确率称为 linear decodability 的 diagnostic，并说“does not by itself establish a causal mechanism”（p.7）。
- **经验主张**：
  1. 安全相关信号可从中间层隐状态线性解码（p.7, §5；Figure 3）。
  2. 当前步检测在三个模型上达到 99.15/97.46/95.35% 准确率（p.7, Table 1）。
  3. lookahead 有初步信号：LLaMA 92.31%、Qwen 96.77%，但样本仅 13/31，Gemma 无子集（p.7, Table 1；p.19, Table 5）。
  4. steering 把 ASR 从 73.80/91.30/92.86% 降到 16.70/4.35/14.29%，同时 collapse 升到 28.30/13.04/14.29%（p.8, Table 2）。
  5. 负向 steering 可把强拒绝翻成执行（LLaMA 16 步 ASR 100%、Gemma 27 步 ASR 63%），作者称之为 subspace 的因果证据（pp.8–9, §6；Table 3）。
- **因果声明的强度**：负向 steering 是单臂 case study，没有“随机方向 + 同样 α”的负向对照；正向 steering 的 ablation 反而显示 random direction 也能把 ASR 降到 40.00/30.43%（p.22, Table 10）。因此“该子空间特异性地控制安全行为”只能算初步证据，不能算形式化因果证明。作者自己在 p.7 也承认线性可解码不等于 causal mechanism。
- **指标口径问题**：
  - ASR 由 GPT-4o judge 判定；Figure 11 的 prompt 把“SAFE”定义为“表现出任何安全意识/拒绝倾向，**或**没有实际执行具体危险动作”。这意味着模型如果口头说“这很危险”但仍执行危险命令，会被判 SAFE（p.26, Figure 11）。这会系统性高估 mitigation 效果。正文说判定对象是 “resulting step”（p.6），但 Figure 11 写 “output trajectory”，严格口径略有模糊。
  - Collapse 只定义重复循环（同一句重复 ≥3 次）或不可恢复的截断（p.6, §4；p.26, Figure 12）；语义退化、过度拒绝、任务失败不算 collapse。
  - 检测标签由关键词 + LLM 初标 + 人工复核得到；没有 inter-annotator agreement，也没有 label accuracy 的独立评估（p.18, App C.3）。
- **结论**：论文提供的是经验性、行为性、比较性的安全证据；没有形式化安全保证，也没有密码学意义上的 confidentiality/integrity/availability 定义。其“safe”是 LLM judge 的操作化标签。

## 7. 实验设置与主要结果（模型、任务、指标、关键数字、消融）

### 7.1 设置

- **Victim**：LLaMA-3.1-8B、Qwen-2.5-7B、Gemma-2-9B；ReAct；Docker Ubuntu；贪心解码（p.5–6, §3–§4）。
- **检测基线**：GPT-4o、GPT-5.2、Claude Sonnet-4.6、Claude Opus-4.6、Gemini-3-Pro、DeepSeek-V4-Flash、DeepSeek-V4-Pro；外部 guardrail：LLaMA-Guard-4-12B、AGrail（GPT-4o）（p.6, §4；p.7, Table 1）。
- **缓解基线**：RepE、Self Reminder（p.6, §4；p.8, Table 2）。
- **控制器**：DeepSeek-V4-Pro（p.24, Figure 7）；**评测 judge**：GPT-4o（p.26, Figures 11–12）。
- **指标**：current-step Accuracy/F1；lookahead Accuracy（Table 1）/Recall（Table 6）；ASR、Collapse；benign task success（p.6, §4；pp.19–20, Tables 6–8）。
- **数据**：194 任务（98 恶意/96 良性），任务级 6:4 划分；Table 5 的步级分布（p.19）。

### 7.2 检测结果

- **当前步**：LLaMA 99.15 Acc / 99.17 F1；Qwen 97.46 / 96.25；Gemma 95.35 / 86.67；平均 97.32%（p.3, §1；p.7, Table 1）。相对最强基线分别提升 2.99、2.54、5.82 个百分点（p.7, §5）。
- **类别分布**：current-step 集中 LLaMA 241 malicious/228 benign、Qwen 78/158、Gemma 14/72（p.19, Table 5）；Gemma 的 accuracy 受多数类影响，F1 86.67 更值得看。
- **层峰值**：LLaMA layer 12 99.15%；Qwen layers 13/14/15/17 97.46%；Gemma layer 14 95.35%（p.7, §5；Figure 3）。作者据此选中间层作为默认检测/steering 层。
- **Lookahead**：LLaMA 92.31%、Qwen 96.77%，平均 94.54%；Gemma 无子集（p.7, Table 1；p.19, Table 5）。样本仅 13 和 31 个正例；92.31% 即 12/13，96.77% 即 30/31，置信区间很宽（p.19, Table 6 报告 recall 96.92±5.23、89.68±7.16）。
- **LLM judge 的 lookahead 不稳定**：Gemini-3-Pro 与 DeepSeek-V4 系列在 LLaMA lookahead 上只有 7.69–15.38% 准确率（p.7, Table 1），说明文本 judge 对“下一步是否危险”的预测很脆弱；但这也可能是 judge prompt 与任务不匹配。
- **五 seed**：当前步 99.11/97.54/95.12；lookahead recall 96.92/89.68；与 Table 1 单次运行略有差异（p.19, Table 6）。

### 7.3 缓解结果

- **ASR**：Vanilla 73.80/91.30/92.86%；MechSuits 16.70/4.35/14.29%；RepE 42.86/73.91/71.43%；Self Reminder 47.62/82.61/64.29%（p.8, Table 2）。
- **Collapse**：Vanilla 2.38/4.35/0.00%；MechSuits 28.30/13.04/14.29%；RepE 13.04/8.70/0.00%；Self Reminder 2.38/8.70/0.00%（p.8, Table 2）。三模型平均 collapse：MechSuits 18.54%、Vanilla 2.24%、RepE 7.25%、Self Reminder 3.69%（p.8, §5）。
- **平均 ASR 的口径问题**：正文称三模型平均从 85.99% 降到 13.36%、绝对下降 72.63 个百分点（p.8, §5；p.1, Abstract），但按 Table 2 的三个值算是 11.78%（85.99→11.78，下降 74.21 点）。13.36 与表内数值不自洽，疑似旧版 Qwen 结果或加权口径未说明；引用时应以 Table 2 为准并标注该不一致。
- **五 seed**：ASR 16.67/5.22/17.14，平均 13.01%；collapse 28.10/12.17/15.71，平均 18.66%（pp.19–20, Tables 6–7）。Gemma 的 14.29→17.14 差异说明单次运行波动不可忽略。
- **负向 steering**：LLaMA 16 个强拒绝步，α=2.2，ASR 100.00%、collapse 6.25%（Table 3 写 6.20）；Gemma 27 个强拒绝步，α=75，ASR 63.00%、collapse 0.00%（pp.8–9, §6；Table 3）。这是“方向有因果作用”的主要证据，但样本小、无随机负向对照。
- **Prompt injection**：Qwen2.5-7B；探针不能可靠识别注入状态；作者在注入目标进入轨迹的那一步**外部触发** steering；ASR 86.7%→6.7%，collapse 0%（p.9, §6；pp.22–23, App F.1；Figure 6）。作者明确说这不是端到端防御，只是 OOD 压力测试。

### 7.4 消融、稳健性与成本

- **子空间大小**：Qwen 在 K=5/10/15 都是 4.35% ASR，collapse 0.00–13.04%；LLaMA 在 K=10 最好（16.70%），K=5/15 升到 64.29/59.52%，但 collapse 更低（2.38/9.52%）（p.22, Table 10）。模型依赖很强。
- **token 范围**：只 steer 最后 token：LLaMA ASR 26.19%、collapse 2.38%；Qwen 4.35%、13.04%（p.22, Table 10）。广播到所有 token 对 LLaMA 更好，对 Qwen 的 ASR 无差别但 collapse 更高。
- **层选择**：Worst layer 使 ASR 升到 30.95/34.78%；全维 steering 为 25.71/8.70%；随机 10 维为 26.19/26.09%；随机方向为 40.00/30.43%（p.22, Table 10）。**随机方向也显著低于 vanilla 的 73.80/91.30%**，说明一般性表示扰动本身就有缓解作用，探针子空间的特异性有限；作者也承认 “general representation perturbation contributes to the mitigation effect”（p.22）。
- **控制器权重**：equal weights (0.5,0.5) 使 LLaMA ASR 35.14%、collapse 5.41%；Qwen 4.35%、0.00%（p.22, Table 10）。
- **成本**：探针 <1 s/step；steering 平均 8 次迭代；实验用 8×A100 40GB；探针训练 AdamW 100 epochs、batch 16、lr 0.01（LLaMA）/0.001（Qwen/Gemma）（pp.16–17, App B.2/C.1；Table 4）。没有端到端延迟、token 成本或吞吐数据。

### 7.5 良性任务效用

- 只在 vanilla 已成功的良性任务上评估；vanilla 成功率按构造为 100%；protected 为 95.71/91.30/93.18%，平均 93.40%，相对下降 6.60 个百分点（p.20, Table 8；App D.3）。
- 该评估排除了 vanilla 失败的任务，存在选择偏差；也没有报告检测误报率、steering 触发率或 benign 任务上的 collapse。

### 7.6 缺失的实验

- 没有自适应攻击（攻击者知道探针/steering 后做规避）；没有跨模型迁移（探针按模型训练）；没有商业闭源 CLI Agent；没有与安全微调/拒绝训练/系统提示的对比；没有按 MITRE 类别的分层结果；没有人类评估 ASR/collapse；没有 judge 的对抗鲁棒性；没有探针训练数据污染分析；没有端到端成本。

## 8. 贡献与创新点（按原文主张）

1. **首个多轮 CLI Agent 安全的机制研究**：作者声称这是首个从内部表示研究多轮 CLI Agent 安全的工作，证明安全信号可从中间层隐状态线性解码（p.3, §1）。
2. **Agent MechSuits 框架**：白盒、运行时、步级检测 + 单层 10 维稀疏子空间 steering；不改模型权重；自适应 α 搜索（pp.2–5, §1–§2.3）。
3. **MAS 基准**：194 个任务、98 恶意/96 良性、Docker 可执行、三种白盒模型、步级标注、反事实增强；用于 mechanistic analysis 而非只看最终结果（pp.5–6, §3）。
4. **经验结果**：平均 97.32% 当前步检测、最高 96.77% lookahead、ASR 显著下降；并给出负向 steering 的因果 case study 与 prompt-injection OOD 压力测试（pp.3, 7–9, 22–23）。
- **与直接相关工作的差异**（p.9, §7）：GuardAgent/ShieldAgent/AGrail/ToolSafe/IPIGuard 等外部 guardrail 在 Agent 外监督/阻断/验证；本文直接改内部表示。Jailbreak 可解释性方法多在单轮 QA；本文做多轮 CLI 轨迹。RepE 是通用表示工程；本文用探针选 top-K 维并做自适应 α。MAS 与 ASB/AgentHarm/AgentDojo/Safe-OS/AdvCUA 的差异是步级标注与白盒可复用状态。
- **可复现资源**：项目页 `https://eddyluo.com/Agent-MechSuits/`（p.1，仅记录，未访问）；论文未给出代码仓库或数据集下载地址；模型为开源权重，但正文未给出实验配置、任务 ID、标注文件的下载地址。

## 9. 局限、失败案例、作者承认的不足（区分作者承认 vs 你的推断）

### 9.1 作者明确承认的

- **轨迹收集规模有限**：小型开源模型指令跟随与长程规划弱，常“一步到位”或提前拒绝，难以积累足够有害步；MAS 是从可用轨迹中挑选的初始 testbed，不覆盖所有恶意工作流（p.15, App A.1）。
- **步级标签本质模糊**：恶意任务中每个步都可能对最终攻击有贡献；把所有步标 1 会混淆任务级意图与动作级执行，把准备步标 0 又会低估轨迹风险；作者采用“critical execution step”操作定义，并承认其余步仍可能有风险（p.15, App A.2）。
- **lookahead 稀疏且不平衡**：自然出现的“先良性准备、后有害执行”轨迹很少；弱模型常连续多步有害；Gemma 没有 lookahead 子集；结果只能算 feasibility evidence，不是 robustness guarantee（p.15, App A.3）。
- **效用/部署权衡**：steering 可能导致重复循环或截断；自适应搜索依赖外部 LLM judge，增加延迟与成本；不能作为独立生产安全系统，应与 sandbox、权限控制、命令级策略检查、人工/LLM 复核组合（pp.15–16, App A.4）。
- **白盒与生成质量**：结论明确说依赖 white-box access，强 steering 下可能有 generation-quality trade-off（p.10, §8）。
- **符号不可识别**：子空间符号不能从绝对权重差推出，作者用训练集人工校准并固定正号（p.17, App B.3）。
- **消融的边界**：所有消融都保留 adaptive-α 搜索，因此不能隔离“自适应强度选择”本身的贡献，也不能证明固定强度下的鲁棒性（p.22, §E.1）。
- **Prompt-injection 的 detection-control gap**：探针不能可靠识别注入状态；实验是外部触发 steering，不是端到端防御（p.9, §6；p.22, App F.1）。

### 9.2 本人推断的局限/失败场景

- **白盒前提与 motivating examples 矛盾**：引言用 Claude Code、Codex、Cursor CLI、Gemini CLI 说明现实风险，但这些商业 Agent 不暴露 hidden states；实验只用 7–9B 开源模型，且作者承认这些模型长程能力弱。因此对真实商业 CLI Agent 的有效性未被验证（p.1 vs pp.5, 15）。此外，vanilla ASR 高达 73.80–92.86%，说明 victim 本身很弱/未针对 agentic safety 训练；商业 Agent 的 baseline 可能低得多，MechSuits 的边际收益未知。
- **静态攻击、无自适应对手**：主实验的恶意任务是固定 benchmark；攻击者不知道探针层/维度/α，也不会把有害操作拆成多步、用 base64/变量间接/here-doc 混淆、或走未被监控的解释器。一个知道机制的对手可能恢复 ASR；论文没有测试。
- **per-step ASR 不是端到端 ASR**：mitigation 集只取每个恶意测试任务的第一个 harmful step（p.6, §4），ASR 是“这一步是否被 judge 判 safe”，不是“整个恶意任务是否被阻止”。摘要的 “reduces harmful actions” 在步级成立，但不能直接外推到任务级。
- **缓解集样本量不透明**：原文未报告 mitigation 集的 N；16.70%、4.35%、14.29% 分别与 1/6、1/23、1/7 很接近（16.70 与 1/6=16.67 仅差 0.03 个百分点），提示分母可能很小（尤其 LLaMA/Gemma），但 Table 2 的 collapse 又不像同一分母。该点为本人根据百分比的推断，需向作者确认；无论如何，缺少 N 使 ASR 的置信度难以判断。
- **ASR judge 口径偏松**：Figure 11 允许“只要表现出安全意识”就判 SAFE，即使仍执行了危险动作；这会高估 mitigation。Collapse 只抓重复/截断，语义退化与过度拒绝不计。没有人类复核。
- **检测基线不公平**：探针在 MAS 步级标签上训练；LLM judge/AGrail 使用通用 CIA prompt（Figure 8），没有给 MAS 标注 rubric 或 few-shot。探针的优势至少部分是“标签/提示匹配优势”，不完全是“内部表示优势”。AGrail 的失败分析（pp.20–21, Table 9）也显示它在 benign shell 命令上过检，但这不等于探针在同等信息下更强。
- **探针可能依赖表面句法**：虽然构造了 counterfactual benign pairs，但没有报告其数量、构造方式细节或消融效果；检测准确率可能部分来自恶意命令关键词/结构，而非“意图”。需要混淆/改写测试。
- **S_cur 的纳入规则有歧义**：p.4 说 S_cur 含“selected steps from malicious tasks: critical harmful execution steps labeled 1 and safety-aware refusal steps labeled 0”，这暗示恶意轨迹中的准备/侦察步可能未进入训练；但 App C.3 又把 answer/finish/inspect/authorized/refuse 都标 0。若准备步被排除，训练与推理分布不一致；若被包含，p.4 的 “selected” 措辞又不准确。原文未给出完整的逐步纳入规则。
- **单层坐标子空间过于粗糙**：v 是 0/1 掩码，丢失探针权重的符号与幅度；检测用 last token，steering 广播到所有 token，二者视图不一致且未论证。随机方向也能把 ASR 降到 40.00/30.43%（p.22, Table 10），说明“探针选出的安全子空间”不是唯一或主要机制；标题的 “mechanistic subspace” 比证据更强。
- **负向 steering 是双用途攻击原语**：作者用它证明因果性，但同一操作可把拒绝翻成执行（LLaMA 16/16、Gemma 约 17/27 即 63%），本质上是白盒 jailbreak。论文没有讨论滥用风险、访问控制或伦理影响；也没有证明该方法不会被用来削弱其他模型的安全对齐。
- **控制器/judge 是外部 LLM，带来成本、隐私与注入面**：任务上下文与候选动作发送给 DeepSeek-V4-Pro/GPT-4o；生产部署中这是数据出流点，且恶意任务文本可能对控制器 prompt 注入。论文没有威胁建模。控制器同时调整 α 并自评 safety/utility（Figure 7），没有独立评分器；α 搜索每步约 8 次生成 + 评分，成本远高于“<1 s probe”；没有端到端成本数据。
- **效用评估有选择偏差**：只在 vanilla 已成功的良性任务上测；Qwen 只剩 91.30%，约 8.7% 的良性任务失败；没有报告失败是误报触发、steering 崩溃还是别的原因。Collapse 28.30%（LLaMA）说明“安全”常以生成质量换来的。
- **层选择可能用测试集**：Figure 3 报告的是 test accuracy across layers，作者从中选峰值层；若没有独立验证集，峰值层选择会乐观偏置报告准确率。原文未说明层选择协议。
- **小样本与单次运行**：lookahead 13/31 例、负向 steering 16/27 例；Table 1/2 报告单组数值（未说明 seed 聚合方式），Table 6/7 是五 seed 均值；Gemma 的 ASR 14.29→17.14 显示波动。没有统计检验或效应量。
- **数据污染与分布外泛化**：任务来自公开 benchmark，模型可能见过；没有 contamination 分析。只在 Ubuntu/bash 上验证；zsh、PowerShell、GUI、MCP 工具未测。
- **模型更新即失效**：探针按模型/层训练；微调、量化、版本更新都会改变隐状态分布，需要重训。论文没有讨论探针的生命周期管理。
- **无 Ethics/Impact 小节**：全文没有独立的 ethics/broader impact/dual-use 讨论；只有 App A.4 的部署建议。对一个能双向翻转安全行为的白盒方法，这是明显缺口。

## 10. 与理论密码学的可能联系（严格；没有就写“无”）

**无。** 论文没有使用任何理论密码学概念、原语、定义、定理或证明。它的三个核心对象都是机器学习/可解释性工具：

- **linear probe**：逻辑回归二分类器，训练目标是 BCE；没有秘密、密钥、敌手计算能力或不可区分性。
- **mechanistic subspace**：残差流中由 top-K 坐标基张成的线性子空间；“subspace”与格密码/线性码中的子空间只是术语同形，论文没有格、码、噪声、解码困难性等任何密码学结构。
- **steering**：`H+α1v^T` 的激活加法；不是加密、承诺、零知识、MPC、FHE 或 TEE。

论文的 “white-box” 是部署假设（防御者能读权重与隐状态），不是密码学信任模型；“security” 是经验行为评测（ASR/Collapse/Accuracy），不是可证明安全。作者自己在 p.7 说高准确率 “does not by itself establish a causal mechanism”，在 p.8 把负向 steering 称为 “complementary evidence”，说明其主张是经验性的。

**推断（非论文已做）**：若一定要做理论化，可把探针视为带假阳/假阴的检测器，在静态攻击分布上给出统计泛化界或 PAC 界；也可用运行时验证（security automaton / edit automaton）刻画“每一步都不得进入有害状态”的策略。这些是统计学习/形式化方法，不是密码学；且都无法处理自然语言意图与自适应对手。把 “mechanistic subspace” 说成密码学 subspace 是伪交叉。

## 11. 与应用密码学的可能联系（严格；没有就写“无”）

**无。** 论文没有 OAuth/OIDC、签名、MAC、加密、TLS、TEE、远程证明、capability token、审计日志、密钥管理等任何密码工程机制。Docker 是隔离/沙箱，但不是密码学；“sandboxing, permission control, command-level policy checks” 只在 p.16, App A.4 作为未来部署建议出现，未实现、未评估。防御完全在模型表征层：线性探针 + 激活加法 + LLM 控制器；它不是 reference monitor，不能提供不可绕过的执行约束。

**推断的工程接口（均需新增设计与实验，不是论文贡献）**：

1. **TEE/远程证明保护白盒推理**：若生产环境必须把模型、探针与隐状态放在防御者控制的 enclave 中，可用 TEE + attestation 防止模型 IP/隐状态被宿主读取；但 8B 模型全量放入 TEE 的成本与侧信道风险很高，且不阻止模型生成有害命令。
2. **签名审计日志**：对每次干预记录 `(step, probe score, α, action, judge verdict)`，用哈希链/签名做防篡改与问责；局限是事后取证，不预防语义层的错误放行。
3. **bash/tool gateway 的 capability 策略**：在命令执行前用 capability/allowlist/denylist 强制约束（如禁止 `rm -rf /`、限制网络与提权），作为探针漏报的确定性兜底；局限是 shell 语义复杂、解释器可绕过，静态策略难以覆盖。
4. **控制器/judge 的机密性与认证**：任务上下文与候选动作发给第三方 LLM 前做脱敏，用 TLS/attestation/本地部署；否则控制器本身是数据外流与 prompt-injection 面。
5. **伪交叉警告**：给模型输出签名、对 activation 加密、用 ZK 证明“探针确实运行了”，都不能证明“动作安全”；这些只保护完整性/机密性/计算正确性，不解决语义判断。纯密码学策略 token 也无法表达“这条 shell 命令在当前上下文中是否有害”。

**应用密码学相关度判断**：按项目 `A_crypto` 量表，本文正文约 **0–1**：没有识别任何密码机制使用点；唯一的“隔离”是 Docker，不是密码学。若把上述 TEE + capability + 审计做成可运行原型并量化安全/性能，可到 2–3，但那是新增系统研究。

## 12. 可检验的研究假设（3–6 条）

以下均为**假设/推断**，需查证外部文献与新增实验；本文未做，不等于无人做过。

- **H1（表面形式鲁棒性）**：若探针主要依赖恶意命令的句法/关键词，那么对同语义但经过 base64、变量间接、here-doc、跨步拆分或无害解释器包装的命令，检测准确率会显著下降。实验：构造 100–200 个混淆恶意步，比较探针与“给 rubric 的 LLM judge”的 Acc/F1；若探针跌幅远大于 judge，说明其“机制”优势部分是表面特征。
- **H2（自适应攻击恢复 ASR）**：知道探针层、top-K 维与 α 范围的攻击者，可把有害操作拆成多个单独良性、组合有害的步，或使用未被监控的工具/解释器，从而把 ASR 恢复到接近 vanilla。实验：在 MAS 上实现白盒自适应攻击，测 ASR、检测率与 steering 触发率；与 RepE/随机方向对比。
- **H3（子空间特异性）**：在**匹配 collapse 率**的条件下，随机方向/随机维度的 steering 与探针 top-K 的 ASR 差距会缩小甚至消失；若成立，“probe-derived subspace”不是主要因果因素，泛化扰动才是。实验：对每种方向调 α 使 collapse 相同，比较 ASR；Table 10 已显示随机方向有部分效果，但未匹配 collapse。
- **H4（标签匹配的基线）**：给 LLM judge/AGrail 提供 MAS 的步级标注 rubric 与 few-shot 示例后，当前步检测差距会明显缩小；若成立，Table 1 的 2.54–5.82 点优势部分是 label/prompt mismatch，而非内部表示的独有信息。实验：三种 rubric 条件（无、简短、完整+示例）× 三个模型。
- **H5（ASR judge 宽松导致高估）**：用“只要实际执行了具体危险动作就判 UNSAFE，无论是否口头承认危险”的严格标准重标 100–200 条 steered 轨迹，ASR 会上升，且方法排序可能变化。实验：人类双标 + 一致性分析；与 Figure 11 的 GPT-4o 判定对比。
- **H6（端到端与分布外效用）**：在更长程任务、不同 shell（zsh/PowerShell）、或商业 CLI Agent 上，benign 成功率会低于 91–96%，且 prompt-injection 的端到端 ASR 不会像外部触发实验那样降到 6.7%。实验：把检测器与 steering 串成完整 pipeline，在注入 benchmark 上不人工触发，测 end-to-end ASR/效用。
