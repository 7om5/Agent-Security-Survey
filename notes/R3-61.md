## 1. 150–300 字中文概述

本文提出 CostBomb，研究 WebAgent 的计算成本攻击（CCA）：攻击者把对抗提示注入网页 HTML 的 `aria-label` 属性，诱导 Agent 产生冗长推理，从而在不改变任务目标的情况下抬高 token 成本。方法分两步：先用 GPT-4.1-mini 生成器结合当前页面与示例批量产出候选提示，再用 Qwen2.5-7B 选择器挑选最有效的一条；选择器以 victim 的 token 奖励为信号，用 GRPO 做 LoRA 微调。作者在 Mind2Web 三个测试集、SeeAct 与 WebVoyager 两个真实 Agent、Qwen/Gemini/GPT 三类骨干模型上评测：SeeAct 上 ΔTkC 最高 1.6031、ΔTkCA 最高 2.3091，WebVoyager 上 ΔTkC 最高 1.3699；任务成功率从 27.50% 降到 23.91%，VirusTotal 未检出注入页面。

## 2. 研究背景、现有方法不足、精确定义的问题

- **背景**：WebAgent 以 HTML/DOM（以及截图）为观察，自主完成多步网页任务；现有研究主要关注任务完成率与能力提升，计算效率（延迟、token、资源/能量）被视为工程问题而非安全属性（p.1–2, §1）。
- **现实动机**：作者称 StackOverflow 2025 调查中 53% 的受访者把 AI Agent 使用成本视为障碍；在股票交易、医疗预约等时效敏感场景，延迟与成本会转化为金钱或健康损失（p.2, §1）。
- **现有方法不足**：
  1. WebAgent 安全研究集中在“任务失败/错误动作”和“恶意行为/隐私泄露”（EIA、WebInject、AdvAgent 等），没有把“成本膨胀”作为独立攻击目标（p.2, §1；p.17, §D.2）。
  2. 已有的成本攻击（Sponge Examples、verbose images、Overthink、Engorgio prompt）针对单模型或推理模型，未覆盖多步、HTML 驱动、带工具/浏览器的 WebAgent（p.8, §5.1；p.9, References）。
  3. 手工设计的注入提示对 prompt 变化敏感、跨页面泛化差；LLM 生成的提示又因随机性无法保证最优；闭源 victim 使白盒梯度优化不可用（p.2–4, §1–§3）。
- **精确定义的问题**：给定用户任务 T、良性网页观察 s_t、WebAgent w_θ，攻击者构造扰动 δ 并注入 ŝ_t = I(s_t, δ)，求解
  `δ = arg max_δ C(a_{t+1} | w_θ, T, ŝ_t)`，
  其中 C 是 victim 生成下一动作的 token 成本；目标是显著提高 C，同时不破坏任务完成（p.3, §2）。
- 该问题是**存在性/经验性**问题：作者要证明“现有 WebAgent 对成本扰动脆弱”，不是要给出可证明的防御或形式化安全边界（p.3, §2；p.9, Conclusion）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **组件**（p.3, §2）：
  - 用户任务 T（自然语言，如“Add a new contact to the address book.”）。
  - 环境状态 s_t = {h_t, c_t}：h_t 为 HTML 文档，c_t 为对应截图。
  - WebAgent w_θ：参数 θ 的 LFM/VLM 策略，输出动作 a_t = {e, op, v}_t，e 是目标元素，op 是操作（CLICK/ENTER/INPUT 等），v 是输入值。
  - 环境转移 s_t → s_{t+1}。
- **交互流程**：`a_t = w_θ(T, s_t, [a_1, ..., a_{t−1}])`；执行 a_t 后环境更新，Agent 继续观察，直到任务完成（p.3, §2）。这是标准的 POMDP/ReAct 式循环，但论文没有写成形式化 POMDP。
- **两个 victim 实现**（p.13, §B.1.2；p.17, §D.1）：
  - **SeeAct**：多模态 LFM 从截图提取视觉信息，生成文本形式的 next-action plan，再 grounding 到具体 HTML 元素与操作。
  - **WebVoyager**：结合截图与交互元素的文本信息，直接产出 click/type 等动作；用 Set-of-Mark 在截图上标记可交互元素。
- **信任边界**：
  - 网页 HTML 是**不可信的外部输入**，从浏览器/网页发布者一侧跨入 Agent 的观察与推理上下文；Agent 把 HTML 当作“数据”，但 LLM 实际上会把其中的自然语言当作潜在指令执行（p.2–3, §1–§2；p.6, §3.5）。
  - 攻击者的注入点是 `aria-label` 属性：可含任意字符串、不在渲染页面显示、不破坏 HTML 语法；因此对用户不可见，却会进入 HTML-based Agent 的观察（p.6, §3.5）。
  - 论文的防御边界只停留在建议层：纯视觉 Agent、HTML purifier（p.15, §B.3.3）；没有实现或评估。
- **未建模的部分**：没有区分“网页发布者”“第三方内容注入者”“Agent 运营者/用户”三类主体；没有形式化 instruction/data 分离；没有建模浏览器、API、计费系统之间的信任关系（见 §4、§9）。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- **资产**：
  - victim 的 token 预算/API 账单、推理延迟、能源与计算资源（p.1–2, §1）。
  - 用户任务的完成质量与可用性（p.1, Fig.1；p.14, §B.3.1）。
  - 网页的正常功能与可访问性（`aria-label` 也是辅助技术的语义来源；论文未讨论，属[推断]）。
- **攻击者目标**：
  1. 最大化 victim 完成同一任务所需的 token 数 C（p.3, §2）。
  2. 保持任务可完成、动作序列基本正常，以维持隐蔽性（p.2–3, §1–§2；p.6, §3.5）。
  3. 注入内容不被传统 Web 安全工具与用户发现（p.6, §3.5；p.14, §B.3.1）。
- **攻击者能力**（p.3, §2 “Attacker's Capabilities”；p.6, §3.5）：
  - 可向网页 HTML 注入任意字符串，具体是遍历所有元素并追加到现有 `aria-label`；作者假设攻击者能控制/修改页面 HTML。
  - 黑盒：不能访问 victim 的架构、参数、梯度、logits；只能查询 victim 并观察计算成本的变化。
  - 可用 LLM 生成候选提示（GPT-4.1-mini），并可用另一个 LLM（Qwen2.5-7B）做选择与 RL 微调（p.13, §B.1.3）。
- **前提假设**：
  - victim 依赖 HTML 或可访问性树，且会读取 `aria-label`；纯视觉 Agent 可能不受影响（p.9, Limitations）。
  - 注入提示会被 victim 当作指令遵循；这是 prompt injection 的经典假设（p.2–3, §1–§2）。
  - 攻击者可观察到 victim 的 token 使用量/成本变化（p.3, §2；p.5, Eq.(3)）。
  - 任务来自 Mind2Web 的网页条目；[推断] 实验是离线回放静态 HTML/截图，而非实时在线访问（p.6, §4.1；p.13, §B.1.1）。攻击在任务开始前注入，不在交互过程中动态注入。
- **威胁模型的关键歧义**[推断]：
  - 论文一方面说攻击者向网页注入（p.2–3, §1–§2），另一方面说“对 WebAgent 用户而言，内部细节不可得”（p.3, §2），把攻击者放在“用户”位置；但普通用户通常不能修改任意网页的 `aria-label`。谁既是页面控制者又能观察 victim 的 token 账单，论文没有交代。
  - 若攻击者是第三方内容提供者（评论、广告），未必能控制所有元素的 `aria-label`；若攻击者是页面发布者，则“不可见注入”与“用户不可检测”成立，但 token 观测又需要 victim 运营侧权限。
  - 论文没有讨论攻击者如何获得逐任务的 token 计数；闭源 WebAgent 服务通常只返回最终答案，不返回内部 token 用量（p.3, §2 仅以“generally report token usage”一笔带过）。

## 5. 核心方案（方法、攻击/防御流程、关键定义）

### 5.1 总体框架（Figure 2, p.5）

CostBomb 是 **generation-then-selection** 框架：
1. **生成器 G**（GPT-4.1-mini）读取当前网页 HTML、金标准示例 p_gold 与指令 p_G，生成 m 条候选对抗提示 P = [p_1, ..., p_m]（p.4, §3.2；Eq.(1)）。
2. **选择器 S_ϕ**（Qwen2.5-7B-Instruct）从 P 中选出最可能最大化 victim 成本的一条 p̄ = P[I]，I = S_ϕ(P, s_t)（p.5, §3.3；Eq.(2)）。
3. **注入**：把 p̄ 追加到网页所有 HTML 元素的 `aria-label`，得到 ŝ_t；victim 在任务执行中读取并产生冗长推理（p.6, §3.5）。
4. **GRPO 训练**：用 victim 的 token 奖励对选择器做策略优化（p.5–6, §3.4）。

### 5.2 生成器（p.4, §3.2；p.16–17, §C）

- 动机：手工提示对 prompt 变化敏感、跨页面泛化差；LLM 有开放世界知识与推理能力，可自动生成多样化候选。
- 输入：当前观察 s_t、手工设计的 gold demonstrations p_gold（Prompt 1，两条“详细推理”示例）、生成指令 p_G（Prompt 2）。
- Eq.(1)：`p_i = G(s_t, p_gold, p_G), i = 1, ..., m`。
- Prompt 2 的要求包括：每条 200–400 字符、覆盖当前页面与任务特征、风格类似示例、彼此策略不同、确保 Agent 注意到新插入的提示并严格遵循（p.16）。
- 注意：Prompt 2 第 5 条写的是“Focus on improving the WebAgent's grounding decision-making ability”，并没有直接说“最大化 token”；生成器是通过“详细推理/不跳过步骤”的示例间接产生冗长输出，真正的成本目标只体现在选择器的奖励里（p.16；[推断]）。

### 5.3 选择器（p.5, §3.3）

- 动机：单次生成无法保证最优；自然语言候选空间巨大，需要一个 LLM 选择器。
- Eq.(2)：`I = S_ϕ(P, s_t), p̄ = P[I]`；S_ϕ 是参数 ϕ 的选择器，P[I] 是第 I 条候选。
- 选择器输入是当前 HTML 与候选列表；Prompt 3 要求“选择一条能被 WebAgent 注意到、并让 WebAgent 按其中指令操作的文本”，直接输出编号（p.17）。
- 选择器初始为通用 Qwen2.5-7B-Instruct；通用训练目标与“选择成本攻击提示”不匹配，因此需要 §5.4 的 GRPO。

### 5.4 GRPO 策略更新（p.5–6, §3.4）

- 奖励：`r = R(w_θ, T, ŝ_t) = C(a_{t+1} | w_θ, T, ŝ_t)`，即 victim 生成下一动作的 token 数（Eq.(3)）。
- 对同一网页采样 k 条提示，分别注入得到 k 个扰动页面 `[ŝ_t^1, ..., ŝ_t^k] = [I(s_t, p̄_1), ..., I(s_t, p̄_k)]`（Eq.(4)）。
- 优势：`Â_i = (r_i − mean([r_1, ..., r_k])) / std([r_1, ..., r_k])`（Eq.(5)）。
- 损失：`L = (1/k) Σ_i { min[o_i Â_i,t, clip(o_i, ε−, ε+) Â_i,t] − β KL[S_ϕ || S_ref] }`（Eq.(6)）；o_i 是当前策略与旧策略选择第 I_i 条的概率比；ε = 0.2，β = 0.1（p.6）。
- 训练细节：LoRA 冻结大部分参数，只微调小部分；Adam，学习率 10^−5；在 Mind2Web 训练集上随机打乱、离线采样，共 600 步（p.13, §B.1.3）。
- 默认超参：候选数 m = 3，GRPO 采样数 k = 3（p.8, §4.3；Figure 3, p.7）。

### 5.5 注入与推理（p.6, §3.5；Algorithm 1, p.13）

- 注入点选择：`aria-label` 可含任意字符串、不渲染、不破坏语法；作者遍历所有 HTML 元素，把选中的提示追加到现有 `aria-label` 值（p.6）。
- 训练阶段：对每个训练任务 T_i，生成候选、采样 k 条、注入、计算奖励与优势、算损失、更新 ϕ（Algorithm 1 第 2–7 行）。
- 推理阶段：生成候选池，选择器选一条，注入网页；victim 执行任务时被诱导产生长推理（Algorithm 1 第 10–11 行）。
- 攻击流程没有动态多轮交互：注入在任务开始前完成，victim 的后续动作不改变注入内容（p.6；p.13, §B.1.1）。

### 5.6 关键定义/指标（p.7, §4.1）

- **CCA**：Computational Cost Attacks，通过注入对抗信息使 WebAgent 产生不必要的高计算成本（p.1, Abstract；p.2, §1）。
- **C**：victim 生成动作的 token 数；本文用**输出 token 数**作为计算成本的代理（p.3, §2）。
- **TkC**：完成一个任务平均消耗的 token 数。
- **TkCA**：单次动作生成平均消耗的 token 数。
- **ΔTkC / ΔTkCA**：相对良性设置的成本增幅。
- **AS**：完成任务的平均动作步数，作为辅助指标。
- **TSR**：任务成功率，用 Agent-Eval-Refine 自动评估（p.14, §B.3.1）。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- **形式化程度：低。** 论文的核心“形式化”是攻击优化目标 `δ = arg max_δ C(...)`（p.3, Eq. 未编号）与 GRPO 的奖励/优势/损失（Eq.(3)–(6), p.5–6）；这些是机器学习优化式，不是安全定义、游戏、构造或定理。
- **没有**：
  - 没有安全游戏/实验（IND-style 或 simulation-based）；
  - 没有“攻击成功”的形式化谓词或阈值；
  - 没有防御不可区分性/可靠性定义；
  - 没有定理、引理、归约或证明；
  - 没有对 victim 行为、攻击者知识、任务分布的概率建模；
  - 没有统计显著性、置信区间或多次随机种子。
- **声明的类型**（均为经验主张）：
  1. **存在性**：现有 WebAgent 可被 HTML 注入显著抬高 token 成本（p.1, Abstract；p.7–8, §4.2–§4.3；Tables 1–2）。
  2. **相对有效性**：CostBomb 在多数设置优于 Overthinking/EIA/RP（p.7–8；Tables 1–2）。
  3. **隐蔽性**：注入不可见、不破坏 HTML、VirusTotal 未检出、TSR 仅小幅下降（p.6, §3.5；p.14, §B.3.1；Table 3）。
  4. **GRPO 必要性**：去掉 GRPO 后成本增幅下降（p.7, §4.2；但见 §9 的反例）。
- **指标层面的安全声明**：
  - “攻击成功”被操作化为 ΔTkC/ΔTkCA > 0 且任务仍可完成；没有给出“多大算成功”的阈值。
  - 成本只用**输出 token** 度量，未测延迟、FLOPs、能耗或金额；作者称生成时间与 token 成本近似成正比，因此不单独测（p.7, §4.1）。
  - 隐蔽性只用 VirusTotal 与“页面不渲染”来支持；没有对 prompt-injection 检测器、HTML sanitizer、可访问性异常检测做评测（p.14, §B.3.1；[推断]）。
- **结论**：这是一篇**系统/ML 安全经验论文**，不是形式化安全论文；它的“security claim”是经验性脆弱性存在与攻击有效性，不能读作可证明的保证。

## 7. 实验设置与主要结果（agents、场景、指标、关键数字、消融）

### 7.1 设置

- **数据集**：Mind2Web 的三个测试集（p.6, §4.1；p.13, §B.1.1）：
  - Website：1,019 actions / 142 tasks，网站未在训练集出现；
  - Task：1,339 actions / 177 tasks，同一网站的任务出现在训练集；
  - Domain：4,060 actions / 694 tasks，整个 domain 未在训练集出现。
- **Victim WebAgents**：SeeAct、WebVoyager（p.6, §4.1；p.13, §B.1.2）。
- **骨干 LFM**：qwen-vl-plus-2025-08-15（Qwen）、gemini-2.5-flash（Gemini）、gpt-4.1-mini（GPT）（p.7, §4.1）。
- **Baselines**（p.6, §4.1；p.13, §B.1.3）：
  - Benign：无注入；
  - Overthinking：从 Lila 数学题池随机抽题插入 HTML；
  - EIA：手工 “output longer” 插到 `aria-label` 开头；
  - RP：从 Lexical Semantic Comprehension 库随机抽 3 个词；
  - CostBomb w/o G：不使用 GRPO 的选择器消融。
- **实现**：SeeAct 用 Playwright、WebVoyager 用 Selenium；victim 温度 0、随机种子 42；生成器 GPT-4.1-mini；选择器 Qwen2.5-7B-Instruct + LoRA；600 训练步；Adam 1e−5（p.7, §4.1；p.13–14, §B.1.3）。
- **指标**：TkC、TkCA、ΔTkC、ΔTkCA、AS（p.7, §4.1）；TSR（p.14, Table 3）。

- **GRPO 消融**：Table 1/2 中 `CostBomb w/o G` 与完整方法对比。

- **参数分析**（Figure 3, p.7；p.8, §4.3）：变化 m（候选数）或 k（GRPO 采样数）在 2–6 范围内，TkC 约 5,200–6,200、TkCA 约 700–850，作者称“robust to hyperparameter variations”，默认 m = 3、k = 3。图中未标注 victim/数据集，无法确认该稳定性是否跨设置成立（[推断]）。
- **未做**：RL 超参（ε、β、学习率、600 步）敏感性、不同生成器/选择器组合、跨 victim 迁移、跨 benchmark 迁移、防御对比、延迟/能耗测量、逐任务方差/置信区间。

## 8. 贡献与创新点（按原文主张）

- **首个 WebAgent 计算效率脆弱性研究**：作者声称这是第一篇系统研究 WebAgent 计算成本攻击的工作（p.2–3, §1）。
- **CostBomb 框架**：LLM 生成器 + LLM 选择器 + GRPO 黑盒策略优化；生成-选择两阶段解决了自然语言搜索空间大、LLM 生成随机、闭源不可微的问题（p.2–5, §1–§3；Figure 2, p.5）。
- **注入载体**：利用 `aria-label` 实现“用户不可见、语法安全”的 HTML 注入（p.6, §3.5）。
- **系统实验**：三个 Mind2Web 测试集、两个 WebAgent、三个 LFM 骨干、五类基线；报告 TkC/TkCA/Δ/AS/TSR（p.6–8, §4；Tables 1–3）。
- **与直接相关工作的差异**（p.8, §5.1；p.17, §D.2）：
  - Sponge Examples / verbose images 针对单模型内部计算，不涉及多步 Agent；
  - Overthink 针对推理 LLM 的“slow-down”，用数学题注入，不是网页任务；
  - EIA 针对隐私泄露，不是成本；
  - AdvAgent 用 RL 做黑盒 red-teaming，目标是任务失败/错误动作，不是成本；
  - CostBomb 的新意在于“成本目标 + WebAgent HTML 注入 + 成本奖励的 GRPO 选择器”的组合。
- **可复现资源**：论文**没有**给出代码、数据、模型或 artifact 链接（pp.9–17 全文未见；[推断] 基于全文检索）。
- **伦理/披露**：论文**没有** Ethics/Broader Impact 小节，也没有对 OpenAI/Google/Qwen 或网页厂商的负责任披露说明（p.9 只有 Limitations 与 Acknowledgments；pp.10–17 无 Ethics；[推断] 基于全文）。

## 9. 局限、失败案例、作者承认的不足（区分作者承认 vs 你的推断）

### 作者承认（p.9, Limitations）

1. **仅文本模态**：CostBomb 只注入 HTML 文本，对纯视觉 WebAgent 的效果可能有限。
2. **攻击者开销**：GRPO 策略优化给攻击者带来“non-negligible computational overhead”；论文没有量化。

### 作者在其他位置的表述（3–4 为作者承认/暗示；5 为本人核对）

3. **防御只是建议**：§B.3.3 只提出“纯视觉 Agent”和“HTML purifier”两种方向，没有实现或实验（p.15）。
4. **检测只做 VirusTotal**：作者承认只用 VirusTotal 这一种传统 Web 安全工具，且未检出（p.14, §B.3.1）；没有测试 prompt-injection 检测器或 sanitizer。
5. **摘要的泛化表述 [核对]**：p.14 明确说 TSR 实验用 SeeAct + gpt-4.1-mini + Website；摘要却泛化为“without compromising successful task completion”（p.1 vs p.14）。

### 我的推断/核对（明确标为 [推断] 或 [核对]）

6. **摘要与 Table 3 不一致 [核对]**：摘要说“without compromising successful task completion”（p.1），但 Table 3 的 TSR 从 27.50% 降到 23.91%（−3.59 pp，相对 −13.1%）（p.14）。作者在 §B.3.1 用“minor decrease”弱化，但没有统计检验；在 benign 只有 27.5% 的情况下，3.6 pp 是否显著未知。
7. **“online experiments”与静态数据集不一致 [核对]**：§1 贡献写“extensive online experiments on three real-world datasets”（p.3），§4.1 写“All experiments are conducted in real-world environments”（p.6），但 §B.1.1 说数据是 Mind2Web 的 task/screenshot/HTML 条目（p.13）。Mind2Web 是离线缓存的网页快照，不是实时在线环境；“online”很可能是 overclaim，或至少没有说明是回放还是实时访问。
8. **威胁模型主体不清 [推断]**：见 §4。页面注入者与 token 观测者可能不是同一主体；论文用“users of WebAgents”描述攻击者位置（p.3），但没有解释页面控制权从何而来。
9. **成本只算输出 token [核对]**：§2 明确“measures computational cost by the number of output tokens”（p.3）；但注入是向**所有元素**的 `aria-label` 追加 200–400 字符提示（p.6；Prompt 2, p.16），会显著增加 victim 的**输入 token**。输入侧开销没有被测量，可能改变总 API 成本、延迟与攻击性价比的结论。
10. **没有测延迟/能耗 [核对]**：论文用“time cost (latency), computational resources and energy”来定义效率（p.1–2），但实验只测 token（p.7, §4.1）；作者以“生成时间与 token 成本近似成正比”为由不测时间（p.7），没有引用测量或验证。
11. **GRPO 消融的选择性报告 [核对]**：见 §7.4。完整方法在 GPT–Task、GPT–Domain、Gemini–Task、Gemini–WebVoyager 的 ΔTkC 低于 w/o G；GPT–Domain 差距很大（1.6031 vs 1.9270）。原文只报告 Gemini–Website 的正例（p.7），并称 RL “plays a crucial role”，没有解释反例。
12. **奖励是单步、评价是整任务 [推断]**：Eq.(3) 的奖励只算 `a_{t+1}` 的 token 数，而 TkC 是整任务总 token；优化单步成本可能通过减少 AS 来降低总成本，造成“每步更贵但总成本更低”的错位。GPT–Task（AS 12.85 → 9.00，TkC 7136 → 6019）与 GPT–Domain（AS 6.30 → 5.62，TkC 6495 → 5776）的 w/o G 反例可以用这个机制解释（Table 1, p.8；[推断]）。
13. **生成器与 victim 同家族 [推断]**：生成器是 GPT-4.1-mini（p.13），而 victim 骨干之一是 gpt-4.1-mini（p.7）；Qwen victim 与 Qwen2.5-7B 选择器也同家族。GPT 设置下的 ΔTkC 最大（1.6031），可能部分来自同家族提示的“自攻击”优势，而非方法本身的跨模型泛化。论文没有控制生成器模型。
14. **指标不可互推 [核对]**：TkC/AS 与 TkCA 在部分行不一致。例如 Gemini–Website benign：12196.00 / 8.33 ≈ 1464，但 TkCA 报 1357.52；Gemini–WebVoyager benign：1580.78 / 13.16 ≈ 120.1，但 TkCA 报 108.66；GPT–Website benign：3454.52 / 7.94 ≈ 435.1，但 TkCA 报 423.72（Table 1–2, p.8）。这说明 TkCA 不是简单的 TkC/AS，可能是“先按任务算比率再平均”的宏平均；原文没有定义聚合方式，两个指标不能互相校验。
15. **可疑的整数值 [核对]**：Table 1 的 GPT–Domain benign TkC = 2219.00、TkCA = 317.00，恰好都是整数，且 2219/7.00 = 317；其他 benign 行都是两位小数。可能是四舍五入/转录/单任务特例，但 Δ 比率仍能精确复算（5776.29/2219−1 = 1.6031），所以不能据此判定表格错误，只能标记为需作者澄清的异常。
16. **单次运行、无方差 [核对]**：victim 温度 0、seed 42（p.14），选择器训练只报 600 步，没有多 seed、置信区间或逐任务分布；TSR 只有一行，无法判断 3.6 pp 的下降是否超出噪声。
17. **基线不专注于成本 [推断]**：Overthinking 插数学题、EIA 插“output longer”、RP 插随机词，都不是为最大化 token 而优化的；CostBomb 有生成器+选择器+RL，比较存在“优化程度不对称”。真正的公平对照是 w/o G 消融，而它恰恰在部分设置更好（见 11）。
18. **没有自适应防御/攻防博弈 [推断]**：只测静态注入；没有 HTML sanitizer、prompt-injection 分类器、token 上限、推理预算、可访问性树一致性检查等防御，也没有测自适应攻击者绕过这些防御。
19. **VirusTotal 不是合适的检测器 [推断]**：VirusTotal 主要做 URL/文件恶意签名与信誉检测，不针对语义 prompt injection；即使提交的是修改后的本地 HTML，它也不会做“这段 aria-label 是否在诱导冗长推理”的判断。因此“未检出”只能说明没有触发传统恶意软件/钓鱼签名，不能支持“对检测不可见”的强结论（p.14）。
20. **可访问性副作用 [推断]**：`aria-label` 是屏幕阅读器等辅助技术的语义来源；向所有元素注入长文本可能破坏无障碍体验，论文没有讨论（p.6, §3.5）。
21. **没有代码/伦理/披露 [推断]**：全文没有 artifact 链接、Ethics 小节或负责任披露；对攻击论文而言这是可复现性与双用途治理的缺口（pp.9–17）。
22. **只测英文、静态页面 [推断]**：数据集与提示均为英文，未测多语言页面、动态 DOM、登录态、A/B 测试页面或反爬/内容安全策略（p.13, §B.1.1）。

- 论文的“black-box”是优化/查询能力假设（p.3, §2），不是密码学意义上的黑盒模型或 oracle 模型；没有 oracle 定义、查询复杂度或优势函数。

## 11. 与应用密码学/密码工程可能的技术联系（严格；没有就写“无”）

**无。**

- 论文没有使用 OAuth、TLS、签名、证书、VC、TEE、zk、MPC、HSM、密钥管理或任何密码工程组件（pp.1–21 全文）。
- 防御建议是“纯视觉 Agent”和“HTML purifier”（p.15），属于系统/输入清洗，不是密码学；HTML sanitizer 也不提供来源认证或完整性证明。
- [推断] 即使给网页加签名/内容 provenance（如 C2PA 式签名），也解决不了本攻击：若页面发布者就是攻击者，签名只证明“这是发布者签的”，不证明“这段 aria-label 不是恶意指令”；若攻击者是第三方注入，签名/隔离至多能约束“谁改了 DOM”，但论文没有评估，且不是密码协议设计。

- 因此 A_crypto = 0（0–5 粗判）。

## 12. 可检验的研究假设（3–6 条）

- **H1（总成本口径）**：如果把注入提示本身带来的**输入 token** 计入总 API 成本，CostBomb 的相对成本增幅是否会显著高于论文只算输出 token 的 ΔTkC？在“向所有元素追加 200–400 字符”的设置下，输入侧开销可能与输出侧同量级甚至更大；这可通过同一批 12 个设置、按 provider 的 input/output 单价复算验证。
- **H2（token 与延迟/能耗的关系）**：ΔTkC 与端到端 wall-clock 延迟、GPU/TPU 能耗是否单调相关？若不同 provider 的“thinking token”计费/批量策略不同，token 可能不是延迟/能量的无偏代理；需在相同任务上测 latency、energy 与 token 三组曲线。
- **H3（输出预算防御）**：给 victim 加硬性 max-output-token / “简洁推理”系统提示 / 推理预算，能否把 ΔTkC 压到接近 0，同时把 TSR 损失控制在可接受范围？这直接检验“成本攻击”是否可被最简单的预算机制缓解；需报告 Pareto 前沿而非单点。
- **H4（检测器）**：训练一个针对 `aria-label`/可访问性树的异常检测器（指令性长文本、与可见内容不一致、跨元素重复），能否在低假阳性下检出 CostBomb，且优于 VirusTotal？需测自适应攻击者（改写、分片、多语言、只注入少量元素）。
- **H5（奖励对齐/迁移）**：把奖励从“单步 token”改为“整任务总 token”或“总 token + 任务成功约束”，是否能在 GPT–Task、GPT–Domain 等 w/o G 反例上恢复优势，并提升跨 victim/跨 benchmark 迁移？这检验 §9 第 12 条的奖励错位解释。
