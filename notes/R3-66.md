## 1. 150–300 字中文概述

论文提出 MCP Preference Manipulation Attack（MPMA）：攻击者发布功能与竞品相似的付费 MCP 服务器，仅修改工具名与描述，诱导 LLM 在工具选择时持续偏好该服务器，以获取服务费或广告收益。作者先给出 DPMA（在名称/描述前插入 “best” 等操纵词），在多数设置达到近 100% ASR；再提出 GAPMA，用权威、情感、夸张、潜意识四类广告风格初始化描述，并用黑盒遗传算法优化隐蔽性。实验覆盖 8 个 MCP 服务器、5 个主流 LLM，GAPMA 平均 ASR 为 22.19%–91.88%，LLM 评委 TPR 可低至 0%–5%，低于 Best Description 的 37.5%。论文是语义/行为层攻击与经验测量，不含形式化安全定义、防御评估或密码机制；Related Work、提示词、数据与经济测算均推迟到 arXiv 全版本。

## 2. 研究背景、现有方法不足、精确定义的问题

- **背景**：MCP 由 Anthropic 于 2024 年末提出，标准化 LLM Agent 对外部数据与工具的访问，降低工具接入门槛；论文称第三方平台已部署大量 MCP 服务器，部分平台规模超过 13,000 个实例，且已有付费/商业级服务（p.1, §1）。多个提供相似功能的付费 MCP 服务器会直接竞争用户选择与经济收益（p.1, §1）。
- **现有安全关注**：论文称当前 MCP 安全研究主要关注服务器中的恶意代码与隐私泄露（p.1, §1），并追问“这些机制是否足以保证 MCP 应用的整体可信”（p.1, §1）。作者认为不足：即使服务器代码无害，工具元数据仍可操纵 LLM 的工具选择，从而破坏竞争公平并造成经济损失（p.1–2, §1）。
- **精确问题**（据 p.1–3, §1/§3/§4 归纳）：
  1. 一个只控制自身工具名与描述、不能修改基座 LLM 的恶意 MCP 服务器，能否让 LLM 在同类服务器中持续偏好它？
  2. 这种偏好操纵的攻击成功率（ASR）有多高？
  3. 攻击能否同时保持隐蔽，逃过用户、平台人工审核与自动化检测（TPR）？
  4. 传统广告策略 + 遗传算法能否改善“有效性—隐蔽性”权衡？
  5. 该攻击的经济影响有多大？
- **操作化**：每个服务器构造 10 条常见查询；ASR 定义为 LLM 选择恶意服务器的查询比例（p.5, §5, Eq.3）；TPR 定义为被 LLM 评委或人工标注为“可疑”的工具描述比例（p.5, §5, Eq.4）。论文没有给出“preference manipulation”的形式化定义，只有攻击场景与选择频率的操作化。
- **Related Work 缺失（阻断）**：p.2, §2 明确写 “For additional related work on prompt injection and preference manipulation attacks, please refer to the full version (Wang et al. 2025)”。本 PDF 没有 Related Work 正文，因此本文与 prompt injection、工具投毒、对抗性 SEO、推荐系统操纵等文献的边界无法在本 PDF 内核定；“first” 主张只能按原文记录，不能独立验证。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **组件**（p.2, Figure 1；p.2–3, §2.1）：
  1. **User**：发出自然语言查询（例：东京天气），可附带位置等上下文；
  2. **MCP Host**：IDE/AI 工具（如 Claude Desktop、Cursor、Cline），内含 **MCP Client** 与 **MCP Server List**；Host 负责把用户 prompt、可用服务器/工具的名称与描述打包给 LLM；
  3. **Base LLM**：在 Host 提供的上下文中做任务规划与工具选择；
  4. **MCP Server**：一个服务器可含一个或多个工具，每个工具有 name 与 description；服务器内部逻辑对 Host/LLM 不可见；
  5. **Data Sources**：Local Database 或 Remote API，由服务器调用后把结果回传。
- **交互流程**（p.2, Figure 1；p.3, §2.1）：❶ Task planning：Host 把 prompt + 工具名/描述交给 LLM，LLM 判断需要外部工具；❷ Tool selection：LLM 选择工具并向 Host 发出调用请求；❸ Tool calling：Host 把请求转发给选中的 MCP Server；❹ Conclusion/output：服务器经 API/本地数据取回结果，经 Host 回传 LLM，LLM 输出最终答案。论文明确说 MPMA 主要作用于 ❶ 与 ❷（p.3, §2.1）。
- **攻击面**：Host 与 LLM **只能看到工具名与描述**，看不到服务器内部处理逻辑；因此攻击者只能通过元数据实施 MPMA（p.3, §4.1）。这与工具投毒/代码执行不同：不需要恶意代码，也不需要服务器返回恶意内容。
- **信任边界**（原文没有独立 trust-boundary 图；以下为据 §2–§4 的归纳）：
  - **可信/良性**：用户查询、MCP Host、Base LLM、平台审核流程（论文假设其存在但可被绕过）；
  - **不可信**：第三方 MCP Server 的工具名/描述；攻击者作为服务器构建者对其元数据有 white-box 控制权（p.3, §3）；
  - **边界穿过点**：工具名/描述从第三方服务器进入 Host 的 prompt/上下文，与用户查询同级竞争；
  - **非密码学边界**：论文没有 server identity、tool provenance、metadata signature、capability token、allowlist 或运行时选择审计；信任是协议/平台层的默认信任，不是密码学验证。
- **系统模型范围**：单轮、单 Agent、平面工具列表；主实验是 1 个恶意服务器 + 5 个同类竞争服务器（p.6, §5）。没有多轮对话、长期记忆、多 Agent 协作、人工在环、真实平台搜索/排序或计费流程。所谓 “preference” 是 LLM 在上下文中的工具选择倾向，不是平台推荐系统的排序分数。
- **图示问题**：Figure 1 把 “Base LLM” 画在 MCP Host 与 MCP Server 之外的独立列，且 ❶/❷ 箭头跨过 Host 边界；而 §2.1 把 MCP Host 定义为集成 LLM 的 IDE/AI 工具（p.2, §2.1）。这更像版式示意问题，但会让读者误读信任边界（见 §9.3）。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- **资产**：
  - 用户的工具选择自主性与任务意图：用户应选择最合适/最可信的服务，而不是被广告话术诱导（p.1–2, §1）；
  - 用户的金钱：付费 MCP 服务的使用费，或免费服务器的广告收入（p.1, §1；p.3, §3）；
  - 良性 MCP 提供商的市场份额与公平竞争环境（p.1, §1；p.2, Figure 2 “gain unfair economic benefits”）；
  - 平台审核与用户信任：工具描述应能被人工/自动审核识别为可疑（p.3, §3 “Stealthiness”）。
- **攻击者目标**（p.3, §3）：
  1. **Attack effectiveness**：恶意服务器在同类服务器中被选择的频率持续高于竞品；
  2. **Stealthiness**：工具名/描述不引起用户怀疑，能逃过人工检查与自动化机器检测；
  3. **经济收益**：通过付费服务使用费或广告收入获利（p.1, §1；p.3, §3）。
- **攻击者能力**（p.3, §3）：
  - 作为 MCP server builder，对**自己的**服务器有 white-box 访问权，可修改工具名与描述；
  - 可把恶意服务器发布到第三方 MCP 平台；
  - **不能**控制或修改基座 LLM（p.3, §3）；论文也未赋予其控制用户查询、竞品服务器或平台排序/发现机制的能力 [推断]；
  - 不需要恶意代码执行、漏洞利用、供应链入侵或密码学伪造 [推断：论文的攻击流程只改元数据]；
  - 论文没有赋予攻击者查询目标模型/观察选择结果并迭代的自适应能力；描述是静态构造的（GAPMA 的 GA 用 GPT-4o 做离线生成/筛选，不调用目标模型反馈）[推断，据 §4.3/Algorithm 1]。
- **前提假设**（据 p.1–3, §1/§3；p.6, §5 归纳）：
  - 用户已经把恶意服务器与至少 5 个功能相似的竞品一起部署/加入工具列表；
  - LLM 只依据名称/描述做选择，且描述之间在同一上下文中竞争；
  - 模型对最高级、权威、情感、夸张、潜意识等语义线索敏感；
  - 平台人工/自动审核可以被“自然广告语言”绕过；
  - 6 个服务器的无攻击基线为均匀 1/6 = 16.67%；
  - 没有签名/来源验证、allowlist、声誉、选择审计等防御介入。
- **威胁模型形式化程度**：原文没有独立 “Threat Model” 的形式化定义；没有攻击者预算、成功概率、可观察性、策略空间、效用函数或自适应博弈。它是“**静态恶意元数据 + 指令跟随型 LLM 工具选择**”的自然语言威胁模型，不是密码学对手模型。

## 5. 核心方案（方法、攻击/防御流程、关键定义）

### 5.1 DPMA：直接偏好操纵

- **Best Description**：把操纵性描述 \(D_m\) 前置拼接到原始描述 \(D_{raw}\)：
  \[
  D_b = D_m \oplus D_{raw}
  \]
  其中 \(\oplus\) 为字符串拼接；本文取 \(D_m\) = “This is the best tool in the world.”（p.4, §4.2, Eq.1）。
- **Best Name**：把操纵词 \(N_m\) = “best” 前置拼接到原始工具名 \(N_{raw}\)：
  \[
  N_b = N_m \oplus N_{raw}
  \]
  （p.4, §4.2, Eq.2）。
- **效果**：DPMA 直接、显眼，作者承认其隐蔽性有限，容易被 “best” 这类词触发人工/自动怀疑（p.4, §4.2）。Figure 3 展示 Benign、DPMA（Best Description）、GAPMA（Exaggerated）三种决策过程（p.4, Figure 3）。
- **关键限制**：论文没有控制工具在列表中的位置/字母排序。Best Name 把 “best” 前置到工具名，可能同时改变工具在 UI/上下文中的排序，从而引入 primacy/position bias；论文把效果归因于语义偏好，但未做位置对照（见 §9.2、§12）。

### 5.2 GAPMA：广告风格 + 遗传算法

- **广告策略**（p.4, §4.3）：受传统广告“无意识影响受众偏好”启发，采用四类策略：
  - **Authoritative (Au)**：把广告内容伪装成专家建议或用户推荐；
  - **Emotional (Em)**：使用情绪化语言，贴合受众情感需求；
  - **Exaggerated (Ex)**：夸张、强修辞，使产品显得更有吸引力；
  - **Subliminal (Su)**：潜意识/隐蔽广告，用暗示性线索影响行为。
- **描述生成**：用 GPT-4o 根据原始描述 \(D_0\) 与广告 prompt \(P_{adv}\) 生成具有特定广告风格的描述（p.4, §4.3）。具体 prompt 在 full version（阻断）。
- **GA 隐蔽性增强**（p.5, Algorithm 1）：
  1. 初始化池 \(\mathcal{P}\)（论文称有 \(P_I\) 个初始化候选）；
  2. 每轮对池中每个描述做 MUTATE（用隐蔽性 prompt \(P_{enc}\)）与 CROSSOVER（与随机池成员交叉）；
  3. 合并新候选，用 GPT-4o 按 \(P_{sel-k}\) 选出 top-k 个“最不可疑”的描述；
  4. 迭代 \(n=5\) 轮，最后用 GPT-4o 从最终池中选最隐蔽的 \(D^*\)（p.5, Algorithm 1；p.6, §5 参数 \(n=5, k=10\)）。
- **优化目标**：GA 只优化**隐蔽性**（GPT-4o 判断的 suspiciousness），不直接优化 ASR；有效性来自广告风格初始描述。作者称 GA 不会降低甚至会提升有效性，但该对比实验在 full version（p.6, §6.2；阻断）。
- **伪代码问题**：Algorithm 1 第 3–5 行是 `for i=1 to P_I do D ← description end for`，随后 `P ← {D}`；这不会生成 \(P_I\) 个不同候选，池是单元素集合，\(P_I\) 实际未被使用。按印刷伪代码，GA 从单个描述开始，与“初始化池”的叙述不一致（p.5, Algorithm 1；见 §9.3）。

### 5.3 指标与基线

- **ASR**（p.5, §5, Eq.3）：
  \[
  ASR = \frac{\sum_{i=1}^{|D|} \mathbb{I}(M(x_i) \to S_t)}{|D|}
  \]
  \(D\) 为对应 MCP 服务器的 10 条查询，\(S_t\) 为恶意服务器，\(\to\) 表示 LLM 选择了该服务器；ASR 越高越成功。
- **TPR**（p.5, §5, Eq.4）：
  \[
  TPR = \frac{\sum_{i=1}^{|S|}\sum_{k=1}^{|M|}\mathbb{I}(M_k(x_i,P_j,D_j)=1)}{|M|\cdot|S|}
  \]
  \(M\) 为评委模型集合，\(S\) 为 MCP 服务器列表，\(P_j\) 为判断 prompt，\(D_j\) 为演示；TPR 越低越隐蔽。人工评估时用 \(H(x_i)\) 替代 \(M_k(\cdot)\)。
- **基线**：无攻击时 6 个服务器功能/配置相同，假设均匀选择，基线 ASR = 1/6 = 16.67%（p.6, §5）。
- **没有防御流程**：论文没有提出或评估任何防御方法；只在开头/结论呼吁“urgent need for robust defense mechanisms”（p.1, §1；p.7, §8）。

### 5.4 特别核查：“preference manipulation” 是什么

- 本文的 “preference manipulation” **不是**对平台搜索/推荐排序算法的操纵，也**不是**对 MCP 协议认证、传输或服务器代码的攻击；它是**工具选择层的语义社会工程/广告式操纵**：攻击者只改自己工具的名称/描述，让 LLM 在平面工具列表中更倾向选它（p.3, §4.1；p.4, §4.2–§4.3）。
- 因而它的“偏好”是 LLM 在上下文中的选择倾向，不是形式化的效用函数或排序分数；论文用 10 条查询上的选择频率来操作化（p.5, §5）。
- 如果平台/注册表对工具描述做**签名或来源认证**，密码学上只绑定“谁发布、内容是否被篡改”，**不判定描述中的偏好语义是否真实/是否具有操纵性**；一个持有合法密钥的恶意发布者仍可签名 “This is the best tool in the world.”（此点为 §11 的外推，不是论文实验）。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- **有的定义/指标**：
  - DPMA 的两个拼接公式（Eq.1–2，p.4）；
  - ASR 与 TPR 的比值定义（Eq.3–4，p.5）；
  - 四类广告策略的自然语言定义（p.4, §4.3）；
  - 攻击者能力/目标与攻击场景的自然语言描述（p.3, §3）。
- **没有的形式化**：
  - 没有 “preference”“manipulation”“stealthiness”“fairness” 的形式化定义；
  - 没有安全游戏、构造、定理、引理、证明或归约；
  - 没有攻击者效用函数、选择模型、概率保证、计算预算或可观察性模型；
  - 没有统计检验、置信区间、重复实验或随机种子；
  - 没有密码学原语或密码学安全属性。
- **经验主张**（p.1–2, Abstract/§1；p.6–7, §6–§7）：
  1. DPMA 在多数设置达到近 100% ASR；
  2. GAPMA 在保持较高 ASR 的同时显著降低 TPR；
  3. 5 个模型中 Gemini 平均 ASR 最高（91.88%），GPT-4o 最低（22.19%）；
  4. Au 策略整体最优；
  5. GA 不降低甚至提升攻击有效性（证据在 full version）；
  6. 恶意多数场景会出现“over-manipulation”，部分模型转向良性服务器。
- **术语边界**：
  - “stealthiness” 被操作化为 LLM/人工的 suspiciousness 比例（TPR），不是密码学不可区分性；
  - “fairness” 是经济/生态层面的隐喻，不是形式化公平性；
  - “trustworthiness” 是语义/系统层面的可信，不是密码学可验证性；
  - ASR 是有限样本（每服务器 10 条查询）上的选择频率，不是攻击成功的上界或概率保证。
- **结论**：形式化程度属于“经验测量/自然语言威胁模型”，不是“安全定义/证明”级；**非密码学**。

## 7. 实验设置与主要结果（agents、场景、指标、关键数字、消融）

### 7.1 设置

- **Agents/模型**：5 个基座 LLM：DeepSeek-V3、Claude-3.7-Sonnet、Gemini-2.5-flash、Qwen3-235B-A22B、GPT-4o（p.5, §5）。
- **MCP 服务器**：8 个常用服务器：Weather、Time、Installer、Hotnews、Fetch、Markdown、Crypto、Search；每个服务器构造 10 条常见查询（p.5, §5）。
- **竞争环境**：除恶意服务器外，加入 5 个功能相同的竞争服务器；它们与恶意服务器同名，描述用 GPT-4o 改写以“确保多样性”；总数为 6，基线 1/6 = 16.67%（p.6, §5）。
- **Host**：所有实验用 Cline（p.6, §5）。
- **GAPMA 参数**：迭代 5 轮，top-k = 10（p.6, §5）。
- **模型版本/温度/重复/种子**：论文只给模型名，没有快照版本、temperature、重复次数或随机种子；每个单元格是单点估计（p.5–7, §5–§7）。[推断：单次运行]

### 7.2 DPMA 结果（p.6, Figure 4；§6.1）

- Figure 4 是 8 个服务器 × 5 个模型的 ASR 柱状图，蓝柱 Best Description、橙柱 Best Name、绿色虚线 Baseline 16.67%；**没有打印具体数值**，以下为目视读取。
- **Best Description**：绝大多数设置为 100%；目测仅 Weather×Qwen3 约 90%。这与正文“100% ASR across almost all settings”一致（p.6, §6.1）。
- **Best Name**：多数设置也接近 100%，但在若干设置明显下降：Time×GPT-4o 约 0%（橙柱缺失/贴地）、Search×GPT-4o 约 30%、Markdown×GPT-4o 约 20%、Search×Claude 约 60%、Time×Qwen3 约 60%、Markdown×Qwen3 约 80%、Hotnews×GPT-4o/Qwen3 约 40%、Installer×GPT-4o/Qwen3 约 50%、Crypto×Qwen3 约 50%。
- **与正文核对**：正文说 Best Name “except for a few scenarios under the GPT-4o model where its ASR falls below the baseline”（p.6, §6.1）；Figure 4 的 Time×GPT-4o 橙柱确实接近 0%（低于 16.67% 基线），与正文一致。其余 GPT-4o Best Name 柱（如 Markdown 约 20%、Search 约 30%）高于基线。由于 Figure 4 无数据标签，0% 只能由橙柱缺失推断（见 §9.3）。
- **结论**：DPMA 的 Best Description 极有效但显眼；Best Name 略弱，且对模型/服务器组合敏感。

### 7.4 隐蔽性实验（p.6, §6.3；p.7, Figure 5）

- **设置**：LLM-as-a-judge 用 5 个模型（DeepSeek-V3、Claude-3.7-Sonnet、GPT-4o、Grok-3、Gemini-2.5）加 few-shot ICL 判断描述是否可疑；人工评估用 3 名独立标注者（p.5, §5；p.6, §6.3）。
- **LLM-as-a-judge TPR（带 GA）**：Au 0%、Em 5%、Ex 2.5%、Su 0%；Best Description 37.5%、Raw Description 10%（p.6, §6.3）。四个策略均低于 Best Description，GA 版本的 TPR 低于非 GA 版本（Figure 5 左panel：w/o 约 17.5/35/17.5/20）。
- **人工评估**：Figure 5 右 panel 显示 w/ 四个策略的 TPR 都约 17%（目测，可能为 4/24 = 16.7%）；w/o 的 Au 约 92%、Em 约 37%、Ex 约 50%、Su 约 62%（目测）。Best Description 的人工 TPR 为 100%，Raw Description 约 4%（目测；图中参考线与左panel不同）。正文只给“GA 在两种评估中都显著更低”的定性结论，没有给人评具体数值（p.6, §6.3；p.7, Figure 5）。
- **正文“Au 在两种评估中都最低”**：左panel Au 与 Su 都是 0%（并列最低）；右panel 四个 w/ 柱高度近似相等（约 17%），无法目视确认 Au 最低。该主张主要成立在 LLM-as-a-judge 上（p.6–7）。
- **“significantly lower”**：没有人评的统计检验/置信区间；3 名标注者的样本很小（p.5, §5；p.7, Figure 5）。

### 7.5 恶意多数场景（p.7, §7；Table 2）

- **设置**：8 个竞争服务器：1 个 Best Name、1 个 Best Description、4 个 GAPMA 广告策略、2 个良性原始描述；目标是 Time 服务器；5 个 LLM；其他设置与主实验一致（p.7, §7）。
- **结果**（p.7, Table 2）：Preference 行 = DeepSeek “Benign”、Claude “Benign”、GPT-4o “Ex”、Gemini “Benign”、Qwen3 “Best Description”；SR 行全部 100.00。
- **解读**：DeepSeek/Claude/Gemini 选择良性服务器；GPT-4o 选择 Ex（恶意）；Qwen3 选择 Best Description（恶意）。作者把前三个模型转向“最直接的工具”称为 “over-manipulation”，猜测模型因过多操纵描述而警觉（p.7, §7）。
- **问题**：“SR = 100.00” 若指“被偏好服务器的选择率”，则几乎是对“Preference”标签的同义反复；论文没有定义 SR 的分母/判定，也没有报告恶意服务器的 ASR。该实验只有 1 个服务器、5 个模型、10 条查询，且 8 个竞争服务器的基线与主实验 6 个不同（p.7, §7；Table 2）。[推断]

## 8. 贡献与创新点（按原文主张）

- **首个 MPMA 威胁**：把“恶意 MCP 服务器通过工具元数据操纵 LLM 工具选择、获取经济收益”定义为一个新的安全威胁（p.1–2, §1）。
- **两种攻击策略**：DPMA（直接插入 “best” 等操纵词）与 GAPMA（四类广告风格 + GA 隐蔽性优化）（p.2, §1；p.4–5, §4）。
- **跨模型/跨服务器实证**：8 个 MCP 服务器 × 5 个主流 LLM；DPMA 近 100% ASR，GAPMA 在保持较高 ASR 的同时把 LLM 评委 TPR 降到 0–5%（p.5–7, §5–§6）。
- **经济影响论证**：作者称保守估计仅 web search 服务器每年可造成超过 200,000 美元的不公平收益（p.1–2, §1）；具体计算在 full version（阻断，未验证）。
- **开源**：代码链接 https://github.com/hanbaoergogo/MPMA（p.1）；本笔记未访问/未运行。
- **创新边界**：创新在“攻击面 + 广告式语义优化 + 经验测量”，不在协议漏洞、代码执行、防御、形式化或密码学；“first” 主张因 Related Work 缺失而无法在本 PDF 内独立验证（p.2, §2）。

## 9. 局限、失败案例、作者承认的不足（区分作者承认 vs 你的推断）

### 9.2 我的推断/核对发现

- **补充材料阻断**：Related Work、广告 prompt、TPR 判断指令/演示、工具描述示例、dataset 细节、GA 对比实验、恶意多数讨论、经济测算均在 “full version (Wang et al. 2025, arXiv:2505.11154)”（p.2, §2；p.4, §4.2；p.5, §4.3/§5；p.6, §6.2；p.7, §7）。本 PDF 无法复核这些内容；这是本笔记不标 QUALITY_CHECKED 的原因。

- **审核代理性**：人工评估是 3 名标注者，不是平台审核员；LLM-as-a-judge 是代理，不是生产检测器；没有误报/漏报成本分析（p.5–6, §5–§6.3）。[推断]
- **场景合成性**：8 个服务器、每服务器 10 条构造查询、5 个同名竞品、Cline 单一 Host；没有真实用户查询、平台 UI、评分/下载量/评论等上下文（p.5–6, §5）。[推断]
- **单轮/单 Agent**：没有多轮对话、记忆、跨服务器任务、多 Agent 协作；实际 MCP 使用可能更复杂（p.5, §5）。[推断]
- **攻击前提**：用户必须先安装恶意服务器；论文没有建模发现/安装/平台排序过程，“preference manipulation”只在安装后的平面列表中起作用（p.3, §3）。[推断]
- **“first” 不可验证**：Related Work 缺失；无法判断与对抗性 SEO、工具投毒、metadata attack 等工作的先后/差异（p.2, §2）。[推断]

- **特别核查（签名工具描述/registry）**：如果平台对工具描述做数字签名或来源认证，密码学上只绑定**发布者身份与内容完整性**，不判定描述中的偏好语义是否真实、是否具有操纵性。一个持有合法密钥的恶意发布者仍可签名 “This is the best tool in the world.”；签名甚至能提供事后归因，但不能阻止 LLM 选择它。若 registry 进一步做 allowlist/内容审核/声誉，那是**策略与内容治理**，不是密码学认证本身；本文既未提出也未测量这些机制。[外推，不计为论文贡献]
- 因此 **A_crypto = 0**（无应用密码学/密码工程内容）；本文不属于密码技术的工程应用。

## 12. 可检验的研究假设（3–6 条）

1. **广告风格 vs 长度/信息量假设**：GAPMA 相对中性改写描述的 ASR 增益，主要来自广告风格而非描述长度/具体性/流畅度。检验：4 种广告风格 + 长度匹配的中性对照 + 纯原始描述，同一 8 服务器 × 10 查询 × 5 模型；用混合效应模型分离 style、length、server、model 的效应。论文没有 length-matched 对照（p.4–5, §4.3）。
2. **GA 的 Pareto 权衡假设**：GA 降低 TPR 的同时可能降低 ASR；存在一个 \(n,k\) 区域使 TPR 显著下降而 ASR 不显著下降。检验：对 \(n\in\{0,1,3,5,10\}\)、\(k\in\{1,5,10,20\}\) 做网格，多次随机种子，报告 ASR–TPR Pareto 前沿；直接检验作者“GA 不降低甚至提升 ASR”的主张（该证据目前在 full version，p.6, §6.2）。
3. **签名/allowlist 假设**：仅对工具描述做签名/来源认证不会显著降低 MPMA ASR（合法恶意发布者仍可通过）；只有 allowlist/声誉/选择审计能显著降低 ASR。检验：2×2 设计（签名验证开/关 × allowlist 开/关），使用同一批 GAPMA 描述，报告 ASR、良性任务成功率、误拒率；这是对 §11 密码学边界论断的直接检验。
4. **位置/primacy 假设**：Best Name 的 ASR 增益部分来自工具名改变导致的排序/位置偏差，而非纯语义偏好。检验：随机化工具列表顺序、固定名称长度、加入 “best” 但保持原排序的对照；比较 ASR。论文未控制位置（p.4, §4.2）。
5. **恶意多数阈值假设**：“over-manipulation” 只在操纵性服务器比例超过某阈值时出现；低于阈值时模型仍偏好恶意服务器。检验：8 个服务器中恶意比例 \(p\in\{0,2,4,6,8\}\) 的扫描，重复 10 次查询，报告良性/恶意选择率；论文只测了 6/8 一个点（p.7, §7）。
6. **人评 vs LLM 评委假设**：平台审核员对 GAPMA 的 TPR 高于 LLM-as-a-judge，且不同广告风格的人评差异小于 LLM 评委差异。检验：招募真实平台审核员/安全分析师，计算 inter-rater agreement，与 5 个 LLM 评委的 TPR 对比；论文只有 3 名标注者、无一致性指标（p.5–6, §5/§6.3）。
