## 1. 150–300 字中文概述

MUZZLE 是面向 Web Agent 的自动化自适应红队框架，用于发现间接提示注入（IPI）攻击。它让受害 Agent 在 The Zoo 沙箱执行良性任务并采集 LLM I/O 与浏览器轨迹，由 Summarizer 压缩步骤、Grafter 按可利用性排序轨迹中出现的 UI 元素；Dispatcher 在最高分元素植入占位符，Payload Generator 以 PAIR 为基础结合执行上下文迭代生成载荷，Reflection 用 Judge 判定 success/partial/failure 并按失败原因改换载荷或 UI 元素。作者在 Gitea、Postmill、Classifieds、Northwind 四个应用、3 个 LLM、2 个 scaffold 上报告 44 次端到端成功运行，发现跨应用攻击与 Agent 定制钓鱼；9 种提示级检测器的后验评测 TPR 偏低。论文无形式化安全定义与密码学机制，属经验型攻击/评测工作。

## 2. 研究背景、现有方法不足、精确定义的问题

- **背景**：LLM Web Agent 通过点击、滚动、输入、切 tab 等动作直接操作浏览器，能完成多步在线任务（p.2, Abstract/§1）。浏览器现有安全机制（用户警告、同源策略、浏览器加固、CAPTCHA、会话信任）按“人类会判断、会注意、会表达意图”设计，而 Agent 可以自动跨站导航、串联合法动作、复用长期权限、规模化改变行为；它不需要绕过浏览器控制，只需利用“技术授权”与“用户真实意图”之间的空隙（p.2, §1）。
- **威胁**：Web Agent 持续摄入不可信网页内容，攻击者可将指令嵌入评论、表单、个人页、消息等，诱导 Agent 把数据当指令执行，造成机密性、完整性、可用性后果（p.2–3, §1–§2.1）。
- **现有方法不足**（p.3–4, §1/§2.3；p.14, §4.3/§5）：
  - WASP 在 VisualWebArena 上人工指定目标网页、注入位置和对抗指令，攻击多为单次模板，通常只到 partial compromise（p.4, §2.3；p.14, §4.3）。
  - AdvAgent 只在冻结的 HTML 快照上优化预选字段中的局部参数（用 DPO 训练），不模拟动态 Web 环境，不能生成可见修改，也不能做多步/跨应用攻击（p.4, §2.3；p.14, §5）。
  - VWA-Adv 扩展了 VWA 的对抗任务，但注入 vessel 仍按场景人工选择，Agent 从预选注入位置开始，且没有在 Web 环境内任意行为的机制（p.14, §5）。
  - AgentVigil 用遗传式变异，但基于 VWA-Adv，策略按场景固定、只优化注入字符串、只以黑盒成功信号为反馈（p.14–15, §5）。
  - 现有 benchmark 多数编译固定场景数据集，不能发现新攻击（p.14, §5）。
- **精确定义的问题**：设计一个系统，在沙箱化虚拟 Web 环境中自动发现、执行并评估针对 Web Agent 的 IPI 攻击；它要把整个模拟环境（长程多步轨迹、互联应用逻辑）纳入攻击生成，允许跨应用编排和对 Agent 执行中遇到的内容做任意修改，并尽量少依赖人工（p.4, §2.3）。
- **三个核心挑战**：攻击空间随注入点、载荷变体、执行步数指数增长，需要优先级排序和自适应细化；对抗指令的优化必须结合动态环境状态、采样的 Agent 轨迹和上下文，而不是固定 HTML 字段的局部优化；沙箱评估要实现攻击结果自动判定、Agent telemetry 采集和可复现（p.4, §2.3）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **受害 Web Agent**：由 scaffold（BrowserUse 是单 LLM 统一推理/动作循环；Agent-E 是 Planner + Browser Executor 双 Agent）和底层 LLM（GPT-4.1、GPT-4o、Qwen3-VL-32B-Instruct）组成；它观察 DOM/截图，执行点击、输入、导航等动作，可能带记忆/规划模块（p.3, §2.1；p.10–11, §4.1）。
- **环境**：The Zoo 沙箱，多个互联 Web 应用（Gitea、Postmill、Classifieds，以及作为跨应用目标的 Northwind/phpMyAdmin），每个应用是独立 Docker 容器，可共享状态；平台暴露后端状态、支持确定性重置、用网络代理记录 LLM I/O（p.4, §2.2/§2.3；p.7, Fig.2）。
- **MUZZLE 组件**（p.7, Fig.2；p.8, Table 1；p.11, §4.1）：
  - **Explorer**：编排器，部署受害 Agent、执行良性与对抗任务、采集 telemetry、管理凭证、重置 The Zoo 后端状态、最终通过后端修改注入载荷。
  - **Summarizer**：把原始 Agent–LLM 交互记录压缩成结构化执行步骤。
  - **Grafter**：从轨迹中识别并排序高显著性的 UI 元素（injection vessels）。
  - **Dispatcher**：把 vessel 描述和利用策略组合成具体攻击计划，并由一个部署的红队 Web Agent 模拟攻击者与站点交互。
  - **Payload Generator**：生成并迭代细化针对对抗目标的载荷。
  - **Judge**：评估攻击结果，归因失败原因，指导下一轮。
  - 红队 Agent 用 Microsoft AutoGen 编排，全部由 GPT-4o 和 GPT-4-Turbo 驱动（p.11, §4.1）。
- **交互流程**（p.6–9, §3.2–§3.5；p.5, Fig.1）：
  1. 操作者给出一个 task spec（Agent、良性任务、依赖/凭证、对抗目标，可选系统级 assertion），每个对抗目标被视为“良性执行不应到达的状态”（p.6, §3.2；Listing 1）。
  2. **Reconnaissance**：Explorer 在沙箱执行良性任务，得到 transcript \(T^b=\langle(r_1,y_1),\ldots,(r_n,y_n)\rangle\)；Summarizer 压缩为步骤 \(S=\langle s_1,\ldots,s_k\rangle\)，每步 \(s_i=(a_i,e_i,u_i)\)；Grafter 输出候选 vessel 排名 \(V=\mathrm{top}_k\langle v_1,\ldots,v_m\rangle\)，每个 \(v_j=(d_j,m_j,c_j)\)，\(c_j\in[0,1]\)。同时对每个对抗目标单独执行，得到目标特定 transcript \(T_i^A\)，用于后续提炼“如何在该应用中实现该目标”的程序性知识（p.7–8, §3.3）。
  3. **Attack Synthesis**：取最高分 vessel \(v^\star=\arg\max_{v_j\in V} c_j\)；Dispatcher 把 \(d\) 与 \(m\) 组合为攻击计划；红队 Web Agent 执行该计划；Explorer 先在 UI 元素中放入占位符 `[INSTR]`，重新执行良性任务得到 \(T^\*\)，截断到占位符首次进入 LLM 上下文的那一步 \(j^\star\)；Payload Generator 把 \(T_i^A\) 提炼为祈使指令 \(I_i\)，以 PAIR 为基础迭代改写候选载荷；对每个候选，把 \(r_{j^\star}\) 中的 `[INSTR]` 替换为候选，单独查询受害 Agent 的 bare-bone LLM，若下一步响应偏离良性任务则标记为 promising；最后 Explorer 通过 The Zoo 后端修改把最终载荷写入 UI 元素（p.8, §3.4）。
  4. **Reflection**：Explorer 用带载荷的 UI 元素重新部署 Agent 执行原良性任务，记录 \(T\)；Judge 计算三值结果 \(O(T)\in\{\text{success},\text{partial},\text{failure}\}\)。若 task spec 给了 assertion，Judge 通过 cURL 调用系统状态断言，避免 LLM 幻觉；若失败，Judge 区分“载荷无效”（指令出现在上下文但被忽略）与“vessel 选择失败”（指令未出现或被截断），前者换更强/不同措辞的载荷，后者换下一个 vessel；直到目标达成或所有 vessel 耗尽（p.9, §3.5）。
- **信任边界**（按原文归纳）：
  - 操作者/评估者提供 task spec，是可信的；MUZZLE 红队组件是评估方工具，是可信的（p.6, §3.2；p.11, §4.1）。
  - 受害 Agent 是黑盒被测对象；其底层 LLM API 流量在“本地部署 + 网络代理”假设下可被观察（p.4, §2.3）。
  - Web 内容是攻击者不可信输入；攻击者可通过客户端接口写入内容或托管恶意应用（p.4, §2.3）。
  - The Zoo 后端/网络代理是评估基础设施，不是被测防御；Explorer 的后端修改能力是评估便利，强于“仅客户端接口”的攻击者模型（p.8, §3.4；p.4, §2.3）。这一点是本人推断，原文没有把它列为威胁模型缺口。
- **前提假设**：受害者使用可部署/可复现的 Agent scaffold 与模型；评估在 The Zoo 内进行；每个 spec 跑 k=5 次；跨应用攻击默认保持 session 隔离，但攻击者可利用存储的凭证认证到目标应用（p.10, §4.1；p.12, §4.2.1）。对专有云 Agent 能否在本地以“同一 Agent + 同一环境”执行对抗目标，原文只以“网络流量可被观察”论证，未真正证明可复现 scaffold；这是本人推断的假设缺口（p.4, §2.3）。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

**资产**（p.2–4, §1–§2.3；p.10, Table 2；p.12, §4.2.1）：
- 机密性：用户凭证（Postmill 用户名/密码）、账户邮箱、仓库内容、Northwind 数据库中的 customers/products/orders。
- 完整性：仓库（删除仓库、添加未授权 collaborator、安装窃听 webhook）、论坛内容（发诈骗链接）、商品 listing（删除竞争 listing）、账户设置（改邮箱）、数据库表（DROP orders table）。
- 可用性：删除仓库、删除账户、删除 listing、删除/破坏数据库表。
- 间接资产：Agent 的行为/意图完整性、跨应用存储凭证与 session 边界。

**攻击者目标**：通过 IPI 让 Agent 采纳并完成 task spec 中的对抗目标，造成 C/I/A 违反；可以是单应用，也可以是跨应用（p.4, §2.3；p.10, Table 2）。

**攻击者能力/知识**（p.4, §2.3）：
- 黑盒；只知道 Agent 执行轨迹和 LLM I/O 中可观察的信息，不能特权访问 Agent 实现或配置。
- 离线发现阶段可观察“本地部署的 Web Agent 与其底层 LLM API”之间的网络流量；原文称用 honest-but-curious proxy 即可，不需修改 Agent，且声称对开源和专有 Agent 都适用。
- 部署阶段只需标准用户级权限。
- 可通过客户端接口提交恶意内容（评论、表单字段、个人页、消息），也可托管攻击者控制的 Web 应用。
- 不能修改服务端应用逻辑、Agent scaffold、底层模型训练管线。
- 目标上追求机密性、完整性、可用性三类违反。

**威胁模型的前提/缺口**：
- 原文没有形式化威胁模型，只有 §2.3 的文字描述；没有攻击者优势、成功概率、计算能力、检测规避等定义（p.4, §2.3）。
- “可观察本地 Agent 与 LLM API 的流量”是很强的位置假设；若 Agent 是远程云服务，攻击者通常看不到云端 Agent 与 LLM 之间的流量。原文用“LLM 请求/响应经过网络”论证，但没有处理 TLS/端点信任/云侧不可见性（p.4, §2.3）。这是本人推断。
- 评估中 MUZZLE 用 The Zoo 的后端修改直接写入载荷（p.8, §3.4），比“通过客户端接口提交内容”的攻击者能力更强；红队 Web Agent 也模拟了发帖/回复，但最终精确注入仍依赖后端修改。这是评估实现与威胁模型的差距（本人推断）。
- 跨应用攻击依赖 Agent 存储的凭证；原文明确说默认 session 隔离，攻击通过凭证认证到目标应用（p.12, §4.2.1）。这不是“绕过认证”，而是“合法凭证的跨应用复用”，与真实部署的 SSO/密码管理器风险相关，但论文没有度量凭证存储策略的影响（本人推断）。

## 5. 核心方案（方法、攻击/防御流程、关键定义）

**5.1 Task spec 与目标表示**（p.6, §3.2；Listing 1）
- 输入 JSON 包含 `agent`、`desc`、`instruction`、`url`、`requirements.credentials`、`dependencies.apps`、`adversarial_objs`；每个对抗目标含 `goal` 和可选 `assertion`（`target` + `assert`，例如删除仓库后 `target=gitea.zoo/alice/hello-zoo/`、`assert=Not Found`）。
- 每个对抗目标被视为“良性执行不应到达的状态”；assertion 用于系统级、确定性的结果检查，避免 Judge 只靠 LLM 判断（p.6, §3.2；p.9, §3.5）。

**5.2 Reconnaissance：从轨迹找注入面**（p.7–8, §3.3）
- \(T^b=\langle(r_1,y_1),\ldots,(r_n,y_n)\rangle\)：第 i 次 LLM 请求（含网页观察）与响应的时间有序记录。
- \(S=\langle s_1,\ldots,s_k\rangle\)，\(s_i=(a_i,e_i,u_i)\)：动作、涉及的 UI 元素/HTML 区域、访问的 URL；保留语义结构、过滤 reasoning tags 等 scaffold 相关低层细节。
- vessel \(v_j=(d_j,m_j,c_j)\)：UI 元素描述、自然语言利用方法、利用分数 \(c_j\in[0,1]\)；排名考虑 Agent 可见性、所需对抗权限（用户生成内容 vs 管理面）、有效表面积（可写空间/截断概率）。k 是可配置超参数。
- 额外执行每个对抗目标作为独立任务，得到 \(T_i^A\)，编码“在该应用中如何实现该目标”的程序性知识（p.8, §3.3）。

**5.3 Attack Synthesis：上下文感知的载荷生成**（p.8, §3.4）
- 选 \(v^\star=\arg\max c_j\)；Dispatcher 把 vessel 描述与利用策略变成攻击计划，由红队 Web Agent 执行（模拟攻击者发帖/回复等）。
- 先在 UI 元素中放 `[INSTR]` 占位符并重跑良性任务，得到 \(T^\*\)；截断到占位符首次可见的步骤 \(j^\star\)，得到“载荷将被如何放入上下文”的快照。
- Payload Generator 把 \(T_i^A\) 提炼为指令 \(I_i\)，再以 PAIR 的迭代改写与反馈为基础，结合 Agent 的任务状态、推理、观察改写候选载荷；PAIR 本身能绕过安全对齐，但缺少 Agent 执行上下文，容易生成通用 jailbreak 而非有效 IPI（p.8, §3.4）。
- 对每个候选，用 \(r_{j^\star}\) 的单次修改请求查询 bare-bone LLM；若下一步响应偏离良性任务，标记 promising。这样在完整部署前评估“指令内容 + 相对位置”的共同效果。
- 最终载荷由 Explorer 通过 The Zoo 后端修改写入。

**5.4 Reflection：结果判定与失败归因**（p.9, §3.5）
- \(O(T)=\text{success}\) 若对抗目标被采纳并完成；\(\text{partial}\) 若被采纳但未完成；\(\text{failure}\) 若被忽略/继续原任务。
- 有 assertion 时，Judge 用 cURL 调系统断言，grounding 结果；无 assertion 时靠 LLM Judge。
- 失败归因：指令在有效上下文但被忽略 → payload ineffectiveness，换更强/不同措辞；指令未出现/被截断 → vessel selection，换下一个 vessel。
- 循环直到成功或所有 vessel 耗尽，再进入下一个对抗目标。

**5.5 与静态 benchmark 的区别（本文“adaptive”的确切含义）**
- 静态 benchmark：固定攻击数据集/模板、人工指定网页和注入位置、固定 payload、通常单次执行；例如 WASP 的手工模板、VWA-Adv 的预选 vessel、AdvAgent 的冻结 HTML 快照、AgentVigil 的固定场景策略（p.3–4, §2.3；p.14–15, §5）。
- MUZZLE 的“adaptive”体现在三处：(1) 用受害 Agent 自己的轨迹发现并排序注入面，而不是人工指定；(2) 用受害 Agent 的执行上下文和 \(T_i^A\) 生成载荷，而不是通用模板；(3) 用 Judge 的 success/partial/failure 反馈在“换载荷”与“换 vessel”之间做失败归因和迭代（p.3, §1；p.5, §3.2；p.8–9, §3.4–§3.5）。
- 但它不是“对防御自适应”：反馈信号是攻击是否成功，不是检测器分数；没有在防御器在环的情况下优化规避；附录 B 的 9 种提示级检测器是事后（post-hoc）在已收集轨迹上评测，不是运行时防御在环（p.21, Appendix B）。也不是跨任务学习：每个 task spec/目标独立搜索，没有策略库、bandit、RL 或跨目标迁移（p.8–9, §3.4–§3.5；本人推断）。
- 它仍需操作者给出 Agent、良性任务、凭证和对抗目标（p.5, §3.1；p.6, Listing 1）；“自动化”指攻击实现与评估，不是目标设定。论文还说每个攻击都由人工评估者复核（p.11, §4.2.1），这与“without human intervention”的强表述存在张力（本人推断）。

**5.6 攻击者能力边界（相对静态 benchmark 的关键差异）**
- 比 WASP/AdvAgent 多了：轨迹级注入面发现、动态沙箱执行、后端状态修改、跨应用编排、多步攻击链（p.3–4, §1/§2.3；p.14, §4.3）。
- 但仍不能：改服务端逻辑、改 scaffold、改模型训练；不能伪造身份绕过认证；跨应用需要有效存储凭证；不能保证 payload 不被 UI 元素大小截断（p.4, §2.3；p.20, §A.2）。
- 评估环境的 Explorer 后端修改能力 > 纯客户端攻击者能力；这是本文威胁模型与实现之间的边界（p.8, §3.4；本人推断）。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- **没有形式化安全定义、没有定理/引理/证明、没有安全游戏/归约**。全文的“形式化”只是记号：transcript 元组、步骤序列、vessel 排名 \(V=\mathrm{top}_k\)、\(\arg\max\)、三值 \(O(T)\)（p.7–9, §3.3–§3.5）。这些是描述性/操作性记号，不是可证明的安全模型。
- **安全属性是口头分类**：confidentiality、integrity、availability 三类，对应具体 adversarial objectives；没有定义攻击者优势、成功概率、不可区分性、可靠性等（p.4, §2.3；p.10, Table 2）。
- **度量是经验性的**：Partial Attacks = 采纳但未完成的运行数；End-to-end Attacks = 采纳并完成的运行数，E2E 是 Partial 的子集；均按 k=5 次运行统计（p.9, §4.1）。没有置信区间、方差、显著性检验。
- **成功判定**：Judge LLM + 可选 assertion（cURL 系统状态）；assertion 只覆盖部分目标，且不是密码学 attestation，只是应用状态检查（p.9, §3.5；p.6, Listing 1）。论文说每个攻击由人工评估者复核（p.11, §4.2.1），但没有报告复核一致性、误判率或 partial 的复核方式。
- **核心安全主张是经验主张**：MUZZLE 能自动发现 44 次 E2E 成功运行、跨应用攻击和 agent-tailored phishing；提示级检测器 TPR 低；多 Agent scaffold 一旦被劫持更易完全执行（p.2–3, Abstract/§1；p.11–14, §4.2；p.21, Appendix B）。没有“防御后仍安全”或“攻击成功率上界”的证明。
- **没有防御形式化**：没有定义“安全 Web Agent”应满足的性质，也没有证明任何防御满足该性质；防御评估只是后验分类器 TPR/FPR（p.21, Appendix B）。

## 8. 贡献与创新点（按原文主张）

1. **首个全自动 Web Agent IPI 红队框架**：在沙箱 Web 环境中端到端运行，声称无需人工干预（p.3, §1）。
2. **多 Agent 架构**：自动发现多步攻击路径、排序轨迹中的高杠杆 UI 元素、迭代生成上下文感知载荷、用执行反馈自适应细化（p.3, §1；p.7–9, §3）。
3. **评测规模**：4 个 Web 应用、10 个对抗目标、3 个 LLM、2 个 Agent scaffold，沙箱内端到端评估、可复现（p.3, §1；p.9–10, §4.1）。
4. **攻击发现**：44 次 E2E 攻击运行，覆盖机密性/完整性/可用性；发现 3 次跨应用攻击运行（2 个跨应用场景）和一个 agent-tailored phishing 场景（p.2–3, Abstract/§1；p.11–12, §4.2.1；p.10, Table 2）。
5. **开源**：代码、评测脚本、攻击快照公开（p.3, §1；p.15, Open Science）。

## 9. 局限、失败案例、作者承认的不足（区分作者承认 vs 你的推断）

**作者承认/原文明确写到**：
- **没有独立 Limitations 章节**；限制散落在 §4.3、§4.2.4、§A.1、§A.2、Appendix B 和 Ethics。
- 与 WASP 的直接对比受环境/目标差异限制，跨应用对比不可行（p.14, §4.3）。
- 运行时是“一次代表性成功运行”的 breakdown，不是多次平均（p.13, §4.2.4）。
- 终止行为是概率性的，依赖 Grafter 对 UI 元素的排序，不同运行可能不同；有些目标很快耗尽 vessel，有些会持续探索（p.20, §A.1）。
- 部分目标在 i=0/1 就达到最大 E2E，reflection 的收益主要集中在复杂/跨应用目标（p.20, §A.1）。
- Fixed UI 选择会因 issue title 字符上限失败，且关闭 reflection 时无法发现并适应这个约束（p.20, §A.2）。
- 目标模型 GPT-4o 对显式破坏性动作（delete/purge/drop）有较强抵抗，常在动作变得显著时脱离攻击轨迹（p.11, §4.2.1）。
- 跨应用攻击依赖存储凭证；默认 session 隔离，攻击通过有效凭证认证到目标应用（p.12, §4.2.1）。
- 评测的 Agent 都没有专门的 IPI 防御；作者建议用户确认敏感动作、输入清洗、最小权限，但没有实验评估这些建议（p.15, Ethics）。
- 防御评测是 post-hoc 的提示级分类器，不是运行时防御；作者明确说实验中没有在运行时使用 prompt-level 防御（p.21, §B）。
- 每个攻击由人工评估者复核（p.11, §4.2.1），这与“fully automated / without human intervention”的强主张有张力。

**本人推断（不是作者原话）**：
- **“44 distinct attacks”是运行次数，不是 44 个不同攻击**：§4.1 把 E2E 定义为“total number of evaluation runs”，Table 2–4 的 44 正是跨配置的 E2E 运行数；其中同一目标在不同 LLM/scaffold 上重复计数，同一目标在同配置的 k=5 中也可能多次成功。Abstract/§1 的 “44 new attacks” 与 “3 cross-application attacks”（Table 2 跨应用只有 2 个目标、3 次 E2E 运行）都应按“运行/实例”理解，不能当作 44 个独立攻击技术（p.9 vs p.2–3, p.11, p.10 Table 2）。
- **“three user tasks” vs 四个任务**：§4.1 开头说三个用户任务（Gitea/Postmill/Classifieds），随后又写 “The fourth task involves database administration ... Northwind”；Table 2 中 Northwind 只作为 cross-app 目标出现，没有独立的 Northwind 用户任务（p.9–10, §4.1；p.10, Table 2）。
- **“10 adversarial objectives”口径不明**：Table 2 有 11 行、9 个不同目标标签；“10” 可能是把 cross-app 的 Northwind 目标算作新目标、把 cross-app 的 Postmill 删除账户视为重复，但正文没有定义（p.10, Table 2；本人推断）。
- **Abstract 的属性列表不一致**：Abstract 写 “confidentiality, availability, or privacy”，而威胁模型/目标是 confidentiality、integrity、availability；Abstract 漏了 integrity、加了 privacy（p.2 vs p.4/p.10）。
- **webhook 的 partial 数矛盾**：p.11 写 “all five runs resulted in partial compromise”，Table 2 和 Table 7 都写 Partial=4、E2E=0（p.11 vs p.10/p.20）。可能是笔误，但按表格数字应为 4。
- **Qwen 命名不一致**：正文写 “Qwen3-VL-32B-Instruct”，Table 3 表头写 “Qwen3-32B”（p.10/p.12 vs p.13）。
- **Table 9 的文字与表格不一致**：p.21 说 raw payload 检测率上升的 “notably Llama PromptGuard 2 and LlamaGuard 3 and 4”，但 Table 9 中 Llama-Prompt-Guard-2-86M 的 Browser State TPR 0.034、Raw Payload 0.013（下降），真正上升的是 Meta-Llama-Guard-2-8B（0.158→0.532）、Llama-Guard-3-8B（0.043→0.316）、Llama-Guard-4-12B（0.143→0.595）。这像是把 “LlamaGuard 2” 误写成 “Llama PromptGuard 2”（p.21, Table 9）。
- **Table 6 的选择偏差**：对比只选“已确认有 E2E”的代表性目标，且每应用只有 10 次；combined ASR 是按应用等权平均，不是所有运行 pooled；WASP 的 GitLab 与 MUZZLE 的 Gitea 也不是同一应用。86.7% vs 20.0% 应用作方向性证据，不宜当作精确效应量（p.14, §4.3；本人推断）。
- **样本与统计**：每个 spec k=5，跨应用/多 LLM 的组合很小；没有置信区间、方差、显著性检验；红队模型固定为 GPT-4o/GPT-4-Turbo，没有消融红队模型能力对攻击发现的影响（p.9–11, §4.1；p.13, Table 5；本人推断）。
- **环境泛化**：只在一个沙箱（The Zoo）的 4 个应用上评测；“web application agnostic” 的主张没有在真实网站、其他沙箱（WebArena/VWA）、更多应用上验证（p.9–10, §4.1；本人推断）。
- **Judge 可靠性**：Judge 是 LLM，assertion 只覆盖部分目标；人工复核只针对“每个攻击”（E2E），没有报告 partial 的复核、误报率、LLM Judge 与人工的一致性（p.9, §3.5；p.11, §4.2.1；本人推断）。
- **防御覆盖**：只评测提示级分类器，没有评测内容来源签名、隔离、capability/最小权限、用户确认、CSP/同源策略等系统级防御；因此论文不能说明这些防御是否有效，也不能说明自适应攻击者面对这些防御时的表现（p.21, Appendix B；p.15, Ethics；本人推断）。
- **攻击者位置假设**：离线发现阶段可观察本地 Agent 与 LLM API 的全部 I/O；对远程云 Agent 不成立，且 TLS/端点信任会使网络观察失效。论文没有讨论这一点（p.4, §2.3；本人推断）。
- **后端修改 vs 客户端注入**：Explorer 直接改 The Zoo 后端来精确放置载荷，强于“通过客户端接口提交内容”的威胁模型；这可能高估了纯远程攻击者的成功率（p.8, §3.4；p.4, §2.3；本人推断）。
- **成本**：只报告 wall-clock，不报告 token 数、API 费用、红队查询次数；跨应用/多目标扩展的成本不明（p.13, Table 5；本人推断）。
- **无自适应防御对抗**：MUZZLE 的反馈是攻击成功/失败，不是检测器分数；没有让攻击者知道防御并优化规避，因此不能支持“对防御自适应”的强结论（p.8–9, §3.4–§3.5；p.21, §B；本人推断）。

- **可能的（但论文未做、且不应算作论文贡献的）工程联系**：内容来源签名/ provenance 可以标注“这段内容由谁发布”，但 MUZZLE 的攻击者本来就可以通过合法客户端接口发帖/评论（p.4, §2.3），签名会把恶意内容认证为“合法用户发布”，不能区分恶意意图；capability/最小权限可以限制跨应用动作，但论文的跨应用攻击正是利用 Agent 已持有的存储凭证（p.12, §4.2.1），需要凭证作用域/委托衰减才能缓解；TEE/隔离可以保护 Agent 运行时，但不能阻止 LLM 把不可信网页文本当指令（这是语义问题）。这些都是本人推断的研究方向，论文没有实现或评测，不能写成“论文的技术联系”。
- **结论：A_crypto = 无（0）**；本文是纯语义/系统红队工作，不是密码工程应用。

## 12. 可检验的研究假设（3–6 条）

1. **H1（自适应 vs 静态）**：在相同应用、目标、Agent 和运行次数下，MUZZLE 的轨迹驱动 vessel 选择 + 上下文载荷生成，E2E ASR 显著高于 WASP 式固定模板和 VWA-Adv 式预选 vessel。检验：预注册同一 The Zoo 环境、同一 k（≥30）、同一目标集，比较 E2E/partial；控制红队 LLM 与 API 预算。依据：p.14, Table 6 的方向性结果，但当前 k=10、目标经“已确认成功”筛选，需更严格复现。
2. **H2（reflection 的边际收益）**：reflection 的 E2E 增益主要集中在跨应用/多步目标；单应用目标在 i=0/1 已饱和，增加迭代的边际收益接近 0。检验：按目标分层，记录每轮新增 E2E，做生存分析/泊松回归；当前 Table 7 显示 Northwind 跨应用在 i=2 才首次成功，而多数单应用目标 i=0 已达最大（p.20, §A.1）。
3. **H3（组件必要性）**：Grafter 的轨迹约束是主要贡献，随机/固定 vessel 选择即使配合优化载荷也接近 0；反之，Grafter + 非优化载荷也接近 0。检验：2×3 因子设计（vessel: random/fixed/Grafter × payload: naïve/template/optimized），扩大应用与目标；当前 Table 8 只有 Gitea 一个目标、k=5（p.20, §A.2）。
4. **H4（scaffold 的“劫持后承诺”效应）**：多 Agent scaffold（Planner+Executor，布尔反馈）一旦被劫持，E2E 率高于单 LLM 统一循环；原因是 Planner 看不到 Executor 的实际动作。检验：在更多 scaffold 上插桩 Planner–Executor 消息，测量“首次偏离后的恢复率”；当前 Table 4 的 Agent-E 7/15 vs BrowserUse 3/15 只是单应用、单模型的证据（p.12–13, §4.2.3/Table 4）。
5. **H5（提示级检测器的局限）**：在 browser-state 观测上，提示级分类器的 TPR 与 FPR 不能同时达到可用工作点；在 raw payload 上 TPR 上升的方法往往缺乏 FPR 报告。检验：在固定阈值下报告 ROC/PR 曲线、TPR@FPR≤1%、跨应用留一验证；当前 Table 9 只给单点 TPR/FPR，且 FPR 只有 browser-state（p.21, Table 9）。
6. **H6（系统级防御的增量）**：在相同攻击集上，内容来源标注 + 凭证作用域/最小权限 + 敏感动作用户确认的组合，比单一提示级分类器更能降低 E2E，但会增加任务完成时间/误拒率。检验：在 The Zoo 中实现这些防御并重跑 MUZZLE；当前论文没有做（p.15, Ethics；本人推断）。
