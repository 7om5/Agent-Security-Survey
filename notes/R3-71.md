## 1. 150–300 字中文概述

论文把间接提示注入（IPI）的成败归因于检索环节：先把恶意文本拆成承载任意攻击目标的 attack fragment 与保证被检索的 trigger fragment，再用黑盒 Cross-Entropy Method 仅通过 embedding API 优化约 10 个 token 的前缀，使单个恶意条目在自然查询下进入 top-5。作者在 11 个 BEIR 语料（默认 GTE）与 FiQA 上的 8 个 embedding 模型上报告接近 100% 的 Recall@5，并在 RAG（11 个 LLM）与 AutoGen/Magentic-One 邮件 Agent 上做端到端攻击；GPT-4o 多 Agent 代码执行并外泄 SSH 密钥的报告值为 80%。查询改写、困惑度过滤、token masking 三种防御均被自适应变体绕过。所谓 “in the wild” 实际是公开基准语料与 Enron 邮件语料上的合成注入，并未探测真实部署（p.15）。

## 2. 研究背景、现有方法不足、精确定义的问题

**背景。** 检索增强 LLM 系统的典型流程是：用户查询 \(q\) 经 embedding 模型 \(E\) 编码，从外部语料 \(\mathcal{D}\) 中按余弦相似度取 top-\(K\) 文档，再由基座 LLM 生成回答或调用工具/Agent（p.2–3, §1 与 Figure 1）。这条 pipeline 把外部数据变成模型上下文的一部分，因此攻击者可以把指令写进被检索的文档，形成间接提示注入（IPI）；EchoLeak 等真实事件表明，恶意邮件可以在用户不直接交互的情况下导致数据外泄（p.2, §1，引用 [2]）。

**现有方法的不足。** 作者把 prior work 的评测概括为“默认恶意文本已经在上下文中”，典型做法包括：把恶意文本放进“latest email”并让用户显式要求处理它；构造只含一个恶意文本的语料；要求用户查询包含优化过的 trigger token；或对 retriever 做后门微调（p.2, §1；p.14, §7）。这些设置把“检索之后会发生什么”演示得很充分，却没有回答“自然查询下恶意文本是否会被检索到”。作者在 BEIR 的 11 个检索语料上观察到，未经优化的恶意文本在自然查询下几乎从不被检索（p.3, §1；p.7–8, Table 1 与 Figure 2 的 Vanilla 基线）。另一方面，白盒方法（HotFlip、PoisonedRAG）需要 embedding 模型梯度，而现代部署常用闭源 embedding API；黑盒的 Query+（把查询本身重复到恶意文本前）收益有限，ArguAna 上仅约 20% Recall@5（p.3, §1；p.4–5, §2.1/§3.1；p.7–8, §4.1）。

**精确定义的问题。** 给定任意自然查询 \(q\) 和攻击者指定的 attack fragment \(D_{\mathrm{adv}}\)，构造前缀 \(x\)，使 \(x \parallel D_{\mathrm{adv}}\) 进入 \(\mathcal{D}\cup\{x\parallel D_{\mathrm{adv}}\}\) 的 top-\(K\)，从而让 \(D_{\mathrm{adv}}\) 被 LLM 执行（Problem Definition 1，p.4）。进一步把前缀搜索写成带 token 预算 \(n\) 的 \(\varepsilon\)-optimal 问题：在 \(x\in\mathcal{V}^n\) 上寻找 \(f(x)>f(x^*)-\varepsilon\)，其中 \(f(x)=\mathrm{sim}(E(q),E(x\parallel D_{\mathrm{adv}}))\)，黑盒调用 \(f\) 的次数受预算 \(B\) 限制（Problem Definition 2，p.5）。作者声明 \(D_{\mathrm{adv}}\) 本身如何构造、下游影响如何，不在本文范围，属于直接提示注入文献（p.4, §2.1 “Scope of this work”）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

**组件与流程。** 系统由用户、查询 embedding、外部语料/向量库、基座 LLM、工具与（多）Agent 组成（p.3, Figure 1；p.4, §2）。流程分三步：Step 1 用户提交自然查询（如“检查报销流程邮件并总结”）；Step 2 将查询 embedding 后从语料中检索 top-\(K\)；Step 3 LLM 基于查询与检索内容生成回答、调用工具或执行代码，攻击后果被画成 3-a 错误回答/DoS、3-b 垃圾信息、3-c 运行代码（p.3, Figure 1）。

**RAG 设置。** 检索文档直接拼进 LLM 上下文，攻击目标是让模型对任意查询输出固定短语（如 “Yes”），即 targeted answer attack（p.10, §5.1）。

**单 Agent 设置。** 使用 AutoGen 的 round-robin 调度，四个工具：邮件检索、send-email、contact-list、Python 执行；基座模型为 GPT-4o 与 GPT-4o-mini，工具均通过 MCP 实现（p.11, §5.2）。

**多 Agent 设置。** 使用 AutoGen 中的 Magentic-One：Orchestrator 把任务分派给 FileSurfer（读文件）、Coder/Computer Terminal（写/执行代码），并加入一个带邮件检索、send-email、contact-list 工具的 retriever agent（p.11, §5.2）。作者的解释是：每个 Agent 只有有限上下文，代码执行 Agent 把来自“可信队友”的 Python 当成良性内容，且根本看不到恶意邮件或用户查询（p.13, §5.2 “Multi-agent amplification”，[原文解释]）。

**信任边界（按原文归纳）。** 外部语料/邮件是攻击者可以写入的不可信输入（p.4, §2.1：unverified parties, online sources, email systems）；检索到的文本与用户查询被放进同一上下文，系统没有 instruction/data 分离或来源标签（p.10–11, §5.1/§5.2，[推断]）；基座 LLM 是可能被注入指令影响的执行者；MCP 工具与多 Agent 队友消息被 Agent 当作可信动作接口/可信队友内容（p.11–13，[PDF证据+推断]）；用户资产（邮箱、联系人、SSH 密钥）位于工具可达范围。论文没有给出形式化的信任边界或 capability 模型，以上为对其文字与实验设置的归纳。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

**资产。** 用户邮箱内容与联系人列表、`~/.ssh` 下的 SSH 密钥、Agent 的行为/回答完整性、收件人的邮箱与点击行为（钓鱼 worm 传播）、代码执行环境（p.12, Table 2；p.13, §5.2）。RAG 场景的资产是答案正确性/模型输出完整性（p.10–11, §5.1）。

**攻击目标。** 四类：(1) Answer manipulation：让 Agent 输出攻击者指定答案；(2) Phishing worm propagation：恶意邮件携带自复制指令与钓鱼链接，Agent 回信时把两者一起转发；(3) Tool misuse：诱导 Agent 枚举联系人并群发钓鱼链接；(4) Code execution：让 Agent 在正常任务中执行任意 Python，例如从 `~/.ssh` 外泄密钥（p.11–12, §5.2；p.12, Table 2）。

**攻击者能力/知识。** 黑盒设置：不知道外部语料 \(\mathcal{D}\) 的内容（除了自己能注入的条目），不知道 retriever 与 LLM 的参数；只能通过标准 API 查询 embedding 模型 \(E\)，获得 token 序列的向量；只能注入一个恶意条目，模拟 stealth attack；可以指定任意 attack fragment \(D_{\mathrm{adv}}\)；目标查询 \(q\) 是自然的、任意的（p.4, §2.1）。算法最多进行约 150,000 次黑盒 embedding 调用，商业 API 成本约 $0.21–$0.76 每条目标查询（p.8–9, §4.1）。

**前提假设。** top-\(K\) 取 \(K=5\)，相似度为余弦；语料在攻击期间静态；攻击者能够写入目标语料或用户邮箱；embedding 服务可按 token 序列查询且无严格的滥用检测/速率限制被建模；检索系统是纯 embedding 检索，不含 hybrid 检索或 reranking（p.14, §8 明确承认未评估）；LLM 会把检索内容当上下文并可能遵循其中指令。**论文没有形式化的攻击者优势、成功概率、计算能力或检测规避定义**；预算 \(B\) 只用于算法复杂度讨论（p.5, §3.1）。此外，trigger 是针对特定目标查询 \(q\) 优化的：每个数据集取 100 个 query，每个 query 生成并注入一个恶意条目（p.6–7, §4），这意味着现实部署中攻击者需要预先知道或猜测查询，或为多个查询分别投放；论文未把“跨查询泛化”作为威胁模型的一部分（[推断]，基于 p.6–7 与 p.9–10 只讨论跨模型/位置/attack fragment 的迁移）。

## 5. 核心方案（方法、攻击/防御流程、关键定义）

**5.1 分解与检索条件。** 恶意文本写成 \(x\parallel D_{\mathrm{adv}}\)：\(D_{\mathrm{adv}}\) 是攻击载荷，\(x\) 是只负责提升检索相似度的 trigger fragment（p.3, §1；p.4, §2.1）。定义 \(f(x)=\mathrm{sim}(E(q),E(x\parallel D_{\mathrm{adv}}))\)；\(x\parallel D_{\mathrm{adv}}\) 进入 top-\(K\) 等价于 \(f(x)\) 超过未污染语料第 \(K\) 名的相似度阈值（p.4–5, §3.1）。由于攻击者看不到语料，该阈值未知，精确求解被作者称为 NP-hard，证明被推到“full arXiv version”（p.5, §3.1；本 PDF 无此证明）。因此转而求 \(\varepsilon\)-optimal：在 token 预算 \(n\) 下找 \(f(x)>f(x^*)-\varepsilon\)（Problem Definition 2，p.5）。

**5.2 CEM Attack。** 使用完全因子化分布 \(p(x)=\prod_{i=1}^{n}p_i(x[i])\)，每轮采样 \(N\) 条序列，计算 \(f\)，取分数最高的 \(\lambda N\) 条作为 elite，按 \(p_i^{(t+1)}(v)=(1-\alpha)p_i^{(t)}(v)+\alpha\bar p_i(v)\) 更新每个位置的分布，其中 \(\bar p_i(v)\) 是 elite 中第 \(i\) 位为 token \(v\) 的比例；迭代 \(T\) 轮后输出最优序列（p.5–6, §3.2 与 Algorithm 1）。默认参数：\(n=10\)、\(N=5000\)、\(T=30\)、\(\lambda=0.2\)、\(\alpha=0.55\)，总计最多 150,000 次打分调用（p.7, §4；p.8, §4.1）。初始化为均匀分布；算法只需黑盒调用 \(f\)，不需要 embedding 梯度（p.5–6）。

**5.3 理论声明。** Theorem 1 声称：若打分函数对各 token 位置线性可加，即 \(f((x_1,\ldots,x_n))=\sum_i f_i(x_i)\)，则 \(T=O(\log|\mathcal{V}|)\)、每轮 \(N=O(\log(1/\delta))\) 时，算法以至少 \(1-\delta\) 的概率返回 \(f(x)\ge f(x^*)-\varepsilon\) 的序列（p.6, §3.2）。证明被推迟到附录；本 PDF 不含证明。定理陈述中没有显式给出 \(T,N\) 对 \(\varepsilon\) 的依赖，且线性可加假设与真实 embedding 的非线性池化存在张力；作者只用“现代 sentence embedding 常做 pooling、对 token 顺序不敏感”来 motivate（p.6, “Remark on factorization and linearity”）。

**5.4 基线与融合。** Query+ 直接把目标查询 \(q\) 作为前缀（“repeat query”）；Vanilla 不加前缀；Ours 用 CEM 学到的 10-token 前缀；Ours (Fusion) 把 trigger fragment、用户查询、attack fragment 拼接起来（p.7, §4.1；p.12, §5.2）。Fusion 是 CEM 与 Query+ 的融合，用来同时提升检索相似度与下游执行概率（p.12, §5.2）。

**5.5 迁移与隐蔽性分析。** 跨 embedding 模型（Figure 5）、跨位置（Figure 6）、token 随机分散（Figure 7）、跨 attack fragment（Figure 8）四个维度评估 trigger 的可复用性；结论是同一 Qwen 家族内迁移较好、跨架构较差，位置和分散在多数模型上仍有效，但 OpenAI embedding 的位置敏感性使分散攻击降到 6%（p.9–10, §4.2）。

**5.6 防御与自适应攻击。** 评估三种“无需攻击者优化信息”的防御：查询改写、困惑度过滤、token masking。自适应攻击分别用多改写联合优化、重复恶意文本降低困惑度、把 trigger token 分散到全文来绕过；作者结论是三者都不能提供持久保护（p.13–14, §6）。细粒度结果与 Appendix B/B.1/B.2 被引用但不在本 PDF 中。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

**原文的安全声明。** (C1) 检索是 IPI 的决定性瓶颈；未经优化的恶意文本在自然查询下不会被检索（p.3, §1；p.7–8, Figure 2）。(C2) 把 IPI 分解为 trigger fragment 与 attack fragment，并用黑盒 CEM 构造 trigger，可在 11 个基准、8 个 embedding 模型上达到接近 100% 的检索（p.2, Abstract；p.3, Contributions）。(C3) 一旦检索成功，单个恶意文档可以在 RAG 与单/多 Agent 系统中劫持行为，GPT-4o 多 Agent 代码执行/SSH 外泄达到 80%（p.2, Abstract；p.12, Table 2）。(C4) 查询改写、困惑度过滤、token masking 等防御不足以阻止检索，自适应攻击可绕过（p.13–14, §6）。

**形式化程度。** 论文给出了两个优化问题的定义（Problem Definition 1/2，p.4–5）和一个 CEM 的 utility 定理（Theorem 1，p.6），但**没有安全定义、攻击游戏、敌手优势、归约或端到端安全保证**。Theorem 1 是“在给定线性打分结构下逼近最优 \(f(x)\)”的优化/统计保证，不是“恶意文本一定进入 top-\(K\)”的检索保证：它不对未观测语料的竞争阈值作任何声明。所谓 “guarantee the retrieval for any attack fragment”（p.2–3）在形式上没有成立——Algorithm 1 以特定 \(D_{\mathrm{adv}}\) 为输入优化 \(x\)；Figure 8 只显示同一 trigger 对其它 attack fragment 的余弦相似度有提升，并未报告 top-5 检索率或端到端 ASR（p.10, Figure 8）。NP-hard 陈述被推到本 PDF 之外的 full arXiv 版本（p.5），本 PDF 无法核验。安全性主要是经验主张，指标为 Recall@5、MRR@5、nDCG@5 与 ASR（p.7, §4.1；p.11, §5.1；p.20, Appendix A.1）。

**“in the wild” 的界定。** 标题中的 “in the wild” 指“自然查询 + 真实语料”，不是对真实部署的测量：数据来自 BEIR 公开检索基准与 Enron 公开邮件语料，恶意内容由作者合成注入；Ethics 明确写 “no real-world deployments were probed”（p.15）。因此 C1–C4 都应理解为受控基准上的可行性结论，而非野外发生率或真实系统被攻陷率。

## 7. 实验设置与主要结果（agents、场景、指标、关键数字、消融）

**检索实验。** 11 个 BEIR 数据集：MSMARCO（8.8M docs）、TREC-COVID（0.171M）、NFCorpus（0.036M）、Natural Questions（2.7M）、HotpotQA（5.2M）、FiQA-2018（0.058M）、ArguAna（0.087M）、DBPedia（4.6M）、SCIDOCS（0.026M）、FEVER（5.4M）、SciFact（0.052M）（p.7, Table 1）。每个数据集取 100 个 query，每个 query 注入一个恶意条目，指标为 Recall@5（0/1，平均），K=5；默认 embedding 为 gte-modernbert-base（139M 参数、768 维），另在 FiQA 上评测 8 个模型：GTE、Contriever、Qwen3-Embedding-0.6B/4B/8B、Voyage-3.5-lite、OpenAI text-embedding-3-small、Qwen-v4（p.7, §4）。实现基于 BEIR 与 FAISS，H100 服务器（p.7）。

**主要检索结果。** Figure 2（p.8）：Vanilla（空前缀）在所有数据集上 Recall@5 为 0；CEM 在 NFCorpus、SciFact 等上接近 100%，在 MSMARCO、ArguAna 上随前缀长度增加而上升，约 15 token 时通常超过 80%、有时 90%；Query+ 明显较低，ArguAna 约 20%（p.7–8, §4.1）。Figure 4（p.8）：FiQA 上 8 个模型，GTE/Contriever/Qwen3-0.6B/4B/8B/Voyage/Qwen-v4 均为 100%，OpenAI 为 90%。作者据此称“更强的 embedding 模型不提供鲁棒性”（p.8, §4.1）。**注意：8 个模型只在 FiQA 上评测，11 个数据集主要用默认 GTE；Abstract 的“11 benchmarks and 8 embedding models”容易被读成完整交叉网格，但 PDF 并未给出该网格（[推断]，基于 p.7–9 的实验描述）。**

**成本与效率。** 默认设置最多 150,000 次黑盒调用；商业 API 生成一个 trigger 约 $0.21（Voyage-3.5-lite 或 OpenAI text-embedding-3-small），Qwen-v4 最多 $0.76；开源模型在单张 H100 上约 1.6 分钟（Contriever）、2.3 分钟（GTE）、7.6 分钟（Qwen3-0.6B），几乎全部时间用于 embedding 计算（p.8–9, §4.1）。

**迁移性。** Figure 5（p.9）：trigger 在 Qwen 家族内跨模型迁移较好；跨架构较差。正文称 Qwen3-0.6B 构造的 trigger 到 OpenAI 只有 10%，但矩阵该单元格为 30；正文称 OpenAI 构造的 trigger 平均 74%、8 个模型中 7 个超过 60%（除 Contriever），但矩阵该列约为 71%，且 GTE（40）也低于 60（见 §9 不一致）。Figure 6（p.10）：位置 0 优化的 trigger 移到其它位置，多数模型仍 >50%，OpenAI 在位置 20 附近降到接近 0；直接在末尾优化仍可达 60%。Figure 7（p.10）：token 随机分散后，GTE 90、Contriever 22、Qwen3-0.6B 68、Qwen3-4B 91、Qwen3-8B 80、Voyage 88、OpenAI 6、Qwen-v4 86。Figure 8（p.10）：用为一个 attack fragment 优化的 trigger 去增强其它 attack fragment，余弦相似度从约 −0.1 提升到最高约 0.76（图中散点最高约 0.88，正文与图存在轻微读数差异）。

**RAG 端到端。** 11 个数据集；正文称 11 个 LLM（Qwen3 0.6B–32B、LLaMA-3 3B/8B、Vicuna 7B/13B，含 base 与 instruction-tuned），但 Figure 9 实际列出 12 个模型行（见 §9），ASR 定义为“干净语料不产生目标回答、污染语料产生目标回答”的比例，5 个随机种子平均（p.11, §5.1）。Figure 9（p.11）：多数模型/数据集 ASR 接近 1；Qwen 系列整体很高；Llama3-3B 明显较低（多列 0.1–0.3）；MSMARCO 整体较低；无前缀时 ASR 为 0；instruction-tuned 通常更脆弱（p.11）。知识 poisoning 变体在 NQ、LLaMA-2-7B 上达到 ASR 0.58（2-token trigger），单 token 0.50，与 PoisonedRAG 的 0.58 持平（p.11, §5.1 “Extension to knowledge poisoning”）。

**Agent 端到端。** Enron 邮件语料，挑选有 ≥50 封收发邮件的用户，用 Claude Sonnet 4 生成 10 个 FAQ；每个问题注入一封恶意邮件；单 Agent AutoGen（GPT-4o/4o-mini，4 个 MCP 工具），多 Agent Magentic-One（p.11–12, §5.2）。Table 2（p.12）关键数字：GPT-4o 多 Agent 代码执行 ASR：Ideal 58%±18、Query+ 56%±5、CEM 72%±16、Fusion 80%±7；GPT-4o 单 Agent 代码执行仅 2%–4%；GPT-4o 多 Agent 钓鱼 worm 的 Phishing 为 CEM 66%±17、Fusion 84%±11，Worm 为 CEM 0%±0、Fusion 18%±13；工具滥用 Sent/Phishing 在 GPT-4o 上为 92%–98%，GPT-4o-mini 较低（58%–84%）；targeted answer 在 Agent 设置下 GPT-4o CEM 仅 2%±4、Query+ 14%±5、Fusion 16%±11，GPT-4o-mini CEM 0%、Fusion 4%（p.12, Table 2）。作者强调“现实检索 + Fusion”在多 Agent 代码执行上甚至超过“ideal already-in-context”基线（80% vs 58%），并称 prior IPI 评测可能低估风险（p.13, §5.2）。

**防御实验。** 查询改写：多数数据集 Recall@5 下降 <10%，但攻击者对多个改写联合优化后性能完全恢复甚至超过基线；困惑度过滤：恶意文本初始困惑度较高，但重复文本可把困惑度降到低于干净文档；token masking：随机 mask 在 trigger 变长后几乎无效，部分删除仍保留足够 token（5 个已可高召回），且 trigger token 可分散、看起来 benign（FiQA 中最常见 token 是 “business”）（p.13–14, §6）。作者没有评估需要微调目标模型的防御（SecAlign、DataSentinel、StruQ），理由是目标是闭源专有 LLM（p.14, §6 “Scope”）。

**消融。** Figure 10（p.21）：在 MSMARCO、n=10 下，增加迭代数 \(T\) 或每轮样本数 \(N\) 会提升 trigger 与查询的相似度；更小的 elite fraction \(\lambda\) 通常更好，但极端小后收益递减；平滑系数 \(\alpha\) 相对稳定（p.21, Appendix A.2）。Appendix A.1 还报告 MRR@5 与 nDCG@5，并声称随前缀长度单调提升（p.20–21）。

## 8. 贡献与创新点（按原文主张）

1. **首个自然查询下的端到端 IPI 攻击**：横跨 RAG 与单/多 Agent 系统，覆盖多种攻击目标（DoS/错误回答、钓鱼 worm、工具滥用、代码执行）；作者称此前工作多在“恶意文本已在上下文”的假设下评测（p.3, §1；p.9–10, §5）。
2. **trigger/attack 分解与检索瓶颈的形式化**：把 IPI 拆成“保证检索的 trigger fragment”和“承载任意目标的 attack fragment”，并把 trigger 构造识别为核心瓶颈（p.3, §1；p.4–5, §2–§3）。
3. **黑盒前缀优化算法与理论分析**：采用并改造 Cross-Entropy Method，只通过 embedding API 优化前缀；给出线性打分结构下的 \((\varepsilon,\delta)\)-utility 定理；在 11 个 IR 基准、8 个 embedding 模型上评估（p.3–4, Contributions；p.5–6, §3.2；p.7–9, §4）。
4. **防御评估**：评估查询改写、困惑度过滤、token masking，并展示自适应变体可以绕过，主张现有防御不足以阻止检索（p.4, Contributions；p.13–14, §6）。

作者在 Limitations 中明确承认：Algorithm 1 的核心 CEM 是已有技术，本文贡献在于把它适配到 IPI，不主张 CEM 的原创性（p.14, §8 “Novelty”）。因此“创新点”应理解为问题形式化、攻击面定位与系统性端到端评测，而非新的优化原语。

## 10. 与理论密码学的可能联系（严格）

**无。** 本文没有密码学定义、安全游戏、构造、定理或归约。Theorem 1 是一个 \((\varepsilon,\delta)\)-utility guarantee，属于黑箱优化/统计学习理论：\(\varepsilon\) 是目标函数 \(f(x)\) 相对最优值的近似误差，\(\delta\) 是算法失败概率，不是密码学安全参数；不能与 differential privacy 的 \((\varepsilon,\delta)\) 或密码学中的 negligible/advantage 概念混同。所谓 “NP-hard” 是前缀优化问题的计算复杂性陈述，且其定义与证明被推到不存在的 full arXiv 版本（p.5），不构成密码学困难性假设。论文的“攻击成功”由 Recall@5/ASR 经验度量，不存在 IND/模拟/不可区分等密码学安全目标。故 \(T_{\mathrm{crypto}}\) = 无 / 0。

## 11. 与应用密码学/密码工程可能的技术联系（严格）

**无直接贡献。** 本文没有使用或评估 TLS、OAuth、数字签名、Verifiable Credentials、TEE、zk、attestation 等密码技术；系统实现只用 embedding API、FAISS、MCP 工具与 LLM API（p.7, p.11），论文不分析这些通道的认证、传输安全或密钥管理。

与“内容来源签名/来源认证”的关系需要严格区分：论文在 Related Work 中引用了 FATH（authentication-based test-time defense against IPI）[87]，但**没有评估**来源认证/签名；Section 6 只评估查询改写、困惑度过滤、token masking（p.13–14, §6；p.14, §7）。因此不能从本文实验得出“签名能缓解合法页面被注入”的结论。**我们的推断**是：来源签名/来源认证只能证明来源与完整性（内容由某个已认证的发布者/账户发出且未被篡改），不能证明内容中的指令是良性的；如果攻击者拥有合法账户、在合法页面注入用户生成内容，或合法发布者被攻陷，签名仍然有效，检索排序也不会因签名而改变，LLM 仍可能执行其中的指令。来源认证若与 allowlist、内容完整性日志、instruction/data 分离结合，可能降低“未认证来源”这一子集的攻击面，但对“合法页面被注入”本身不是充分缓解；本文没有做这个实验。故 \(A_{\mathrm{crypto}}\) = 无 / 0（仅有被引用但未评估的认证式防御，不能算应用密码学贡献）。

## 12. 可检验的研究假设（3–6 条）

- **H1（跨模型泛化）**：在未参与调参的 BEIR 语料与未参与 Figure 4/5 的 embedding 模型（如 BGE-M3、Cohere embed）上，n=10 的 CEM trigger 的 Recall@5 仍显著高于 Query+（例如 >80% vs <50%）；若目标模型架构与参考模型差异大，则提升幅度会显著缩小。检验：固定 100 个自然 query、单条目注入、top-5，比较 CEM/Query+/Vanilla，并按模型家族分层。
- **H2（来源认证的边界）**：在邮件 Agent 中，对发件人做签名/来源认证并只允许认证来源进入检索，能降低“未认证攻击者”注入的 ASR，但对“攻击者通过合法账户发送”或“合法页面被注入”的 ASR 无显著影响。检验：2×2 设计（认证/未认证 × 攻击者账户合法/非法），测量 R@5 与端到端 ASR；预测签名主效应只在未认证来源上显著。
- **H3（自适应防御）**：任何仅对查询做改写的防御，在攻击者以同一预算对多个改写联合优化后，Recall@5 会恢复到不低于原始攻击的水平；恢复程度与改写数量、优化预算正相关。检验：固定 trigger 长度与 API 预算，比较多改写训练/未见改写测试的 Recall@5。
- **H4（语料竞争度）**：未污染语料第 K 名文档与查询的相似度（corpus competition level）对攻击成功有负向预测作用，且该效应强于语料规模、文档长度、查询长度。检验：以 query 为单位做 logistic 回归，因变量为 CEM 是否进入 top-5，自变量包括 competition、log(#docs)、D-Len、Q-Len；预测 competition 系数显著为负（注意 p.8 正文有一句方向写反，应以 Figure 3 与 MSMARCO 例子为准）。
- **H5（多 Agent 放大）**：在相同基座模型、相同 poisoned email 与相同检索结果下，多 Agent 编排（Orchestrator 分派、代码 Agent 不见原始恶意文本）会显著提高代码执行 ASR，而单 Agent 的 targeted answer ASR 仍然很低；差异主要由上下文隔离/“可信队友”归因造成，而非检索率差异。检验：对单/多 Agent 做 2×2（检索成功/失败 × 单/多 Agent），并在多 Agent 中增加“共享完整上下文”消融；预测多 Agent 的代码执行 ASR 显著高于单 Agent，而 targeted answer 不随编排显著提升。
- **H6（困惑度防御失效）**：重复恶意文本可把其困惑度降到干净文档水平以下，使基于困惑度的过滤器在保持攻击 Recall@5 的同时把检测率降到随机水平附近。检验：测量原始/重复/改写恶意文本与干净文档的 PPL 分布，计算过滤器在固定 FPR 下的 TPR；预测重复后 TPR 显著下降且 Recall@5 不降。
