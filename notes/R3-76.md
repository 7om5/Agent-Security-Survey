## 1. 150–300 字中文概述

本文提出 RAGworm：把越狱提示 j、复制指令 r 与恶意指令 m 拼成“对抗性自复制提示”，随邮件进入收件人 RAG；用户触发草稿生成时，检索到的提示迫使 LLM 复述 j/r/m 并执行 m，生成的邮件再感染下一位用户的 RAG。作者在 15 个模型/应用中测试自复制（13 个完全成功，Claude Sonnet 3.7 为 0/5），在 LangChain+FAISS+GTE-Base 邮件助手上评估检索、载荷与 20 跳持久性；由 10–13 个检索位 × 2.54 收件人 × 0.7 折减估算每个被感染客户端再感染约 20 人。防御 DonkeyRail 比较输入邮件与输出的 BLEU/METEOR/ROUGE-L 最高分，用轻量分类器判定；TPR=1.0 时 BLEU 的 FPR=0.017，延迟 7.6–38.3 ms，OOD AUC 0.79–1.0。全文无密码学机制。

## 2. 研究背景、现有方法不足、精确定义的问题

- **背景（p.1–3, §1–§2）**：GenAI 应用通过 RAG 接入外部知识；RAG 已成为 Copilot、Gemini for Workspace 等产品的常规组件。已有 RAG 安全研究集中在单应用：RAG membership inference（p.1, p.3）、RAG entity extraction（p.1, p.3）、RAG poisoning（backdoor、misinformation、blocking retrieval；p.1, p.3）。另一条线是 Promptware（p.3, §2）：经明文、不可见文本、混淆文本、图像、音频注入的恶意提示族，但既有变体是“volatile”的，不持久、不感染新应用。
- **现有方法不足（p.2, p.10, §1, §5.1）**：
  - 人工在环（human-in-the-loop）不可靠：人有自动化偏差/习惯化决策、过度信任 AI 解释、缺乏安全专业知识（p.2, p.10）。
  - GenAI-as-a-judge 需要额外推理，成本高，不适合高吞吐/实时（p.10, §5.1(1)）。
  - 基于策略的缓解（只纳入可信发件人的邮件、只纳入用户回复过的邮件、完全排除收件）会降低可用性，且不能阻止“已知/可信发件人后来被攻陷”的感染（p.10, §5.1(2)）。
  - 内容长度阈值可用自适应缩短绕过，且长邮件误报高（p.10, §5.1(3)）。
  - 越狱检测对已知分布有效，对 OOD 越狱退化（p.10, §5.1(4)）。
- **精确定义的问题（p.1, p.3, §1, §3.1）**：攻击者能否把 RAG poisoning 从单个应用放大到整个 GenAI 生态？具体地，构造一种满足三性质的提示——(1) Self-replication：`LLM(pre1‖m‖suf1) → pre2‖m‖suf2`；(2) Immutability：`LLM(LLM(...LLM(pre1‖m‖suf1))) → pre*‖m‖suf*`；(3) Model Independence：上述性质与具体 LLM 无关——并把它嵌入邮件，使每个受影响应用执行恶意动作、同时污染下一个应用的 RAG。作者把这种“可持久化 + 可感染新客户端”的 Promptware 变体称为 RAGworm（p.2–3, p.5）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **说明**：本文的“agent”不是具备计划—工具调用循环的自主 Agent，而是 **RAG-based GenAI email assistant / GenAI 应用**；攻击面是邮件内容进入 RAG 后的 indirect prompt injection。这一点影响其在 Agent Security 语料中的定位：它是“LLM 应用/GenAI 生态”层，而非工具执行层【推断，基于 p.5–6 的系统描述】。
- **组件（p.6, Fig.1；p.5–6, §3.3, §4.1.1）**：
  - 攻击者 u1（外部邮件发送者）。
  - 受害者 u2、u3…，每人有一个 GenAI 邮件客户端 c_i。
  - 每个客户端一个 **RAG database**（实验实现：LangChain + FAISS VectorStore + GTE-Base embedding + LangChain time-weighted retrieval；p.5–6, §4.1.1）。
  - 一个 **GenAI Engine**（LLM 服务；实验主模型 Gemini 1.5 Flash，另有 Gemini 2.0 Flash、GPT-4o Mini、LLaMA 3.2 3B、Gemini 1.5 Pro、Claude 3.5 Sonnet；p.6, p.9, p.10）。
  - 邮件传输通道（客户端之间发送 email；p.5–6）。
- **交互流程（p.5–6, Fig.1）**：
  1. 攻击者向 u2 发送含自复制提示的邮件 e1；双方可往来若干封（correspondence cr1）。
  2. c2 把 cr1 存入 RAG；e1 由此进入 c2 的数据库（Initial Compromise）。
  3. u2 触发“写新邮件/回复/润色草稿”；c2 用 RAG 检索 top-k（实验中 k=10）相关 correspondence。
  4. c2 把检索到的 k 封邮件与用户主题/草稿一起送 GenAI Engine；e1 中的提示迫使模型复述 j/r/m 并执行 m。
  5. 模型输出作为草稿返回 c2；u2 发送给 u3；c3 把 correspondence cr2 存入 RAG，c3 成为新宿主（Propagation）。
- **信任边界（按原文归纳 + 推断）**：
  - 攻击者在生态外，只能发邮件；不要求知道客户端模型、RAG 配置或 embedding（p.4, §3.2.3）。
  - 每个客户端的 RAG DB 是独立信任域；邮件内容是不可信输入，但被 RAG 当作上下文，进而被 LLM 当作指令执行（indirect prompt injection；p.5–6）。
  - GenAI Engine 是第三方服务（Fig.1 单独一列）；RAG DB 在客户端侧（Fig.1 中与 c_i 同框）。
  - **原文没有给出形式化信任边界、认证、完整性或来源校验**；Fig.1 只有数据流箭头，没有 trust boundary/attestation 标注（p.6, Fig.1）。因此“客户端信任 RAG 内容”“下游信任上游邮件”都是隐含假设【推断】。
  - DonkeyRail 位于客户端内、LLM 输出之后、邮件发送之前（p.11, §5.3）；它只检查本次 inference 的输入与输出，不检查邮件传输层，也不验证发件人【推断】。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- **资产（按攻击目标归纳；p.4, §3.2.2；p.5, §4）**：
  - 用户 RAG 中的机密邮件/个人信息（姓名、电话、地址、私密内容；Listing 1 p.3 明确要求“up to 20 unique pieces of private information”）。
  - 生成邮件的完整性与收件人对发件人的信任（phishing、tone manipulation）。
  - 用户/组织声誉（toxic output、embarrassing）。
  - 生态可用性（文中提到 RAG jamming 作为可复用恶意行为；p.5, §3.3.1）。
- **攻击者目标（p.4, §3.2.2）**：(1) promoting content（spam，实验中为 Walmart 促销）；(2) phishing（恶意链接）；(3) embarrassing users（toxic output 或数据泄露）；并在生态层面放大攻击。
- **攻击者能力（p.4, §3.2.3）**：极轻量——只能向生态内另一用户发送一封邮件；不知道客户端模型架构、RAG 设置或 embedding 算法；可使用互联网上公开的越狱提示（p.3–4）；可替换 j 与 m，因而提示是 polymorphic 的（p.4, p.5）；不做 fine-tuning、不直接访问数据库、不攻陷账号。
- **前提假设（p.4–6, §3.2.1, §3.3, §4.1）**：
  - 目标应用满足四特征：接收用户输入；主动更新数据库（收到的邮件自动入库）；属于生态（可与其他客户端互通）；客户端间通信依赖 RAG-based inference（p.4, §3.2.1）。
  - 用户会触发草稿生成（写新邮件、回复、润色、甚至自动回复）；作者称之为 **½-click**：技术上用户发起，但行为高频、近乎被动（p.5, §3.3.1）。
  - 检索到的 worm 位于 top-k；实验中固定 k=10，作者称这是保守下界（p.6, §4.1.1）。
  - LLM 会服从 j 并复述 j/r/m；用户会直接发送草稿而不人工检查；部署中没有专用护栏。
  - 数据集为 Enron（40 用户、2,000 封）与 Hillary Clinton（1,500 封用于 OOD/大 RAG）；邮件为英文。
- **威胁模型的关键限制**：攻击者不需要模型访问、不需要知道 embedding、不需要数据库写权限；这与许多需要白盒/梯度的 prompt injection 攻击不同。但攻击依赖“RAG 主动索引收到的邮件”这一产品行为，作者以 Copilot 的索引行为作为现实依据（p.4, §3.2.1，引 [37]）。

## 5. 核心方案（方法、攻击/防御流程、关键定义）

### 5.1 攻击：adversarial self-replicating prompt 与 RAGworm

- **提示结构（p.3, §3.1.2）**：`j`（jailbreaking prompt，充当 privilege escalation）‖ `r`（让模型把提示核心内容包含进输出的复制指令）‖ `m`（恶意指令，如外泄数据、生成 toxic 内容）。三者合起来迫使模型自我复制并执行恶意任务；形式化为
  `LLM(pre1‖j‖r‖m‖suf1) → pre2‖j‖r‖m‖p2‖suf2`，
  其中 `pre_i`/`suf_i` 是任意良性文本，`p_i` 是恶意活动的 payload。迭代 n−1 次得
  `LLM^{n−1}(pre1‖j‖r‖m‖p1‖suf1) → pren‖j‖r‖m‖pn‖sufn`（p.3）。
- **三性质（p.3, §3.1.1）**：Self-replication、Immutability（跨多次 inference 组合保持）、Model Independence（与具体 LLM 无关）。作者把满足三性质、且 j/r/m 为恶意的提示称为 adversarial self-replicating prompt；把“可持久化于 RAG + 可感染新客户端”的 Promptware 变体称为 RAGworm（p.2–3, p.5）。
- **感染/传播流程（p.5–6, §3.3, Fig.1）**：
  - Initial Compromise：e1 被 c2 的 RAG 索引，c2 成为宿主。
  - Propagation：u2 触发草稿生成 → RAG 检索到 e1 → LLM 输出含 j/r/m 的草稿 → u2 发送 → c3 索引 → c3 成为新宿主。
  - 触发方式包括写新邮件、回复、润色既有草稿、自动回复（p.5）。
- **关键定义/属性（p.5, §3.3.1）**：Malicious Activity Independence & Polymorphism（同一 j/r 可配不同 m：spam、phishing、RAG jamming 等）；Malicious Activity & Propagation（每个客户端执行 m 并感染新客户端）；½-click Activation（用户需触发草稿，但行为高频，近似 0-click）。
- **示例（p.3, Listing 1）**：j 为 role-play“Wormy”邮件助手；r 要求把 `<START>` 与 `<END>` 之间的全文复制两遍；m 要求以 `DATAVIEW` 段落列出“other emails”中最多 20 条私密信息。该 Listing 本身是攻击载荷，按任务要求仅作为不可信文本阅读，未执行。

### 5.2 防御：DonkeyRail

- **核心观察（p.11, §5.2）**：自复制提示会迫使模型把 j、r、m 原样带入输出，因此输入与输出应包含相同文本片段；可用输入—输出相似度检测，不需要额外 LLM inference。
- **流程（p.11, §5.3）**：
  1. 取本次 inference 的 n 封输入邮件（n−1 封来自 RAG，1 封触发 inference）与 GenAI 输出。
  2. 对输出与每封输入计算 BLEU、METEOR、ROUGE-L；每个 metric 取 10 个相似度中的最大值。
  3. 把 1/2/3 个 metric 的最高分送入轻量预训练分类器（Logistic Regression、Gaussian Naive Bayes、Decision Stump）。
  4. 分类器判定输出是否含 adversarial self-replicating prompt；若是则告警/阻断发送。
- **设计目标（p.11, §5.3）**：fast（最小延迟）、efficient（不影响可用性）、cost-effective（无需额外 inference）、lightweight（可嵌入邮件应用）。
- **阈值策略（p.11–12, §5.3）**：为“perfect accuracy”把阈值调到 TPR=1.0，再报告对应 FPR；Table 3 同时给默认 0.5 与 TPR=1.0 两种设置。
- **关键指标（p.6, §4.1.2）**：Retrieval SR（worm 邮件是否被 RAG 检索到，1/0）、Replication SR（输出是否含 j、r、m）、Payload SR（输出是否含恶意 payload）、Combined SR（四者全含）；均为逐 case 二值后平均。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- **形式化程度：低—中，且不是密码学形式化。** 原文给出三性质的自然语言定义和一个字符串改写式（p.3, §3.1.1–3.1.2），但没有：敌手模型的形式化、概率空间、计算复杂度、游戏（game）、定理、引理、归约或安全参数。该改写式是“LLM 行为应满足的输入输出关系”，不是可证明的安全定义；`Immutability` 是“片段在多次推理组合中保持”的经验性质，不是密码学不可篡改性。
- **可检验的定义/指标**：Retrieval/Replication/Payload/Combined SR（p.6）；TPR、FPR、AUC（p.11–12）；latency（p.13）。这些是统计指标，不是密码学优势（advantage）。
- **经验主张（按原文）**：
  - 13 个 SOTA 模型/应用对自复制提示完全易感（Table 1 p.4：15 个测试对象中 13 个 15/15 或 5/5；ChatGPT o3-mini 2/5；Claude Sonnet 3.7 0/5）。
  - 单个被感染客户端平均再感染约 20 个新客户端（p.9, §4.3.2；Insight 3 p.9）。
  - DonkeyRail 在 TPR=1.0 时 FPR=0.017（BLEU）或 0.005（BLEU+METEOR+ROUGE-L）（p.12, Table 3；p.13, Insight 4）。
  - 延迟 7.6–38.3 ms（BLEU，10–50 docs；p.13, Insight 4）；预处理全组合 7.63–937.00 ms（p.13, Table 4）。
  - OOD：新 use case AUC 0.99–1.0；新 jailbreak AUC 0.96–1.0；Hillary 数据集 AUC 0.79–0.97（p.14, §5.5, Figs.11–12）。
- **声明的层次（重要）**：原文把多个不同强度的主张混在一起，阅读时应分层：
  - L1 自复制：Table 1 的 15 个模型/应用（p.4）——经验。
  - L2 检索：作者自建 LangChain/FAISS/GTE-Base 邮件助手，Enron/Hillary（p.7–8）——经验，限特定实现。
  - L3 载荷执行：4 个模型 × 3 种 payload（p.9, Table 2）——经验。
  - L4 多跳持久：20 跳、4 个模型（p.10, Fig.8）——经验，但模型间差异大。
  - L5 单客户端再感染 20 人：由检索窗口 × 收件人数 × 0.7 折减推导（p.9）——估算 + 模拟，不是端到端观测。
  - L6 生态级 super-linear：由 L5 的分支假设推出（p.9, Insight 3；p.10, Fig.7）——未直接测量；Fig.7 画的是“单个 infected user 的累计发信量”，不是“累计感染人数”【推断】。
  - L7 真实产品 full RAGworm：Gemini Advanced Gmail 仅为定性 PoC，且 §3.3.2 只报告生成 worm-carrying draft（p.5）；贡献段却称“full RAGworm”（p.2）——主张强于证据。
- **声明强度冲突**：标题/摘要说“Preventing the Propagation”（p.1），§6 明确说 DonkeyRail 是“mitigation … not a prevention mechanism”（p.14）。按作者自己的限定，应把 DonkeyRail 视为“提高攻击成本的内容检测器”，而非“阻止传播的安全机制”。

## 7. 实验设置与主要结果（agents、场景、指标、关键数字、消融）

- **“agents”/场景**：RAG 邮件助手（LangChain + FAISS + GTE-Base + time-weighted retrieval），用户为 Enron 40 名员工（2,000 封 sent emails）与 Hillary Clinton（30,000+ 封；OOD 实验用前 1,500 封；大 RAG 实验用 200/500/1,000/2,000/4,000 子集）。主模型 Gemini 1.5 Flash；对比 Gemini 2.0 Flash、GPT-4o Mini、LLaMA 3.2 3B、Gemini 1.5 Pro、Claude 3.5 Sonnet（p.6, p.9, p.10）。
- **攻击侧结果**：
  - **自复制（p.4, Table 1）**：6 个 foundation LLM（Gemini 2.0 Flash、Gemini 1.5 Flash、GPT-4o Mini、GPT-4o、GPT-4.1、LLaMA 3.2 3B IT）均 15/15；9 个应用（Gemini 2.5 Pro Web、Gemini Advanced Gmail、Copilot Outlook、Copilot Work Mode、Copilot Web Mode、ChatGPT 4.5、ChatGPT o1、ChatGPT o3-mini、Claude Sonnet 3.7）中 7 个 5/5，o3-mini 2/5，Claude Sonnet 3.7 0/5。13 个完全易感。
  - **检索（p.7–8, Figs.3–6）**：5 种 time-weighted 函数；所有方法到 rank 5 可靠，rank 10 前近完美，rank 12–13 后基本为 0；blended b=0.75 在 rank 10 降为 0。RAG size 200–4,000 影响很小（Fig.4）；5 种 embedding、4 种 payload 影响边际（Fig.5）；Fig.6 热图（Hillary）显示最后成功检索 rank 1–15，主要由 retrieval function 决定。
  - **载荷执行（p.9, Table 2；300 dpi 核对）**：Gemini 1.5 Flash 三种 payload 均 1.000/1.000/1.000；GPT-4o Mini Combined 0.998–0.999；Gemini 2.0 Flash Combined 0.921–0.991；LLaMA 3.2 3B Combined 0.622–0.935（最低为 Information Leak：Replication 0.867、Payload 0.639、Combined 0.622）。
  - **传播估计（p.9, §4.3.2）**：检索窗口取约 11（范围 10–13）× 平均 2.54 收件人/邮件 = 28 potential infections；再乘 0.7（Enron 中每收 1 封发 2.34 封，约 70% 交互为 outgoing）≈ 20 new users per compromised client。
  - **传播时间线（p.10, Fig.7）**：10 封/天约 3 天达到 20；3–5 封/天约一周；1 封/天约 20 天。Fig.7 左轴是“Cumulative Emails Sent”，不是感染人数。
  - **多跳持久（p.10, Fig.8；300 dpi 核对）**：20 跳后 Claude 3.5 Sonnet ≈100%；GPT-4o Mini ≈92%；Gemini 1.5 Flash ≈78%；Gemini 1.5 Pro ≈64%。正文只报告 Claude 与 Gemini 1.5 Pro 两条，未提另外两条的下降。
- **防御侧结果**：
  - **训练/测试数据（p.11, §5.3）**：100 个 Enron 员工 RAG（每人 50 收 + 50 发）；5,000 benign + 5,000 worm-injected = 10,000；70% train / 30% test；特征为 3 个相似度最高分；3 种轻量分类器。
  - **检测（p.12, Table 3；Figs.9–10）**：AUC 0.95–1.00；TPR=1.0 时 BLEU FPR=0.017、METEOR 0.012、ROUGE-L 0.131、B&R 0.038、B&M 0.008、R&M 0.007、B&R&M 0.005。作者推荐 BLEU（单特征、最低延迟）或 B&R&M（最低 FPR、最高延迟）。
  - **延迟（p.13, Tables 4–5；Insight 4）**：10 docs 预处理 7.63 ms（BLEU）–187.40 ms（B&R&M）；25 docs 19.08–468.50 ms；50 docs 38.15–937.00 ms；分类 0.019–0.061 ms；BLEU 的 end-to-end 约 7.67/19.2/38.3 ms（10/25/50 docs；三种分类器略有差异，Logistic Regression 为 7.67/19.19/38.37）。作者对 25/50 docs 是线性外推，不是实测。
  - **OOD（p.14, §5.5, Figs.11–12）**：3 个新 use case（Cowboy/Walmart/Phishing）AUC 0.99–1.0；20 个未见 jailbreak AUC 0.96–1.0；Hillary Clinton 数据集 AUC 0.79–0.97。
- **消融维度**：retrieval function（5）、RAG size（5）、embedding（5）、payload（4）、模型（Table 2 4 个；Fig.8 4 个）、跳数（5/15/20）、阈值（0.5 vs TPR=1.0）、特征组合（7）、分类器（3）、OOD（3 轴）。**没有与任何外部护栏基线对比**（如 Llama Guard、prompt-injection detector、jailbreak detector），也没有 adaptive attack 实验。

## 8. 贡献与创新点（按原文主张）

1. **易感性测量（p.2, p.4）**：13 个 SOTA LLM/应用对 adversarial self-replicating prompt 完全易感；付费 Gemini Advanced for Gmail 也易感，作者称 demo 展示了“full RAGworm”。
2. **从单应用到生态的放大（p.2, p.9）**：把已有 RAG poisoning 研究（backdoor、misinformation、blocking retrieval）从 individual application 放大到 ecosystem；通过链式 indirect prompt injection 放大攻击后果。
3. **DonkeyRail（p.2, p.11–13）**：提出、实现并评估内容相似度护栏；GitHub 开源；声称 TPR=1.0、FPR=0.017、7.6–38.3 ms、OOD 稳健。
4. **Promptware 新变体（p.2–3, p.5）**：首个同时具备“持久化于 RAG”和“感染新 LLM 应用”的 Promptware 变体；既有变体是 volatile 的。
- 原文的“first”主张集中在 p.3：“To the best of our knowledge, we present the first variant of Promptware with the ability to persist in an LLM application … and to infect new LLM-powered applications.” 该主张是文献综述层面的，不是形式化新颖性证明。

## 9. 局限、失败案例、作者承认的不足（区分作者承认 vs 你的推断）

### 9.1 作者承认的不足（p.14, §6；p.9, p.10）

- **Overtness**：实验使用可见的提示与可见 payload；攻击者可用 ASCII smuggling、白色字体、非文本多模态输入隐藏提示，但 payload 对“attentive user”仍可见（p.14）。
- **Adaptive Attacks 未测试**：作者明确说没有测试 adaptive attacks；DonkeyRail 可能被“让 LLM 改写提示以降低 BLEU/ROUGE/METEOR 重叠、但保留语义”绕过；因此它是“mitigation … in one factor”，不是 prevention（p.14）。未来方向是 embedding-space 语义相似度（p.14）。
- **数据集有限**：只有 Enron 与 Hillary Clinton；Enron 来自 2001 年，现代邮件行为可能已变化；缺少真实多用户邮件数据集（p.9, p.14）。
- **人工在环不可靠**：作者用三条理由论证（偏差/习惯、过度信任 AI、缺乏安全知识），因此不把 human-in-the-loop 当作可靠防御（p.2, p.10）。
- **策略型缓解的缺陷**：排除不可信发件人不能防“可信发件人后来被攻陷/账号劫持”；排除未回复邮件或全部收件会损害可用性（p.10）。
- **上下文规模保守**：固定 k=10，商业系统上下文更大；作者称这是 lower bound（p.6）。
- **攻击者模型保守**：不假设攻击者了解用户数据或能 fine-tune； tailored worm 可提高深 rank 检索，但超出威胁模型（p.8）。

### 9.2 我的推断/核对发现（非作者承认）

- **“20 new clients”是估算，不是端到端观测**：它由 10–13 检索位 × 2.54 收件人 × 0.7 折减推出（p.9）；Fig.7 是单用户累计发信量的模拟，不是多用户感染曲线；论文没有跑“20 个真实客户端互相感染”的实验【推断】。
- **“super-linear propagation”未被直接测量**：要得到生态级超线性，需要假设每个新宿主也完成 20 次再感染；论文只给出单客户端估计与单链 20 跳持久性（p.9–10）。Fig.7 的 y 轴是 emails sent，不是 infected users；因此“super-linear”是模型推论，不是观测【推断】。
- **防御评估缺基线**：只比较 3 种轻量分类器与 7 种特征组合，没有与 Llama Guard、prompt-injection detector、jailbreak detector 或商用护栏对比；§5.1 对它们的否定是论证性的，不是实验性的（p.10–13）【推断】。
- **阈值在测试集上选到 TPR=1.0**：Table 3 的 TPR=1.0/FPR 是在 30% test split 上报告；若阈值也是在同一 test split 上调到 TPR=1.0，FPR 估计偏乐观；论文未说明阈值是在 train/validation 还是 test 上选，也未给置信区间/交叉验证（p.11–12）【推断】。
- **FPR 的 benign 分布偏窄**：benign 样本是“模型对 10 封良性上下文的生成回复”，不包含真实邮件中常见的“引用原文回复/转发全文”；这类邮件与 worm 输出在 BLEU/ROUGE-L 上可能同样高，真实 FPR 可能高于 0.017（p.11, §5.3）【推断】。
- **只覆盖“草稿生成”这一条输出通道**：DonkeyRail 在每次 inference 后运行，但实验只评估写新邮件/回复/润色；若助手被要求“总结这封邮件”“转发原文”“把邮件内容写入日历/文档”，worm 可能经未覆盖通道传播（p.11, §5.3）【推断】。
- **单模型训练/测试**：主实验用 Gemini 1.5 Flash；未测试“在一个模型上训练 DonkeyRail、在另一个模型上部署”的迁移 FPR/TPR（p.9–13）【推断】。
- **“full RAGworm”证据不足**：§3.3.2 只报告 Gemini Advanced Gmail 中检索、执行、复制并生成 worm-carrying draft；没有报告发送给第二个用户、第二个用户 RAG 被污染、或第二轮生成（p.5）。贡献段 p.2 的“full RAGworm”强于该证据；demo 在 GitHub，PDF 内不可核验【推断/证据缺口】。
- **½-click 的概念张力**：RAGworm 需要用户触发草稿并发送，不是 Morris 式无交互网络蠕虫；作者用“½-click”承认这一点（p.5）。因此“worm”是类比，不是严格的自我传播恶意软件；传播率依赖用户使用习惯【推断】。
- **“Model Independence”被自己的数据反驳**：定义说 regardless of LLM（p.3），Table 1 有 Claude 0/5、o3-mini 2/5（p.4），Fig.8 的 Gemini 1.5 Pro 20 跳降到 64%（p.10）。更准确的表述是“多数模型易感、程度随模型/跳数变化”；作者在 Insight 1 用了“Most”，但定义仍写“regardless”【推断/原文内部不一致】。
- **“Immutability”不是绝对**：Fig.8 显示 20 跳内多条曲线下降；Table 1 也非全部 15/15。作者没有定义“保持”的阈值（例如 j/r/m 完全一致才算成功，还是语义等价），Replication SR 的操作化（人工/自动、精确/模糊匹配）未说明（p.6, §4.1.2）【推断/可复现性缺口】。
- **“Hillary AUC 0.79 仍称 high”**：p.14 说 “maintains high AUC … ranging from 0.79-0.97”；0.79 只能算中等，作者的措辞偏乐观【推断】。

## 11. 与应用密码学/密码工程可能的技术联系（严格；没有就写“无”）

**无。**

- 原文没有使用 OAuth、TLS、数字签名、HMAC、证书、VC、TEE、远程认证、zk 或任何密码学协议；DonkeyRail 是纯内容相似度（BLEU/METEOR/ROUGE-L）+ 轻量分类器（p.11–13），不含密钥、签名或认证。
- **边界说明（非原文机制，[推断]）**：原文 §5.1(2) 讨论了“只把可信发件人的邮件纳入 RAG”的来源隔离策略，但这是策略级白名单，不是密码学认证；作者自己指出它在“已知/可信发件人后来被攻陷”时失效（p.10）。即使加入 DKIM/S-MIME/签名或可验证来源，也只能认证“邮件由该域名/账号发出且未被篡改”，不能认证“邮件内容不是指令”；被攻陷的合法账号仍可发送 worm，且 worm 由受害者的助手在受害者账号下重写并作为新邮件发出，出站签名仍然有效。因此签名/来源认证不能阻止“合法内容被改写后的自我复制”，最多支持信誉/白名单策略，而该策略的缺口已被作者承认（p.10）。原文没有评估任何此类机制，故不构成 §11 的技术联系。

## 12. 可检验的研究假设（3–6 条）

1. **H1（跨模型迁移）**：在 Gemini 1.5 Flash 上训练的 DonkeyRail，直接部署到 GPT-4o/Gemini 2.0/Claude 的输出上时，TPR=1.0 阈值下的 FPR 会显著高于 0.017。检验：固定阈值，跨模型测试同一 Enron 划分；报告 FPR/TPR 与置信区间。
2. **H2（改写自适应攻击）**：让 LLM 在保留 j/r/m 语义的前提下改写措辞，使 BLEU/ROUGE-L 降到阈值以下，可显著降低 DonkeyRail 的 TPR（作者在 p.14 预测此风险但未测）。检验：构造 100 条语义等价、n-gram 重叠低的 worm，测 TPR。
3. **H3（来源认证的边界）**：仅允许已签名/可信发件人的邮件进入 RAG，不能阻止被攻陷的合法账号发起的 RAGworm；传播链仍可在下游继续。检验：两客户端 testbed，u1 为可信但被控账号，观察 u2→u3 的感染率。
4. **H4（真实 FPR）**：在包含“引用原文回复/转发全文”的真实邮件分布上，DonkeyRail 的 FPR 会高于 0.017，因为良性引用与 worm 输出在 BLEU/ROUGE-L 上同属高相似度。检验：收集含 quote-reply 的良性邮件，按 p.11 流程重测。
5. **H5（生态级传播）**：论文的“20 new clients/client”在真实多用户、非固定 k=10、有商用上下文窗口的部署中会低于估计；端到端 20 客户端实验的二次感染数会显著小于 20。检验：多客户端仿真/部署，记录实际 infected users over time，而不是累计发信量。
6. **H6（通道覆盖）**：把 DonkeyRail 只挂在“草稿生成”通道，无法阻止同一 worm 经“总结/转发/导出到文档”等通道传播；扩大通道覆盖后总阻断率才会接近论文的 TPR。检验：同一 infected RAG 上枚举 4 种输出任务，测各通道的 worm 输出率。
