## 1. 150–300 字中文概述

PriMobiBench 是首个面向 VLM 驱动移动 GUI Agent 的视觉隐私泄露基准。作者指出，Agent 以连续截图为主要观测并上传云端 VLM，模型提供方或第三方可读取这些截图，既直接提取屏幕敏感信息，又跨帧聚合碎片线索推断用户画像。论文构建 5 大类 25 个隐私属性、30 种视觉呈现形式的分类体系，合成 50 个用户画像，在 16 个 Android 应用上采集 320 条轨迹并注入 2,960 个隐私元素，形成 MobiLeak。作者评测 5 个 VLM 的逐帧识别与画像构建，报告最高 82.5% 识别率和约 70% 画像成功率；并提出基于 UI 元素分割与任务相关性过滤的像素化缓解，声称最多降低 58% 画像成功率、仅约 8% 任务性能损失。该工作是经验性测量基准，不含密码学定义或可证明隐私保证。

## 2. 研究背景、现有方法不足、精确定义的问题

- 背景：移动 GUI Agent 以截图流为主要观测，通过 VLM 完成跨应用任务；由于端侧算力不足，截图常上传云端 VLM，模型提供方或第三方因此获得用户的屏幕视觉流（p.1–2）。截图包含消息、健康、财务、位置等高密度个人信息，且会随任务执行形成持久轨迹（p.1, p.3）。
- 现有方法不足：MobileSafetyBench [16] 关注操作安全与主动攻击（如 prompt injection）；SAPA-Bench [20] 关注单张截图的隐私意识/敏感元素识别；MLA-Trust [44]、OS-Sentinel [37]、PrivScreen [48] 侧重信任或安全评测。它们主要处理“单屏、显式秘密、是否识别/redact”，缺少跨多步轨迹的累积推断与 visual profiling（p.1–3, Table 2 p.3）。
- 研究缺口（原文）：没有基准系统评估“VLM 从连续截图流中提取并聚合隐私线索、构建用户画像”的能力；现有工作把隐私当作单步识别问题，而非 inference-based、trajectory-level 风险（p.2–3, §2.2）。
- 精确定义的问题（原文 RQ）：
  - RQ1：VLM 能在多大程度上利用 GUI Agent 轨迹构建准确、全面、侵入性的用户画像？（p.2）
  - RQ2：能否在不灾难性损害 Agent 功能的前提下缓解 visual profiling？（p.2）
- 论文的答案形态：构造 PriMobiBench/MobiLeak，测量逐帧隐私识别与轨迹级画像构建；再提出任务相关性过滤的像素化缓解，测量隐私下降与任务效用损失（p.1–2, p.5–6, p.10–13）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- 组件（Fig.1 p.1；Fig.2 p.4）：
  - Target Device：Android 手机/应用（16 个应用，5 类任务），运行 mobile GUI agent；agent 捕获截图并执行 tap/scroll/type 等低层动作（p.1–3, p.5）。
  - Cloud Side：云端 VLM 负责感知/推理；执行轨迹（截图 + 动作）在云端或日志中保留（Fig.1 p.1；§3 p.4）。
  - Adversary：模型提供方，或能访问执行数据的第三方；从轨迹中做 direct privacy extraction 与 user profiling（Fig.1 p.1；§3 p.4）。
  - Evaluator：论文用 5 个 VLM 做隐私识别/画像构建（p.7），另用 4 个 agent 系统做任务效用评估（p.11）。
- 交互流程：用户任务 → agent 截屏 → 截图送云端 VLM → VLM 返回动作 → agent 执行 → 新截图 → 循环；轨迹被记录/保留（p.1, p.3–4）。论文评测时把“轨迹的所有截图按时间顺序喂给 VLM，收集逐帧隐私预测，再在同一对话上下文中让模型构建画像”（p.6, §5.1）。
- 信任边界：
  - 设备侧应用/OS 与云端 VLM/日志之间是主要边界；敌手在云端或第三方侧，设备侧被视为正常执行环境（Fig.1 p.1；§3 p.4）。
  - 缓解方案在设备/本地侧插入 UI 分割与过滤，再上传云端（Fig.8 p.11），因此隐含“本地过滤组件可信、云端不可信”的假设；论文没有形式化该信任假设，也没有讨论本地模型被攻破的情形（本人推断，基于 p.11）。
  - 一个结构性张力：云端 VLM 同时是 agent 的感知/决策依赖和被指控的隐私敌手；论文没有把“感知模块”和“敌手”分离，而是用同一个模型能力来度量泄露（p.1, p.4, p.7）。
- 评测模型与真实 agent 的差异：隐私评测直接对 base VLM 提问，不运行 agent 的完整动作策略；任务效用评测才使用 UI-TARS-1.5-7B、GUI-Owl-7B、AutoGLM-Phone-9B、Mobile-Agent-v3（p.11）。因此“隐私泄露”度量的是 VLM 在给定截图序列和提取 prompt 下的能力，而非端到端 agent 部署中的实际外发量（本人推断）。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- 资产：
  - 屏幕上的 25 个隐私属性（Identifiers、Social Attributes、Behaviors & Preferences、Health、Financial Information；Table 7 p.17）。
  - 由这些属性聚合成的用户画像（ground truth profiles；p.5）。
  - 原始截图/执行轨迹、应用使用上下文、任务与行为模式（p.4–6）。
  - 次要资产：Agent 的任务效用/动作一致性（防御的代价；p.11–13）。
- 攻击者身份：模型提供方，或能访问 mobile GUI agent 执行数据的第三方（§3 p.4）。
- 攻击者能力：
  - 可观察正常任务执行产生的视觉流/截图；可跨交互聚合信号（p.4）。
  - **不能**影响或操纵 agent 的动作流；威胁模型限定为 passive leakage，而非恶意 UI 操纵/主动注入（p.4）。
  - 评测中敌手被建模为可对 VLM 发出隐私提取与画像构建 prompt（p.6–7, p.20），这比“仅被动读取日志”更强；论文没有单独论证这一能力假设（本人推断）。
- 攻击者目标：从截图提取敏感信息，并系统聚合为全面、可能侵入性的用户画像；不要求 agent 执行任何越界恶意动作（p.4）。
- 前提假设：
  - 截图在正常 agent 执行中产生并被云端服务记录/保留，例如 API abuse-monitoring 默认最多 30 天，某些应用状态/对话更久（p.4，引 [1,26]）。
  - 模型只接收原始截图，不接收元数据（p.6）。
  - 合成画像/插入的隐私信息可作为 ground truth；轨迹的人为噪声被有意抑制（p.5–6）。
  - 敌手不攻破设备、不篡改 UI、不做网络侧攻击；这些在威胁模型外（p.4）。
- Out-of-scope：主动 UI 操纵、prompt injection、设备入侵、网络窃听、侧信道；论文明确把 passive leakage 与 active attacks 分开（p.4）。

## 5. 核心方案（方法、攻击/防御流程、关键定义）

### 5.1 数据构造：分类体系 → 画像 → 轨迹 → 注入

- 隐私分类体系（§4.1 p.4–5；Table 7 p.17）：
  - 5 大类、25 个细粒度属性：Identifiers 7 个、Social Attributes 5 个、Behaviors and Preferences 5 个、Health 4 个、Financial Information 4 个。
  - 构建方法：以 GDPR [6] 和 OpenAI/Anthropic 隐私政策 [1,30] 为政策来源，交叉检查 SAPA-Bench [20] 与 CORE [7] 的覆盖，再对 GUIOdyssey [21]、OS-Atlas [41] 做 policy-seeded open coding；两名作者独立编码，分歧讨论解决，直到 codebook saturation；最后两人独立复标、共识裁决（p.4）。
  - 视觉呈现形式：5 种 outside-app（App Icons、Gallery Thumbnails、Push Notifications、Status Bar、Widgets）+ 25 种 in-app（Account Name、Advertisement、Alarms、Battery Usage、Bookmarks、Carts、Chat Messages、Contacts、Content Feeds、Delivery Address、Device Information、Email Address、General Location、Music Playlists、Name、Order Records、Phone Number、Posts、Profile Pages、Purchase Information、Search History、Schedules、Storage Usage、Time Zone、User Avatar），合计 30 种（p.5–6；Table 8 p.18）。
- 用户画像（§4.2 p.5）：
  - 50 个合成画像，每个覆盖全部 25 个属性；先对核心属性（Gender、Occupation、Income Level、Content Interests、Shopping Preference、Medical Profile 等，Table 9 p.18）在预定义空间采样，形成 profile core；再用 LLM-assisted completion 补全其余属性，保持语义一致（如收入与职业一致）。
  - 画像作为插入与评测的 ground truth；多个轨迹可按时间链接，用于 evolving-profile 实验（p.5, p.14, §E.4 p.21–22）。
- 轨迹采集（§4.3 p.5）：
  - 16 个 Android 应用，覆盖 general tools、information retrieval、web shopping、media entertainment、social sharing 五类（Table 10 p.19）。
  - 用 Mobile-Agent-v3 [45] 自动执行固定高层动作序列；每个 app–task pair 的轨迹长度/UI 状态相近；平均 11.4 张截图。
  - 帧级标注：当前应用/任务、关联画像、候选插入位置、视觉呈现形式（p.5）。
  - 为降低方差，刻意抑制失败动作、误点击、意外弹窗等执行噪声；作者承认真实噪声可能进一步增加泄露（p.5）。
- 隐私注入（§4.4 p.5–6）：
  - 每轨迹插入约 7–10 个隐私属性，模拟稀疏、上下文相关的真实界面（p.6）。
  - Runtime Injection（多数）：通过 ADB shell、预配置表单、可编辑 UI、确定性脚本在截图前原生渲染；视觉/语义一致（p.6）。
  - Visual In-painting（约 32%，947/2,960 个元素）：对无法原生渲染的区域，用 GPT-5.1 [28] 合成与画像/应用上下文一致的隐私内容，再用 GPT-Image-1 [29] 重绘到目标区域；约束位置、布局、周边 UI（p.6, §C.4 p.17；Fig.10 p.19）。
  - 质量控制：每张修改截图由一名作者和一名外部研究生独立复核语义正确性与视觉合理性；in-painting 子集平均 96.8% 语义正确、95.1% 视觉合理；分歧讨论解决，不合格重新生成（p.6）。
- 数据集（§4.5 p.6）：
  - MobiLeak：320 个样本（16 应用 × 每应用 20 个 profile–task 组合），2,960 个隐私元素，30 种呈现形式，50 个画像。
  - 样本 = 一个用户画像 + 一个 app-specific task scenario；支持帧级识别与轨迹级画像评测（p.6）。
  - 构造效度注意：隐私信息是**有意注入**的 ground truth，而非自然出现的弱线索；这会影响“从看似无害的碎片线索推断画像”这一主张的外推（本人推断，见 §9）。

### 5.2 评测流程

- 隐私信息识别（§5.1 p.6–7）：
  - 对每条轨迹，按时间顺序把全部截图喂给目标 VLM；模型逐帧列出可见的隐私信息；与 ground-truth 描述文件用 LLM-based judge 做语义比对（p.6–7）。
  - Prompt（Fig.11 p.20）要求“只报告屏幕上明确可见的信息，不要推断、猜测或假设未清晰显示的信息”；输出按 `Screenshot <index>` 分节。
- 用户画像构建（§5.1 p.6–8）：
  - 在识别阶段的同一对话上下文中，再次提示模型根据累积视觉证据推断画像属性；与 ground-truth 画像比较（p.6, p.8）。
  - 4 种提示策略：open-ended、structured、chain-of-thought (CoT)、iterative prompting；只评最终画像（p.8, Table 3 p.8）。
  - Prompt（Fig.12 p.20）给出 `{ATTRIBUTE_LIST}`，要求“只使用上面已识别的隐私信息”“不要引入新信息或重新查看截图”“不要猜测或推断超出已提取证据的缺失值”。
- Judge：GPT-5-mini 做二值语义判定（预测是否语义蕴含 ground truth），temperature=0；400 个分层案例上与人类标注 98.5% 一致（p.7, §D.3 p.18；Fig.13 p.20）。

### 5.3 缓解流程（防御）

- 目标：在不严重损害 agent 任务执行的前提下，降低云端 VLM 可提取的隐私信息（§6.1 p.10）。
- 三步（§6.2 p.10–11；Fig.8 p.11）：
  1. UI Element Segmentation：用 Qwen3-VL-8B [3] 从原始截图识别 UI 组件及其 bounding boxes，输出元素级结构（文本、图标、图像等）。
  2. Task-Relevance and Privacy-Sensitivity Analysis：用 Qwen3-VL-8B 对每个元素做 prompt-based 分类，判断其是否服务于当前决策（task relevance）以及是否属于隐私分类体系（privacy sensitivity）；只有“任务无关且隐私敏感”的元素被标记保护。
  3. Sensitive Region Protection：对标记元素做 element-level pixelation（mosaic blurring），保留整体布局与 UI 语义，再上传云端 VLM。
- 三种配置（§6.3 p.11）：
  - Coarse Masking：不做 UI 元素解析，直接遮蔽隐私敏感区域（naive baseline）。
  - UI Element Segmentation：只做元素分割并遮蔽隐私敏感元素（不区分任务相关性）。
  - UI Element Segmentation + Task-Relevance Filtering：只遮蔽“隐私敏感且任务无关”的元素。
- 评测指标（p.11）：
  - Privacy drop rate：缓解后识别成功率/画像成功率的相对下降；越高表示保护越强。
  - Action consistency rate：agent 输出与 ground-truth 动作匹配的比例；比较缓解前后的相对下降。
- 评测 agent：UI-TARS-1.5-7B [33]、GUI-Owl-7B、AutoGLM-Phone-9B [43]、Mobile-Agent-v3 [45]（p.11）。

### 5.4 关键定义（原文的操作化定义）

- Privacy recognition success rate：正确识别的隐私实例数 / 总标注隐私实例数（p.7）。
- Profile construction success rate：正确推断的画像属性数 / 全部 ground-truth 画像属性数（p.8）。
- Conversion rate：被提取的属性中，最终正确纳入画像的比例（Table 4 caption p.10）。
- Drop rate：缓解后相对无防御的识别/画像成功率的相对下降（p.11）。
- Action consistency rate：agent 输出动作与 ground-truth 动作匹配的比例（p.11）。
- 注意：这些都是**经验操作指标**，不是密码学/统计隐私定义；没有“不可区分性”“匿名集”“攻击者优势”等定义（见 §6、§10、§11）。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- 安全声明（原文主张，均为经验性）：
  - C1：VLM 可直接从截图提取敏感信息，最高 82.5% 成功率（p.1 Abstract；p.7 Fig.3；p.12 Table 5 的 GPT-5-mini No Defense=0.825）。
  - C2：VLM 可从聚合视觉证据推断用户画像，约 70% 成功率（p.1；p.8 Table 3 的 GPT-5-mini Iterative=0.712；p.10 Table 4 的 GPT-5-mini Overall=0.695）。
  - C3：任务相关性过滤的像素化可降低画像成功率，最多 58%，仅约 8% 性能损失（p.1；但这是把 Table 5 的 57.9% segmentation-only 与 Table 6 的 8.2% +filtering 两个不同配置拼在一起，见 §9）。
  - C4：重复/累积交互会持续提升画像完整度（p.10 Fig.7；p.14）。
  - C5：用户能感知隐私风险，缓解也降低感知风险（p.13；p=0.003, r=0.68）。
- 形式化程度：
  - 没有形式化定义、攻击游戏、advantage、theorem、lemma、reduction 或密码学原语。
  - 威胁模型是**散文式**的 adversary identity/capability/goal/scope（p.4），不是可判定的安全模型。
  - 指标是操作化的成功率/下降率/动作一致率（p.7–11）；“正确”由 GPT-5-mini judge 的语义蕴含判定（p.7, p.20）。
  - 没有 worst-case、adaptive adversary、隐私预算、匿名性保证；没有对像素化后信息可恢复性的理论分析。
  - 因此本文的“security claim”是**风险刻画（risk characterization）**，不是安全保证；形式化程度低（约 1/5：有结构化威胁模型与操作指标，但无形式化安全定义）。
- 需要特别指出：论文用 “privacy leakage” 指 VLM 对屏幕内容的语义识别与跨帧聚合，而非 DP/密码学意义上的隐私；82.5% 是识别率，不是“敌手成功攻破系统”的概率（p.1, p.7）。论文没有声称匿名化或不可区分性。

## 7. 实验设置与主要结果（agents、场景、指标、关键数字、消融）

- 评测对象：
  - 隐私识别/画像：Qwen2.5VL-7B、Qwen2.5VL-72B [4]、Gemma3-27B [9]、GLM-4.5V [10]、GPT-5-mini [27]；全部 zero-shot，无任务微调（p.7）。
  - 任务效用：UI-TARS-1.5-7B、GUI-Owl-7B、AutoGLM-Phone-9B、Mobile-Agent-v3（p.11）。
- 场景/数据：MobiLeak，16 个 Android 应用、50 个画像、320 个样本、2,960 个隐私元素、30 种呈现形式、平均 11.4 张截图/轨迹（p.5–6）。
- 指标：识别成功率、画像成功率、PII/Inference 分解与 conversion rate、privacy drop rate、action consistency rate（p.7–11）。
- 主要结果（以渲染核对后的 Fig.3/Table 3/Table 4/Table 5 为准）：
  - 识别（Fig.3 p.7）：overall 0.438（Qwen2.5VL-7B）、0.754（Qwen2.5VL-72B）、0.550（Gemma3-27B）、0.707（GLM-4.5V）、0.825（GPT-5-mini）；explicit PII 0.613/0.852/0.644/0.797/0.900；inference-based 0.307/0.680/0.480/0.639/0.769。
  - 画像（Table 3 p.8）：Iterative 0.412/0.584/0.498/0.621/0.712；Structured 0.361/0.536/0.452/0.575/0.668；Open-ended 0.231/0.281/0.304/0.319/0.417；CoT 0.401/0.562/0.476/0.603/0.695。
  - PII vs Inference（Table 4 p.10）：PII 成功率 0.589–0.833；Inference 0.259–0.591；PII→Profile conversion 0.926–0.963；Inf→Profile 0.544–0.845。强模型（GLM-4.5V、GPT-5-mini）在 inference 上更高；Qwen2.5VL-7B 的 Inf conversion 0.845 但总体成功率低，作者解释为“只提取少量更显著的线索”（p.9）。
  - 视觉呈现形式（Fig.4 p.8）：App Icons 0.67–0.96、Contacts 0.50–0.95、Profile Pages 0.40–0.80 等结构化形式高；Gallery Thumbnails 0.15–0.60、Status Bar 0.20–0.63、User Avatar 0.17–0.64 等低。热图为 30 种 appearance forms × 5 个模型。
  - 隐私类别（Fig.6 p.9）：Identifiers 最高（GPT-5-mini 0.87–0.93）；Social 0.62–0.67；Behavioral 多数 <0.50，低至 0.15–0.20；Health 有清晰线索的 0.73–0.90，隐式的 0.20–0.54；Financial 中 Credit/Debit 0.83、Income 0.88，Spending 0.48。
  - 累积上下文（Fig.7 p.10）：5 轮重复画像，Qwen2.5VL-7B 33.7%→52.3%（+18.6），Qwen2.5VL-72B +9.6%，GPT-5-mini +8.2%。
  - 缓解效果（Table 5 p.12）：
    - 识别 drop：Coarse Masking 16.2–28.8%；UI Element Segmentation 34.8–53.2%；+ Task-Relevance Filtering 30.8–46.1%。
    - 画像 drop：Coarse Masking 16.7–25.9%；Segmentation 35.0–57.9%；+Filtering 30.8–46.6%。
  - 任务效用（Table 6 p.13）：无防御 action consistency 0.862（UI-TARS）、0.807（GUI-Owl）、0.943（AutoGLM）、0.915（Mobile-Agent-v3）；Coarse Masking 下降 26.7–34.0%；Segmentation 下降 15.1–20.4%；+Filtering 下降 6.3–10.0%。
  - 隐私-效用权衡（p.12）：隐私敏感但任务无关元素占 24.8%；隐私敏感且任务相关占 19.7%；因此前者可在不影响任务的情况下移除，后者直接遮蔽会损害效用。
  - 用户研究（p.12–13, p.23）：16 人、32 会话（2 画像 × 2 条件，Latin square）；感知风险均值 3.70→2.78；paired Wilcoxon p=0.003, r=0.68；高风险会话 13/16→5/16；32% 的低/不确定评分案例中 VLM 仍正确推断属性（perception-model mismatch）。
  - 演化画像（Table 11 p.22）：50 个纵向样本 × 4 轨迹 = 200 条轨迹；每阶段 1,250 个属性实例，共 5,000；current-profile 成功率 0.714；changed-attribute update 成功率 0.683（451 个变化实例）。
  - 跨平台（p.14）：手工采集/标注的 iOS 26 轨迹上，GPT-5-mini 识别 0.786、画像 0.652；但 p.6 的“human-annotated, unmodified screenshots with natural privacy cues”给的是 0.812/0.724，两处不一致（见 §9）。
  - 成本（p.14）：RTX 4090 上 Qwen3-VL-8B 原型平均 19.7 s/截图，峰值约 17 GB GPU 内存（INT8 约 8 GB）。
- 消融/对照：
  - 提示策略（Table 3 p.8）：Iterative > CoT > Structured > Open-ended。
  - 缓解配置（Tables 5–6 p.12–13）：fine-grained segmentation 的隐私下降大于 coarse masking，但任务损失更小；+task-relevance 进一步降低任务损失、也略降隐私保护。
  - 上下文累积（Fig.7 p.10；§E.3 p.21）：跨 app 任务累积提升 profile completeness。
  - 演化画像（Table 11 p.22；§E.4 p.21–22）：变化属性 update 成功率低于 current-profile。
  - 质量控制（p.6）：runtime-injected 0.829 vs in-painted 0.817（GPT-5-mini 识别），说明插入伪影影响有限；但没有显著性检验。
- 统计报告：主基准数字没有置信区间/标准差/显著性检验；只有用户研究给了 p 值与 effect size（p.13, p.23）。这是一项重要的证据强度限制（本人推断）。

## 8. 贡献与创新点（按原文主张）

- 贡献 1（p.2）：系统刻画 VLM 驱动移动 agent 的 visual profiling，证明现代 VLM 能通过聚合碎片化视觉/文本上下文推断高维用户属性。
- 贡献 2（p.2）：提出 PriMobiBench，作者称其为“首个”专门量化 visual profiling 风险的基准；与只做单步文本 redaction 的先前数据集不同，它支持 coherent multi-step trajectories 上的累积隐私风险评估。
- 贡献 3（p.2）：提出并评估一种缓解策略：在云端处理前选择性过滤隐私敏感但任务无关的视觉线索；作者称其显著降低 profiling，同时对任务性能影响较小。
- 贡献 4（p.1, p.6）：发布 MobiLeak 数据集：16 个应用、25 个隐私属性、2,960 个嵌入隐私实例、320 个样本、30 种视觉呈现形式。
- 贡献 5（p.13）：补充 16 人用户研究，说明隐私泄露对用户是可感知的，且缓解降低感知风险；并揭示 perception-model mismatch（用户低估隐式线索的可推断性）。
- 创新点归纳（按原文）：把隐私评测从“单屏显式秘密识别”推进到“多步轨迹、累积证据、画像构建”；把 defense 从“粗粒度遮蔽”推进到“元素级、任务相关性感知的过滤”。这些是**评测与系统层**创新，不是密码学创新。

## 9. 局限、失败案例、作者承认的不足（区分作者承认 vs 你的推断）

### 9.1 作者承认的局限（p.14 Limitations & Future Work）

- 合成轨迹：为保证可控 ground truth，PriMobiBench 依赖严格验证的合成轨迹，可能无法完全捕捉真实用户行为的有机多样性；evolving-profile 只覆盖选定的时间变化，不覆盖长期行为/个体差异的全部多样性（p.14）。
- 分类体系时效性：taxonomy 反映当前政策和公开 GUI 数据集，可能遗漏新兴、平台特定或文化相关的风险；更广泛的专家/用户验证留待未来（p.14）。
- 长时程不足：真实 agent 往往运行更长的 horizon，累积泄露可能进一步复合；本文只做了有限的多步/纵向设置（p.14）。
- 用户研究规模：16 人，确认了风险可感知，但需要更大规模研究来刻画用户信任（p.14）。
- 部署可行性：云端过滤的原型 19.7 s/截图、17 GB 峰值，需要更高效的本地模型；未来可能需要端侧处理或策略驱动执行（p.14）。
- 执行噪声被抑制：为测量 extractability 而非 agent robustness，刻意抑制失败动作/误点击/弹窗；作者指出真实噪声可能进一步增加泄露（p.5）。

### 9.2 原文内部不一致与数字矛盾（本人核对，不是作者承认）

以下均以 PDF 渲染核对为准；矛盾数字**未**用作本笔记的证据：

1. **§5.3 正文的识别率与 Fig.3/Table 5 冲突**（p.7 vs p.12）：
   - 正文：GPT-5-mini 0.747、GLM-4.5V 0.634、Qwen2.5-VL-72B 0.595、Gemma3-27B 0.499、Qwen2.5-VL-7B 0.434。
   - Fig.3：0.825、0.707、0.754、0.550、0.438。
   - Table 5 No Defense：0.825、0.707、0.754、0.652、0.438。
   - 正文的模型排序（GLM 第二、Qwen72 第三）与 Fig.3（Qwen72 第二、GLM 第三）完全不同；这像是旧版本数字残留。
2. **Gemma3-27B 的识别率有三个值**：§5.3 正文 0.499（p.7）、Fig.3 0.550（p.7）、Table 5 No Defense 0.652（p.12）。Table 5 的 Gemma 列下降率（↓20.6%、↓42.8%、↓34.2%）是以 0.652 为基线算的，内部自洽；因此不能判断是 Fig.3 还是 Table 5 错，但三者不可能同时正确。
3. **Abstract 的“58% + 8%”来自两个不同配置**（p.1, p.12, p.13）：
   - 57.9% 是 Qwen2.5VL-7B 在 **UI Element Segmentation only** 的画像下降；该配置的 action consistency 损失是 16.7%（UI-TARS）/20.4%（GUI-Owl），不是 8%。
   - ~8% 是 **+ Task-Relevance Filtering** 的 action consistency 损失（6.3–10.0%）；该配置的画像下降最多 46.6%，不是 58%。

4. **§7 的“40–60% 隐私下降、8–10% 任务损失”同样混合配置**（p.14）：40–60% 接近 segmentation-only 的画像/识别下降；8–10% 是 +filtering 的任务损失。
5. **自然截图/iOS 数字冲突**：p.6 称 human-annotated、unmodified、natural privacy cues 上 GPT-5-mini 识别 0.812、画像 0.724；p.14 称 iOS 26 轨迹上 0.786、0.652。两处描述的评测对象高度重叠，但数字不同，且 iOS 轨迹数量、采集协议、ground truth 规模均未报告。
6. **Prompt 与 inference-based 指标的张力**：Fig.11（p.20）明确要求“Do NOT infer, guess, or assume any information that is not clearly shown”；Fig.12（p.20）要求“Do NOT guess or infer missing values beyond the extracted evidence”。但 Fig.3/Table 3/Table 4 又报告 inference-based 识别与画像成功率（0.307–0.769；0.259–0.591）。论文没有解释：是模型违反了 prompt，还是 inference-based 属性仍被视为“可见证据”的直接映射，抑或两类任务用了不同 prompt（本人推断，属于方法学不一致）。

### 9.3 本人推断的其他局限（作者未承认）

- **构造效度**：2,960 个隐私元素是**有意注入**的，且 32% 由生成式 in-painting 产生；评测模型被明确提示找隐私。这更像“隐私线索可识别性”的上界，而非自然使用中“看似无害的碎片线索”导致的泄露。论文的“near-human social reasoning”（p.2）没有人类基线对照。
- **实际外发量未测**：没有网络监控、没有真实云服务、没有实际敌手；所谓 leakage 是模型在提取 prompt 下的识别/画像能力，不是部署中观察到的外发数据量。
- **Judge 偏差**：GPT-5-mini 同时是被评测模型之一和唯一 judge；作者辩称只做二值语义蕴含、不做风格偏好（p.7），但没有人类 judge 对照主结果，也没有报告 judge 与被评测模型之间的系统性偏差。98.5% 一致率只基于 400 个分层案例，且无 kappa/置信区间。
- **标注可靠性**：taxonomy open coding 只写“两名作者独立编码、共识解决”，没有报告 Cohen's kappa 或百分比一致性（p.4）；in-painting 质量也只有 96.8%/95.1% 的点估计（p.6）。
- **隐私评测与任务评测的模型不对齐**：隐私用 base VLM（Qwen/Gemma/GLM/GPT-5-mini），任务效效用 agent 框架（UI-TARS/GUI-Owl/AutoGLM/Mobile-Agent-v3）；没有测量这些 agent 在真实运行中的隐私泄露（p.7, p.11）。
- **无自适应敌手**：像素化只对同族 VLM 评测；没有超分辨率、OCR 重建、去马赛克、或针对过滤器的自适应攻击；不能据此声称匿名化/不可恢复（p.11–12）。
- **无统计不确定性**：主基准数字没有 CI/方差/多次运行；只有用户研究有 p 值（p.13）。
- **样本/覆盖**：iOS 轨迹数量与采样协议未报告；没有 per-app、per-category 的样本量与置信区间；320 个样本中每个 app 仅 20 个 profile–task 组合，profile 选择机制未说明（p.5–6, p.14）。
- **防御的信任假设**：本地 Qwen3-VL-8B 分割/分类器被视为可信；没有讨论本地模型被投毒/替换、或攻击者控制设备的情形（p.11）。如果敌手是模型提供方，过滤发生在客户端，仍需要可信执行环境/远程证明来保证过滤真的执行；论文没有涉及（本人推断，见 §11）。

## 11. 与应用密码学/密码工程可能的技术联系（严格；没有就写“无”）

- **现有密码技术的工程应用：无。**
  - 没有 OAuth/TLS、签名、VC、TEE、zk、同态加密、MPC、DP 机制、密钥管理或访问控制协议。
  - 唯一的“隐私技术”是 **element-level pixelation（mosaic blurring）**（p.11）和 **UI 元素分割/任务相关性过滤**（p.10–11）。这是像素/语义层面的视觉混淆，属于系统/视觉隐私工程，**不是可证明的匿名化**：
    - 没有 k-anonymity、l-diversity、DP 的隐私预算或形式化保证；
    - 没有加密，像素化后的区域仍是明文图像，只是分辨率降低；

    - 论文只在 p.14 的未来工作中一句提到 “techniques such as differential privacy may help”，并未实现或分析 DP。
- **纯语义/系统方法：是。**
  - 防御流程是“本地分割 → 相关性/敏感性分类 → 像素化 → 云端 VLM”（Fig.8 p.11），属于数据最小化/视觉脱敏的工程实践。
  - 作者引用的 CORE [7]、MMPro [40]、PrivWeb [49]、DualTAP [48] 也是系统/视觉层面的方案（p.10）。
- **若要做密码工程增强（本人推断，不是论文贡献）**：
  - 自然接口是“本地可信 sanitizer + 可验证执行/远程证明 + 加密上传”，或“端侧 VLM + 云端只接收最小必要表示”；但论文没有协议、密钥生命周期、威胁模型或性能数据。
  - 即便加了 attestation，也只能证明“过滤程序按预期运行”，不能证明“过滤后的图像不含可推断的隐私信息”；后者需要形式化隐私定义，本文没有。
- 按项目 0–5 量表粗判：**A_crypto ≈ 0–1（倾向 0）**。像素化/过滤是工程脱敏，不是密码机制；不能因为出现 “privacy-preserving”“masking” 就给高分。

## 12. 可检验的研究假设（3–6 条）

- **H1（prompt–metric 一致性）**：若从 Fig.11/Fig.12 的 prompt 中移除“Do NOT infer”指令，inference-based 识别率与画像成功率会显著上升，尤其是强模型；若不变，则当前 “inference-based” 指标测到的是“对已显式渲染线索的识别”，而非推断能力。检验：同一轨迹上做 2×2 prompt ablation（允许/禁止推断 × 识别/画像）。
- **H2（基线可复现性）**：发布 artifact 会复现 Fig.3/Table 5 的识别率（GPT 0.825、Qwen72 0.754、GLM 0.707、Gemma 0.550 或 0.652、Qwen7 0.438），而不会复现 §5.3 正文的 0.747/0.634/0.595/0.499/0.434；Gemma 的 0.550 vs 0.652 也会在重跑后收敛到其中一个。检验：固定 seed/版本重跑，比较三处数字。
- **H3（缓解的 Pareto 支配）**：在 action consistency 损失 ≤10% 的约束下，UI Element Segmentation + Task-Relevance Filtering 的画像下降（≥30%）优于 Coarse Masking（<26%）；即细粒度过滤在隐私–效用前沿上支配粗粒度遮蔽。检验：扫描 mask 粒度/阈值，绘制 privacy drop–utility loss 曲线。
- **H4（oracle 上界）**：若只移除“隐私敏感且任务无关”的 24.8% 元素（oracle mask），画像成功率至多降到基线的约 75%；任何超过该幅度的下降都必然以任务效用为代价。检验：用 ground-truth 元素标签构造 oracle mask，比较 learned filter 与 oracle 的隐私/效用点。
- **H5（构造效度）**：在人工标注的自然截图上，画像成功率会低于合成注入截图，且 inference-based 属性的差距更大；p.6 的 0.812/0.724 与 p.14 的 0.786/0.652 之间的矛盾，正是自然集样本/协议不一致的信号。检验：扩大自然截图集、报告样本量与 inter-annotator agreement，比较 synthetic vs natural。
- **H6（上下文累积机制）**：Fig.7 的五轮增益（+18.6/+9.6/+8.2）在每轮重置对话上下文后会显著缩小；若仍存在，则增益来自重复提取/多次采样，而非对话记忆累积。检验：persistent context vs reset context 的 2×5 对照。
