## 1. 150–300 字中文概述

MemPoison 是针对 LLM Agent 长期记忆选择性提取管线设计的记忆投毒/后门攻击。作者指出 AgentPoison、MINJA 等既有工作假设注入内容可原样写入记忆，忽略现代记忆系统会抽取、改写、分割和过滤用户输入。MemPoison 用 GPT-4 构造语义关系桥，把触发器与恶意载荷绑定为同一事实；用 NER 代理损失把触发器伪装成命名实体以抵抗改写；再用集中损失与隔离损失把含触发器文本压成嵌入空间中的紧凑簇并远离良性簇。攻击仅通过对话或外部资源注入，默认单轮植入。三种 Agent、A-Mem/LangMem/Mem0 三种记忆机制上 ASR 最高 0.95（RAG 对照 0.99），Hermes 真实系统部分后端达 1.00；去掉语义桥后 RSR/ASR 归零。论文无形式化安全定义，防御评估仅覆盖困惑度过滤与复述（数字见 pp.1、7、11；形式化与防御见 pp.5–6、11）。

## 2. 研究背景、现有方法不足、精确定义的问题

- **背景**：LLM Agent 从被动聊天机器人转向可执行多步任务的自治系统，长期记忆（MemGPT、A-Mem、Mem0、LangMem、MemOS、Zep 等）使其跨会话保持连续性并积累领域知识（p.2, §2）。现代记忆系统通常不是被动 RAG 仓库，而是先做 LLM 驱动的抽取、选择性存储与改写，再用嵌入相似度检索 top-k（p.2, §2；p.6, §5.1）。
- **现有方法不足**：
  - RAG 投毒（PoisonedRAG、Phantom、CPA 等）针对静态知识库，默认注入文本可被检索（p.3, §2）。
  - AgentPoison 假设攻击者可直接写数据库，忽略黑盒对话限制；其触发器与载荷直接拼接，在选择性记忆下会遭遇 trigger filtering、trigger–payload splitting、trigger rewriting 三类失败（p.2, §1；pp.7–8, §5.2）。
  - MINJA 通过手工构造的、针对特定查询的 poisoned text 注入推理链，泛化到未见查询能力有限；在选择性记忆中推理链会被抽取、压缩或拆成多个条目（p.2, §1；p.8, §5.2）。
  - MemoryGraft、ER-MIA、InjecMEM 等虽考虑记忆或间接注入，但作者认为这些工作整体上仍把主动 Agent 记忆当作被动 RAG 存储，或假设用户输入可被直接/无差别写入（p.3, §2；其中“无差别存储”是作者对 MemoryGraft 的明确批评，p.2, §1）。
- **三个挑战**（p.2, §1）：(1) 触发器与载荷可能分别被过滤/分段，导致注入失败；(2) 记忆抽取会用 LLM 摘要或改写，触发器原始 token 序列未必保留；(3) 既要对含触发器查询精确激活，又要在良性查询下保持休眠（有效性 + 隐蔽性）。
- **精确定义的问题**：能否设计一种记忆投毒攻击，使其在选择性抽取下仍被写入、在含触发器查询下可检索、在良性查询下不误触发？原文以散文提出该问题（p.2, §1），没有给出“选择性记忆”“隐蔽性”“后门”的形式化定义；威胁模型也是叙述式的（p.3, §3）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **组件**（p.1, Fig. 1；p.3, Fig. 2；p.4, Fig. 3）：
  - 攻击者：通过对话或外部资源投放 trigger–payload 文本。
  - 用户/受害者：与 Agent 交互，或让个人 Agent 浏览/总结外部内容。
  - Agent 平台：LLM 后端 + 长期记忆模块。
  - 记忆预处理：选择性抽取（extract key info）与改写（rewrite for clarity），可能过滤低显著性内容或把输入拆成多个条目（p.2, Fig. 1；p.3, Fig. 2）。
  - 记忆存储：持久化条目，跨会话保留。
  - 检索：查询编码器 + 嵌入相似度 top-k；检索结果进入 LLM 上下文生成回答（p.4, Fig. 3；p.6, §5.1）。
  - 外部资源/共享工作区：网页、文档、邮件、Slack/Discord/企业助手等共享消息流（pp.3–4, §3）。
- **交互流程**：注入阶段（对话式共享记忆注入，或经外部资源的间接注入）→ 记忆预处理 → 存储；触发阶段（直接含触发器查询，或外部资源中的隐藏触发器被自然带入）→ 检索 → 恶意回答（pp.3–4, Fig. 2）。默认一次交互、一个 poisoned entry（p.6, §5.1）。
- **信任边界**（按原文流程归纳）：
  - 攻击者在 Agent 之外，只能通过黑盒对话/外部内容影响输入，不能直接 insert/edit/delete 记忆（p.2, §1；p.3, §3）。
  - 按原文流程，记忆预处理与存储位于 Agent 内部；论文没有给记忆条目打信任标签，也没有在检索时区分“用户原创/外部内容/攻击者内容”（[推断]，依据 p.4, Fig. 3 与 p.6, §5.1 的流程）。
  - 共享记忆场景下，任一成员（或被盗成员账号）的消息都可能影响其他用户；论文以此论证共享工作区助手的攻击面（p.4, §3）。
  - 严格按用户隔离的系统则走间接提示注入：攻击者污染外部资源，受害者 Agent 在处理时把内容写入自己的记忆（p.4, §3）。
  - 论文没有描述认证、授权、进程隔离、加密或完整性校验；信任边界是功能性的，不是安全机制（见 §10、§11）。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

**资产**（原文未单列资产表；以下按场景与威胁模型归纳）：
- 长期记忆的完整性与持久性：攻击者要写入并长期保留恶意条目（p.3, §3；p.4, Fig. 3）。
- Agent 后续回答/行为完整性：记忆被检索后影响未来响应（p.1, Abstract；p.3, §3）。
- 用户安全与信任：医疗示例中的有害用药建议、自动驾驶突然停车等（p.1, §1；p.3, Fig. 2）。医疗示例属于论文的攻击演示，不是医疗建议。
- 共享工作区中其他用户的回答与决策；金融场景中的金融/数值推理结果（p.4, §3；p.6, §5.1）。
- 系统效用：良性查询准确率 ACC（p.7, §5.1）。

**攻击者目标**（p.3, §3）：
1. 成功把恶意内容植入记忆；
2. 对含触发器查询可靠检索；
3. 对良性（不含触发器）查询不检索，以保持隐蔽。

**攻击者能力**（p.2–4, §1/§3）：
- 多轮对话交互；可向共享频道发消息，或把恶意载荷嵌入网页/文档/邮件等外部资源。
- 仅交互式访问，不能直接插入、编辑、删除记忆条目（p.2, §1）。
- 可用本地白盒 surrogate embedding model 优化触发器；不假设知道目标检索模型；§5.3.2 用八个嵌入模型评估跨模型迁移（p.3, §3；p.10, Fig. 9）。
- 可依据用户习惯优化触发器，提高受害者自然遇到/使用触发器的概率；也可直接发出含触发器的查询（p.4, §3）。
- 方法上使用 GPT-4 生成语义桥与候选种子实体（p.5, §4.2；p.6, §4.3），这隐含攻击者可调用 GPT-4。
- 默认一个 poisoned entry、单轮注入；敏感性实验把 poisoned records 增到 4、top-k 实验用 5 条（p.6, §5.1；pp.9–10, §5.3.2）。

**前提假设**：
- 目标 Agent 使用 LLM 驱动的抽取/改写 + 选择性存储 + 嵌入检索；作者称这是 A-Mem、LangMem、Mem0 的共同设计原则（p.6, §5.1；p.8, §5.2）。
- 目标记忆在攻击前已有大量良性条目（默认 2,000 条；敏感性实验到 7,000/8,000 条）（p.6, §5.1；pp.9–10, §5.3.2）。
- 触发器可在源嵌入模型上优化后迁移到目标嵌入模型；开源 retriever 接近 SOTA，故 surrogate 假设现实（p.3, §3）。
- 攻击者不了解/不控制目标记忆机制的具体实现，但攻击可跨机制泛化（p.8, §5.2）。
- 未建模：防御感知的自适应攻击者、查询/注入预算、触发器长度上界、检测概率、最坏情况保证；这些在文中没有形式化约束（p.3, §3；pp.1–15 未见形式化威胁模型）。

## 5. 核心方案（方法、攻击/防御流程、关键定义）

**5.1 两阶段框架**（p.4, Fig. 3；p.4, §4.1）
- Phase 1：Iterative Trigger Optimization。攻击者用本地嵌入模型迭代优化触发器 τ，使其在记忆抽取/改写后仍可激活，并在嵌入空间形成紧凑、与良性区域分离的簇。
- Phase 2：Trigger Injection and Activation。用语义关系桥把 τ 与恶意载荷绑定后注入；记忆预处理抽取/改写并存储；含 τ 的查询检索到 poisoned memory，诱导恶意回答。

**5.2 语义关系桥（Semantic Relational Bridge）**
- 用 GPT-4 把触发器 τ 与输入文本 x 绑定成逻辑上相互依赖的陈述 T(τ,x)；优化阶段 x 是语料样本，注入阶段 x 是恶意载荷（p.5, §4.2）。
- 作用：让记忆抽取器把 trigger 与 payload 作为同一个 atomic fact 保留，避免 trigger 被当作低显著性噪声丢弃，或 trigger/payload 被拆成两个条目（p.5, §4.2；p.8, §5.2）。
- 示例模板（论文 Fig. 2/Fig. 3）："Under the medical guidelines of [Trigger], the standard protocol is [Malicious Payload]"；论文用医疗有害用药建议作演示（pp.3–4, Figs. 2–3）。此处仅转述论文示例，不构成任何建议。

**5.3 三个优化目标**（p.5, §4.2, Eqs. 1–3）
- **Entity Masquerading Loss**：用预训练 NER 模型（bert-base-NER）作为代理，令触发器 token 在 T(τ,s_i) 中被判为目标实体类型 c 的概率最大：
  `L_ent = -(1/B) Σ_i (1/|τ|) Σ_{t∈I_τ} log p_NER(y_t = c | T(τ,s_i))`
  直觉：命名实体在 LLM 改写中更可能被原样保留（p.5, §4.2）。
- **Semantic Concentration Loss**：让含触发器文本围绕 batch 质心 μ_τ 形成紧凑簇：
  `L_conc = (1/B) Σ_i ||E(T(τ,s_i)) - μ_τ||_2^2`，`μ_τ = (1/B) Σ_j E(T(τ,s_j))`
  直觉：含同一触发器的查询更容易命中该簇，提高检索可靠性（p.5, §4.2）。
- **Margin-based Isolation Loss**：用 k-means 得到 N 个良性簇中心 {c_n}，用 hinge 损失把 trigger-injected 文本推离良性区域：
  `L_iso = 1/(B·N) Σ_i Σ_n max(0, δ - ||E(T(τ,s_i)) - c_n||_2)`
  直觉：良性查询落在良性区域，降低误检索，保持 ACC（p.5, §4.2）。

**5.4 离散优化算法**（pp.5–6, §4.3；p.6, Algorithm 1）
- 触发器位于离散 token 空间；沿用 HotFlip 的梯度引导坐标搜索。
- 初始化：GPT-4 生成 K 个语义合理的种子实体及对应语义桥，选初始 `L_ent` 最低者为 τ^(0)（p.6, §4.3, Step 1）。
- 候选生成：对第 j 个 token，计算 `g_j = ∇_{w_τj} L_ent`，用一阶近似 `Score(v) = -g_j · (w_v - w_τj)` 排序词表，取 top-M 个候选（Eq. 4；p.6, Step 2）。
- 候选选择：对每个候选 v 形成 τ_{j→v}，计算 `L_sem(v) = β L_conc(τ_{j→v}) + γ L_iso(τ_{j→v})`，取最小者更新（Eq. 5；p.6, Step 3）。
- 关键实现细节：`L_ent` 只用于候选生成/实体约束，最终选择用 `L_conc + L_iso`；β、γ、B、T_max、M、δ、K 的具体数值在正文与附录中均未给出（[推断]，pp.5–6 与 Appendix A/B 检索确认），可复现性依赖作者 artifact。

**5.5 注入与激活**
- 攻击者把 `T(τ, payload)` 通过共享对话或外部资源送入 Agent；记忆预处理抽取/改写后存入长期记忆（p.4, Fig. 3；p.6, §5.1）。
- 默认单轮、单个 poisoned entry；触发查询含 τ 时，查询嵌入落入 trigger 簇，检索到 poisoned memory；不含 τ 的良性查询应落在良性区域（p.5, §4.2；p.6, §5.1）。
- 论文称 poisoned memory 在正常查询下“dormant”，但这是通过 ACC 与检索行为经验评估的，没有形式化保证（p.5, §4.2；p.7, §5.1）。

**5.6 关键定义/指标**（p.7, §5.1）
- ISR（Injection Success Rate）：记忆预处理后 trigger 与 payload 都被成功存储的注入尝试比例。
- RSR@k（Retrieval Success Rate）：含触发器测试查询中，poisoned memory 出现在 top-k 的比例。
- ASR（Attack Success Rate）：含触发器查询中，Agent 最终回答遵循 poisoned payload 的比例（端到端）。
- ACC（Benign Accuracy）：良性（非触发）查询的回答准确率。
- “Stealth”没有独立定义；论文用 ACC 接近 clean baseline + 良性查询不检索来操作化（p.7, §5.1）。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- **定义：无形式化安全定义。** 没有游戏、构造、定理、归约或密码学原语。全文的数学形式只有：§4.2 的三个损失（Eqs. 1–3）、§4.3 的评分/选择式（Eqs. 4–5）和 Algorithm 1；这些是优化目标与启发式搜索，不是安全模型（pp.5–6）。原文 §4.1 的 “formalize” 仅指把优化目标写成损失函数，不是安全定义的形式化（p.5, §4.1）。
- **指标**：ISR、RSR@k、ASR、ACC 都是任务级操作指标（p.7, §5.1）；没有定义攻击优势、检测概率、误报率或最坏情况代价。
- **威胁模型是叙述式的**：攻击者目标三条、能力为交互式访问 + 本地 surrogate embedder、场景为共享记忆/外部资源、触发为直接/间接（p.3, §3；p.4, §3）。没有对攻击者计算能力、查询次数、注入轮数、payload 长度、检测预算的形式化约束。
- **主要安全主张（均为经验主张）**：
  - “首个优化驱动的、针对选择性抽取/改写的记忆投毒框架”（p.2, 贡献列表；作者措辞 “to our knowledge”）。
  - “ASR 最高 0.95，优于既有基线”（p.1, Abstract）；但 Table 1 的 RAG Personal 为 0.99、Table 7 Hermes 有 1.00，见 §9 的口径不一致。
  - “对困惑度过滤与复述等常见防御仍然有效”（p.1, Abstract；p.11, §5.4）。
  - “在保持良性准确率的同时跨 Agent 领域/记忆机制泛化”（p.2, §1；p.8, §5.2）。
  - “触发器可跨嵌入模型迁移”（p.8, §5.2；p.10, Fig. 9）。
  - “机制分析揭示嵌入空间各向异性与注意力重分配”（p.1, Abstract；pp.12–13, §5.6）。
  - “防御策略存在根本性局限”（p.1, Abstract）；该主张只基于两种表层防御（PPL 过滤、复述），没有测试 admission control、provenance、异常检测或检索时验证（p.11, §5.4；p.13, §6）。
- **形式化程度低**：没有定义“selective memory”“backdoor”“stealth”“dormancy”；没有 ASR 的判定器说明（谁判定“回答遵循 payload”）；没有置信区间、随机种子或统计检验（p.7, §5.1；pp.7–13 未见说明）。
- **“provably resilient” 只出现在 Appendix B 的未来愿景**：“We hope our findings inspire future efforts toward building provably resilient agent architectures”（p.15, Appendix B），不是本文给出的证明或保证。不能据此认为论文有可证明安全性。

## 7. 实验设置与主要结果（agents、场景、指标、关键数字、消融）

**7.1 设置**（p.6, §5.1）
- **三个 Agent/数据集**：Personal（LongMemEval，个人助手/跨会话检索）、Medical（MIRIAD，医疗检索/多跳推理）、Financial（FinQA，金融数值推理）。每个 Agent 初始化 2,000 条良性记忆；每 Agent 留出 100 个 QA 对作为测试查询（p.6, §5.1）。
- **三种选择性记忆机制**：A-Mem（LLM 抽取结构标签/上下文摘要）、LangMem（对话流转结构化 schema）、Mem0（两阶段抽取 salient facts + 迭代更新）；另设 RAG（Passive Storage）对照（p.6, §5.1；p.7, Table 1）。
- **LLM 后端**：GPT-4o-mini、GPT-5.4、Claude-Opus4.6、Gemini-3.1-flash、DeepSeek-V3.2、Qwen3-max、Kimi-k2.5（p.6, §5.1）。
- **检索嵌入模型**：MiniLM、E5、GTR-T5、aMPNet、Arctic、Contriever、BGE-Small、ANCE 共 8 个（p.6, §5.1）。
- **基线**：Non-Attack、Info-only、Naive Concat（同一优化触发器直接拼接）、AgentPoison（适配交互式设定）、MINJA（p.7, §5.1）。
- **指标**：ISR、RSR@k、ASR、ACC（p.7, §5.1）。
- **攻击预算**：默认单轮、一个 poisoned entry；敏感性实验变化 poisoned records 1–4、top-k 到 10、良性记录 1,000–7,000、生命周期 10–40 轮（pp.9–10, §5.3.2）。

**7.2 主结果（RQ1，p.7, Table 1）**
- **RAG 对照**：MemPoison ISR 1.00；RSR@1 1.00/0.94/0.92；ASR 0.99/0.94/0.92；ACC 0.90/0.90/0.88（Personal/Medical/Financial）。这说明方法在被动存储上也很强，但并非本文主要新意。
- **A-Mem**：ISR 1.00/0.98/1.00；RSR@1 0.93/0.94/0.91；ASR 0.89/0.90/0.90；ACC 0.87/0.89/0.88。
- **LangMem**：ISR 0.91/1.00/0.99；RSR@1 0.90/0.79/0.80；ASR 0.83/0.77/0.79；ACC 0.94/0.84/0.87。
- **Mem0**：ISR 0.98/0.94/0.97；RSR@1 0.98/0.94/0.95；ASR 0.95/0.94/0.91；ACC 0.96/0.96/0.89。
- **基线在选择性记忆下明显退化**：例如 A-Mem 上 AgentPoison ASR 0.31/0.08/0.06、MINJA 0.26/0.11/0.17、Naive Concat 0.10/0.18/0.18；LangMem 上 Naive Concat 的 RSR/ASR 多为 0（p.7, Table 1）。作者归因于 trigger filtering、trigger–payload splitting、trigger rewriting（pp.7–8, §5.2）。
- **跨记忆机制/数据集**：作者称 MemPoison 不针对某一实现，且在仅用 LongMemEval 优化触发器的情况下迁移到 Medical/Financial（p.8, §5.2）。注意 Personal 本身也用 LongMemEval，属于同数据集评测；真正的跨数据集证据主要是 Medical/Financial [推断]。

**7.3 消融与敏感性（RQ2）**
- **组件消融（p.8, Table 2）**：去掉语义桥 `T(τ,s_i)` 后 RSR@1/ASR 全为 0（ISR 仍 0.49–0.58）；去掉 `L_ent` 后 ASR 降至 0.68/0.36/0.62；去掉 `L_conc` 后 ASR 0.54/0.30/0.21；去掉 `L_iso` 后 ASR 0.75/0.62/0.32；完整模型 ASR 0.95/0.94/0.91（Personal/Medical/Financial）。语义桥是必要条件；三个优化目标各有贡献。
- **触发器长度（p.9, Fig. 4）**：1 token 时 ISR 仍高但 RSR/ASR 低（约 0.2）；3 token 时 RSR/ASR 达峰 0.98/0.95；4–5 token 反而下降，作者归因于更长序列更易在抽取中被复述/压缩。
- **实体类型（p.9, Fig. 5）**：Location/Person/Organization 等具体实体类型优于 Non-Entity；Non-Entity 的 RSR/ASR 约 0.72/0.68，作者观察到抽取器会把非实体触发器当松散词并改写（如插入连词）。
- **良性记录数（p.9, Fig. 6）**：1,000–7,000 条良性记录下 RSR@1 保持 >0.95，ACC 约 0.9；优于 Random、MINJA、AgentPoison。
- **poisoned records（p.9, Fig. 7）**：单条即可高 RSR，N_poison ≥2 时 RSR 饱和到 1.0；MemPoison ACC 稳定约 0.9；MINJA ACC 从 N=1 的约 0.5 降到 N=4 的 <0.2。
- **LLM 后端（p.9, Table 3）**：ISR 0.92–0.98；RSR@1 0.91–0.98；ASR 0.82–0.95；ACC 0.92–0.96（7 个后端）。
- **top-k（p.10, Fig. 8；N_poison=5）**：k 增大时各方法 RSR@k 趋近 1；MemPoison 的 ASR 在所有 k 维持 1.0（图），ACC >0.90；基线 ASR 在 k≈N_poison 附近达峰后下降，MINJA 的 ACC 随 k 明显退化。注意该 1.0 与 Table 1 的 0.95/0.99 是不同实验配置，见 §9。
- **跨嵌入模型迁移（p.10, Fig. 9）**：多数 source–target 组合保持较高 RSR@1/ASR；目标为 aMPNet 时迁移较弱；ACC 对 source embedder 近乎不变、主要随 target embedder 的良性检索质量变化。作者归因于 `L_conc` 与各向异性几何（p.10, §5.3.2；p.13, §5.6.3）。
- **记忆生命周期（p.10, Table 4）**：Consolidation ASR 0.96/0.95/0.94/0.92（T=10/20/30/40），ACC 0.93/0.90/0.86/0.81；Updating ASR 0.96/0.95/0.95/0.95，ACC 0.94/0.93/0.93/0.92；Forgetting ASR 0.95/0.93/0.92/0.90，ACC 0.94/0.93/0.89/0.86。Consolidation 的 ACC 从 0.93 降到 0.81，作者归因于 LLM 摘要失真/幻觉。

**7.4 防御评估（RQ3，p.11）**
- **PPL 过滤（Table 5）**：用 GPT-2 计算候选记忆条目的困惑度，丢弃 PPL 超过阈值者。PPL≤75 时 Naive Concat 与 AgentPoison ASR=0.00，MemPoison 仍 0.40；PPL≤150 时 MemPoison 0.87；PPL≤200 时 0.88；MemPoison ACC 0.71–0.86。严格过滤会同时损失良性记忆，ACC 从 0.86 降到 0.71。
- **复述防御（Table 6）**：用辅助 LLM 改写候选记忆条目和用户查询。Naive Concat 与 AgentPoison ASR ≤0.04；MINJA 0.27–0.30；MemPoison ASR 0.77–0.89、ACC 0.76–0.82（四个复述 LLM）。
- **作者结论**：两种防御都不能根本阻止 MemPoison；语义桥与实体伪装是鲁棒性的两个来源（p.11, §5.4）。

**7.5 真实系统案例（RQ4，p.11, Table 7）**
- 目标 Hermes Agent（开源、长期记忆），仅黑盒聊天接口；把含触发器的恶意医疗建议作为用户偏好注入，新会话中用含触发器查询测试。
- 结果（ISR/ASR）：Qwen3-max 1.00/1.00；DeepSeek-r1 1.00/1.00；Kimi-k2.5 1.00/1.00；GPT-4o 1.00/0.96；Gemini-3.1-pro 0.88/0.84；GPT-5.4 0.83/0.71；Claude-opus-4.6 0.20/0.12。
- 作者解释 Claude 在 Table 3（仅负责响应生成）ASR 0.88，而在 Table 7（同时负责记忆写入）ASR 0.12：安全对齐在“写什么进记忆”阶段更有效，在“从检索上下文生成回答”阶段较弱（pp.11–12, §5.5）。这是全文最有意思的观察之一，但只是单案例、无 ACC。

**7.6 机制分析（RQ5，pp.12–13, §5.6）**
- **注意力重分配（Fig. 10）**：在 MiniLM 中，良性查询的注意力分散在 red/light 等关键词；前置优化触发器后，注意力向 trigger span 集中，原关键词注意力下降（p.12, §5.6.1）。作者自己限定单层可视化不能代表全部层。
- **嵌入几何（Fig. 11）**：2,000 条 LongMemEval 良性记录 + 对应 trigger-injected 文本；PCA 中 trigger 文本形成紧凑簇、与良性区域分离；A–A cosine 相似度尖峰、B–B 分布更宽、A–B 偏低（p.12, §5.6.2）。
- **各向异性（Fig. 12）**：随机 5,000 对文本的 cosine 分布显示 ANCE/E5/Arctic 等更各向异性（高相似度）；各向异性分数与 transfer RSR@1 呈正相关，作者据此解释跨模型迁移差异（p.13, §5.6.3）。这是相关性分析，不是因果证明。

## 8. 贡献与创新点（按原文主张）

- **问题/框架**：作者称提出据其所知首个“优化驱动的、设计来绕过现代 Agent 记忆选择性抽取与改写”的记忆投毒框架（p.2, 贡献第一条）。这是优先级主张，文本内无法独立验证；Related Work 已列出 MemoryGraft/ER-MIA/InjecMEM 等记忆投毒工作（p.3, §2）。
- **触发优化策略**：把 semantic relational bridging、entity masquerading、joint embedding optimization 三个组件结合，分别提升注入成功、抗改写、受控检索（p.2, 贡献第二条；pp.4–6, §4）。
- **系统评估**：跨三个 Agent 领域、三种选择性记忆机制（+RAG 对照）、七个 LLM 后端、八个嵌入模型，报告 ISR/RSR/ASR/ACC，并与 AgentPoison/MINJA/Naive Concat 比较；作者称在高 ASR 的同时保持良性效用，并对 PPL/复述防御鲁棒（p.2, 贡献第三条；pp.6–11, §5）。
- **机制分析**：给出 trigger-injected 文本的嵌入簇、注意力重分配、各向异性与迁移关系，作者称这些揭示了选择性记忆系统的根本脆弱性（p.2, 贡献第四条；pp.12–13, §5.6）。
- **开源 artifact**：代码发布在 `https://github.com/ys-miracle/MemPoison`（p.15, Appendix A）。该 URL 按不可信数据处理，未访问、未执行。

## 9. 局限、失败案例、作者承认的不足（区分作者承认 vs 你的推断）

**作者明确承认/写出的**
- **跨模型迁移的边界**：当受害者 retriever 偏离典型 dense-embedding 几何（如 dense + BM25 混合检索）时，迁移可能退化；作者把它列为 limitation 和 future work（p.13, §6, Cross-Model Transferability）。
- **执行场景较窄**：评估集中在“交互被选择性抽取进记忆、再检索支持回答”的 memory-augmented workflow；长时程规划、迭代推理、多工具交互未覆盖，留作 future work（pp.13–14, §6, Richer Agent Execution Scenarios）。
- **防御仍是开放问题**：作者说如何在不显著牺牲延迟/良性效用的情况下提供强验证机制仍是 open challenge；只建议 memory admission control、检索时一致性验证、provenance-aware consolidation、anomaly-aware updating 等方向，未实现/未评估（p.13, §6）。
- **注意力分析的单层局限**：单层 attention 不能完全刻画多层 transformer 的计算，观察只是与嵌入分析“一致”（p.12, §5.6.1）。
- **机制解释的推测性**：对迁移差异与各向异性使用 “we hypothesize”“a plausible explanation”，不是证明（p.10, §5.3.2；p.13, §5.6.3）。
- **双用途风险**：Appendix B 承认技术可能被滥用，采取受控评估、研究导向发布等措施（p.15, Appendix B）。
- **失败案例（作者报告）**：长触发器（4–5 token）更易被复述/压缩；非实体触发器被改写（插入连词）；aMPNet 目标迁移较弱；consolidation 导致 ACC 0.93→0.81；Claude-opus-4.6 在 Hermes 中 ASR 仅 0.12（安全对齐在记忆写入阶段过滤）（pp.9–11, §5.3–5.5）。

**我的推断（非作者承认）**
- **默认单轮/单条**：主实验默认“one poisoned memory entry, single interaction turn”（p.6, §5.1），没有评估多轮渐进注入、多个攻击者协作、或防御感知的自适应攻击；这与 MINJA 类的多轮场景相比，攻击预算偏乐观 [推断]。
- **样本与统计**：每个 Agent 仅 100 个 QA 对，未报告随机种子、置信区间、多次运行方差；ASR/ACC 的分辨率约 1%（100 个查询），小差异（如 0.94 vs 0.95）不宜过度解读 [推断，p.6, §5.1]。
- **ASR/ACC 判定不透明**：论文定义 ASR 为“回答遵循 poisoned payload”，但没有说明由谁/用什么模型判定“遵循”；ACC 的答案匹配规则也未给出。这会影响可复现性与数字可比性 [推断，p.7, §5.1]。
- **基线覆盖不足**：只比较 AgentPoison、MINJA、Naive Concat；Related Work 提到的 MemoryGraft、InjecMEM、ER-MIA 没有作为基线（p.3, §2；p.7, §5.1）。因此“优于既有基线”的范围有限 [推断]。
- **记忆机制覆盖有限**：只测 A-Mem、LangMem、Mem0；没有 MemGPT、MemOS、Zep 等同样在 Related Work 中出现的系统（p.2, §2；p.6, §5.1）[推断]。
- **防御评估过窄**：只测 PPL 过滤与复述；没有测作者自己在 §6 建议的 admission control、provenance、异常检测、检索时验证；因此“defenses have fundamental limitations”是过度概括（p.11, §5.4；p.13, §6）[推断]。
- **真实系统案例缺 ACC**：Hermes 只报告 ISR/ASR，没有良性准确率/延迟；无法判断注入是否损害正常功能（p.11, Table 7）[推断]。
- **超参数缺失**：B、T_max、M、β、γ、δ、K、目标实体类型 c、默认触发器长度均未在正文/附录给出；论文没有实验附录，复现依赖 artifact（pp.5–6, §4.2–4.3；Appendix A/B 检索）[推断]。
- **触发器的自然性**：Fig. 10 的示例触发器 “Vietnam Cerambycidae Cerambycidae” 看起来不自然；虽然 PPL 过滤下仍达 ASR 0.40，但这说明“stealth”主要是对自动过滤的 stealth，不一定能骗过人类审查或更强的语义检测 [推断，p.12, Fig. 10；p.11, Table 5]。
- **共享记忆的信任假设**：共享工作区场景假设攻击者能在频道中发消息；论文没有讨论成员认证、权限、消息来源标注。如果部署方有写入访问控制，这条路径会被限制；但外部资源间接注入仍可绕过 [推断，p.4, §3]。
- **“首个”主张**：无法从文本内部验证；且“optimization-driven + selective extraction”这一细分限定使主张较窄，不能等同于“首个记忆投毒” [推断，p.2, §1；p.3, §2]。

**原文内部不一致 / 数字口径问题（不得当作单一结论证据）**
- **ASR 上限口径**：Abstract 说 “attack success rates up to 0.95”（p.1），但 Table 1 的 RAG Personal 为 0.99（p.7），Table 7 Hermes 有 1.00（p.11）。0.95 可能只指选择性记忆机制（Mem0 Personal 0.95），但摘要没有限定；本文不把“0.95”当作全局最大值，分别引用 0.99（RAG 对照）与 1.00（Hermes，部分后端）。
- **“ASR=1.0 across all k”**：§5.3.2 说 MemPoison 在所有 k 维持 ASR=1.0（p.10, Fig. 8），但 Table 1 选择性记忆最高 ASR 为 0.95（Mem0 Personal）。Fig. 8 是 N_poison=5 的另一配置，二者不必然矛盾，但“by design”措辞过强；本文以 Table 1 为主结果，Fig. 8 只作趋势证据。
- **默认攻击预算**：§5.1 说默认一个 poisoned entry、单轮交互（p.6），§5.3.2 又变化到 N_poison=1–4、Fig. 8 用 5 条（pp.9–10）。原文用 “Unless otherwise specified” 兜底，但没有明确哪些实验覆盖默认值；读者容易把敏感性设置误当主设置。
- **“most tested models”**：§5.5 说 Hermes 上“大多数模型”高 ASR（p.11），但 Table 7 中 GPT-5.4 0.71、Gemini-3.1-pro 0.84、Claude-opus-4.6 0.12，7 个里只有 4 个 ≥0.96；“大多数”是措辞偏乐观。
- **A-Mem Personal ACC**：Table 1 中 Non-Attack 0.91、MemPoison 0.87（p.7），下降 4 个百分点；正文说“largely preserving benign accuracy”（p.8）。总体成立，但该单元格是明显的效用损失，不应忽略。
- **复述防御的基线叙述**：§5.4 说 Naive Concat 与 AgentPoison 几乎被完全抑制（ASR ≤0.04），Table 6 确实如此；但 MINJA 仍有 0.27–0.30 ASR，正文没有讨论这一中间基线（p.11, Table 6）。这是选择性叙述，不是数字矛盾。
- **命名/记号**：Table 3 用 “Claude-Opus4.6”，Table 7 用 “Claude-opus-4.6”；Fig. 8 caption 用 “N = 5”，正文用 “N_poison = 5”；属于排版/记号不统一，不影响结论。
- **抽取层面的错位（非论文错误）**：`pdftotext` 把 Table 1/5/6/7 的行列打散；例如 Table 7 的七个后端在纯文本中被拆成多行，Table 1 的 A-Mem/LangMem/Mem0 区块交错。已用 200/300 dpi 渲染核对，本笔记不采用错位文本中的数字。

- **密码学能防什么、不能防什么（严格区分）**：签名/Merkle/访问控制能防**未授权写入**、提供来源与篡改证据；但 MemPoison 的威胁模型里攻击者没有直接写数据库，poisoned entry 是 Agent 自己的抽取管线“授权”写入的。因此密码学写入认证**不能检测授权写入的恶意内容**，也不能判断一条语义上连贯的医疗建议是否有害。MemPoison 的核心问题是“授权管线写入了攻击者诱导的内容”，不是“未授权第三方篡改”。

## 12. 可检验的研究假设（3–6 条）

- **H1（语义桥是共抽取的必要条件）**：去掉 `T(τ,x)` 后，trigger 与 payload 无法作为同一记忆条目被保留，RSR/ASR 应显著下降。检验：Table 2 的 w/o `T(τ,s_i)` 已给 RSR/ASR=0（p.8）；可进一步直接测量抽取后条目中 trigger 与 payload 的共现率，控制 payload 长度与抽取器。
- **H2（实体伪装提高改写后的触发器存活率）**：在相同嵌入优化下，实体型触发器比非实体触发器在 LLM 改写后保留原始 token 序列的比例更高，ASR 更高。检验：Table 2 的 w/o `L_ent` 与 Fig. 5 的 Non-Entity 对比（pp.8–9）；可加入“逐字保留率/编辑距离”作为中介变量。
- **H3（集中 + 隔离损失共同决定检索精度与良性效用）**：`L_conc` 主要提高 trigger 查询的 RSR，`L_iso` 主要降低良性查询误检索；二者应呈可分离的效应。检验：Table 2 的 w/o `L_conc`/`L_iso`（p.8）与 Fig. 6 的 benign records 曲线（p.9）；可在固定嵌入模型下测量 A–A/A–B/B–B 相似度分布（Fig. 11）。
- **H4（各向异性越强，跨嵌入迁移越强）**：目标嵌入模型的 anisotropy score 与 transfer RSR@1 正相关；混合检索（dense+BM25）会削弱迁移。检验：Fig. 9/Fig. 12 的相关性（pp.10, 13）；可预注册 anisotropy 指标，在更多嵌入模型与 hybrid retriever 上复现。
- **H5（表层过滤不足，语义 admission 更强）**：PPL/复述只能部分抑制 MemPoison；加入语义一致性检查、来源信任或人工审核应显著降低 ASR，但可能带来 ACC/延迟代价。检验：Table 5/6 的现有防御（p.11）作为下界；新增 admission control 或 retrieval-time verification 作为处理组，报告 ASR、ACC、延迟三元组。
- **H6（安全对齐的作用阶段不对称）**：同一 LLM 作为“记忆写入判定器”时比作为“响应生成器”时更能抑制攻击。检验：Table 3 的 Claude ASR 0.88（仅生成）vs Table 7 的 0.12（同时写入）（pp.9, 11）；可在同一 backbone 上做 2×2 切换实验（写入/生成角色分离），控制 memory mechanism 与 payload。
