## 1. 150–300 字中文概述

本文是大规模在野网页提示注入测量。作者从 Common Crawl 2025-10 快照的 1.2B URL、24.8M 主机中，用 3,963 个指示词匹配出 31,206 个候选，再经半自动人工验证确认 15,387 个注入，分布于 11,722 页、2,042 主机，并以 Censys/Shodan 补充。54 个模板覆盖 95%；80.6% 来自第一方站点运营者，17.6% 来自第三方平台内容，1.8% 来自用户；70% 位于 HTTP header、注释、结构化数据等天然不可见通道，87% 总体不可见；65% 的已归档基线页面在 12 个月前已含注入。效果评估为 100 prompt × 4 种页面表示 × 13 模型 = 5,200 次网页摘要实验：plain text 最高 8%（小模型），HTML/raw 降至 0.2%–1.1%，但 HTML/raw 错误率分别为 20.3%/25.8%，低有效率不能解释为鲁棒。论文是测量与表征研究，不含形式化安全定义或密码机制（数据页：pp.2–11；详见 §13）。

## 2. 研究背景、现有方法不足、精确定义的问题

- **背景。** LLM web agent 把开发者指令与从 Web 检索的不可信内容放进同一自然语言上下文，执行浏览、搜索、抽取、客服、HR 筛选等任务（p.2, §2.1）。站点侧传统的 robots.txt 偏好不保证被 LLM agent 遵守，dark patterns 与 cloaking 也被用来干扰自动访问（p.1, §1；p.12, §9）。
- **现有工作的不足。** 作者把缺口概括为：已有提示注入研究主要在受控或 benchmark 环境中证明“能否成功”，尚未回答站点与内容所有者是否已经在页面中部署 prompt-like 指令（p.1, §1）。工业报告（Google 对 Common Crawl 的分析、Palo Alto Networks 的遥测）描述了案例，但作者称其未给出公开 Web 的定量 prevalence 或对 objectives、structure、targets、delivery mechanisms 的系统表征（p.12, §9）。
- **方法上的取舍。** 作者考虑过 ML 检测与全文 perplexity 检测，但在 1.2B 页规模上计算不可行，因此改用 keyword indicator 过滤 + 人工验证（p.3, §3.1）。这决定了其结果的性质：precision-oriented、对已知文本模式的 lower bound，而不是对全部注入的无偏估计（p.12, §10.1）。
- **精确定义的问题。** 五个 RQ：(1) prevalence 与模板、引入者；(2) objectives、targets、techniques 与威胁模型；(3) inclusion（位置、嵌入方式、可见性）；(4) distribution（生命周期、内容类别、站点流行度）；(5) effectiveness（不同页面表示下对 LLM 的影响）（p.2, §2.2）。
- **关键定义。** “LLM web agent”是“以 Web 作为任务执行一部分、把开发者指令与不可信 Web 内容组合起来的 LLM 系统”（p.2, §2.1）。“Indirect prompt injection”是“LLM 被诱导遵循嵌入在不可信外部内容中的指令”；漏洞根源是开发者指令与第三方数据被组合进单一自然语言上下文，缺少可靠的 instruction/data 边界（p.2, §2.1）。这两个定义是操作性的，不是形式化定义。
- **概念重构。** 论文把 in-page prompt injection 描述为多利益相关者现象：既有 offensive（disruption、reputation、exfiltration），也有 defensive（data protection、AI bot identification），还有 underspecified 的 generic override（p.6, §5.2；p.7, §5.3）。因此“攻击者”不是单一角色，部分注入是站点运营者的访问控制/威慑手段。这一点对威胁模型与“来源认证能否缓解”的判断很关键（见 §4、§11）。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- **组件。** (a) 开发者/系统指令；(b) 用户任务；(c) Web 内容：HTTP response headers、response body（HTML 元素、注释、结构化数据、metadata）、site-level 资源（sitemap.xml、security.txt）；(d) LLM；(e) 可选的浏览器/工具/动作接口（p.2, §2.1；p.8, §6.1–6.2）。论文的测量对象是 (a)+(b)+(c)→(d) 这一 ingestion/interpretation 子链路。
- **交互流程（论文评估的版本）。** 取一个页面 → 序列化为四种表示之一（plain text、HTML、raw response、Playwright snapshot）→ 与摘要任务指令拼接 → LLM 输出摘要。没有工具调用、没有多步浏览、没有记忆、没有动作执行（p.10, §8；p.12, §10.1）。
- **真实 agent 的流程（论文只作背景）。** 真实 web agent 还会导航页面、选择工具、基于内容做决策；恶意内容因此可能不只是偏置回答，还可能触发 unintended actions 或泄露敏感上下文（p.2, §2.1）。但论文明确说其实验“不评估 end-to-end web agents”，只隔离“网页内容的 ingestion 与 interpretation”这一共同组件（p.10, §8）。
- **信任边界。** 开发者指令被视为 trusted；Web 内容被视为 untrusted；二者在同一自然语言上下文中拼接，缺少可靠的边界保持机制（p.2, §2.1）。页面内容的来源被分为 first-party（站点运营者）、third-party platform content（如招聘帖子、市场 listing）、user interactions（评论、论坛、社交媒体）（p.4, §4）。这是描述性的 provenance 分类，不是密码学来源认证；论文没有给出任何完整性/认证机制来强制这个边界。
- **目标 agent 类别。** Table 3 列出 Data Scraping Agent (DS)、Search Engine Agent (SE)、Customer Support Agent (CS)、HR Screening Agent (HR)、Task Executor Agent (TE)；作者根据 prompt 语义推断其目标类别（p.6, Table 3；p.7, §5.3）。这些是“被针对的类别”假设，不是实际部署中被攻击的 agent 实例。
- **评估系统与真实系统的差距。** 评估中的“agent”是一个执行网页摘要的 LLM，不是带工具/动作的 agent；因此本文的系统模型只能说明“注入内容能影响模型的网页理解”，不能说明“能劫持真实 agent 的动作”。这是解读所有 effectiveness 数字的前提（p.10, §8；p.12, §10.1）。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

**资产（按论文的风险叙述归纳）：**
- Agent 任务与输出的完整性：模型是否按用户任务总结，还是被页面指令改写（p.10, §8）。
- 内容所有者对自动访问/复用/索引的控制权：版权、个人信息、反爬、AI bot 检测（p.6, §5.2；p.7, §5.3）。
- Agent 上下文中的用户数据、内部 API、事务系统：客服 agent 靠近后端，即使低 prevalence 也可能高影响（p.7, §5.3）。
- 声誉与下游可见性：搜索/摘要管道中的实体、产品、来源排序（p.6, §5.2）。
- 模型上下文窗口/可用性：garbage injection 用随机串、重复废话、超长文本耗尽上下文（p.6, §5.2）。
- 系统 prompt/API key 等秘密：Data Exfiltration 仅 13 例，但包含 reveal system prompt、leak secrets（p.6, Table 3）。

**目标（Table 3, p.6；含 offensive/defensive/underspecified，故“攻击者”应理解为内容投放者，而非单一恶意角色）：**
- Offensive：System Disruption or Degradation 8,894（其中 Garbage Injection 8,469）、Reputation Manipulation 1,521（content promotion 1,040、citation forcing 542、positive review 502、SEO backlink 346、job candidate 48）、Data Exfiltration 13（reveal system prompt 9、leak secrets 4）。
- Defensive：Data Protection 4,093（personal information 2,141、copyright 2,051、social media bots 151）、AI Bot Identification 3,096（challenge-response 2,499、honeypot 598）。
- Underspecified：Generic Content Override 2,632。
- 这些类别是多标签人工编码；子类数字不能简单相加当作父类分解（见 §9 的内部不一致）。

**投放能力（按角色；不预设恶意）：**
- First-party 站点运营者：完全控制 HTTP response headers 与 body，可插入自定义 header（X-AI、X-LLM 等）、HTML、注释、结构化数据、metadata，并用 CSS 隐藏；可针对 “if you are an LLM” 之类条件措辞。论文测得 9,731/12,075（80.6%）的 Common Crawl 注入来自 first-party，其中 5,408（55.5%）经 HTTP headers（p.4, §4）。
- Third-party 内容所有者：控制平台上的 listing/Job posting 等内容，2,124/12,075（17.6%），2,058 页、25 主机（p.4, §4）。
- 用户：控制评论、论坛、社交媒体内容，220/12,075（1.8%），127 页、81 主机（p.4, §4）。
- 投放者不需要访问 agent、模型参数或防御；只需要其内容被 agent ingestion。测量的是已部署的静态 prompt，不是自适应、多轮、可查询的攻击（p.10, §8；p.12, §10.1）。

**前提假设：**
- Agent 会把 Web 内容放进与开发者指令相同的上下文；没有可靠的 instruction/data 分离（p.2, §2.1）。
- 隐藏内容（header、注释、CSS 隐藏元素、结构化数据）可能被 agent 的处理管线读取；论文的四种表示正是为了测试这一点（p.10, §8）。
- 页面可被 crawler 发现；但论文承认 agent-targeted cloaking 会让测量漏掉只对 AI 投放的注入（p.12, §10.1）。
- 评估是一次性、静态 prompt、单页摘要；没有自适应攻击、没有多轮交互、没有工具动作、没有防御（p.10, §8；p.12, §10.1）。
- 模型可能遵循内容中的指令；effectiveness 是“是否遵循注入指令而非摘要任务”的人工判定（p.10, §8）。

**威胁模型的关键特殊性。** [推断] 传统间接提示注入假设“第三方内容不可信、开发者指令可信”。本文的数据显示 80.6% 的注入来自 first-party（站点运营者本身），因此“合法来源”就是注入者；这使“来源认证/签名”只能证明“谁写了这段内容”，不能证明“这段指令被用户/开发者授权”。这一点在 §11 展开。

## 5. 核心方案（方法、攻击/防御流程、关键定义）

**5.1 数据收集与候选挖掘（p.3, §3–3.1）**
- Common Crawl：使用 2025-10 的 CC-MAIN-2025-43 子集；50 个 worker 按 WARC 文件序号 round-robin（worker i 处理 i, i+50, i+100, …），每个 worker 上限 25M URL；最终约半个 corpus，1.2B unique URL、24,834,442 hosts、约 200 TiB 未压缩内容；耗时约四周（p.3, §3）。
- Censys/Shodan：作为补充发现源，检索匹配至少一个 indicator 的快照，共 3,346 个候选（p.3, §3）。
- Indicator：从先前工作、博客、行业报告、公开攻击演示中人工收集 seed，再对 keyword 组件做变体替换；去重后 3,963 个 indicator（p.3, §3.1）。
- 匹配：Aho–Corasick 多模式匹配，线性于输入；Censys/Shodan 用其搜索 API；共 31,206 个候选（CC 27,860、Censys 2,805、Shodan 541）（p.3, §3.1；p.3, Table 1）。

**5.2 验证（p.3–4, §3.2）**
- 每个 match 提取：indicator、1000 字符上下文、source location（header/body）、syntactic container（HTML 元素、meta、JSON-LD、注释等）（p.3, §3.2）。
- 分组：按 exact indicator、normalized context、match position、inclusion method 分组，以便对候选家族联合验证（p.3, §3.2）。
- 规则：(1) header matches 保守地直接视为 true positive；(2) 对剩余候选人工检查 1,000 个 grouped instances，识别 tutorial、源码示例、CSS/JS 注释、`<code>`/`<pre>` 等 benign 类；(3) group-level labeling（相同 HTML 标签、URL 参数、Chrome Topics 主题的 prompt 赋同一标签）；(4) representative page review（按 domain/topic 抽代表页在浏览器中检查）；(5) priority review（display:none、近零字号、低对比度、“if you are an LLM” 等）；(6) instance-level review（剩余未解决候选逐条判断是否“对自动模型/agent 的指令”而非描述/引用/解释）（p.4, §3.2）。
- 两名 reviewer 在不相交分区上工作；每个 reviewer 随机抽 200 条交叉验证；分歧讨论至共识；31,206 个候选中确认 15,387 个（p.4, §3.2）。

**5.3 下游分析（p.4–5, §3.3；p.5, §4–5.1）**
- Lexical template：HTML decode、lowercase、去标点、空白归一化、数字/字母数字替换为 `<INT>`/`<RAND>`；token set；token-overlap 相似度超过 τ=0.75 归为同一模板；15.3K prompt → 363 个模板；54 个（14.8%）覆盖 95%；最大模板 3,504 个注入、2,722 页；144 个模板只出现一次（p.5, §4；p.5, Figure 1；p.4, Table 2）。
- Objectives/targets：all-MiniLM-L6-v2 编码 + DBSCAN（cosine，eps=0.4）聚类；两名研究者独立标注，允许 one-or-more objective/target 多标签；类别从数据归纳，迭代细化；每 reviewer 200 条交叉验证（p.5, §5.1）。
- Techniques：把每种 technique 写成 NLI hypothesis，用 facebook/bart-large-mnli 计算 entailment，概率 > τ=0.7 判为存在；technique 集合来自先前工作 [16,53]；所有标签人工复核（p.5, §5.1）。八种 technique：Authority Pressure (AuP)、Conditional Targeting (CondT)、Content Injection (ContI)、Output Constraint (OutC)、Identity Rewrite (IdRw)、Jailbreak (Jail)、Role Play (Role)、Task Override (TO)（p.6, Table 3 表注）。
- Inclusion/visibility：surface（header/body/site-level）+ mechanism（custom header、HTML element、comment、metadata、structured data）；对 HTML 注入用 headless Chrome + Playwright + CDP，等待 30 秒客户端渲染，定位 DOM 元素，检查 CSS display/visibility、尺寸、clip、font-size、contrast、opacity、offscreen、viewport、occlusion、z-index 等（p.8, §6.1；p.8, Table 4）。非渲染通道（header、comment、structured data、metadata）按构造视为 non-visible（p.8, §6.1）。
- Ecosystem：Internet Archive 取 3/6/12 个月前的最近快照（最大一周偏差），每个时间点最多重试五次；Tranco ZWZ5G（2026-02）；Chrome Topics API 推断主题（p.9–10, §7.1–7.2）。
- Effectiveness：去重 prompt，随机选 100 个，每个唯一 prompt 随机选一页；同一 100 个样本用于所有模型和表示；四种表示 × 13 模型 = 5,200 次运行；人工检查是否遵循注入指令、是否显式识别注入（p.10, §8.1）。

**5.4 关键定义（操作性）**
- “Validated prompt injection”：indicator match 经上下文/渲染/语义检查后，被判定为“对自动模型或 agent 的指令”，而非教程、引用、源码示例或新闻讨论（p.4, §3.2）。
- “Lexical template”：归一化后 token-overlap 相似度 >0.75 的 prompt 家族（p.5, §4）。
- “Non-visible by construction”：header、comment、structured data、metadata-only 等浏览器不渲染的通道（p.8, §6.1）。
- “Non-visible（rendering）”：HTML 元素经 CSS 隐藏/遮挡/移出视口等（p.8, Table 4；p.9, §6.4）。
- “Effectiveness”：模型遵循注入指令而不是执行摘要任务（人工判定）；“Detection”：模型显式指出存在 prompt injection（p.10, §8.1）。
- 这些定义都是操作性的，不是形式化安全定义；没有攻击游戏、没有 advantage、没有 theorem。

**5.5 攻击/防御流程**
- 攻击流程（论文测量的现象）：内容所有者/用户把指令嵌入 header 或页面 → 服务器返回给 crawler/agent → agent 序列化为某种表示 → LLM 把指令当任务覆盖 → 输出被污染/任务被劫持。论文不构造新攻击，只测量已部署的 prompt。
- 防御流程：论文没有实现或评估防御。它只给出建议：优先检测/抵抗 task override 模式、检查 early-ingestion 与 non-visible 内容、利用 X-AI 类 header/HTML 结构/可见性作为检测信号、针对 54 个模板家族（p.12, §10.2；p.15, §C.1）。这些是假设性建议，不是经实验验证的防御。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- **形式化程度：无。** 全文没有形式化安全定义、攻击游戏、构造、定理、归约或密码学原语。§2.1 的 LLM web agent 与 indirect prompt injection 是自然语言定义；§5 的 objective/target/technique 是人工编码类别；§8 的 effectiveness/detection 是人工判定。文中出现 “formalized/formalizing” 仅在 Related Work 引用他人工作时（p.11, §9），不是本文的贡献。
- **指标。**
  - Prevalence：validated instances、pages、hosts、templates；以 Common Crawl 为 primary，Censys/Shodan 为补充（p.3, Table 1）。
  - Structure：template 数量、top-k 覆盖率、最大模板计数（p.5, §4）。
  - Objectives/targets：六类 objective、五类 target 的人工多标签计数（p.6, Table 3）。
  - Inclusion：surface/mechanism 计数、non-visible 比例（p.8–9, §6；Table 5/6）。
  - Persistence：3/6/12 个月前快照中仍含注入的页面比例（p.9, Table 7）。
  - Effectiveness：followed injection / total trials；Error：context/format 失败；Detection：显式识别注入（p.10, Table 8；p.11, Figure 2）。
- **经验主张（作者明确或隐含）。**
  - 15,387 个 validated injections 是从 1.2B URL 中得到的“web-scale dataset”；作者称这是首个 in-the-wild web-scale prompt injection dataset（p.2, §1；p.14, Appendix A）。
  - 54 个模板覆盖 95%，说明高度结构化、可复用（p.5, §4）。
  - 80.6% first-party、17.6% third-party、1.8% user，说明多利益相关者生态（p.4, §4）。
  - 70% 非可见（by construction）、87% 总体非可见（p.9, §6.4）。
  - 65% 的页面在 12 个月前已含注入，说明持久性高（p.9, Table 7；p.10, §7.1）。
  - plain text 最高 8%（小模型）、HTML/raw 0.2%–1.1%，说明“flattening amplifies susceptibility”（p.11, §8.2；p.12, §10.2）。
- **声明强度。** 这些是经验关联/测量结果，不是安全保证。论文自己把 prevalence 定位为“precision-oriented lower bound”（p.12, §10.1），把 effectiveness 定位为“controlled webpage summarization setting rather than end-to-end web agent compromise”（p.10, §8）。没有置信区间、显著性检验、inter-annotator agreement 统计或因果识别；因此不能把 8%、65%、87% 当作精确的总体参数。
- **“Detection ≠ resistance”。** 论文报告 6 个案例：模型显式识别了恶意指令但仍遵循（例如切换德语、采用注入风格、在警告页面内容的同时返回请求输出）（p.11, §8.2.2）。这是论文最重要的安全语义观察之一：检测率不是防御成功率。

## 7. 实验设置与主要结果（agents、场景、指标、关键数字、消融）

**7.1 测量语料（p.3, Table 1；p.4, §4）**
- 输入：1.2B URLs、24,834,442 hosts；31,206 candidates（CC 27,860、Censys 2,805、Shodan 541）。
- **数据来源与执行边界（关键）。** 发现阶段使用 Common Crawl WARC（2025-10 快照的约半个 corpus，50 workers，每 worker ≤25M URL）与 Censys/Shodan 搜索 API；不向任何站点注入内容。验证/可见性阶段对已识别页面做 headless/headful Chrome 加载（2026-01，3.2K HTML 注入子集），属于观察性页面访问；effectiveness 阶段把已保存的页面表示送给 13 个 LLM 做网页摘要，不驱动真实 web agent、不执行工具动作、不访问注入指令指定的外部 endpoint（p.3, §3；p.8–9, §6；p.10, §8）。因此“真实站点是否被执行”的准确答案是：页面被渲染/观察过，但没有被攻击或注入；agent 动作没有被执行。
- 验证结果：15,387 injections、11,722 pages、2,042 hosts、363 templates。
  - Common Crawl：12,075 injections、9,676 pages、285 hosts、283 templates。
  - Censys：2,771 injections、1,868 pages、1,700 hosts、99 templates。
  - Shodan：541 injections、178 pages、155 hosts、18 templates。
- Provenance（Common Crawl）：first-party 9,731（80.6%）、7,491 pages、179 hosts；third-party content owner 2,124（17.6%）、2,058 pages、25 hosts；user interactions 220（1.8%）、127 pages、81 hosts（p.4, §4）。全数据集口径：78.4% first-party、20.1% third-party、1.4% user（p.5, §4）。
- 头部模板（Table 2, p.4）：T1 3,504/2,722/373；T2 1,463/1,463/2；T3 1,181/1,025/5；T4 1,023/1,019/1,018；T5 998/856/12；T6 550/548/1；T7 541/540/1；T8 458/458/1；T9 1,262/359/1；T10 326/319/15（格式为 injections/pages/hosts）。

**7.2 目标与手法（p.6, Table 3）**
- 六类 objective：System Disruption 8,894、Reputation 1,521、Data Exfiltration 13、Data Protection 4,093、AI Bot Identification 3,096、Generic Content Override 2,632。
- 约 99% 的注入含 Task Override；43% 含 Jailbreak framing（p.2, Abstract；p.7, §5.4）。这两个比例是作者报告值；由于 Table 3 的 technique 列是多标签，无法从表中简单求和复算（见 §9）。
- 目标类别：crawler/data scraper 是主导目标；search/summarization 次之；HR 与 customer support 是更窄但更高风险的类别（p.7, §5.3）。这些目标标签由 prompt 语义人工推断，不是实际 agent 行为观测。

**7.3 嵌入与可见性（p.8–9, §6）**
- Surface：HTTP headers 7,887（6,444 pages、1,648 hosts，Table 5）；body 7,216（5,325 pages、403 hosts，正文）或 7,500（Table 5 类目和）；site-level 284 个注入、13 个 site（原文标 ~0.6%，分母未明）（p.8, §6.2；p.8, Table 5）。正文与表的具体差异见 §9。
- Mechanism：custom headers（X-AI 6,535、X-LLM 1,022 等）、HTML 元素（`<div>` 2,851、`<p>` 1,105 等）、structured data（1,996，主要是 JSON-LD）、metadata（`<meta>` 213、`<title>` 8）、comments（HTML 356、JS 318、XML 1）（p.8, §6.3；p.8, Table 5）。
- Visibility：10,779（70.0%）属于 non-visible by construction；HTML 元素 4,608 中 2,703（58.6%）经渲染隐藏、236（5.1%）可见、86 个注入（37 页）所在页不可达、1,583（34%）prompt 已移除；总 non-visible 13,483（87.6%）（p.9, §6.4；p.9, Table 6）。
- 隐藏手法：color/contrast 2,397、occlusion 1,860、viewport 1,802、text size 1,358、zero-size 851、display:none 281、clipping 108、opacity 20、off-screen 20、z-index 29（p.8, Table 4；p.9, §6.4）。多种手法常共现。

**7.4 持久性与生态（p.9–10, §7）**
- Internet Archive：基线为 2025-10 的 9,676 个 CC 页面；3/6/12 个月前分别有 93.1%/77.3%/65.8% 的已归档页面仍含注入；归档页面获取率 89%–95%，网络超时 ≤1.0%（p.9, Table 7；p.10, §7.1）。
- 站点流行度：top-ranked（≤10K）注入率较低，100K 以上升高，集中在 100K–1M；job listings、web hosting、shopping、phone service 等在低/中 rank 也偏高；Banking、Air Travel 偏低（p.10, §7.2）。这些趋势的图（Figures 6、8）在 [58]，本 PDF 不含，无法核对。

**7.5 有效性实验（p.10–11, §8）**
- 设置：网页摘要任务；100 个去重 prompt（每个唯一 prompt 一页，所有模型/表示共享）；四种表示：plain text（BeautifulSoup4）、HTML（保留 tags/attrs/scripts/comments）、raw response（含 headers/metadata）、snapshot（Playwright SnapshotForAI）；13 个模型；5,200 runs（100×4×13）；人工检查 compliance 与 detection（p.10, §8.1）。
- 模型：Table 9 列出 13 个（LFM-2 2.6B、Qwen 3.5 0.8B、Llama 3.1 8B、Qwen 3.5 9B、Step-3.5 Flash 11B、Mistral Small 24B、Qwen 3.5 27B、Qwen 3.5 35B、GPT-OSS 120B、DeepSeek V3.2、Llama 3.1 70B、Seed 2.0 Mini、GPT-5.4）（p.15, Table 9）。按渲染页分组为 Small 3（LFM-2 2.6B、Qwen 3.5 0.8B、Llama 3.1 8B）、Medium 5（Qwen 3.5 9B、Step-3.5 Flash 11B、Mistral Small 24B、Qwen 3.5 27B、Qwen 3.5 35B）、Large 3、Closed 2；与 Table 8 的 1,200/2,000/1,200/800 一致。8B 的 Llama 3.1 归 Small，“Medium (8B–70B)” 标签在 8B 边界上略含糊；文本流容易误读。
- 主结果：plain text 全体 3.9%；small 在 text 上 8.0%；HTML/snapshot 1.1%；raw 0.2%（p.10–11, §8.2；p.11, Figure 2）。Small 总体 4.2%、large 1.2%、medium 0.6%、closed 0.6%（p.10, Table 8）。
- Error：text 0.7%、HTML 20.3%、raw 25.8%、snapshot 3.5%（p.11, §8.2.1）。作者归因于 context window：HTML/raw 更长，超过部分模型容量；因此 HTML/raw 的低 effectiveness 不能被解释为更好的注入抵抗（p.11, §8.2.1）。
- Detection：small 4.8%、medium 20.7%、large 13.8%、closed 25.1%（p.10, Table 8；p.11, §8.2.2）。有 6 个“识别但仍遵循”的案例（p.11, §8.2.2）。
- 消融：仅做了 page representation 与 model size 两个维度的比较；没有对 objective、channel、template、visibility、defense 的分层消融，也没有重复运行/温度/置信区间。作者称趋势在模型类别与表示间一致，但没有给出统计检验（p.10, §8.1）。

**7.6 数值可信度**
- 可靠：Table 1 的总数、Table 6 的可见性分解（除 off-by-one）、Table 7 的持久性、Table 8 的 effectiveness/error/detection 行内算术。
- 不可直接当证据：§6.2 的 header/body 计数与 Table 5 不一致；Table 3 的子类因多标签不可加总（口径未说明）；§10.2 的“87% 中 70%”与 Table 6 不符。详见 §9。Table 8/9 的分组经渲染页核对为 3/5/3/2，与 trials 一致；文本提取的错位不构成数字矛盾。

## 8. 贡献与创新点（按原文主张）

作者在 p.2 列出五点贡献：
1. **首个 web-scale in-the-wild prompt injection 数据集**：15.3K validated instances，来自 1.2B URLs、24.8M hosts（p.2, §1）。这是作者的主张；“first”限定为学术界首个 web-scale in-page measurement，论文同时承认 Google/Palo Alto 的并行工业报告（p.12, §9），所以不是“首个发现该现象”。
2. **证明 prompt injection 已大规模部署且高度结构化**：54 个模板覆盖 95%（p.2, §1；p.5, §4）。
3. **刻画生态系统**：offensive/defensive objectives、target agents、temporal persistence、deployment strategies，揭示多利益相关者格局（p.2, §1；p.6–10）。
4. **证明注入主要是隐藏的、位于 early ingestion 通道**：70% 非可见 by construction、87% 总体非可见、53% 在 headers 或 early HTML（p.2, §1；p.9, §6.4；p.12, §10.2）。
5. **评估真实世界有效性**：5,200 trials、13 models、4 page representations（p.2, §1；p.10–11, §8）。

方法与概念层面的附加贡献（按原文叙述归纳）：
- 可复用的 web-scale indicator + Aho–Corasick + 半自动人工验证 pipeline（p.3–4, §3）。
-  provenance 分类（first-party/third-party/user）与 host-level vs page-level prevalence 的解释框架（p.4, §4）。
-  visibility 分类与 DOM/CSS 隐藏手法测量（p.8–9, §6）。
-  “detection is not resistance” 的定性证据（p.11, §8.2.2）。
-  sanitized dataset 与 labels/scripts 的开放（Appendix A, p.14）。

创新点边界：
- 不是新的攻击构造；不是新的防御系统；不是形式化模型。它的创新在测量对象（in-page、in-the-wild）、规模（1.2B URLs）、多维度表征（prevalence/objectives/inclusion/persistence/effectiveness）和 provenance 视角。
- “first” 与 “widespread” 都需要限定：前者是作者主张，后者在 host 覆盖上高度集中（285 个 CC hosts / 24.8M），见 §9。

## 9. 局限、失败案例、作者承认的不足（区分作者承认 vs 你的推断）

### 9.1 作者明确承认的局限
- **覆盖偏差**：Common Crawl 可能低估 authenticated/platform-restricted 内容（如社交媒体 feed），而这些正是个性化 agent（客服等）常工作的场景（p.12, §10.1）。
- **Agent-targeted cloaking**：恶意站点可以只对特定 AI agent 投放注入、对普通 crawler/用户提供良性内容；Common Crawl 捕获不到（p.12, §10.1）。
- **检测偏差**：indicator-based、text-only，可能漏掉 implicit、obfuscated、non-English、unseen、multimodal（截图）注入；结果是 precision-oriented lower bound，不是 exhaustive enumeration（p.12, §10.1）。
- **有效性外推**：只做 one-off webpage summarization，不是 end-to-end web agent；其他任务、复杂 workflow、专门页面管线、更长交互可能不同；只测“是否影响模型输出”，不测“是否影响后续工具动作”（p.12, §10.1）。
- **可见性分析的样本与歧义**：只分析 2026-01 仍可达的 3.2K HTML 注入页面；~1.1% 页面超时；~34% prompt 已不存在，可能是内容变化，也可能是对自动浏览器的替代渲染；用 headful browser 人工复核（p.9, §6.4）。
- **持久性检索**：Internet Archive 获取率 89–95%，≤1.0% 超时；缺失页面主要是新/短命内容（p.10, §7.1）。
- **无协调性结论**：数据只显示规律性（54 模板、65% 持续 12 个月），不证明 institutionalization 或 coordination（p.15, §C.2）。

### 9.2 我的推断（明确标注为 [推断]）
- **“Widespread” 的高度集中性。** [推断] 绝对计数很大，但 Common Crawl 的 12,075 个注入集中在 285 个 hosts（9,676 页），285/24.8M ≈ 0.0011%；54 个模板覆盖 95%。这更像少数运营者/平台/模板家族的集中现象，而不是全 Web 均匀分布。论文的 host-level vs page-level 讨论部分回应了这一点（p.4, §4），但摘要的 “widespread” 容易被误读。
- **抽样不是概率样本。** [推断] Common Crawl 只处理了 2025-10 的约半个 corpus，按 WARC 文件序号分配，不是随机抽样；Censys/Shodan 是 IP 扫描源，偏向 internet-facing 服务。论文没有给 sampling weights、置信区间或跨源去重细节，因此 15,387 是 convenience corpus 的计数，不是公共 Web 的无偏 prevalence 估计。
- **验证的精度/召回未量化。** [推断] header matches 被直接当作 true positive（p.4, §3.2），可能纳入安全产品/蜜罐/非恶意自定义 header；group-level labeling 和 representative page review 可能传播错误；只有每 reviewer 200 条交叉验证，未报告 Cohen's kappa 或 disagreements rate。49.3% 的候选确认率（50.7% 被拒）说明人工验证有实质作用，但不能当作 Web 上的 precision。
- **有效性样本的混杂。** [推断] 100 个 prompt、每个唯一 prompt 一页、所有模型/表示共享；没有按 channel/objective/template 分层。Header 注入只会在 raw response 中出现，plain text/HTML body 抽取可能看不到；CSS 隐藏/注释/structured data 在不同表示中的保留程度也不同。因此 “plain text 更易被注入” 可能部分反映“哪些注入能在该表示中存活”，而不是单纯的模型脆弱性。论文没有报告这 100 个样本的 channel 分布，这是解释 Figure 2 的关键缺口。
- **单次运行、无统计不确定性。** [推断] 5,200 = 100×4×13，每个 (prompt, model, representation) 只跑一次；没有重复、温度/seed 控制、置信区间或混合效应模型。8% 是 100 个 prompt 上的点估计，抽样误差很宽；“small 8.0% vs others 2.4–3.4%” 的排序未必稳定。
- **误差与有效性的混淆。** [推断] HTML/raw 的 error 率 20.3%/25.8% 远高于 text 0.7%；effectiveness 的分母包含这些失败。作者明确提醒“低 effectiveness 不等于鲁棒”（p.11, §8.2.1），但摘要中的 0.2%–1.1% 仍可能被误读为“结构线索使模型更安全”。
- **目标标签是推断而非观测。** [推断] Table 3 的 target agents 是根据 prompt 语义人工编码的“意图目标”，不是实际部署中观测到的 agent 类型；HR/customer support 的结论基于 48/157 等小样本，不能当作因果证据。
- **防御建议未经评估。** [推断] §10.2/§C.1 建议检测 override、检查 early/non-visible 内容、利用 X-AI header/HTML 结构/visibility 信号、针对 54 个模板；论文没有实现或测量这些防御的 TPR/FPR、对抗自适应或对 benign 页面的代价。它们是研究议程，不是已验证的缓解措施。
- **时间有效性。** [推断] 数据快照是 2025-10；论文 2026 年发表，且引用 Google 报告称 2025-11 至 2026-02 恶意注入增加 32%（p.12, §9）。因此本文的 prevalence 可能已低估当前状态；论文没有讨论自身快照的时间偏差。
- **“Defensive injection” 的规范性。** [推断] 把版权/反爬/AI bot 检测等 defensive prompt 计入 “prompt injection”，扩大了 “attack” 的外延；这在生态学上有意义，但在安全分类上会把“站点访问控制”与“攻击者劫持”混在一起。论文承认 multi-stakeholder（p.2, p.7），但摘要的 “attacks” 措辞仍偏向 offensive 解读。

### 9.4 失败案例与负面结果
- 31,206 candidates 中仅 15,387 确认（49.3%），说明大量 indicator match 是 benign（教程、源码、新闻讨论）；论文用人工验证处理，但没有报告 false negative（p.4, §3.2）。
- 144 个模板只出现一次，长尾显著；54 个模板覆盖 95% 的结论是“头部集中”，不是“全部可枚举”（p.5, §4）。

- 6 个案例模型识别了注入但仍遵循；detection 不是 resistance（p.11, §8.2.2）。
- HTML/raw 的 error 率 20.3%/25.8%，说明“低 effectiveness”很大程度是模型失败/上下文溢出，而不是安全拒绝（p.11, §8.2.1）。

## 11. 与应用密码学/密码工程可能的技术联系（严格；没有就写“无”）

**直接联系：无。** 论文没有使用或评估 OAuth、TLS、签名、VC、TEE、zk、C2PA、HTTP Message Signatures 等任何密码工程机制；它测量的是页面内容中的自然语言指令对 LLM 的影响。**A_crypto = 1/5** 仅表示“可作为应用密码学的讨论背景”，不表示论文使用了任何密码机制；若按“论文实际评估的密码机制”计，则为 **0/5**。

以下是严格标注为 [推断] 的可能技术联系，不是论文的结论：

- **内容来源签名/来源认证能缓解“合法页面被注入”吗？** 只能部分、且不能解决核心问题。
  - 论文的数据：80.6% 的 Common Crawl 注入来自 first-party（站点运营者），17.6% 来自 third-party 平台内容，1.8% 来自用户（p.4, §4）；54.5% 的页面有 header-based 注入（p.8, §6.2）。First-party 注入由合法源服务器发出，TLS 只证明“连接的是该域”，C2PA/内容签名只证明“内容由该发布者签发/未被篡改”；它们都不证明“该指令被用户/开发者授权”，也不区分“合法发布者的恶意/防御性指令”与“合法内容”。签名越完整，越是在证明“这个注入确实来自站点运营者”。
  - 对 third-party/user 内容（合计 19.4%），细粒度签名/VC 可以帮助归因、建立发布者信誉、做 allowlist/denylist，但持有有效密钥的恶意贡献者仍可签名注入；签名证明作者身份与完整性，不证明语义安全。
  - 签名粒度很重要：对 whole response 签名会覆盖 header/comment/structured data 等隐藏注入；只对“可见 DOM”做 attestation 可能过滤掉 87% 非可见注入，但也会排除合法的机器可读结构化数据（JSON-LD、OpenGraph）和 SEO 内容，且仍有 236 个可见注入与 first-party 可见指令。论文没有评估这种 trade-off。
  - 更合适的密码学框架是 **instruction provenance/authorization**：用签名/能力令牌/策略证明“哪条指令由哪个 principal 为哪个 task/agent 授权”，并把 Web 内容严格限制为 data。这不是 content provenance；论文没有提出或测试，但它的 first-party 数据说明了为什么 content provenance 不够。
- **RFC 9309 robots.txt / 访问偏好机制**：论文指出 robots.txt 是 convention，LLM agent 不一定遵守；它在 §C.2 提出需要“non-adversarial, machine-readable, enforceable” 的访问偏好机制，并问 RFC 9309 是否足够（p.15, §C.2）。这是策略/协议工程问题；若要密码化，可考虑签名策略分发、透明日志、发布者凭证，但论文没有做。不要因为出现 “enforceable/standard” 就把它抬成密码学贡献。
- **TEE/attestation**：可以证明 agent runtime 的代码/配置完整性，但不能判断网页自然语言指令的意图；对本文的语义注入问题没有直接帮助。论文没有讨论。
- **zk/VC**：没有使用场景；可以用 VC 证明发布者属性/授权范围，但仍需一个“指令是否被允许”的策略层；论文没有涉及。

**结论。** 内容来源签名/来源认证是“必要但不充分”的工程组件：它能把“来源是否真实”与“指令是否被授权”分开，但不能单独缓解 first-party 合法页面注入；对 third-party/user 内容可辅助归因与过滤。论文本身没有评估任何此类机制，其建议方向是检测（override 模式、visibility、template families）与更可执行的访问偏好，而不是密码学。

## 12. 可检验的研究假设（3–6 条）

- **H1（隐藏通道过滤的收益与盲区）。** 在相同的 100 个 prompt 上，若在 ingestion 前移除 header/comment/structured-data/metadata 等 non-visible-by-construction 内容，plain-text 摘要的 attack effectiveness 会显著下降；但该过滤对 236 个 visible HTML 注入无效。操作化：2×2（过滤/不过滤 × 表示）重复实验，记录 effectiveness 与 false-negative（正常机器可读内容被误删）。预期：过滤显著降低总体 effectiveness；但 236 个 visible HTML 注入不受影响，且若策略只保留可见内容，first-party 的可见指令仍在。
- **H2（模板家族检测的泛化边界）。** 基于 54 个高频模板的检测器在新 Common Crawl 快照上对已知家族召回高，但对 144 个 singleton/长尾模板召回低；其 FPR 在 benign 教程/源码页面上不可忽略。操作化：时间外推的 held-out crawl + 人工验证，报告 per-family recall 与 page-level FPR。预期：头部家族 recall 高、长尾低；FPR 由 `<code>/<pre>` 与新闻讨论主导。
- **H3（表示效应 vs 上下文失败）。** 在控制输入长度/截断后，plain text 的 effectiveness 仍高于 HTML/raw/snapshot；若把 HTML/raw 截断到与 plain text 相同 token 预算，差距缩小但不消失。操作化：按 token 长度分层/匹配，混合效应模型，重复运行。预期：表示效应部分独立于 context-window error，但当前论文的 0.2%–1.1% 被 error 稀释。
- **H4（来源与持久性）。** First-party（operator-controlled）注入的 12 个月持久性高于 third-party/user 注入；因为前者由站点运营者稳定部署，后者随帖子/评论生命周期消失。操作化：按 provenance 分层重算 Table 7 的 3/6/12 个月留存，并做生存分析。预期：first-party 留存更高；论文当前没有按 provenance 分层报告，这是可检验的空白。
- **H5（来源签名对 first-party 无效、对 third-party 部分有效）。** 在合成 agent pipeline 中，对 third-party/user 内容加签名/VC 并要求 allowlist，可降低这两类的 injection success；对 first-party header/body 注入无显著效果（因为签名由同一运营者生成）。操作化：三种来源 × 签名/不签名 × 是否验证，测量 effectiveness 与可用性代价。预期：third-party/user 有部分收益，first-party 无收益；这直接检验“来源认证能否缓解合法页面注入”。
- **H6（检测-遵循差距）。** 模型显式识别 injection 的概率与最终遵循概率正相关但不等同；在高 detection 的 closed-source 模型上仍存在 non-trivial 的“识别但遵循”率。操作化：对 5,200 条响应做 detection/compliance 双标，报告 P(comply | detect) 与 P(comply | not detect)。预期：P(comply | detect) 非零（论文已给 6 例），detection 不能作为安全代理。
