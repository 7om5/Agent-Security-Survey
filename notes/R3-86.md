## 1. 150–300 字中文概述

MetaMancer 研究开放工具生态中 LLM Agent 工具选择阶段的实用攻击。作者将攻击建模为语义约束下的双层优化：上层最大化目标查询上恶意工具被选中的端到端概率，下层刻画受害者的 retrieve-then-select 流程，并约束元数据自然性、描述与 schema 的语义一致性及运行时有效性。方法用五个角色化 LLM Agent 在本地 surrogate 生态中做阶段感知的检索/选择失败归因、约束审计、冲突消解与原子更新，在黑盒迁移假设下联合优化工具名、描述和 schema。ToolBench 与 MCPTools 上（20 任务、9,729 个候选工具、8 个目标 LLM、6 种防御），无防御 ASR 为 92.7%/93.8%，六防御平均 91.2%/92.2%，比最强基线在防御下的 39.7%/35.3% 高 50 余个百分点。作者另提出 CVR 防御，仅暴露由必需参数定义的核心视图，将 ASR 降至 18.0%/17.6%，并用自适应攻击揭示有效性与可用性的权衡。

## 2. 研究背景、现有方法不足、精确定义的问题

- 背景：LLM Agent 越来越多地调用第三方工具，工具选择因此成为安全边界；选择主要由工具元数据（name、description、schema）中介。攻击者不必控制模型、system prompt 或用户查询，只要让恶意工具在检索与选择中被视为最优匹配，即可把执行重定向到自己的工具（p.1 Abstract、§1）。
- 现有方法不足（p.2 Table 1；p.2–3 §1–2）：ToolCommander（NAACL'25，仅 description，gradient-based，20 个候选）、Select Me（arXiv'25，仅 description，query-based，20）、MPMA（AAAI'26，仅 description，query-based，heuristic naturalness，6）、AMA（NeurIPS'25，name+description，query-based，3）、ToolHijacker（NDSS'26，仅 description，transfer-based，10）。作者归纳为三点：(i) 多数只优化 selection，忽略大候选池中的 retrieval visibility；(ii) 只改 description，不处理 schema；(iii) 只最大化 ASR，没有显式约束，元数据偏离 benign 分布，易被预防/审计机制检测。
- 精确定义的问题：在严格 transfer-based black-box 下，求元数据 x=(n,d,s)，使
  max_x J_attack(x)=E_{q∼Q_target}[I(t*(q,x)=t_adv)]，
  s.t. L_nat(x)≤ε、L_cons(x)=0、L_valid(x)=0（p.4 §3.3、Eq.(5)–(8)）。
  其中 Q_target、受害者模型/检索器/工具池均不可见；攻击必须同时满足 effectiveness（端到端 retrieve-then-select 成功）、stealth（自然性、语义一致性、运行时有效性）与 robustness（跨任务/生态/模型/防御迁移）（p.2 §1）。
- 三个挑战（p.5 §3.4）：攻击空间跨 name/description/schema 强耦合；效果与约束目标冲突，容易在“有效但暴露”和“合规但无效”之间振荡；无法访问受害者系统，不能直接优化下层决策或上层目标。

## 3. Agent 系统模型（组件、交互流程、信任边界）

- 形式模型：A=⟨R,M,T⟩，R 为 retriever，M 为 LLM reasoning engine，T={t_1,…,t_N} 为工具库；每个工具 t_i 以元数据 x_i=(n_i,d_i,s_i) 暴露（p.3 §3.1）。
- 两阶段流程（p.3–4 §3.1、Eq.(1)–(2)）：
  - Stage 1 Retrieval：R 仅用 n_i⊕d_i 与查询 q 的 embedding 相似度取 top-k；schema s_i 在这一阶段被排除，以避免句法噪声。
  - Stage 2 Selection：M 在 top-k 上读取完整元数据（含 schema），输出 t*(q)=argmax P_M(t_i|q,C(T_k(q)))。
  - 攻击注入后工具库变为 T˜(x)=T∪{t_adv}，检索与选择分别变为 Eq.(3)、(4)（p.4 §3.3.1）。
- 组件与交互（p.6 Figure 2）：受害者侧包括 user query、tool pool（adversarial tool + benign tools）、retriever、top-k candidates、selector，以及 prompt-level prevention、metadata-level detection、agent-level guardrail 三类防御；攻击者侧是独立的 “Surrogate-based Multi-Agent System”，包含 Surrogate Initializer、Objective Evaluator、Constraint Auditor、Aggregator、State Optimizer，虚线标注 “No access to target environment”。
- 信任边界：攻击者是开放生态中的第三方工具发布者，位于受害者系统之外，但可以把自己的工具放进工具池；受害者的模型、检索器、工具库与查询分布不被攻破，只是攻击者不可访问；平台在威胁模型中被建模为只施加格式规则，未被建模为准入审查或安全判定（p.4 §3.2.3）。因此这是“内容/元数据信任边界”，不是代码执行或模型权重边界。受害者的三类防御位于受害者侧，surrogate 生态位于攻击者侧（p.6 Fig.2）。

## 4. 资产、攻击者目标/能力、威胁模型和前提假设

- 资产：工具选择决策的正确性；由选择带来的下游执行/事务/数据访问重定向；用户意图与工具生态的完整性。原文明确说选择恶意工具会 redirect downstream execution（p.1 Abstract），但实验只测到“被选中”，没有测执行后的危害（p.8 §5.1.5）。
- 攻击者目标：在目标领域查询分布 Q_target 上最大化恶意工具被最终选中的概率（p.4 §3.2.1、Eq.(5)）；同时保持自然性、语义一致性、运行时有效性。
- 攻击者能力（p.4 §3.2.3）：以第三方开发者身份在 Apify、PulseMCP、MCP.so 等开放平台发布工具；完全控制发布的 name、description、schema；可加入 optional schema fields，并让 tool-side wrapper 接受/忽略这些字段而不影响必需执行；可基于 source code、API specification 或 draft metadata 初始化；可构建本地 surrogate retriever/LLM/query set/tool pool 进行离线优化（p.5 §4.2）。
- 攻击者不能（p.4 §3.2.2–3.2.3）：访问受害者模型 M 或 retriever R 的内部参数；查询受害者系统获取反馈；知道 benign tool library T 的确切组成或任意 q 的 top-k；知道真实 Q_target；修改输入 prompt 或用户查询；攻破平台。
- 前提假设：平台会接纳该工具并允许其元数据格式；retrieval 只用 name+description；selector 能看到 top-k 的完整 schema；optional fields 在运行时被安全忽略；攻击者可用与 Q_target 不相交但同领域的 Q_surr 近似（p.5 §4.2）。最后一点是较强的领域知识假设；平台准入审查/allowlist 未被建模（推断）。
- 威胁类型：开放工具市场的 metadata/supply-chain poisoning，不是 prompt injection；攻击者不需要污染用户查询或注入外部文档。

## 5. 核心方案（方法、攻击/防御流程、关键定义）

- 双层优化（p.4 §3.3）：下层是注入后的 retrieval（Eq.(3)）与 selection（Eq.(4)）；上层是 Eq.(5) 的 ASR 目标与 Eq.(6)–(8) 的三类约束。由于 Q_target 与受害者系统不可见，实际求解的是 surrogate 上的估计，并依赖迁移。
- Surrogate 生态（p.5 §4.2）：A′=(R′,M′,Q_surr,T_surr)。Surrogate Initializer A_init 从工具源码/API 规格/草稿推断目标领域，构造覆盖代表性用户意图的 Q_surr 与功能重叠但不同的 T_surr，形成“有竞争”的本地 retrieve-then-select 回路；默认 |Q_surr|=10、|T_surr|=10（p.7 §5.1.3）。初始状态 x0 来自源码/API 规格，或由草稿重写而来。
- 五个角色化 Agent（p.5 §4.1；p.6 Fig.2）：
  1. Objective Evaluator A_obj：逐查询判断 t_adv 是否进入 top-k；未进入记为 retrieval failure，进入但未被选中记为 selection failure；分别生成 relevance-oriented（主要改 name/description）与 preference-oriented（可改 name/description/schema）提议。每个提议是 ⟨Intent, Scope, Content⟩（p.5–6 §4.3）。
  2. Constraint Auditor A_const：审计 metadata naturalness（过度最高级、重复关键词、促销修辞、命令式措辞、异常长度/schema 复杂度）与 semantic consistency（description 的功能声明是否被 schema 支持，反之 schema 参数是否有 description 依据；前者失败称 capability hallucination，后者称 schema stuffing）。runtime validity 不在这里做，而留到原子更新阶段作为硬约束（p.6 §4.4）。
  3. Aggregator A_agg：识别冲突提议（作用在同一字段、方向不兼容、无法由单次修改同时满足），把冲突提议“语义投影”为折中形式（弱化暴露性优化、把无依据声明改写为 schema-grounded 功能、用更自然的替代保留任务相关性），过滤明显违反 runtime validity 的提议，输出策略 π_l（p.6–7 §4.5）。
  4. State Optimizer A_opt：把 π_l 落实为原子联合更新（atomic joint updates），主要操作 name、description、parameter descriptions，以及有限的 schema 调整；双向绑定 description↔schema；拒绝修改 mandatory parameter 名称/类型或破坏 call signature 的更新；提交前做结构良构、runtime validity、semantic consistency 的本地验证，失败则修复或丢弃（p.7 §4.6）。
  5. Surrogate Initializer A_init：见上。
  - 迭代 x_{l+1}=A_opt(x_l, A_agg(A_obj(x_l), A_const(x_l)))，直到预算耗尽或达到满意的 surrogate 攻击状态；默认 L_max=10（p.5 Eq.(9)；p.7 §5.1.3）。
  - 注意：默认所有 MetaMancer agents 都以 Qwen-3.5-27B 为 backbone（p.7 §5.1.3），所以“multi-agent”是同一模型上的角色分解与结构化工作流，不是异构模型协作。
- 关键定义：
  - ASR_e2e=ASR_ret·ASR_sel|ret；ASR_ret 为 t_adv 进入 top-k 的查询比例；ASR_sel|ret 为进入 top-k 后被选中的条件比例（p.8 §5.1.5）。
  - Metadata Quality Score（MQS）∈[0,100]，由两个外部 LLM auditor（GPT-5.4-Pro、Gemini-3.1-Pro）打分，覆盖语言异常、显式恶意指令、description-schema 跨字段不一致（p.8 §5.1.5）。
  - L_nat、L_cons、L_valid 分别为自然性、语义一致性、运行时有效性约束；ε 未给出具体数值（p.4 §3.3）。
- 防御 CVR（p.13 §7）：给定 raw metadata（name、description、required parameters、optional parameters），重建“core view”：canonical name、canonical description、required parameters；optional parameters 在工具被选中后才暴露。canonical name/description 在“required parameters 所隐含的能力边界”内重写。对照变体：Desc.-Only Rewrite（只规范化 description，仍暴露完整 schema）、Req.-Only Restrict（只保留 required parameters，不规范化 description）。
- 自适应攻击（p.13–14 §8、Fig.9）：针对 CVR，在满足 stealth 约束的前提下增加 required parameters，把更多语义/能力放进会被 core view 保留的部分；代价是工具接口更重、可用性下降。Fig.9 显示 required parameters 从 1 增至 5 时 ASR 部分恢复，主要来自 retrieval ASR，selection 增益有限。

## 6. 安全声明与形式化程度（定义/指标/经验主张）

- 形式化对象：Agent 元组、retrieval/selection 方程、双层优化 Eq.(3)–(8)、更新 Eq.(9)、ASR 分解与 MQS。它们构成一个**优化问题 formulation**，不是密码学或形式化安全模型：没有 security game、没有 adversary 的成功定义、没有 indistinguishability、没有 theorem/lemma、没有 reduction、没有 soundness/completeness 陈述。
- 约束的形式化程度有限：L_nat≤ε 没有给出距离函数或 ε 取值；L_cons=0、L_valid=0 写成精确等式，但实际由 LLM Constraint Auditor 的语义判断和 State Optimizer 的局部检查近似执行（p.4 §3.3；p.6 §4.4；p.7 §4.6）。原文说这些约束 “mathematically enforce” 三项要求（p.4），这与实现之间存在落差；更准确的表述是“用 LLM 审计器近似约束”，而不是可判定的数学约束（推断）。
- 经验主张：
  - 无防御 ASR 92.7%（ToolBench）/93.8%（MCPTools），六防御平均 91.2%/92.2%，比最强基线高 50+ 个百分点（p.1 Abstract；p.9 Table 3）。
  - 消融显示 w/o A_const 的 ASR 更高（95.0/96.3）但 MQS 降到 60.1/58.7，说明“效果-隐蔽”权衡真实存在（p.9 Table 4）。
  - CVR 把 MetaMancer 的 ASR 降到 18.0%/17.6%，把其他攻击压到 ≤10.8%/9.6%（p.13 Tables 11–12）。
  - 这些是 benchmark 上的经验数字，不是可证明的保证；自适应攻击能把 CVR 下的 ASR 部分恢复（p.14 Fig.9），说明 CVR 也不是形式化防御。
- “first work”“state-of-the-art” 是作者主张（p.3 贡献列表），其依据是 Table 1 的维度对比与 Table 3 的实验；本文未做独立的系统性文献穷举，不能把“first”当作已被证实的优先权声明（推断）。

## 7. 实验设置与主要结果（agents、场景、指标、关键数字、消融）

- 场景与规模（p.7 §5.1.1）：ToolBench 10 个任务、6,932 个候选工具；MCPTools 10 个任务、2,797 个候选工具；合计 20 个任务、9,729 个候选工具。每个任务 100 条查询，每个 benchmark 1,000 条（合计 2,000 条）。Figure 3 的任务工具数之和与 6,932/2,797 一致（p.8 Fig.3）。
- 目标系统（p.7 §5.1.2）：8 个目标 LLM——DeepSeek-V3.2、Qwen-3.5-397B、GLM-4.7、Llama-4-Maverick、GPT-5.1、Gemini-3.1-Pro、Claude-Sonnet-4.5、Grok-4.1；6 个 retriever——BGE-M3、Qwen3-Embedding-8B、Llama-Embed-Nemotron-8B、Text-Embedding-3-Large、Gemini-Embedding-001、Codestral-Embed-2505；默认 k=5。
- 默认攻击设置（p.7 §5.1.3）：五个 agent 均用 Qwen-3.5-27B；L_max=10；surrogate LLM 为 Qwen-3.5-27B、surrogate retriever 为 BGE-M3；|Q_surr|=10、|T_surr|=10；默认目标为 GPT-5.1 + Text-Embedding-3-Large；surrogate 与 target 的 k 均为 5。
- 基线（p.7–8 §5.1.4）：Superlative Injection、Goal Hijacking、Keyword Stuffing、MPMA（GAPMA/Authoritative）、AMA、ToolHijacker；另有 Benign Reference（原始未修改元数据，仅作校准，不作为竞争基线）。
- 指标（p.8 §5.1.5）：ASR_e2e 为主，ASR_ret 与 ASR_sel|ret 为阶段指标；MQS 为 [0,100] 的 LLM 审计分；PPL/PPL_W 为传统 fluency 指标，Table 2 显示 MQS 与 defense-induced relative ASR degradation 的相关性（Pearson −0.793、Spearman −0.777）远强于 PPL（0.177/0.201）与 PPL_W（−0.158/−0.200）（p.8 Table 2）。Benign MQS 基线来自 1,000 个随机抽样的 benign 工具，其 IQR 画在 Figure 1 中，正文未给 exact 数值（p.8 §5.1.5、p.2 Fig.1）。
- 主结果（p.9 Table 3；已按 200 dpi 渲染核对，修正了抽取文本的列错位）：
  - ToolBench 无防御平均：MetaMancer 92.7%，ToolHijacker 88.9%，AMA 37.9%，MPMA 22.5%，SI/KS/GH ≤4.4%，Benign 1.1%。
  - MCPTools 无防御平均：MetaMancer 93.8%，ToolHijacker 83.6%，AMA 43.4%，MPMA 29.2%，启发式 ≤6.1%，Benign 0.4%。
  - 六防御平均：MetaMancer 91.2%/92.2%（相对无防御仅降 1.5/1.6 pp）；ToolHijacker 39.7%/35.3%；AMA 29.9%/32.6%；MPMA 17.9%/22.4%。防御下的领先幅度为 51.5/56.9 pp，对应“超过 50 个百分点”的主张（p.1 Abstract；p.9 Table 3）。
  - 逐目标：MetaMancer 无防御 ToolBench 89.7–94.2%、MCPTools 90.8–96.6%；防御后 89.2–92.5%、89.7–94.1%。ToolHijacker 无防御 84.9–90.7%/77.7–90.3%，防御后 33.8–44.6%/33.0–39.0%（p.9 Table 3）。
- 防御分解（p.11–13 §6；Tables 8–10）：
  - Prompt-level：Instructional 下 MetaMancer 92.5%/93.6%，Sandwich 下 91.0%/92.9%，降幅 <2 pp；ToolHijacker 在 Instructional 下降 24.1–25.3 pp（p.12 Table 8）。
  - Metadata-level：Agent-Scan（TB TNR 99.1、MCP TNR 99.8）与 LLM-as-a-Judge（TB TNR 97.1、MCP TNR 98.6）下，MetaMancer 的 escape rate 均为 100%，ASR 保持 92.7%/93.8%；Goal Hijacking 与 ToolHijacker 被 Agent-Scan 完全拦截（escape 0），LLM-as-a-Judge 把 AMA 压到 40%/30%（p.12 Table 9）。
  - Agent-level：ToolSafe 下 MetaMancer 92.7%/93.7%；VIGIL 下 85.6%/85.4%，是六种防御中唯一造成实质性下降的（−7.1/−8.4 pp）；ToolHijacker 在 VIGIL 下 46.9%/39.8%（p.13 Table 10）。
- 消融（p.9 Table 4）：
  - Full：Ret./Sel./E2E/MQS = 95.2/97.4/92.7/92.9（ToolBench），99.2/94.6/93.8/94.3（MCPTools）。
  - w/o MAS：93.6/95.0/88.9/86.7；98.7/93.0/91.8/89.5——单 agent 退化。
  - w/o A_const：96.7/98.3/95.0/60.1；99.6/96.7/96.3/58.7——ASR 最高但 MQS 崩到 60 左右。
  - w/o A_agg：92.8/94.1/87.3/88.3；98.5/91.7/90.3/90.2——效果与质量同时下降。
  - w/o Schema：95.2/94.3/89.8/68.5；99.2/91.1/90.4/63.7——retrieval 几乎不变，selection 与 MQS 下降，支持“schema 联合优化”的必要性。
- 敏感性（p.9–11 §5.3）：
  - Surrogate/target top-k：25 种 S@k×T@k 组合的 E2E 在 81.3%–93.8% 之间；默认 S@5/T@5 为 92.7%；S@1/T@1 为 93.8%，S@10/T@1 为 81.3%；S@1→T@10 仍有 87.6% E2E 和 98.5% retrieval（p.9–10 Fig.4）。
  - Surrogate 工具数：1→10 使 ASR 从 84.2%→92.7%（TB）、87.8%→93.8%（MCP）；15 反而降到 89.5%/91.2%，原因是 selection 变弱（p.10 §5.3.4、Fig.5）。
  - Surrogate 查询数：1→10 提升到 92.7%/93.8%；15 降到 90.8%/92.2%，主要损害 selection（p.10 §5.3.5、Fig.6）。
  - Backbone：Qwen-3.5 9B→27B 使 E2E 从 85.3%→92.7%（TB）、88.4%→93.8%（MCP）；122B-A10B/397B-A17B 只有边际增益，MQS 升到 94.7/95.3；Gemma-7B、Llama2-7B/13B/70B 均 ≥85.3%，Llama2-70B 为 90.4%/90.8%（p.10 Table 5）。
  - Cross-retriever：6×6 组合的平均 retrieval ASR 为 95.87%（TB）/99.16%（MCP），最低单元格仍 >92%（p.11 Fig.7）。
  - 多阶段 rerank：4 种 reranker、k∈{5,10,15,20}、r∈{5,10} 下 E2E 为 80.6%–92.2%（p.11 Table 6）。
  - 精选竞争池：ToolSim 94.1–95.8%，QuerySim 92.9–94.2%（p.11 §5.3.8、Fig.8）。
- 成本（p.11 §5.4、Table 7）：统一 LLM-call 记账下 MetaMancer 143 次，ToolHijacker 4501、AMA 5151、MPMA 107；MetaMancer 的 143 次换来 92.7%/93.8% 的 ASR，MPMA 更便宜但只有 22.5%/29.2%。
- CVR 结果（p.13 §7；Tables 11–12）：
  - MetaMancer：No Defense 95.2/97.4/92.7 与 99.2/94.6/93.8；CVR 25.1/71.7/18.0 与 27.4/64.1/17.6。retrieval 被打到约 25%–27%，selection 仍有 64%–72%，说明 CVR 主要掐断 retrieval。
  - 对照：Desc.-Only Rewrite 88.0/88.7 E2E；Req.-Only Restrict 89.8/90.4 E2E；VIGIL 85.6/85.4 E2E。单独改 description 或单独限制 schema 都远不如两者同时做。
  - 泛化：SI/KS/GH/MPMA/AMA/ToolHijacker 的 E2E 被压到 ≤10.8%/9.6%；ToolHijacker 降 78.1/74.0 pp；MetaMancer 仍是最抗 CVR 的攻击（18.0%/17.6%）。
- 自适应攻击（p.14 §8、Fig.9）：required parameters 从 1 增到 5，ASR 部分恢复（主要来自 retrieval，selection 增益有限）；接口更重、可用性更差。原文没有给出该图的精确数值表，只能读图；恢复后的 E2E 大约在 70%/63% 量级（读图近似，推断），仍低于无 CVR 的 92.7%/93.8%。

## 8. 贡献与创新点（按原文主张）

- 主张一（p.3 贡献列表）：首个联合优化完整工具元数据（name、description、schema）的实用工具选择攻击，并显式面向 effectiveness、stealth、robustness 三个实践要求；Table 1 用 Manipulated Fields、Pipeline Coverage、Optimization Setting、Constraint Modeling、Candidate Pool 五个维度与 prior work 对比（p.2 Table 1）。
- 主张二（p.3；p.4–7 §3.3–4.6）：把对抗工具选择形式化为严格 transfer-based black-box 下的语义约束双层优化；提出 MetaMancer，用 surrogate 生态 + 五 agent 做 stage-aware effectiveness optimization、semantic constraint auditing、conflict-aware policy aggregation、constraint-compliant atomic updates。
- 主张三（p.3；p.7–11 §5）：在两个互补 benchmark、8 个目标 LLM、6 个 retriever、6 种防御上做广泛实验，声称在保持 stealth/robustness 的同时达到 SOTA；防御下比 prior work 高 50+ pp。
- 主张四（p.3；p.13–14 §7–8）：提出 CVR 轻量防御，用 required parameters 而非 optional parameters 作为核心能力锚点，重建 core view；并设计 CVR-aware adaptive attack，揭示“恢复攻击效果 vs 工具可用性”的权衡。
- 创新点的实质（推断）：与 ToolHijacker 的 undefended ASR 差距其实只有 3.8 pp（TB）/10.2 pp（MCP）；真正大的差距来自防御下 ToolHijacker 的崩溃（39.7/35.3）与 MetaMancer 的稳定（91.2/92.2）。因此本文的核心创新更准确地说是“约束化优化带来的防御鲁棒性/隐蔽性”，而不是无防御绝对 ASR 的大幅提升。

## 9. 局限、失败案例、作者承认的不足（区分作者承认 vs 你的推断）

**作者承认的不足**
- 所有实验都在受控 benchmark 中进行，没有针对真实部署的 agent 服务、第三方市场、生产 API 或真实用户；没有执行真实有害工具动作，也没有访问隐私数据（p.15 Appendix A）。
- 去掉 Constraint Auditor 会得到更高的 ASR（95.0/96.3）但 MQS 大幅下降到 60.1/58.7，说明效果与隐蔽存在真实权衡（p.9 §5.3.1、Table 4）。
- VIGIL 会造成 7.1/8.4 pp 的下降，是六种防御中唯一实质性影响 MetaMancer 的（p.13 §6.3、Table 10）；同时它把 Benign Reference 从 1.1%/0.4% 提高到 6.6%/5.4%（+5.5/+5.0 pp），作者解释为 query/description normalization 的副作用（p.13 §6.3、Table 10）。作者没有量化 benign 误选/效用代价，这一点是本文推断。
- 自适应攻击增加 required parameters 可以部分恢复 ASR，但会让工具接口更重、更不通用，存在 effectiveness-usability 权衡（p.14 §8、Fig.9）。
- surrogate 查询数/工具数超过 10 会损害 selection，说明“更多”不等于“更好”（p.10 §5.3.4–5.3.5）。
- CVR 后仍有 18.0%/17.6% 的残余 ASR，不是完全防御（p.13 Tables 11–12）。
- 原文没有独立的 Limitations 章节；上述条目分散在实验分析和 Appendix A 中（p.9、p.13–15）。

**本文推断的局限/失败模式**
- “端到端”只到 selection，不到 execution。实验度量的是恶意工具是否被选中，没有度量工具执行后的数据外传、事务篡改或下游危害；Abstract 的 “redirect downstream execution” 是机制性断言，不是实测结果（p.1；p.8 §5.1.5）。[推断]
- 威胁模型假设恶意工具能进入工具池并通过平台格式审查；没有评估市场准入、发布者审核、allowlist、签名清单、安装/评分机制对攻击的阻断作用（p.4 §3.2.3；p.11–13 防御集合）。[推断]
- 领域迁移未受检验：Q_surr 与 Q_target 不相交但同领域，攻击者仍需较强的目标领域知识；没有跨领域、跨语言或真实 query drift 的实验（p.5 §4.2）。[推断]
- Naturalness 只由两个 LLM auditor 打分，没有人类评审；MQS 的聚合方式（平均？最小？）未说明，也没有置信区间/样本量；Table 2 的相关系数没有 n、CI 或显著性检验（p.8 Table 2、§5.1.5）。[推断]
- 评审模型与目标模型存在家族重叠：MQS 使用 Gemini-3.1-Pro，而 Gemini-3.1-Pro 同时是 8 个目标 LLM 之一；这可能影响 stealth 结论的外部有效性（p.7 §5.1.2；p.8 §5.1.5）。[推断]
- Agent-Scan/LLM-as-a-Judge 下 100% escape 也可以解释为检测器本身较浅（规则/单次 LLM 判断），而不一定是元数据真的落在 benign 分布内；原文把它解释为后者，但没有人类或分布检验（p.12 §6.2、Table 9）。[推断]
- 对六种防御的评估是 post-hoc：MetaMancer 的 surrogate 优化不建模这些 detector/guardrail，只有针对 CVR 设计了自适应攻击（p.13–14 §8）；因此不能排除“防御感知”的攻击者针对 Agent-Scan/LLM-judge/VIGIL 进一步规避，防御鲁棒性结论可能偏乐观。[推断]
- Runtime validity 只保证 call signature/必需参数不被破坏，不保证工具行为与描述一致，也不保证工具安全；一个“接口合法”的恶意工具仍可执行有害后端逻辑（p.4 §3.2.3；p.7 §4.6）。[推断]
- CVR 依赖一个可信的 canonicalizer 从 attacker-controlled metadata 重写 name/description；该 LLM 本身可能被元数据中的注入内容影响，且 parameter descriptions 是否也被规范化未说明；CVR 也没有评估 benign 工具的效用/可发现性损失（p.13 §7）。[推断]
- CVR 的部署位置与开销未说明：由平台、registry 还是 agent runtime 执行 canonicalization；离线重写如何处理 metadata 更新后的新鲜度，在线重写是否增加每次检索的延迟，均未评估（p.13 §7）。[推断]
- CVR 的“required parameters 定义核心能力”假设可被自适应攻击利用：把更多语义/能力塞进 required parameters 就能部分恢复 ASR；这说明 CVR 是把攻击面从 optional fields 推向 required fields，而不是消除它（p.14 §8、Fig.9）。[推断]
- 防御集合没有覆盖签名 manifest、registry provenance、capability-based authorization、sandboxing 或执行前策略引擎；因此本文不能说明这些机制是否有效（p.11–13 §6–7）。[推断]
- 实验没有报告随机种子、解码温度、重复次数或误差棒；LLM agent 的优化过程有随机性，单次数字的稳定性未知（p.7–11）。[推断]
- 20 个任务的选择标准、100 条/任务查询的构造方式、MQS 的评分 prompt 均未给出，复现难度较高（p.7 §5.1.1；p.8 §5.1.5）。[推断]
- 基线 originally 在 3–20 个候选工具的小池上设计与评估（p.2 Table 1），本文把它们放进 59–2,578 个候选工具的大池（p.2 Table 1；p.8 Fig.3）；这会把“基线不支持大池 retrieval”与“方法本身更弱”混在一起，ASR 差距可能被池规模放大。本文的 large-pool stress test 是合理的，但“SOTA”结论应限定在本文的池规模与 pipeline 下。[推断]

**原文内部不一致 / 数字矛盾**
- Table 4（p.9）与 Table 5（p.10）对同一个默认配置（Qwen-3.5-27B backbone、MCPTools）给出不同的 MQS：Table 4 为 94.3，Table 5 为 92.6；E2E/Ret./Sel. 两边一致（93.8/99.2/94.6）。这属于原文数字不一致，本文在引用 MQS 时以 Table 4 的 94.3 为主，并同时标注 Table 5 的 92.6。从 Table 5 的单调趋势（27B 92.6 → 122B-A10B 92.9 → 397B-A17B 95.3）看，92.6 更像作者意图，但原文没有说明哪个是笔误，无法判定（推断）。
- 轻微措辞不严谨：§6.1 说 prompt-level 下 ASR “remains above 91.0%”，但 Sandwich/ToolBench 恰为 91.0%（p.12 Table 8）；§6.3 说 “above 85.4%”，但 VIGIL/MCPTools 恰为 85.4%（p.13 Table 10）。不影响结论，但“above”应理解为“≥”。
- 抽取层面的错位（非原文错误）：Table 3 的 Claude/Grok 列在 `pdftotext` 中被折到下一行，导致 Claude/Grok 列的低值（实为 AMA 的 38.4/33.0、39.3/28.5 与 MPMA 的 22.1/20.7、23.7/16.0）看起来像 MetaMancer 的低值；200 dpi 渲染确认 MetaMancer 在这两列其实是 94.2/90.8 与 93.2/92.4（ToolBench）以及 96.6/94.1 与 95.4/93.7（MCPTools）（p.9 Table 3）。
- Table 2 与 Figure 3 在抽取文本中交错；Table 7 的 AMA 公式被错配到 MetaMancer 行；Table 8/9/10/12 的行标签错位。均已按渲染核对（p.8–13）。

## 10. 与理论密码学的可能联系（严格；没有就写“无”）

无。

本文没有密码学意义上的定义、游戏、构造、定理、归约或原语。它所谓的 “formalize” 是把攻击写成双层优化问题（p.4 Eq.(5)–(8)），约束是语义自然性/一致性/有效性，不是密码学假设；没有 adversary 的不可区分性、不可伪造性、零知识性、soundness 或 completeness 陈述。全文没有使用 hash、commitment、数字签名、MAC、encryption、ZK、MPC 等原语（pp.1–15）；文中出现的 “signature” 均指 function call signature（p.4、p.7），不是密码学签名。因此 T_crypto 粗判为 0；不应因为出现 “constraint”“validity” 或 “certified”（后者只在引用 ToolCert 的相关工作时出现，p.3）而抬高相关度。

## 11. 与应用密码学/密码工程可能的技术联系（严格；没有就写“无”）

无直接的应用密码学技术联系。

本文没有评估或使用 OAuth、TLS、数字签名、PKI、VC、TEE、zk、allowlist 或 registry。其六种防御是 prompt-level（Instructional、Sandwich）、metadata-level（Agent-Scan、LLM-as-a-Judge）、agent-level（ToolSafe、VIGIL），加上作者自己的 CVR（p.11–13 §6–7）；CVR 是元数据最小化/规范化，不是密码认证。

与本项目相关的边界判断（推断，非原文实验）：
- 本文攻击载体正是工具 name/description/schema（p.3–4 §3.1；p.4 §3.2.3）。在这种载体下，签名工具清单/registry 能认证的是**发布者身份与字节完整性**，不能判定工具描述是否误导、是否夸大了能力、是否与 schema 语义一致。本文威胁模型中的攻击者本身就是合法的第三方发布者并完全控制 metadata（p.4 §3.2.3），所以即使平台要求签名，攻击者签的也是自己的恶意 manifest；签名本身不会降低本文的 ASR（除非配合准入拒绝）。
- Allowlist 可以在**准入层**限制未审计的发布者，可能减少攻击者进入工具池的机会；但本文没有评估 allowlist，且对已经通过准入的恶意发布者，allowlist 不解决描述误导问题。这个区分是 [推断]，不是论文的实验结论。
- 因此本文不能为“签名/registry 能否防御工具选择攻击”提供证据；它只说明语义级检测（Agent-Scan、LLM judge）与运行时 guardrail（ToolSafe、VIGIL）在其实验设置下的效果，以及 CVR 这种非密码学最小化防御的效果（p.12–13）。A_crypto 粗判为 0。

## 12. 可检验的研究假设（3–6 条）

- H1（迁移性）：在本文默认 surrogate（Qwen-3.5-27B + BGE-M3，|Q_surr|=|T_surr|=10）上优化的元数据，迁移到未参与调参的新工具生态（≥1,000 个工具、未见过的目标 LLM）时，六防御平均 ASR 仍显著高于 ToolHijacker，且差距 ≥30 pp。检验：预注册新 benchmark、固定攻击预算、报告 ASR_e2e 的均值与 95% CI（对应 p.9 Table 3、p.10–11 的迁移实验）。
- H2（schema 的阶段非对称性）：联合优化 schema 主要提升 selection，而对 retrieval 影响很小；去掉 schema 后 ΔASR_sel 应显著大于 ΔASR_ret。检验：配对消融，比较 w/o Schema 与 Full 的 ASR_ret/ASR_sel|ret（本文 Table 4 的 95.2→95.2 vs 97.4→94.3 支持该方向，p.9）。
- H3（MQS 作为 stealth 代理）：MQS 与 defense-induced relative ASR degradation 的负相关在未见过的攻击/防御组合上仍然成立（|Pearson|≥0.6），且优于 PPL/PPL_W；若相关性消失，则“高 MQS=隐蔽”不能作为通用结论。检验：扩展攻击/防御矩阵，报告 n、CI、显著性（本文仅给 −0.793/−0.777，无 n/CI，p.8 Table 2）。
- H4（CVR 的作用机制）：CVR 的防御增益主要来自 retrieval 抑制而非 selection 抑制；因此 (a) CVR 下 ASR_ret 大幅下降而 ASR_sel|ret 仍较高；(b) 把语义迁移到 required parameters 的自适应攻击主要恢复 ASR_ret，且恢复幅度与 required parameter 数量正相关、与 benign 工具可用性负相关。检验：2×5 剂量实验，同时测 ASR 与 benign task success/接口复杂度（本文 Table 11 的 25.1/71.7 与 Fig.9 支持 (a)(b) 的方向，p.13–14）。
- H5（签名/allowlist 的边界）：对已注册且签名有效的恶意发布者，签名验证不会显著降低 MetaMancer 的 ASR；allowlist 只在攻击者未能进入列表时降低 ASR。检验：三组对照（无签名、签名+已注册恶意发布者、allowlist 排除该发布者），在同一 benchmark 上测 ASR；这是本文未做、但可由其威胁模型直接推出的实验（p.4 §3.2.3；p.11–13 防御集合）。
- H6（人类自然性评审）：人类评审对“误导性但 MQS 高”的元数据的自然性/可信度评分，会低于 LLM auditor 的 MQS 所暗示的水平；即 MQS 可能高估 stealth。检验：分层抽样 100–200 条元数据，人类评分与 MQS/防御逃逸率做相关分析（本文只用两个 LLM auditor，p.8 §5.1.5）。
