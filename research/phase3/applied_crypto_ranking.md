## 3. 两种排行

### 3.1 按 A_dir（方向内密码工程是否普遍）

1. **B1：3**（两篇均 A=3）
2. A1、B2、B3、B4、D4、G1、G3：1
3. 其余：0

### 3.2 按 A_ceiling（最好的一篇做到什么）

1. **B4：4**（R3-80）
2. **B1：3**（R2-07、R1-03）
3. **G3：2**（R3-43）
4. **A_ceiling=1**：A1、A3、B2、B3、C1、C4、D2、D3、D4、E1、E2、E3、G1、G2、G4、H1（共 16 个叶；R1-01 更正为 1，其余为接口/一般安全功能）
5. 其余 12 个叶：0（A2、C2、C3、D1、F1、F2、F3、H2、H3、I1、I2、I3）

### 3.3 结论

- **B1 是唯一“密码工程广度 + 高度”都成立的方向**：R2-07 给出委托凭证架构（OAuth/OIDC/VC/签名/scope/audience/撤销/审计），R1-03 给出可运行协议（X25519/OTK/X.509/访问 token/ProVerif/性能）。
- **B4 是“单篇 spike”**：R3-80 有 zk 证明原型与端到端实验；同方向 R3-02/R3-75 是 ML/OS 审计，无密码机制。B4 的 A 高度集中在 R3-80。
- **G3 有 2 分，A1 只有 1 分**：G3 的 R3-43 有隐写构造/监控者密钥讨论（不是协议实现）；A1 的 R1-01 只目录化 IAM/OAuth/TEE/工具签名，按“论及≠应用”更正为 A=1。
- **B2/B3/D4/G1/E1/E3 只有 1 分**：有明确密码工程切入点（capability、attestation、消息认证、registry 签名、供应链完整性），但论文未实现/评估。
- **没有任何方向达到 A=5**：缺少“机制创新 + 可复现原型 + 量化安全/性能收益”的完整闭环。

## 4. 关键证据

### R3-80 zkAgent（A=4）
- 用 zkSNARK/zkTLS/zkVM 把 Agent 的 tool observation 与 transcript 绑定，生成 one-shot transcript proof；有 C++ 原型、prove/verify/大小数据、端到端 weather/coding agent 实验。
- 未给 5：zkTLS 信任假设、GPT-2 级性能限制、部署/密钥管理/证明开销未充分评估；没有与现有 Agent 运行时（MCP/A2A）集成的完整协议。
- **证据**：§10/§11；pp.39–40、52–53、原型与实验章节。

### R1-03 SAGA（A=3）
- X25519/OTK/DH/HKDF、ECDSA/Ed25519、X.509/TLS；Provider 注册表、联系策略、访问 token；ProVerif 符号验证；开源实现与性能。
- 未给 4：Provider 强信任；token 是 bearer、未绑定 task；缺端到端攻击实验与 MCP/A2A 集成。
- **证据**：§10/§11；协议/实现/性能章节。

### R2-07 Authenticated Delegation（A=3）
- OAuth 2.0/OIDC/W3C VC/数字签名；委托 token、scope、audience、撤销、审计；user/agent/service/OP 信任边界。
- 未给 4：无原型/实验；更接近 Position/架构。
- **证据**：§10/§11；架构与协议章节。

## 6. 负面证据与限制

1. **A=5 为零**：没有完整“威胁模型 + 机制创新 + 可复现原型 + 量化收益”的闭环。
2. **B4 的 A_dir=1**：R3-80 一篇拉高 ceiling，但方向上不普遍；不能把 B4 整体当作密码工程方向。
3. **B1 只有 2 篇**（low_n）：但两篇分别覆盖架构与实现，证据一致；仍需在阶段四做小规模原型验证。
4. **“论及/用了 OAuth/TLS”不等于 A 高**：R1-01 只在 SoK 中目录化 IAM/OAuth，未实际使用/实现/评估，A=1（原 A=2 已更正）；R3-72 只用 TLS 背景，A=1；R3-20 无密钥 SHA-256 只作标记，A=1。
5. **7 篇 FULLY_READ 不影响 A≥3 结论**：R3-80/R1-03/R2-07 均非 FULLY_READ。

## 7. 应用密码学相关度排行（结论）

**按“最好现有工作”排序**：
1. B4（4，R3-80）
2. B1（3，R2-07 + R1-03）
3. G3（2，R3-43）
4. A1/A3/B2/B3/C1/C4/D2/D3/D4/E1/E2/E3/G1/G2/G4/H1（1；见 §3.2）
5. 其余（0）

**按“方向内普遍性”排序**：
1. B1（3）
2. A1/B2/B3/B4/D4/G1/G3（1）
3. 其余（0）

**一句话**：应用密码工程相关度同样高度集中：B1 是唯一有“架构 + 实现”双证据的方向；B4 是 R3-80 的单点高峰；其余方向最多只有“可插入密码机制”的接口，尚未形成密码工程贡献。
