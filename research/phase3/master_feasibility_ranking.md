# 阶段三：硕士研究可行性 F_master 排行

> 对象：密码学本科、研一、密码工程课题组、AI 基础较弱、缺少组内 Agent Security 直接指导。
> F 是**方向级**判断，0–5；不与 T/A/H 合并。**可行性 ≠ 新颖性**：F 高不代表创新空间大，F 低也不代表方向不重要。

## 1. 评分口径

四个子项（合计 0–5）：
1. **密码学杠杆（0–2）**：现有密码学背景能直接发挥多少。
2. **低 AI/算力依赖（0–1）**：是否可用现成模型 API/开源 harness，避免大模型训练与 GPU。
3. **开放实验条件（0–1）**：是否有开源 Agent 框架、Benchmark、可复现实验。
4. **可定义性与评估（0–1）**：能否定义清晰攻击模型/安全目标，并做可重复的安全/性能评估。

> 这是工作假设，不是客观标准；阶段四若进入候选方向，需要用最小原型再次验证 F。

## 3. F 与 T/A/H 的分离

- **B1**：F=5，T=3/A=3，但 H=2.7（low_n）。它是“密码学匹配 + 可行性高 + 样本小”的方向；阶段四应重点验证其创新空间。
- **B4**：F=4（2+0+1+1），T_ceiling=4/A_ceiling=4，但 T_dir=0/A_dir=1；R3-80 单篇 spike。**低 AI/算力项为 0**：zk 证明仍需较高 CPU/内存，F=4 不代表证明工程便宜。适合做“可验证执行”小原型，但不要假设整个 B4 都有密码学基础。
- **G3**：F=4，T=1/A=1（A_ceiling=2），T_potential=4；消息认证是明确的密码工程接口，但现有论文没有实现签名/MAC/nonce 防御。
- **G1/E3**：F=4，low_n，T/A≤1；适合做“A2A/Skills 供应链的密码学加固”小原型，但需要自己定义威胁模型与 baseline。
- **B2/B3**：F=4，T/A=1；适合做 capability/隔离的密码工程，但论文本身不是密码学。
- **D2/H1**：H=5/4.7，但 F=2/1；热度高不代表硕士能独立做，尤其缺 AI 指导时。

## 5. 风险与前置知识

- **共同前置**：Python、HTTP/OAuth、基本 LLM API、Agent 工具调用；不需要训练大模型。
- **最大风险**：课题组无 Agent Security 直接指导；需要外部合作者/开源社区；论文 baseline 可能来自非密码学团队。
- **算力**：B1/G1/G3/E3/B2 主要是 CPU + API，成本可控；B4 zk 证明需要 CPU/内存，B3 TEE 需要云 TEE；D/H 方向需要 GPU/训练，不适合当前条件。
- **创新风险**：B1/G1/G3/E3 的“加签名/凭证”容易被审稿人视为工程包装；必须定义新的安全性质（scope non-amplification、撤销 soundness、消息认证与语义检测的边界）并做对照实验。
- **与课题组匹配**：B1/B4/G1/G3/E3 最贴近密码工程（认证、协议、凭证、签名、zk、供应链）；A/C/D/H/I 多数是 AI/系统/语义，密码学杠杆低。

## 6. 可行性排行（结论）

1. **B1（5）**：最匹配密码学背景与小组原型；唯一 T/A=3 且 F=5 的方向；但只有 2 篇，需验证创新空间。
2. **B2、B3、B4、E1、E3、G1、G3（4）**：都可做密码工程小原型；其中 B4 有最高 T/A ceiling，G3 有明确消息认证接口，E3/G1 是供应链/协议接口。
3. **A1、A3、C1–C4、D1、D4、E2、I2、I3（3）**：可行但密码学杠杆有限或需要较多 Agent 知识。
4. **A2、D2、D3、F1、F3、G2、G4、I1（2）**：工程/AI 门槛较高，密码学帮助小。
5. **H1、H2、H3、F2（1）**：依赖训练/GPU/白盒模型，不适合当前硕士独立推进。

> **不要把 F 排行直接当选题推荐**：阶段四还要结合 T/A、H、创新空间与导师资源做候选收敛；F 高但 T/A 低的方向（如 B2）需要先补密码学问题定义。
>
> **F≠新颖性（再次强调）**：F=5 只表示“当前研究者较容易构建可验证的研究工作”，不证明该方向存在可发表的创新点。B1 的 F=5 来自“密码学匹配 + 低算力 + 开放工具 + 可定义指标”，不来自“已有工作少”或“问题新”。阶段四必须单独做现有工作充分性检查，不能用 F 分替代。
