# 阶段三评分 Rubric｜2026-11-03

> 本文件在正式评分前制定；四个维度独立评分，不合并为单一总分。
> 评价单位：31 个二级方向为主，9 个一级方向为汇总。样本量 1–2 的方向保留结果但标记“证据不足”。
> 所有分数 0–5；分数是**证据强度**，不是论文质量或方向“好坏”的绝对判断。
>
> **勘误说明（2026-11-06）**：§4 的 A=1/A=2 边界做了最小澄清（“论及密码机制”vs“实际使用/实现/评估”），用于修正 R1-01。该澄清不改变其他论文的评分；只影响同时满足“综述/背景列举”与“无实际使用”的论文。

## 1. 通用原则

1. **先证据、后分数**：每个方向分数必须能回溯到代表论文的笔记/PDF 页码。
2. **区分四类密码学关系**：
   - A. 已有密码学贡献（定义、构造、证明）；
   - B. 使用已有密码学机制的系统工作；
   - C. 可引入密码学方法的潜在问题（研究假设）；
   - D. 主要依赖 LLM 语义判断、不适合密码学直接解决的问题。
3. **不把“可以加签名”当成高分理由**；不把“出现 privacy/verifiable/trust”当成密码学证据。
4. **不预设偏好方向**；校准案例只用于锚定分数，不决定排行。
5. **小样本保护**：n≤2 时，方向分数必须标注 `low_n`；不得用单篇论文的最高分代表整个方向。
6. **聚合规则先于计算**：见 §6。

## 2. H：研究活跃度（0–5）

H 只描述**124 篇样本内**的活跃度；不代表全领域热度。统计前先按 `publication_status` 分层。

### 2.1 三个子指标

**H_volume（0–5）**：样本内主类论文数量。
- 0：0 篇；1：1 篇；2：2 篇；3：3–4 篇；4：5–7 篇；5：≥8 篇。

**H_momentum（0–5）**：2024–2026 的时间分布与连续性。
- 0：无 2024–2026 可定位论文。
- 1：仅 2024，之后无延续。
- 2：以 2024/2025 为主，2026 无新增或明显下降。
- 3：2024–2026 均有论文，节奏稳定。
- 4：2025→2026 增长，且至少 2 篇 2026 正式主会/录用。
- 5：2026 有 ≥3 篇正式主会/录用，且形成连续技术路线（攻击→防御/系统/benchmark）。
- 2026 时间窗口不完整；若 2026 只有 preprint/workshop，降一档。
- 仅 1–2 篇的方向，H_momentum 最高记 3，并标 `low_n`。

**H_breadth（0–5）**：会议/团队/贡献类型覆盖。
- 0：无可用信息。
- 1：单一论文/单一团队/单一 venue。
- 2：2 篇且同一 venue 或同一团队。
- 3：≥2 个 venue 或 ≥2 个独立团队。
- 4：≥3 个 venue 且 ≥3 种贡献类型（attack/defense/benchmark/system 等）。
- 5：≥4 个 venue、多个独立团队、且 attack/defense/benchmark/system 多类型并进。
- 团队信息只用论文作者单位；无法确认时按 venue 计，不臆测。

### 2.2 H 综合

\[
H = 0.30 H_{volume} + 0.45 H_{momentum} + 0.25 H_{breadth}
\]

保留一位小数。H 是**样本内活跃度代理**，不是全领域热度。

### 2.3 分层统计

同时报告：
- **正式主会 published**：`main_conference + published`；
- **正式发表（含 Workshop）**：`published`；
- **宽口径**：所有 124 篇（含 preprint/submitted/accepted_not_published）。
三个口径的方向排序可能不同；以正式主会口径为主，其余为敏感性。

## 3. T_crypto：理论密码学相关度（0–5）

### 3.1 评分锚点

| 分 | 含义 | 判据 |
|---:|---|---|
| 0 | 无自然联系 | 纯 LLM 行为/经验分类/语义判断；无形式化安全目标 |
| 1 | 可类比传统安全属性 | 有 authentication/integrity/privacy 等词，但无密码学核心问题 |
| 2 | 可形式化的信任/隐私问题 | 能写出安全目标，但已有成熟机制可能足够；无新定义/构造需求 |
| 3 | 明确安全模型 + 原语接口 | 能定义攻击者/信任边界，指出签名/MAC/凭证/承诺等接口；可做协议设计或安全性分析 |
| 4 | 值得验证的新定义/协议/构造 | 有非平凡攻击者、证明目标、组合/委托/衰减等新性质；可能形成论文级贡献 |
| 5 | 强而直接的理论密码学问题 | 新安全定义、协议组合性、可证明委托约束、隐私保护协议、可验证计算性质，且有文献证据支撑必要性 |

### 3.2 必须回答的五个问题

1. 保护什么对象，抵抗何种对手？
2. 是否需要密码学原语，而非普通访问控制/系统策略？
3. 适用哪些原语/工具（签名、MAC、凭证、匿名凭证、ZK、MPC、FHE、承诺等）？
4. 目标性质能否形成严谨威胁模型与证明义务？
5. 哪些部分其实是自然语言意图理解误差，密码学不能直接解决？

### 3.3 分数解释

- **已有贡献**（A 类）与**潜在空间**（C 类）分开记录：`T_existing` 与 `T_potential`。
- 方向排行使用 `T_existing`；`T_potential` 单列，标“研究假设”，不得当成已有成果。
- 只有系统集成、没有新定义/证明的工作，T 通常 ≤3；只有调用现成签名/OAuth 的，T ≤2。

### 3.4 校准案例（只锚定，不预设排名）

- **R3-80 zkAgent**：有一 shot transcript 的 zkSNARK/zkTLS/zkVM 构造与形式定义/定理；属“已有密码学贡献”。T_existing 预计 4（应用型新构造），不是 5（不是新密码学原语/基础定义）。
- **R1-03 SAGA**：X25519/OTK/X.509 + ProVerif 符号验证；属“标准原语组合 + 工程协议”。T_existing 预计 3。
- **R2-07 Authenticated Delegation**：委托凭证架构与 OAuth/OIDC/VC 接口，但无安全定义/证明。T_existing 预计 2–3。
- 纯语义防御/benchmark（如 R1-14、R3-22、R3-60）：T_existing 0–1。

## 4. A_crypto：应用密码学/密码工程相关度（0–5）

| 分 | 含义 | 判据 |
|---:|---|---|
| 0 | 无密码工程关系 | 无具体密码机制使用点，也未系统讨论密码机制 |
| 1 | 一般安全功能，或仅在综述/背景中列举密码机制 | 有权限/隔离/审计等一般安全功能；或 SoK/Related Work 只目录化 OAuth/TLS/签名/TEE，**未实际使用、实现或评估** |
| 2 | 现有凭证/加密/认证作为配套 | 论文**实际使用**了 OAuth/TLS/签名等机制，但机制不是核心贡献，也没有协议设计/实验 |
| 3 | 明确密码工程切入点 | Agent 身份凭证、作用域令牌、密钥管理、可信审计、数据共享加密等 |
| 4 | 可集成 Agent 运行时/MCP/A2A/Tool Gateway 的实用协议 | 有威胁模型、原型、可重复的安全/性能实验 |
| 5 | 清晰威胁模型 + 机制创新 + 可复现原型 + 量化收益 | 适合密码工程团队推进的研究路径 |

**A=1/A=2 的最小澄清（勘误）**：A 衡量论文**实际使用、实现或评估**的密码机制，不衡量论文“提到”了多少密码机制。因此：
- 纯 SoK/Position/Related Work 只把 OAuth/OIDC/签名/TEE 当作分类对象或背景 → **A=1**，不是 A=2；
- 论文把现有凭证/加密/认证**作为系统组件实际调用**（即使不是核心创新）→ A=2；
- 只有当密码机制成为明确工程切入点（凭证、令牌、密钥、审计、加密共享）→ A≥3。
- 校准：R1-01 是 SoK，正文 pp.13–15 只目录化 OAuth/OIDC/TEE/ETDI 签名工具定义，无构造/实现/评估，故 A=1（原 A=2 已更正）。R3-43 的隐写构造/监控者密钥讨论属“实际讨论构造”，A=2 保留。

### 4.1 必须回答的六个问题

1. 密码学机制保障的具体安全属性？
2. 处于 Agent 系统哪个信任边界（user/agent/sub-agent/tool/MCP/service）？
3. 不用密码学是否无法可靠解决？
4. 能抵御哪些明确攻击者（链路/恶意服务/恶意 Agent/被攻陷端点）？
5. 是否有可复现实现/公开实验环境？
6. 相比已有协议，Agent 场景引入什么新需求？

### 4.2 校准案例

- **R3-80**：可验证执行 + zkTLS/zkVM，A_existing 预计 3–4（有原型/证明，但集成成本与部署未充分评估）。
- **R1-03**：Agent 治理认证协议，A_existing 预计 3（协议+实现+性能，但 Provider 信任假设强）。
- **R2-07**：委托凭证架构，A_existing 预计 3（接口清晰，无实现/实验）。
- 只在 Related Work 提签名的论文，A≤1。

## 5. F_master：硕士研究可行性（0–5）

面向：密码学本科、研一、密码工程课题组、AI 基础较弱、无课题组内 Agent Security 直接指导。

| 分 | 含义 |
|---:|---|
| 0 | 不适合硕士独立推进：需大规模训练/昂贵算力/强 AI 指导/不可复现 |
| 1 | 门槛很高：核心依赖大模型训练或闭源平台，风险不可控 |
| 2 | 门槛较高：需要较多 AI 工程/数据/算力，但可在外部合作下做 |
| 3 | 可行：可用现成模型 API + 开源 Agent 框架/Benchmark，密码学背景能发挥，原型规模中等 |
| 4 | 较可行：明确威胁模型、公开 benchmark、最小原型可在 3–6 个月完成，评估指标清晰 |
| 5 | 很可行：密码学为核心、算力需求低、实验可复现、与密码工程课题组积累直接匹配，易形成论文 |

### 5.0 四个子项与可复算规则

`F_master = F_crypto_leverage + F_low_ai_compute + F_open_experiment + F_definability`

| 子项 | 范围 | 判据 |
|---|---:|---|
| `F_crypto_leverage` | 0–2 | 2 = 密码学是核心且课题组可直接发挥；1 = 有明确密码接口但非核心；0 = 密码学几乎不适用 |
| `F_low_ai_compute` | 0–1 | 1 = 可用现成模型 API/开源 harness，无需训练或大 GPU；0 = 需要训练/白盒/大算力 |
| `F_open_experiment` | 0–1 | 1 = 有开源 Agent 框架、benchmark 或协议 SDK，可复现；0 = 环境/数据/协议不成熟或成本高 |
| `F_definability` | 0–1 | 1 = 能定义清晰攻击模型/安全目标与可重复指标；0 = 核心是语义判断，指标难界定 |

四个子项必须逐项给出并求和；不得只给总分。`F=5` 只表示“当前条件下较容易形成可验证的研究工作”，**不表示存在可发表的创新点**。一级方向的 F 不评分（null/空），避免用 0 冒充“已评价”。

### 5.1 十个检查项

1. 学习成本与知识门槛；
2. 密码学背景的作用；
3. 是否需要大规模 LLM 训练/昂贵算力；
4. 是否有开源 Agent 框架、Benchmark、可复现实验；
5. 能否定义清晰攻击模型/安全目标；
6. 能否构建最小可行原型；
7. 能否做严谨安全与性能评估；
8. 是否有充分现有工作可比；
9. 是否兼顾密码学/系统安全学术要求；
10. 工程复杂度、依赖风险、创新风险。

### 5.2 评分规则

- F 是**方向级**判断，不是论文级平均；论文级只作为证据（是否开源、是否需训练、是否有 benchmark）。
- 若方向的最佳论文需要白盒模型/大规模训练，F 通常 ≤2；若可用 API + 开源 harness，F ≥3。
- 若方向的核心问题是“LLM 语义判断”，即使工程容易，F 也不应高（缺少密码学可验证问题）。
- **可行性与新颖性分开**：F 高不代表创新空间大；T/A 高不代表硕士能独立完成。

## 6. 方向聚合规则

### 6.1 论文级 → 方向级

- 每篇论文给 `T_paper`、`A_paper`（0–5）与 `evidence_confidence`（high/medium/low）。
- **T_dir** = 置信度加权中位数（high=1.0、medium=0.7、low=0.4）；不取最高分。
- **T_ceiling** = 该方向最高 `T_paper`，单独报告，用于敏感性。
- **A_dir** 同理；**A_ceiling** 单独报告。
- n≤2 时，T_dir/A_dir 直接列出论文分数，不强行给方向分；标 `low_n`。
- 若方向内分数分裂（如一篇 4、其余 0），报告 `T_dir` 与 `T_ceiling` 的差值，并在报告中说明“单篇主导”。

### 6.2 H 与 F

- H 按 §2 公式从计数计算，不用论文分数平均。
- F 按 §5 Rubric 直接给方向分；每个分数附 2–3 条论文证据与限制。

### 6.3 不合并总分

阶段三**不计算** `0.15H+0.20T+0.30A+0.35F` 之类的综合分；四个维度分别排行。阶段四才做候选方向收敛与权重敏感性。

## 7. 证据与置信度

- 每篇论文的 `T_paper/A_paper` 必须给笔记 §10/§11 或 PDF 页码。
- `evidence_confidence`：
  - high：全文+附录已读，密码学判断有明确页码；
  - medium：正文已读但附录缺失/原文不一致；
  - low：FULLY_READ 且关键材料缺失，或仅题名级信息。
- 7 篇 FULLY_READ（R2-25、R3-62、R3-63、R3-64、R3-66、R3-71、R3-84）在密码学评分中标 `evidence_confidence≤medium`；若其 T/A 分数影响方向排名，需做剔除敏感性。

## 8. 输出

- `paper_crypto_evidence.csv`：124 篇论文级矩阵。
- `research_activity.md`：H 统计与趋势。
- `theoretical_crypto_ranking.md`：T 排行。
- `applied_crypto_ranking.md`：A 排行。
- `master_feasibility_ranking.md`：F 排行。
- `sensitivity_analysis.md`：口径/置信度/小样本敏感性。
- `phase3_report.md`：综合报告（仍不合并总分）。
