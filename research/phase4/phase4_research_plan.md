# 阶段四研究计划：从方向到具体密码学问题

> 日期：2026-11-06
> 输入：阶段三修正后的 31 叶 + 9 主类 H/T/A/F；124 篇全文笔记；42 条密码学交叉观察；阶段四范围明确的外部 prior art。
> 目标：筛选 3–5 个**具体研究问题**，重点推荐 1–2 个；不把方向标签当选题。

## 1. 阶段四要回答什么

阶段三回答的是“哪些 Agent Security 方向与密码学接近、且硕士可做”。阶段四必须进一步回答：

1. 哪一种 Agent 运行架构（单 Agent + MCP、A2A 多 Agent、CUA、Skills、记忆/RAG）？
2. 哪些主体（User、Agent、Sub-agent、MCP Server/Tool、Resource Server、Authorization Server、Verifier）？
3. 哪一个授权/信任边界存在缺陷？
4. 攻击者拥有什么能力（恶意子 Agent、被攻陷工具、恶意 MCP server、离线撤销、重放、串谋）？
5. 现有 OAuth/OIDC、VC、UCAN、Macaroon、Biscuit、DPoP、mTLS、TEE、zkVM、透明日志是否已经足够？
6. 为什么需要新的安全性质、协议组合或证明义务，而不是“再加一个签名”？
7. 最小原型能否在 8 周内做出，并给出可证伪的实验？

## 2. 方法与顺序

1. **问题挖掘**：从 124 篇的 Threat Model、Limitations、Future Work、密码学接口，以及阶段三 T/A/F 证据，构造不少于 8 个具体问题（本阶段做 12 个）。
2. **现有技术充分性检查**：逐项检查普通签名、HMAC、OAuth 2.0/OIDC、DPoP/mTLS、Macaroon/Capability/UCAN、策略引擎、OS 隔离、TEE/远程证明、zkVM/zkSNARK、透明日志/供应链签名。
3. **范围明确的外部 prior art**：只对进入候选池的问题查标准原文、正式论文、arXiv/会议论文与可信技术文档；不重新做全领域 Agent Security 综述；外部材料放 `external_prior_art/`，不混入 124 篇。
4. **候选评价**：先过最低门槛，再做多维原始评分、Pareto 比较与权重敏感性；不把所有维度无解释地平均。
5. **3–5 个完整方案**：每个方案给出 A–H 八部分（问题、威胁模型、最接近工作、密码学方案、最小原型、实验、风险、8 周计划）。
6. **1–2 个优先推荐**：明确第一/第二优先、推荐依据、最大不确定性、证伪后的切换方案。

## 3. 证据等级与标签

所有关键论断使用以下标签之一：

- `[PDF证据]`：124 篇语料中的论文原文/笔记页码；
- `[外部 prior art]`：阶段四补充的标准/论文/技术文档，记录 URL/编号/访问日期；
- `[推断]`：基于证据的研究判断，尚未验证；
- `[待验证]`：需要原型、实验或外部查证。

**禁止**：
- 把“124 篇中没看到”写成“全世界没人做过”；
- 把外部 preprints/技术博客写成同行评审事实；
- 虚构论文、标准编号、作者、实验结果；
- 把“增加签名/OAuth/ZKP”本身当成创新；
- 声称密码学能证明 LLM 对自然语言任务的理解。

## 4. 候选门槛与评价维度

### 4.1 最低门槛（先筛，不达标直接淘汰）

| 门槛 | 要求 |
|---|---|
| G1 真实安全需求 | 有明确资产、攻击者、漏洞与攻击路径；不是纯概念 |
| G2 密码学必要性 | 密码学解决关键安全属性；不是可替换的工程组件 |
| G3 现有机制不足 | 成熟机制不能完整解决，或需要新的安全模型/协议组合/证明义务 |
| G4 可执行性 | 有可落地的最小原型或理论验证路径；不是纯哲学问题 |

### 4.2 八维评价（0–5，原始分保留）

1. **D1 真实安全需求**：资产、攻击者、攻击路径是否明确。
2. **D2 密码学研究必要性**：密码学是否核心，而非“加个签名”。
3. **D3 理论研究潜力**：安全定义、威胁模型、协议设计、形式化分析、可证明性质。
4. **D4 应用密码学潜力**：凭证、授权协议、可验证执行、密码工程方案。
5. **D5 创新空间**：与最接近工作相比是否有非平凡差异。
6. **D6 硕士可行性**：密码学本科/研一、AI 弱、无组内 Agent Security 指导。
7. **D7 实验可行性**：开源 harness、协议 SDK、密码库、API/算力成本。
8. **D8 风险严重度**（5 = 最高风险）：理论证明、实现成本、竞争、结果不显著。

### 4.3 权重（仅用于排序，不作为客观标准）

主权重（应用/理论平衡）：

`S = 0.12 D1 + 0.18 D2 + 0.12 D3 + 0.18 D4 + 0.18 D5 + 0.11 D6 + 0.11 D7`

D8 不进入 S，单独报告；D8=5 直接淘汰，D8=4 需有明确缓解方案。

敏感性：
- **理论导向**：D2 .28、D3 .22、D4 .10、D5 .18、D1 .08、D6 .07、D7 .07；
- **应用导向**：D4 .28、D6 .16、D7 .16、D2 .14、D5 .14、D1 .06、D3 .06；
- **创新导向**：D5 .30、D2 .18、D3 .14、D4 .16、D1 .08、D6 .07、D7 .07。

### 4.4 决策规则

1. 先过 G1–G4；
2. 再做 Pareto：若候选 A 在所有维度不劣于 B 且至少一维严格更好，则 B 淘汰；
3. 加权分只用于同档比较，不直接决定选题；
4. 最终推荐必须同时说明：为什么适合密码学背景、Agent Security 需求、理论/应用价值、与最接近工作的差异、最大风险、最小实验、为什么优于其他候选、证伪后的切换。

## 6. 边界

- 本阶段**不实现**完整系统，不训练模型，不产生实验结果；所有“预期结果”均为 `[待验证]`。
- 外部 prior art 只覆盖候选问题，不声称覆盖全领域。
- 124 篇仍是固定语料；外部论文不加入 124 篇，不改变阶段三分数。
- 最终推荐是“值得启动的研究问题”，不是“已经证明可行的论文”。
