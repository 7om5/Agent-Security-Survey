## 3. 一级方向说明

### A. 研究总览、安全评测与审计
- **研究对象**：跨攻击面的安全定义、SoK、通用 benchmark、测量方法、监控审计与漏洞发现。
- **关键安全问题**：如何定义 Agent 安全边界；如何构造可复现的评测；如何发现未知漏洞；如何审计系统行为。
- **代表论文**：R1-01、R3-06、R3-48（A1）；R2-01、R2-02、R2-14、R2-19、R3-14、R3-30、R3-45、R3-49、R3-52、R3-56（A2）；R2-13、R3-55、R3-69（A3）。
- **与相邻方向区别**：面向特定环境/协议/工具的 benchmark 回到 D/E/I 等对象分支；A 只保留跨攻击面的通用评测与审计方法。

### B. 身份、授权、权限治理与可信执行
- **研究对象**：Agent 身份、委托授权、最小权限、capability、隔离、策略审计与可验证执行。
- **关键安全问题**：谁在代表谁行动；授权范围如何绑定、衰减与撤销；策略由谁执行；执行证据是否可信。
- **代表论文**：R2-07、R1-03（B1）；R3-01、R1-02、R2-08、R3-79（B2）；R1-05、R1-06、R3-35、R3-72（B3）；R3-02、R3-75、R3-80（B4）。
- **与相邻方向区别**：B 关注“授权与执行的机制”，D3 关注“注入内容的检测”，H1 关注“模型行为层的拒绝与护栏”。

### C. 隐私、机密性与敏感信息流
- **研究对象**：隐私规范、数据最小化、记忆隐私、跨服务外传、内部信息提取与再识别。
- **关键安全问题**：哪些数据可以进入上下文、记忆或外发；Agent 能否推断出未被直接提供的敏感信息；如何约束信息流。
- **代表论文**：R1-04、R3-07、R3-08、R3-09、R3-42、R3-44、R3-63、R3-81（C1）；R2-11（C2）；R3-10、R2-23、R3-33（C3）；R3-03、R3-11、R3-28、R3-34、R3-59（C4）。
- **与相邻方向区别**：C2 是记忆中的个人隐私；F1/F2 是记忆/知识库的完整性与污染；C4 是信息提取/推断，不是投毒。

### D. 提示注入、任务劫持与行为偏移
- **研究对象**：提示注入的机理、攻击入口、检测防御与多步控制流异常。
- **关键安全问题**：指令与数据能否分离；多源/多模态内容如何影响 Agent；跨动作的攻击链如何检测。
- **代表论文**：R1-09、R3-17（D1）；R1-13、R2-10、R2-15、R3-16、R3-27、R3-38、R3-39、R3-54、R3-70、R3-71、R3-84（D2）；R1-10、R1-14、R2-12、R2-16、R3-04、R3-19、R3-77（D3）；R3-18、R3-20、R3-36、R3-85（D4）。
- **与相邻方向区别**：D2 关注注入入口与攻击构造；D3 关注检测/训练/接口防御；D4 关注跨动作、控制流与轨迹级异常；E 关注工具/MCP/Skills 生态。

### E. 工具、MCP 与 Skills 生态安全
- **研究对象**：MCP 服务器/工具元数据、工具选择、跨工具数据流、Skills 供应链与后门。
- **关键安全问题**：工具描述是否可信；工具组合是否越权；Skills 发布/更新是否可验证；工具生态的供应链攻击。
- **代表论文**：R1-07、R2-17、R3-13、R3-65（E1）；R1-11、R1-12、R3-47、R3-66、R3-86（E2）；R1-08、R3-23（E3）。
- **与相邻方向区别**：E1 是 MCP 协议/工具投毒；E2 是工具选择与跨工具滥用；E3 是 Skills 供应链；C3 是经 MCP 的数据外传，F1 是记忆投毒。

### F. 记忆与知识库完整性
- **研究对象**：记忆/知识库投毒、集体记忆与群体影响、记忆防护与语义监控。
- **关键安全问题**：攻击者能否写入/污染记忆；污染是否传播；防御能否区分恶意与良性写入。
- **代表论文**：R2-03、R3-83（F1）；R3-41（F2）；R3-22、R3-82（F3）。
- **与相邻方向区别**：C2 是记忆隐私；F1/F2 是完整性与污染；F3 是防护机制；G3 是多 Agent 消息级联。

### G. 多智能体通信、协作与信任
- **研究对象**：A2A 协议信任、多 Agent 架构/拓扑评测、级联/串谋/消息篡改、恶意 Agent 检测。
- **关键安全问题**：Agent 间消息是否可信；恶意 Agent 如何检测；串谋/隐写如何识别；拓扑是否泄露。
- **代表论文**：R2-18（G1）；R2-21、R3-12、R3-50、R3-58、R3-62（G2）；R2-22、R3-43、R3-68（G3）；R3-05、R3-24、R3-25、R3-26、R3-67（G4）。
- **与相邻方向区别**：C4 的 R3-59 是拓扑信息提取；G2 是架构/系统评测；G3 是消息/串谋攻击；G4 是检测防御。

### H. Agent 行为安全、对齐与模型脆弱性
- **研究对象**：危险任务/拒绝/运行时护栏、后门/微调/训练数据风险、骨干模型/多模态/表示层鲁棒性。
- **关键安全问题**：模型是否会执行有害任务；拒绝是否可靠；后门是否可植入/检测；多模态与表示层是否稳健。
- **代表论文**：R2-06、R2-24、R3-21、R3-29、R3-31、R3-37、R3-40、R3-53（H1）；R2-04、R2-05、R2-25（H2）；R2-20、R3-32（H3）。
- **与相邻方向区别**：H1 是行为/拒绝/护栏；H2 是训练数据/微调/后门；H3 是骨干/多模态/表示层；D3 是注入检测；B3 是系统隔离。

### I. 真实执行环境、资源与生态外部性
- **研究对象**：Web/GUI/移动/CUA 环境风险、资源滥用/成本攻击、生态传播/内容保护/外部性。
- **关键安全问题**：真实环境中 Agent 能否造成伤害；资源/成本是否被滥用；Agent 生态的外部性如何约束。
- **代表论文**：R2-09、R3-46、R3-57、R3-60、R3-64、R3-73（I1）；R1-15、R3-61（I2）；R3-74、R3-76（I3）。
- **与相邻方向区别**：I1 是具体执行环境；I2 是资源/成本；I3 是生态传播与内容保护；D2 是注入攻击本身；A2 是通用 benchmark。

## 4. 交叉标签（受控词表，v1.1）

分类维度与主类分离；每篇论文可有多个交叉标签，标签可重复计数。

- **身份/授权**：`identity`, `delegation`, `capability`, `least-privilege`, `access-control`, `consent`
- **执行/证明**：`attestation`, `provenance`, `audit`, `verifiable-execution`, `isolation`, `sandbox`, `policy`
- **安全属性**：`privacy`, `pii`, `confidentiality`, `integrity`, `availability`, `accountability`
- **攻击面**：`memory`, `multi-agent`, `mcp`, `skills`, `tool-selection`, `web`, `mobile`, `gui`, `cua`, `prompt-injection`, `jailbreak`, `backdoor`
- **贡献类型**：`benchmark`, `sok-position`, `human-in-the-loop`

## 5. 分类规则

1. **单一主类**：每篇论文一个 `primary_category`，用于计数；允许多个 `secondary_categories` 与 `cross_tags`。
2. **按研究对象而非产出形态归类**：特定环境/协议/工具的 benchmark 归对象分支；只有跨攻击面的通用 benchmark 归 A2。
3. **主类优先级**：若论文同时提出攻击与防御，按“核心研究问题”而非“是否包含防御”归类；核心现象/威胁属于哪个对象，就归哪个主类。
4. **边界注释**：对跨类论文必须在 mapping 中写 `boundary_note`，说明为何选此主类、哪些内容归入交叉标签。
5. **不改变编号**：R1/R2/R3 编号不变；分类迁移只改 mapping，不改论文 ID。
6. **证据可追溯**：每次迁移必须在 `taxonomy_change_log.md` 给出论文 ID、旧类、新类、笔记证据位置（章节/页码）与理由。
